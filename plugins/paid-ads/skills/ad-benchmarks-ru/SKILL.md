# Диагностика рекламных метрик по бенчмаркам РФ

Скилл делает две вещи: (1) **диагностическая процедура** — берёт твои цифры и выдаёт таблицу «метрика / твоё / бенчмарк / вердикт / фикс»; (2) **справочник эталонов** — единая таблица норм, к которой обращаются playbook'и каналов.

> Все цифры — **ориентиры**, не гарантия результата конкретного проекта. CTR/CPM/CPL/CPA сильно зависят от ниши, гео, сезона, качества креативов и посадочной. **Достоверные выводы — только на собственной статистике.** Чужой кейс ≠ KPI твоего проекта.

---

## Когда использовать

1. **«Нормальные ли у меня цифры?»** — есть статистика кампании (кабинет, отчёт подрядчика, скрин) и нужно понять, что в норме, а что проседает → выполни «Процедуру» ниже.
2. **«Подрядчик показывает цифры X — он крутит ботов?»** — дешёвые подписчики/лиды при единичных продажах → Шаг 6 процедуры + `references/spot-the-fraud.md`.
3. **«Что значит ROMI / CAC / AOV и какая норма?»** — определения и формулы → таблица ниже + `references/universal-metrics.md`.
4. **«Какую цифру закладывать в план?»** — быстрый ориентир из сводной таблицы; полноценный медиаплан → скилл `media-planning-ru`.

НЕ использовать для: настройки/ведения кампаний (playbook канала), разбора факта по UTM/GA4 (`full-funnel-analytics-ru`).

## Процедура: сверить свои метрики с бенчмарками

**Шаг 1. Собери входы.** Спроси/извлеки: канал, период, гео (РФ/межд), ниша, цель кампании (лиды/подписчики/продажи) и сырые цифры: показы, клики, расход, лиды/конверсии, **продажи** (обязательно спроси про продажи — без них фрод не отловить). Если даны сырые числа — посчитай производные сам: CTR = клики÷показы×100%, CPC = расход÷клики, CPL = расход÷лиды, CPA = расход÷целевые действия, CR = действия÷переходы×100%.

**Шаг 2. Определи ведущие метрики канала.** По сводной таблице ниже: у Директа ведущие — CTR (Поиск/РСЯ раздельно!), % отказов, CPA; у Telegram Ads — CPM по тематике и цена подписчика; у Meta — связка CPM→CTR→CPC→CR. Прочерк в таблице = метрика не ведущая для канала — не оценивай по ней.

**Шаг 3. Проверь достаточность данных.** Сверь объём с колонкой «Минимум для выводов». Если данных меньше порога (например, <100 кликов в Директе, <50 событий в Meta) — вердикт по этой метрике «➖ рано судить», не выноси приговор.

**Шаг 4. Сравни каждую ведущую метрику с бенчмарком.** Из сводной таблицы; если нужны детальные пороги (лимиты, кейсы, разбивка по тематикам) — открой `references/by-channel.md`. Вердикты: **✅ норма** / **⚠️ тревога** (за пределами нормы, проверить настройку) / **⛔ красный флаг** (паттерн фрода или системная поломка) / **➖ мало данных**.

**Шаг 5. Определи проседающий узел по цепочке.** Читай воронку слева направо: **CPM → CTR → CPC → CR посадочной → CPL → CPA → продажи** — первый сломанный узел и есть точка фикса:
- CPM высокий → аукцион/аудитория/сезон (сузить/сменить аудиторию, пересмотреть ставки, учесть сезонный ×2-3).
- CTR низкий при норм CPM → креатив/заголовок/соответствие оффера аудитории.
- CTR аномально ВЫСОКИЙ (РСЯ >2%, TG >1.5-2% на широких топиках) → подозрение на мусорные площадки/ботов → Шаг 6.
- CPC высокий при норм CTR → ставки/конкуренция по запросам.
- CR посадочной низкий при норм CTR (отказы Поиск >30%, РСЯ >40-50%, Google >45%) → посадочная/оффер/скорость загрузки/несоответствие объявления странице.
- CPL норм, но продаж нет → качество лида (мусорные лиды/боты) или отдел продаж → Шаг 6 + `full-funnel-analytics-ru`.

**Шаг 6. Фрод-скрининг.** Прогони через детектор ботовода (таблица ниже). Главное правило: **дешёвый трафик без продаж = бот-трафик** — проследи путь до продажи, а не до клика/подписки. Совпал красный флаг → вердикт ⛔ и чек-лист проверки подрядчика из `references/spot-the-fraud.md`.

**Шаг 7. Сгенерируй артефакт.** Собери выходную таблицу (шаблон в «## Выход») + блок «Диагноз» (проседающий узел одной фразой) + 1-3 приоритетных действия, отсортированных по влиянию на деньги.

**Шаг 8. Проверь по чек-листу** (внизу) перед выдачей.

## Выход

Артефакт — диагностическая таблица + диагноз + действия. Шаблон (копируй и заполняй):

```markdown
## Диагностика: [канал], [период], [гео/ниша]

| Метрика | Твоё | Бенчмарк | Вердикт | Фикс |
|---------|------|----------|---------|------|
| CTR     | …    | …        | ✅/⚠️/⛔/➖ | … |
| CPC     | …    | …        | …       | … |
| % отказов | …  | …        | …       | … |
| CPL     | …    | …        | …       | … |
| CPA/продажи | … | …       | …       | … |

**Данных достаточно:** да / нет (X из Y минимума — что можно и что нельзя утверждать)
**Диагноз:** проседающий узел — [узел цепочки], потому что [1 фраза].
**Фрод-скрининг:** чисто / ⛔ [какой красный флаг совпал]

**Действия (по приоритету):**
1. …
2. …
3. …
```

Правила заполнения: в «Бенчмарк» — конкретная цифра из таблиц (не «должно быть лучше»); в «Фикс» — действие, а не констатация; если цифры в бенчмарках нет — «н/д в справочнике», **не выдумывай**.

## Пример

**Вход:** «Директ РСЯ за 2 недели: 400 000 показов, 9 200 кликов, расход 60 000 ₽, 150 лидов, отказы 52%, продаж 2. Нормально?»

**Выход:**

## Диагностика: Яндекс.Директ (РСЯ), 2 недели, РФ

| Метрика | Твоё | Бенчмарк | Вердикт | Фикс |
|---------|------|----------|---------|------|
| CTR | 2.3% | РСЯ <2% (идеал <1%) | ⚠️ выше нормы | проверить площадки: приложения `af://`, `id://` с CTR 30-100% → минусовать |
| CPC | 6.5 ₽ | производная, сама по себе ок | ✅ | — |
| % отказов | 52% | РСЯ <40-50% | ⚠️ | чистка площадок + проверка посадочной |
| CPL | 400 ₽ | зависит от ниши | ➖ сверить с юнит-экономикой | — |
| Лиды→продажи | 150 → 2 (1.3%) | конверсии соразмерны объёму лидов | ⛔ | прослушать/просмотреть лиды, путь до продажи |

**Данных достаточно:** да (9 200 кликов >> минимума 100).
**Диагноз:** узел «CPL→продажи» — лиды дешёвые, но не покупают; в связке с CTR >2% и отказами 52% это паттерн мусорных площадок РСЯ (бот-трафик из приложений).
**Фрод-скрининг:** ⛔ «куча дешёвых лидов + единичные продажи».

**Действия:**
1. Отчёт по площадкам → исключить все `af://`/`id://` и площадки с CTR-аномалией.
2. Проверить качество 150 лидов (телефоны, ответы) — сколько живых.
3. Пересчитать CPL только по живым лидам и сравнить с допустимым CAC.

## Быстрый детектор ботовода

Универсальный принцип распознавания серого подрядчика во всех каналах:

> **Дешёвый трафик без продаж = бот-трафик.** Проследи путь до продажи, а не до подписки/клика. Красивый CTR и тысячи дешёвых подписчиков при единичных продажах — почти всегда накрутка.

| Канал | Красный флаг (ботовод) | Норма |
|-------|------------------------|-------|
| **VK Ads** | подписчик **20-40 коп.** | 150-300 ₽ |
| **Telegram Ads** | подписчик **<30-40 ₽**; CTR **1.5-2%+** на широких топиках; серые топики (ASERS/Others, BS and Gambling, Offers and Promotions) | подписчик 150-300 ₽; CTR текст РФ 0.5-0.7% |
| **Яндекс РСЯ** | CTR **>2%** (приложения `af://`, `id://` с CTR 30-100%) | CTR <2%, идеал <1% |
| **Блогеры/посевы** | высокий ERR24 + низкий ER + плоский график + скачки подписчиков | органичный рост, реальные продажи |
| **Любой канал** | куча дешёвых лидов/событий + **единичные конверсии в продажу** | конверсии соразмерны объёму лидов |

Чек-листы проверки по каждому каналу + конкретные формулировки вопросов подрядчику — **`references/spot-the-fraud.md`**.

## Универсальные метрики (определения)

Шпаргалка-минимум; полные формулы и нормы — **`references/universal-metrics.md`**.

| Метрика | Расшифровка | Формула | Что значит |
|---------|-------------|---------|------------|
| **CTR** | Click-Through Rate | клики ÷ показы × 100% | кликабельность объявления |
| **CPM** | Cost Per Mille | расход ÷ показы × 1000 | цена 1000 показов |
| **CPC** | Cost Per Click | расход ÷ клики | цена клика |
| **CPL** | Cost Per Lead | расход ÷ лиды | цена лида |
| **CPA** | Cost Per Action | расход ÷ целевые действия | цена целевого действия |
| **CR** | Conversion Rate | действия ÷ переходы × 100% | конверсия этапа |
| **ROMI** | Return On Marketing Investment | (прибыль − затраты) ÷ затраты × 100% | окупаемость маркетинга |
| **ROAS** | Return On Ad Spend | выручка ÷ рекламный расход | доход на 1 ₽ рекламы |
| **CAC** | Customer Acquisition Cost | расход ÷ новые клиенты | стоимость клиента |
| **LTV** | Lifetime Value | средний доход с клиента за всё время | пожизненная ценность |
| **AOV** | Average Order Value | выручка ÷ число заказов | средний чек |

**Оценка результата по бизнес-модели:** e-commerce → ROMI, ROAS, LTV, CAC, AOV, CR в оплату (лучшая команда = низкий CAC + высокий ROMI/ROAS + объёмы); лидген → то же + CPQL (cost per qualified lead) и CR из лида в квал-лид.

## Когда какой канал

Краткий ориентир (детали по запуску — в playbook'ах):

- **Яндекс.Директ** — РФ, горячий спрос (Поиск) + догрев (РСЯ). Единственный контекст в РФ (Google для рекламодателей заблокирован).
- **Google Ads** — международка/СНГ. CTR Search выше в СНГ (10-15%), ниже на Западе (5-7%).
- **Telegram Ads** — РФ + межд, охват по топикам/каналам. При бюджете <500K₽/мес — только каналы, не топики.
- **VK Ads** — РФ, точные аудитории через парсинг (ключевые фразы — сильнейшая зацепка).
- **Meta Ads** — только межд/СНГ (в РФ запрещена). Сильный алгоритм при аудитории >100-200K.
- **Блогеры/посевы** — органика-подобный охват, портфель 60/30/10, обязательна таблица закупа.

## Чек-лист (перед выдачей диагностики)

- [ ] Спрошены/учтены **продажи**, а не только лиды/подписчики — иначе фрод невидим.
- [ ] Производные метрики пересчитаны из сырых цифр (не взяты на веру из отчёта подрядчика).
- [ ] Сверка идёт по **ведущим** метрикам канала; по прочеркам вердикт не вынесен.
- [ ] Достаточность данных проверена; при нехватке стоит «➖ рано судить», а не приговор.
- [ ] Каждая строка таблицы содержит конкретное число-бенчмарк и конкретный фикс-действие.
- [ ] Диагноз указывает ОДИН первый сломанный узел цепочки CPM→CTR→CPC→CR→CPL→CPA→продажи.
- [ ] Фрод-скрининг выполнен (детектор ботовода прогнан).
- [ ] Ни одна цифра не выдумана — чего нет в справочнике, помечено «н/д».
- [ ] Оговорка про ориентиры (ниша/гео/сезон) присутствует, вывод опирается на собственную статистику клиента.
