Все команды — из корня проекта `~/VideoJobs/<ГГГГ-ММ-ДД>-<slug>/`, созданного `scripts/new_project.py` (в вызове

`<эталон>/`. Время этапов — замеры эталона: журнал `out/chain_v5.log` и проверки 05.10.2026 на

сцены → проверка кадров → звук → рендер и сдача (с. 16). Отступление одно: рендер в MP4 у методички — HyperFrames
(с. 2, 12, 23), здесь — свой `render/render.py`. HyperFrames на такой канве давал 1,3 с на кадр, а `render.py` с
шестью страницами Playwright — 33–67 мс на кадр по часам. Страница при этом совместима с HyperFrames

## 1. Вопросы (с. 16, 23)

Правила методички: пакетами по 3–4 вопроса, у каждого 2–4 готовых варианта, рекомендуемый первым; в каждом пакете
вариант «СТОП — решай сам», после него больше не спрашивать и брать рекомендуемое; уже отвеченное не переспрашивать
(с. 23). Рекомендуемые варианты ниже — решения эталона.

Пакет 1 — стиль и формат:

1. Стиль: оба, карандаш и глянцевое 3D (один сценарий и тайминг на оба) / только карандаш / только 3D /
   СТОП — решай сам.
2. Формат: 16:9 и 9:16 / только 9:16 (рилсы, сторис) / только 16:9 / СТОП.
3. Длина: около минуты, цепочка сцен (эталон — 65,6 с) / около 30 с / до 15 с, одна сцена в 3–4 фазы (с. 17) /
   СТОП.
4. Звук: голос автор + синтезированные эффекты и музыка / только синтез, без голоса (умолчание методички, с. 23) /
   СТОП.

Пакет 2 — сюжет и оформление:

1. Сюжет: 2–3 идеи в одну строку каждая (с. 16) / СТОП.
2. Палитра: тетрадь (графит на клетке) / другая тема из `palettes.md` / брендбук из папки проекта (с. 21, 23) /
   СТОП.
3. Герой: маскот автора (яичница-Сократ, `engine/hero_egg.js`) / новый герой по `engine/hero_template.js` / без
   героя / СТОП.
4. Плакат в конце: продукт, дата, куда идти — дать формулировку / СТОП.

Дал владелец ролики-примеры — разбор по `storyboard.md`, раздел 1 (навык `watch-video`, 3–5 примеров).

## 2. Сценарий → ГЕЙТ 1

1. `SCRIPT_v1.md` по `storyboard.md`: таблица по сценам и «Что проверить при утверждении».
2. Показать владельцу текст и спорные пункты. **Ждать «ок» на этот текст.** До «ок» не озвучивать и не писать
   сцены под голос.
3. После «ок» — `voice/script.txt`: текст для экрана слово в слово.
   - Цифры только парой `{показ|произношение}`: `{11,4 млн|одиннадцать и четыре десятых миллиона}`. Цифру вне пары
     `voice.py` не пропустит — падеж решает человек.
   - Бренды переписываются сами (список `BRANDS` в `voice/voice.py`): Claude Code → «Клод Код», API → «эй-пи-ай».
     Свой бренд — дописать парой в `BRANDS` этого проекта.
   - Ударение, которое v4 путает, — фонетической записью со знаком ударения внутри пары. Подробно — навык
     `elevenlabs` (`~/.claude/skills/elevenlabs/`, раздел про ударения и темп v4).

Черновой тайминг без голоса — чтобы проверить стиль или собрать тестовый ролик 6–10 с (с. 23) до озвучки:

```bash
python timing/fake_timing.py [--rate 2.6]
```

Пишет `timing/timing.json` и `timing/timing.js` с `"draft": true` в той же форме, что `build_timing.py`, с теми же
именами сцен; `render.py` на черновом тайминге предупреждает `DRAFT timing`. Когда придёт голос, времена
сдвинутся, поэтому сцены берут время только из `W('слово')` и `K.scene()`.

## 3. Голос

```bash
python voice/voice.py voice --dry-run                     # что прозвучит: бренды и пары уже подставлены, без API
python voice/voice.py voice --takes 3 [--voice-key ИМЯ]   # озвучка, тратит кредиты
```

- ElevenLabs `eleven_v4`. Голос: `--voice-id`, иначе переменная окружения `ELEVENLABS_VOICE_ID`, иначе переменная,
  названная `--voice-key` (по умолчанию `ELEVENLABS_VOICE_ID`), в `~/.claude/.credentials.master.env`. Ключ `ELEVENLABS_API_KEY` — оттуда же.
- Аудит ударений (`voice/stress_audit.py` + `voice/phones.py`: RUAccent и распознаватель фонем) нужен только при
  `--takes` больше 1 и требует `pip install ruaccent transformers torch librosa huggingface_hub`. Без них скрипт
  пишет об этом, ставит каждому дублю 0 баллов и оставляет первый.
- `--takes N`: до N дублей, каждый тратит кредиты. Каждый дубль проходит аудит ударений, остаётся лучший, на дубле
  без проблем озвучка останавливается. Эталон: 2 дубля, второй без проблем ударения (`voice/alignment.json`:
  `take 1`, `stress_score 0.0`).
- Выход: `spoken.txt`, `voice_take{k}.mp3`, `voice.mp3`, `alignment.json`, `words.json` (`[{w, s, e}]`, слово
  хранит пунктуацию, одиночное тире приклеено к соседу: `'вышло —'`), `voice.wav` 48 кГц стерео.
- Повторный запуск без `--force` кредитов не тратит: пересобирает `words.json` и `voice.wav` из `voice.mp3`.
  Изменился `script.txt` — скрипт остановится с просьбой `--force` (новая озвучка, кредиты).
- `--tempo 1.06` — «чуть быстрее»: растяжка по времени, тайминги слов делятся на тот же коэффициент.
- Проверка: строка итога (`N слов, голос X с, дубль k, проблем ударения S, последнее слово кончается на T с`) и
  прослушка отмеченных слов.
- Голос не из ElevenLabs (запись, другой синтез): нужны те же `voice/words.json` в форме `[{w, s, e}]` и
  `voice/voice.wav`. Слова с таймингами даёт навык `deepgram` (nova-3). На эталоне этот путь не проверялся.

## 4. Тайминг

Правка `timing/timing_config.json`:

- `scenes`: `[имя сцены, первое слово сцены, номер вхождения]` — граница сцены ставится словом, не секундами;
- `pauses`: `[слово, номер вхождения, секунды]` — тишина после слова сверх естественной паузы (стыки сцен, поворот);
- `turn`: `[слово, номер вхождения]` — слово поворота;
- `lead` 0,7 с (первый кадр уже рисунок, голос вступает позже), `tail` 3,6 с (плакат после последнего слова).

```bash
python timing/build_timing.py
```

Печатает длину, таблицу сцен с первыми словами, положение поворота с пометкой `ok` или `OUTSIDE 35-45 %` и
предупреждение, если после последнего слова меньше 3 с. Пишет `timing/voice_final.wav` (голос с паузами),
`timing/timing.json` (для Python) и `timing/timing.js` (`window.TIMING`). Страницы грузят `../timing/timing.js` —
копировать ничего не надо (в эталоне это была ручная копия в `pencil/timing.js`).

Гейт тайминга:

- каждая сцена начинается на своём слове;
- поворот в 35–45 % (с. 17). Эталон вышел на 53 % (конец слова поворота «фраза.», 34,74 с из 65,63; сам щелчок —
  52 %) — поворот правится текстом до сцен, а не кодом после;
- после последнего слова ≥ 3 с под плакат (с. 17).

Любая правка текста, голоса или пауз → заново `build_timing.py` → заново лист звуков и звук (с. 20) → заново
рендер.

## 5. Сцены

- Файлы после разворота шаблона: `pencil/scenes.js` (сцены карандаша), `pencil/lib.js` (готовые рисунки и
  палитры), `engine/hero.js` или `engine/hero_egg.js` (герой), `gloss/scenes3d.js` (3D).
- Устройство файла сцен: `SETUP()` создаёт перо и пишет весь лист звуков `cue(t, kind, g)`; на сцену — функция
  `sN(tt)`; словарь `SCENES = { имя: функция }` по именам из `TIMING.scenes`; `renderAt(t)` выбирает сцену по `t`
  и рисует её от `tt = K.twos(t)`. Образец — `pencil/scenes.js` из шаблона, полный пример —
  `<эталон>/pencil/scenes.js`.
- Имена сцен совпадают в `timing_config.json`, `SCENES` карандаша и `SCENES` + `WALL` в 3D, иначе `renderAt`
  падает с TypeError.
- По кускам: одна-две сцены за заход, после каждой — кадры (этап 6), потом следующая (с. 17).
- ДНК — `dna-pencil.md`, `dna-gloss3d.md`; палитры — `palettes.md`.
- 3D-страница — ES-модули, с `file://` они не грузятся. Шаблонные `render.py` и `still.py` сами поднимают сервер
  на свободном порту внутри своего процесса и дают GPU-флаги (`render/pagekit.py`): держать сервер в фоне не надо,
  с другим проектом порт не столкнётся. В эталоне сервер поднимали руками из корня
  (`python -m http.server 8731 --bind 127.0.0.1`), порт 8731 зашит в его `render.py`; такой сервер умирает при
  перезапуске сессии, а чужой сервер на 8731 молча подсовывает страницы другого проекта.
- WebGL в безголовом Chromium: `--use-angle=d3d11 --enable-gpu --ignore-gpu-blocklist --enable-unsafe-swiftshader`.
  Одна страница 3D на GPU — около 160 мс на кадр, программный WebGL в разы медленнее. Предупреждения шейдеров
  `X4122` / `X4008` в консоли — компилятор D3D, не ошибка.

## 6. Кадры → ГЕЙТ 2

Методичка: перед показом 8–12 ключевых кадров и лист кадров, агент смотрит их сам (с. 4, 11, 16, 23). Снимаются два
листа: сюжет (история читается без звука) и стыки (последний кадр сцены рядом с первым кадром следующей).

Моменты сюжета — кадр 0, середина каждой сцены, кадр сразу после поворота и последний кадр ролика:

```bash
python -c "
import json, math
T = json.load(open('timing/timing.json', encoding='utf-8')); F = T['fps']
f = [0] + [round((s['start'] + s['end']) / 2 * F) for s in T['scenes']] + [round(T['duration'] * F) - 1]
if T.get('turn'): f.append(math.ceil(T['turn']['t'] * F) + 2)
print(','.join(f'{k / F:.10f}' for k in sorted(set(f))))"
python $Q/qa_frames.py cuts timing/timing.json
```

Вторая команда печатает пары кадров у каждого стыка с готовыми временами. Эталон: сюжет — 9 моментов (кадр 0,
7 середин, кадр 1574), стыки — 6 пар (181/182, 439/440, 739/740, 907/908, 1151/1152, 1383/1384).

```bash
python render/still.py pencil/index.html out/qa/story/land <времена сюжета> land --det
python render/still.py pencil/index.html out/qa/cuts/land <времена стыков> land
python render/sheet.py out/qa/sheet_story_land.png 3 0.25 out/qa/story/land_*.png
python render/sheet.py out/qa/sheet_cuts_land.png 4 0.25 out/qa/cuts/land_*.png
```

То же с `port` — для 9:16, с `gloss/index.html` — для 3D.

- `still.py` сам создаёт папку префикса. `--det` снимает каждый момент второй раз в обратном порядке и сравнивает
  пиксели: ловит `Math.random`, часы и состояние между кадрами. `NOT READY` — в странице ошибка JavaScript, скрипт

- Время — точное время кадра `f/24` (`python $Q/qa_frames.py t 240,241`): округлённое `10.083333` даёт предыдущий

## 7. Лист звуков

Лист собирается в `SETUP()` страницы, поэтому его выгружает любой рендер, даже из двух кадров:

```bash
python render/render.py pencil/index.html out/cues.mp4 --to 0.1 --workers 1
python $Q/qa_cues.py out/cues.cues.json
```

→ `out/cues.cues.json`: `[{t, k, g, p?}]` — время в секундах, вид эффекта, множитель громкости, высота щипка в Гц
(только у `snap`). Проверено на эталоне: 2 кадра за 3,4 с, 92 события, совпадают с листом полного рендера.

- Лист у каждой страницы свой. В первой версии эталона он был только у карандаша, и звук всех четырёх роликов
  собирался по нему (у 3D `cues.json` был пуст); потом 3D получила свой лист в `gloss/scenes3d.js` и свой микс на
  стиль (`sound/mix_gloss_land.wav` и т. д.).
- Попадание звука в кадр — до 40 мс (с. 9, 23). На двойках событие, нарисованное при `tt >= T`, появляется на
  первой двойке не раньше `T`, то есть звук, поставленный ровно в `T`, приходит раньше рисунка на величину до
  1/12 с (83 мс). Эталон до правки: 39 из 92 событий звучали раньше рисунка больше чем на 40 мс, худшее — на 80 мс
  (`qa_cues.py`). Лечение, принятое в эталоне (`pencil/scenes.js`, `gloss/scenes3d.js`; `pitfalls.md`, раздел 4):
  событие в сцене начинается при `tt >= T`, а `cue()` сам ставит время на сетку двоек —

  ```js
  const cue = (t, k, g = 1, extra) => CUES.push(Object.assign({ t: +(Math.ceil(t * 12 - 1e-6) / 12).toFixed(3), k, g }, extra || {}));
  ```

  После правки все 92 события эталона стоят на сетке. Если `qa_cues.py` показывает ровно 83 мс у времени вида
  5.917, это округление `toFixed(3)` точки сетки 71/12, а не рассинхрон. Проверка удара в готовом MP4 —
  `frame-checks.md`, раздел 4.1.

## 8. Звук

```bash
python sound/synth.py out/cues.cues.json timing/timing.json timing/voice_final.wav sound/mix.wav
```

- Вместо голоса можно `none` — только музыка и эффекты (годится для чернового тайминга). `--no-music` — без
  музыки, `--music-only out/music.wav` — отдельно музыкальная дорожка.
- Печатает строку музыки (`music: 100 bpm, bar line on … s (cue 'click'), …; form A@…, B@…`) и итог
  (`mix.wav: <длина> s, <N> cues, voice: yes; result <I> LUFS, true peak <TP> dBTP`): громкость меряется по
  записанному файлу, а не берётся из цели.
- Что внутри: эффект синтезируется по виду (`sfx_for`, 28 видов эталона) и кладётся в время из листа; вид без
  рецепта пропускается с `WARNING` (или останавливает синтез — переключатель `UNKNOWN_KIND`). Музыка — щипковый
  синтезатор 100 bpm, тактовая черта ровно на ударе `click`, без него — на слове `turn` из `timing.json`; части
  музыки берутся из сцен. Музыка приседает под голос; смесь голос 1,0 + эффекты 0,9 + музыка 0,62, затухание
  0,6 с в конце; громкость — `loudnorm` в два прохода до −15 LUFS, истинный пик −1 dBTP; 48 кГц.
- Эталонный синтез на ролике 65,6 с — 17 с.
- Падение синтеза должно быть видно: не прятать вывод за `| tail -1 &&`. В эталоне упавший синтез (массивы 19200 и
  24000 при сложении) скрылся за таким конвейером, и в ролик ушёл старый звук. Проверять код выхода и время
  изменения `mix.wav`.
- Эффекты не должны тонуть под голосом: `python $Q/qa_audio.py hit sound/mix.wav <t>` сравнивает громкость 80 мс
  после события со 100 мс перед ним (эталон, щелчок 33,98 с: +27,3 дБ; порог и эталонные «утонувшие» щелчки —
  `frame-checks.md`, раздел 4.1); `qa_audio.py onset … <t>` — где самый громкий отсчёт относительно `t` (эталон:
  +1 мс).
- Громкость мерить на готовом MP4, не только на WAV: AAC поднимает истинный пик. Эталонный `mix_land.wav` −1,0
  dBTP, в MP4 (AAC 192k) −0,6, в превью (AAC 160k) +0,3; шаблонный черновик без голоса — −0,97 в WAV и −0,8 в MP4.
  Методичка требует пик до −1 dBFS (с. 23). Лечение — `TRUE_PEAK = -1.5` в `sound/synth.py`: после AAC 192k
  −1,3 dBTP при тех же −15 LUFS (эталон — `frame-checks.md`, раздел 4; шаблон 05.10.2026 — −1,47 в WAV, −1,3 в MP4).
- Изменилась длина — лист звуков и звук пересобрать: «звук разъехался с картинкой» (с. 20).

## 9. Рендер

```bash
python render/render.py pencil/index.html out/pencil_land_v1.mp4 --fmt land --workers 6 --audio sound/mix.wav --last-frame
python render/render.py pencil/index.html out/pencil_port_v1.mp4 --fmt port --workers 6 --audio sound/mix.wav --last-frame
python render/render.py gloss/index.html  out/gloss_land_v1.mp4  --fmt land --workers 6 --audio sound/mix.wav --last-frame
python render/render.py gloss/index.html  out/gloss_port_v1.mp4  --fmt port --workers 6 --audio sound/mix.wav --last-frame
```

- Опции: `--fmt land|port`, `--extra 'k=v&k2=v2'` (доп. query страницы), `--fps 24`, `--workers 6`, `--from`,
  `--to`, `--audio`, `--q 95` (качество JPEG кадров), `--keep` (оставить кадры), `--last-frame` (последний кадр
  MP4 в `<выход>.last.png`), `--http` (отдать по http и страницу вне `gloss/`), `--gpu` / `--no-gpu` (включить или
  выключить GPU-флаги принудительно).
- Кадры раздаются страницам вперемешку: каждая из N страниц берёт каждый N-й кадр (равная нагрузка). Кадры —
  JPEG в `<выход>.frames/`, сборка — ffmpeg libx264 crf 17 и AAC 192k. Папка кадров стирается в начале и удаляется
  в конце (без `--keep`). Ошибка страницы, пропавший шрифт или скрипт останавливают рендер.
- Звук добивается тишиной до длины видео: короткий микс картинку не обрежет (в эталоне `-shortest` без добивки
  обрезал бы).
- В конце печатает `N frames in X s (Y ms/frame wall, W workers); C cues` и строку `check: video … fps, … s; audio
  …` по `ffprobe`; если длина разошлась с ожидаемой больше чем на 0,05 с — `WARNING`.
- Несколько рендеров — по очереди: GPU и CPU общие. Пример цепочки — `<эталон>/render/chain_v5.sh`
  (журнал в `out/chain_v5.log`).

## 10. Проверка готового MP4 (с. 16, 23)

Проверены на `out/pencil_land_v5.mp4` эталона.

1. Строка `check:` из `render.py` (или `ffprobe` на любом MP4): h264 1920×1080 или 1080×1920, `24/1`, длина = кадры /
   24 (эталон: 1575 кадров, 65,625 с), есть поток aac.

   ```bash
   ffprobe -v error -show_entries stream=codec_type,codec_name,width,height,r_frame_rate,nb_frames -show_entries format=duration -of compact out/pencil_land_v1.mp4
   ```

2. Громкость и пик (с. 23): `I` от −16 до −14 LUFS, пик не выше −1. Эталон: −15,0 LUFS, −0,6 dBTP — превышение
   0,4 дБ из-за AAC (этап 8).

   ```bash
   python $Q/qa_audio.py loud out/pencil_land_v1.mp4
   ```

3. Последний кадр (`<выход>.last.png` от `--last-frame` или `ffmpeg -v error -y -sseof -0.1 -i <mp4> -frames:v 1
   -update 1 last.png`) — посмотреть глазами: плакат, весь текст на месте (с. 18, 23).
4. Звук на месте событий: `qa_audio.py hit <mp4> <t>` и `onset` на 3–4 главных ударах из листа звуков.

Полная таблица проверок MP4 (чёрные и застывшие куски, голос над музыкой) — `frame-checks.md`, раздел 4.

## 11. Внешний критик

```bash
python render/critic.py out/pencil_land_v1.mp4 out/critic_pencil_v1.md [--style "рисованный карандашный мультик"] [--extra "на что смотреть"]
```

- Gemini (`gemini-3.1-pro-preview`, `--model` меняет) смотрит ролик со звуком; платный вызов, ключ `GOOGLE_API_KEY`
  из `~/.claude/.credentials.master.env`. Сценарий — самый свежий `SCRIPT*.md` в корне проекта (или `--script`).
- Ответ — таблица «таймкод | что не так | насколько заметно | как исправить» и три строки: лучшее, худшее, оценка
  1–10.
- Полезен по картинке: читаемость, композиция, куда смотреть. Каждое утверждение проверяется замером до правки:
  - «двигается», «прыгает», «обрезано» → два кадра `still.py` вокруг таймкода и
    `python $Q/qa_frames.py diff A.png B.png x0,y0,x1,y1`. Эталон: критик «видел», как дерево двигается, а замер
    дал 0 изменённых пикселей по всему дереву между 34,5 и 37,7 с (кипят только подписи — так задумано);
  - «нет звука», «эффект не попадает» → `qa_audio.py hit` и `onset` в момент события из листа звуков. Эталон:
    «нет эффектов» на щелчке, а пик там −0,9…−1,1 dBFS и +27 дБ над предыдущими 80 мс;
  - «не совпадает с голосом» → время слова в `timing.json` против кадра события.
- Все сверки критика эталона с замерами (в том числе одна, где он оказался прав: щелчки `snap` тонули под голосом) —
  `frame-checks.md`, раздел 5. Подтвердилось — исправить и снять кадры заново; новая ошибка — строка в
  `pitfalls.md`.

## 12. Превью владельцу → ГЕЙТ 3

Лимит бота Telegram — 50 МБ, ролик пережимается (65,6 с выходят в 32–33,5 МБ):

```bash
ffmpeg -v error -y -i out/pencil_land_v1.mp4 -c:v libx264 -preset slow -b:v 4300k -maxrate 5000k -bufsize 9000k -pix_fmt yuv420p -c:a aac -b:a 160k -movflags +faststart out/preview_pencil_land_v1.mp4
```

Отправка — только владельцу, без звука уведомления: `render/send_preview.py` (есть в каждом проекте). Рядом короткие
HTML-файлы: шапка и подписи к видео (разметка Telegram: `<b>`, `<i>`, `<a>`, `<blockquote>`). Сначала `--dry-run`:
размеры файлов и длина подписей, лимиты — 50 МБ и 1024 знака после разметки.

Подпись-пост оформлять, а не писать сплошным текстом: жирный заголовок, жирные подзаголовки, список с маркерами ▫️,
главная мысль в `<blockquote>`. Сплошной абзацный текст владелец вернул как «стену текста» (05.10). Скрипт печатает
типы сущностей, которые распознал Telegram (`entities {'bold': 8, 'blockquote': 1}`): пустой список означает, что
разметка не сработала.

Свой бот: токен `TELEGRAM_BOT_TOKEN` и чат `PREVIEW_CHAT_ID` — в `~/.claude/.credentials.master.env` (или
`BOT_TOKEN` в окружении и `--chat`); токен никуда не печатается:

```bash
python render/send_preview.py --dry-run out/prev_hdr.html out/preview_pencil_land_v1.mp4:out/cap_land.html
python render/send_preview.py out/prev_hdr.html out/preview_pencil_land_v1.mp4:out/cap_land.html
```

- `send_preview.py [--chat ID] <шапка.html> <видео.mp4>:<подпись.html> […]`; ширина и высота видео ставятся по `port`
  в имени файла. На каждую отправку печатает `True`, номер сообщения и сущности разметки, при отказе — описание
  ошибки Telegram.
- Пик звука превью может быть выше −1 dBFS (второе сжатие AAC) — для просмотра владельцем это не важно; правило
  громкости относится к сдаваемому MP4.
