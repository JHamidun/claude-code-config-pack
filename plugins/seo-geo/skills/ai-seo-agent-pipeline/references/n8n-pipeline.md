# n8n Pipeline — архитектура AI SEO агента (эксперт/

Детальная архитектура low-code workflow на n8n.

> ⚠️ **Статус источника — читать до сборки.** У занятия по агенту **не было доски Miro**, а
> единственный раздаточный артефакт — **JSON-шаблон n8n-workflow**, выгруженный прямо во время
> занятия и разосланный в чат курса (в материалах фигурирует как `AI SEO Writer.json`, 20.5 KiB,
> приложен к уроку в Notion). **Этого файла на руках нет.** Всё, что ниже про состав и связи нод, —
> **реконструкция по устному разбору экрана**, а не дамп оригинала: назначение узлов и
> последовательность верны, точные параметры нод и их имена — нет. Если оригинальный JSON найдётся
> в материалах курса — импортировать его (n8n → Import from File) и считать источником правды,
> а этот файл — комментарием к нему.

> **Где потолок n8n.** Годится, когда делаешь тестовый продукт или внедряешь у себя на небольших
> объёмах — нагрузку выдержит и задачи закроет. Но он «недостаточно гибкий, потому что это больше
> workflow automation, нежели полноценная агентская система»: нет нормального состояния между
> запусками, ветвление и retry описываются нодами вместо кода, tool calling ограничен рамками
> ноды. Боевые агенты у автора метода (клиенты — Semrush, Revolut, Яндекс) написаны **кодом**;
> low-code показывается как способ повторить логику и проверить её до разработки. Тысячи страниц —
> переписывать на код.

## Последовательность (текстом, для чтения без диаграммы)

1. **Trigger** принимает seed-фразу (ключевой запрос). Один запуск = одна страница.
2. (Опц.) **ТЗ из Google Doc** парсится в JSON (intent, keywords, meta, структура, длина).
3. **Perplexity** анализирует выдачу, собирает ссылки (citations), парсит контент, даёт summary.
   Perplexity заменяема любой LLM с браузингом.
4. Из citation-ссылок **извлекаются тексты** → собирается research-материал.
5. **Копирайтер-агент** генерирует SEO-статью по строгому промпту и параметрам. Output — JSON.
6. **Изображения** (LLM) + alt-тексты, оформление в **HTML** по фиксированной структуре блоков.
7a. **Вариант A:** статья → Google Docs → Gmail (на email). Конец.
7b. **Вариант B:** Supabase ищет релевантные опубликованные статьи → вставляются internal links.
8. Финальный **JSON** (смысл не меняется) → **CMS API** → автопубликация в нужной категории.
9. **Supabase** записывает новую статью → растёт база для перелинковки, ускоряется индексация.

## Ролевая цепочка производства статьи (как это устроено в боевой системе)

В продакшене за «копирайтером» стоит не один промпт, а пять ролей — их полезно держать
раздельными даже в n8n, потому что каждую можно чинить отдельно:

| # | Роль | Что делает |
|---|------|-----------|
| 1 | **Research** | Исследует тему и конкурентов, собирает материал (узел 3-4 конвейера) |
| 2 | **Outline** | Собирает аутлайны, драфтит бриф под статью |
| 3 | **Properties** | Прописывает title, мета и остальные свойства страницы |
| 4 | **Writer** | Пишет полноценный драфт и **адаптирует стиль под клиента** (TOV — параметр, а не догадка) |
| 5 | **SEO** | Финализирует и проверяет оптимизацию: какие **primary и secondary keywords** покрыты |

Три агента, которые в разборе идут **после копирайтера** и в базовой схеме часто теряются:

- **Styling-агент** — требования к форме: обязательные ссылки, headings, spacing, курсив, bullet
  points, цитаты, выделение жирным ключевых элементов, гиперссылки.
- **Перелинковка** — тот же styling-агент, подключённый к **Supabase**: ходит в базу
  опубликованных статей, находит похожие и проставляет internal links. «За счёт чего SEO
  продвигается гораздо быстрее».
- **Мета-агент** — формирует title, slug, meta; работает через **negative prompt + positive
  prompt** и **дополнительно перепроверяет статью** на соответствие тому, как она должна была быть
  сгенерирована. То есть последний узел — ещё и контроль качества, а не только метаданные.

## Вариант B по узлам: от ТЗ до опубликованной статьи

Схема, по которой работает клиент автора метода:

1. **Ссылка на Google Doc с брифом** кладётся в чат прямо в интерфейсе n8n.
2. **Нода Google Docs** парсит документ и отдаёт сырой текст дальше.
3. **Нормализующий промпт** превращает сырой текст в **строгий JSON**: `root`, `title`,
   `documentId`, `contentItem`, `type`, `heading`, параграфы, таблицы. В промпте явно прописано,
   что output — **только JSON, без артефактов**: иначе ломается генерация ниже по потоку и тексты
   получаются хуже.
4. **Генерация изображений** + **alt-тексты** для индексации. В разборе картинки генерятся
   ChatGPT с оговоркой, что Nano Banana дал бы качество лучше, «но для задачи получать трафик пока
   достаточно». В стеке пользователя — только разрешённые модели (правило `dont-do`, скилл
   `image-generation`).
5. **Копирайтер** получает весь контекст сразу: нормализованное ТЗ + картинки + требования
   (technical requirements, post structure, keywords, length and depth).
6. **JSON-конвертер** — отдельный узел с жёсткими запретами: **не добавлять новый текст, не
   добавлять секции, не менять смысл**, только преобразовать формат (промпт → `prompts.md` §7).
7. **WordPress через API** принимает JSON и сам публикует статью в заданную категорию, сам
   вставляет картинки в нужные блоки и рисует таблицы.

Наблюдение по результату, которое стоит держать в голове при споре о качестве: «иногда сам артикул
может быть не особо читаемым — при этом его читают, скроллят и прямо вчитываются». Пользовательские
метрики на таких страницах не проваливаются (конверсионные бенчмарки → `programmatic-strategy.md`
→ раздел «Конверсия»).

## Citations vs Search results — две разные игры из одного прогона

Самая недооценённая деталь конвейера. Perplexity (и любая LLM с браузингом) отдаёт **два набора
ссылок**, и обращаться с ними надо по-разному:

| Блок | Что это | Стратегия |
|------|---------|-----------|
| **Citations** | То, на что ссылается сама LLM, формируя ответ. Блок «нужный для LLM» | **GEO-стратегия:** собрать источники, которые модель цитирует по этому запросу → разместиться в них самому → сделать по теме контент лучше оригиналов, чтобы индексироваться выше них |
| **Search results** | Обычная органическая выдача Google/Яндекса | **Классическое SEO:** это позиции, куда мы хотим встать своей страницей |

Дальше агент парсит содержимое по **всем** ссылкам и отдаёт корпус копирайтеру — то есть один
прогон даёт и материал для статьи, и **карту источников для GEO**. Второе обычно теряется:
citations уходят в общую кучу вместе с выдачей и не собираются.

**Что делать в workflow:** после research-ноды разветвить поток. Одна ветка — в корпус для
копирайтера (как сейчас). Вторая — писать citations отдельной таблицей: `query | citation_url |
domain | дата прогона`. Накопленная за месяц таблица — готовый список целей для размещения и
аутрича, отсортированный по частоте появления домена.

Расширение того же приёма: **из каждой спарсенной ссылки выписывать отдельные keywords и
отдельные пользовательские вопросы** — они идут в FAQ-секцию страницы. Именно FAQ-блоки обычно
используются для индексации в LLM.

Полная методология измерения видимости и Citation Share → скилл `geo-aeo-ru`. Ручная версия приёма
(без n8n, одним прогоном в Perplexity) → `skills/seo-machine-ru/references/aeo-geo.md`.

## Три режима входа (один workflow, разные ноды на старте)

Конвейер за узлом 3 одинаков во всех трёх случаях — меняется только то, что подключено на вход:

| Режим | Вход | Когда |
|-------|------|-------|
| **A. Seed-запрос** | n8n Form с полем `query` | Разовая статья, тест конвейера, ручной запуск. Работает и на русском |
| **B. Бриф от редактора** | Менеджер кладёт **ссылку на Google Doc с ТЗ в чат прямо в интерфейсе n8n**; нода Google Docs парсит документ | Редакционный процесс: есть человек, который пишет ТЗ. Бриф содержит описание статьи, ключевые слова, интент, метаданные (title, meta description, meta keywords, robots, canonical), структурированные данные, иногда полную структуру контента |
| **C. База ключей** | Вместо формы/документа — **нода с базой данных готовых ключевых слов**, структура страницы заложена заранее | **Программатика.** Именно так делались страницы вида «Женева → Авориаз»: таблица ключей на входе, конвейер на выходе штампует страницы |

Режим C — то, ради чего строится вся фабрика; режимы A и B — способ отладить качество на единицах
перед тем, как пускать сотни. Таблица ключей для режима C собирается **до** всякой автоматизации
(см. `programmatic-strategy.md` → §1 и §«Что делается руками»).

## Структура `AI SEO Writer.json` (реконструкция для импорта в n8n)

> Это **реконструкция** структуры по описанию узлов из урока курса, а не дамп оригинального файла.
> Оригинальный `AI SEO Writer.json` (20.5 KiB) прикреплён к уроку курса в Notion. Если он у тебя есть —
> импортируй его напрямую (n8n → workflow menu → Import from File) вместо ручной сборки.
> Реконструкция нужна, чтобы собрать эквивалент с нуля.

Минимальный набор нод (Вариант A), которые надо создать в n8n и связать по порядку:

| # | Node type (n8n) | Назначение | Ключевые поля |
|---|-----------------|------------|---------------|
| 1 | **Form Trigger** | приём seed | поле `seed` (text, required) |
| 2 | **HTTP Request** | Perplexity research | POST к Perplexity API, body с промптом research-агента, заголовок `Authorization: Bearer {{PERPLEXITY_API_KEY}}` |
| 3 | **Code** | вытащить citations из ответа Perplexity | парс `choices[].message` + `citations[]` |
| 4 | **Split In Batches** | итерировать по citation-ссылкам | batchSize 1 |
| 5 | **HTTP Request** | GET каждой ссылки | responseFormat: string |
| 6 | **HTML / Code** | strip HTML → чистый текст | оставить `body` текст |
| 7 | **Merge / Aggregate** | собрать research_corpus | конкатенация текстов |
| 8 | **OpenAI / AI Agent** | копирайтер | system-промпт копирайтера, user = corpus, `response_format: json_object` |
| 9 | **Code** | собрать HTML по блокам + ETR | подсчёт слов → reading time |
| 10 | **Google Docs** | создать документ | folder, title = keyword |
| 11 | **Gmail** | отправить на email | to, subject = keyword, body = ссылка на Doc |

Для **Варианта B** добавить после ноды 9:

| # | Node type | Назначение |
|---|-----------|------------|
| B1 | **Postgres / HTTP (Supabase)** | SELECT релевантных статей для internal links |
| B2 | **Code** | вставить internal links в тело (anchor-text по ключам) |
| B3 | **Code** | финальный JSON для CMS (строгая структура, без артефактов) |
| B4 | **HTTP Request** | POST в CMS API (WordPress `/wp-json/wp/v2/posts` / Webflow / Tilda Feeds) |
| B5 | **Postgres / HTTP (Supabase)** | INSERT записи опубликованной статьи |

> Сборка узлов, креды и дебаг — см. скилл **`n8n`**. Здесь — только специфика SEO-конвейера.

## JSON output копирайтера (контракт для CMS)

Строгий вывод — **только JSON**, без markdown-обёрток и артефактов. Текст в JSON смыслово не
меняется и не дополняется на этапе конвертации (правило урока).

```json
{
  "title": "Movers from San Francisco to Los Angeles: Costs, Routes & FAQ",
  "slug": "movers-san-francisco-to-los-angeles",
  "meta_description": "How much it costs to move from SF to LA, routes, timelines, and answers to the most common questions.",
  "canonical": "https://example.com/movers-san-francisco-to-los-angeles",
  "robots": "index,follow",
  "keyword": "movers from san francisco to los angeles",
  "estimated_reading_time_min": 8,
  "key_takeaways": ["...", "...", "..."],
  "html_body": "<h1>...</h1><h2>...keyword in one H2...</h2>...<section class='faq'>...</section>",
  "faq": [
    {"q": "How much does it cost to move from SF to LA?", "a": "..."},
    {"q": "How long does the move take?", "a": "..."}
  ],
  "internal_links": [
    {"anchor": "moving to Los Angeles", "url": "/moving-to-los-angeles"}
  ],
  "images": [
    {"alt": "Moving truck on I-5 between San Francisco and Los Angeles", "src": "..."}
  ],
  "category": "Route pages"
}
```

CMS-узел маппит эти поля на API целевой системы (WordPress/Webflow/Tilda).

## Supabase schema (БД статей + автоперелинковка)

Минимальная таблица для перелинковки в масштабе. Цель: при публикации новой страницы найти
релевантные уже опубликованные и вставить internal links → ускорить индексацию.

```sql
create table seo_articles (
  id            bigint generated always as identity primary key,
  url           text not null unique,
  slug          text not null,
  title         text not null,
  keyword       text not null,
  cluster       text,                      -- 'Resort' | 'Route' | 'Airport' | ...
  summary       text,
  embedding     vector(1536),              -- pgvector: для semantic relink (опц.)
  published_at  timestamptz default now()
);

-- индексы для поиска кандидатов на internal links
create index on seo_articles using gin (to_tsvector('simple', title || ' ' || keyword));
-- при использовании pgvector:
-- create index on seo_articles using ivfflat (embedding vector_cosine_ops);
```

Поиск кандидатов (вариант без embeddings — по ключам/кластеру):

```sql
select url, title, keyword
from seo_articles
where cluster = :current_cluster
  and id <> :current_id
  and to_tsvector('simple', title || ' ' || keyword) @@ plainto_tsquery('simple', :keyword)
order by published_at desc
limit 5;
```

Узел в n8n вызывает этот SELECT, получает кандидатов, нода-Code вставляет `<a>` в `html_body` по
anchor-text. См. `programmatic-strategy.md` → раздел про Supabase.

## Креды и подключения (минимум)

Порядок настройки под Вариант A — четыре credential, **5-10 минут** при готовых аккаунтах:

1. **Perplexity API** — залогиниться → Account Settings → API → **привязать карту** (без биллинга
   ключ не работает) → сгенерировать ключ → в n8n завести credential типа Perplexity API. Скилл
   `perplexity`.
2. **OpenAI** — тем же путём; проверить, что на аккаунте есть деньги (`OPENAI_API_KEY`). Или
   Claude → `claude-api`.
3. **Google Docs** — подключается стандартным OAuth-гайдом n8n. Скилл `gdocs`.
4. **Gmail** — выбрать почту, куда падает готовый материал. Скилл `gmail`.

Дальше: взять **production URL формы**, вписать ключевой запрос — статья придёт на почту.
**Работает и на русском.**

Для Варианта B добавляются:

## Как включить автопубликацию

Автопубликация — «гораздо более сложная история и обычно не для новичков». Два пути:

**Простой (готовая интеграция):** заменить **Gmail-ноду на CMS-ноду**.
- **WordPress** → action *Create New Post* (категория задаётся в ноде).
- **Webflow** → action «создать новый item» в нужной коллекции CMS.
- **Tilda** (RU) → Feeds API, скилл `tilda`.

**Кастомный (через API):** если формат заливки свой — лить HTTP-запросом в API CMS. Так делает
автор метода, потому что у них кастомный формат. Универсального рецепта нет: логика подключения
зависит от шаблона, блога и настроек конкретного сайта — этот кусок всегда допиливается руками.

Порядок внедрения без боли: сначала Вариант A на email → убедиться в качестве текста → потом
подменить последнюю ноду на CMS.
