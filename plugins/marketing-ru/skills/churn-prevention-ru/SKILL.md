# Удержание и снижение оттока (RU)

Снизить добровольный (подписчик решил отменить) и недобровольный (платёж не прошёл) отток платящих через грамотные cancel-флоу, динамические save-офферы, проактивное удержание и dunning. Порт `churn-prevention` из marketingskills: фреймворки, маппинги офферов и плейбуки сохранены; биллинг и комплаенс адаптированы под рублёвый рынок.

**Перед началом прочитай `~/.claude/business-context.md`** (заведи из `~/.claude/templates/business-context.md`, если файла ещё нет) — позиционирование, структура тарифов и цены (месяц/год, trial-период, промо-офферы), карта воронки. Не дублируй цены и метрики — держи их в едином источнике контекста продукта.

## Перед стартом — собрать контекст

1. **Ситуация с оттоком:** месячный churn (добровольный vs недобровольный), активных подписчиков, средний MRR на клиента, есть ли cancel-флоу сейчас, доля trial→churn (не продлили после trial).
2. **Биллинг:** платёжный провайдер (для РФ — напр. ЮKassa/CloudPayments; вебхуки о статусе платежа), месяц/год, поддержка паузы/даунгрейда тарифа, есть ли retention-тулинг.
3. **Данные о продукте:** трекинг использования по подписчику (входы, ключевые действия, сессии), дроп вовлечённости, данные о причинах прошлых отмен, метрика активации.
4. **Ограничения:** B2C vs B2B-когорта (влияет на дизайн флоу), требование лёгкой самостоятельной отмены, тон оффбординга.

## Два типа оттока

| Тип | Причина | Решение |
|-----|---------|---------|
| **Добровольный** | Подписчик решает отменить | Cancel-флоу, save-офферы, exit-опросы |
| **Недобровольный** | Платёж не прошёл (провайдер) | Dunning-письма, умные ретраи |

Добровольный обычно 50-70% оттока; недобровольный 30-50%, но чинится проще.

Три режима: (1) построить cancel-флоу с нуля; (2) оптимизировать существующий по данным; (3) настроить dunning.

## Cancel-флоу

### Структура
```
Триггер → Опрос причины → Динамический оффер → Подтверждение → После отмены
```

### Exit-опрос — фундамент
1 вопрос, single-select + опц. free text, 5-8 причин макс, частые первыми, без чувства вины, рамка «Помогите стать лучше» > «Почему уходите?».

**Категории причин:** дорого; мало пользуюсь/нет времени; не хватает функциональности/контента; достиг цели (получил нужное); ухожу к конкуренту; технические проблемы; временно не нужно; другое.

### Динамические save-офферы — главный инсайт
**Подбирай оффер под причину.** Скидка не спасёт того, кто не пользуется; роадмап фич не спасёт того, кому дорого.

| Причина | Основной оффер | Запасной |
|---------|----------------|----------|
| Дорого | Скидка (20-30% на 2-3 мес) / спец-тариф | Даунгрейд на младший план |
| Мало пользуюсь / нет времени | Пауза (1-3 мес) | Бесплатная сессия с экспертом, план внедрения |
| Не хватает функциональности/контента | Превью роадмапа + сроки | Рекомендация релевантной части продукта |
| Достиг цели | Показать новые/смежные сценарии | Даунгрейд на младший план для сохранения доступа |
| Ухожу к конкуренту | Сравнение + скидка | Фидбэк-звонок с основателем/экспертом |
| Технические проблемы | Эскалация в поддержку | Кредит + приоритетный фикс |
| Временно не нужно | Пауза | Временный даунгрейд |

### Типы save-офферов
- **Скидка:** 20-30% на 2-3 мес — sweet spot; не >50% (приучает отменять ради скидки); time-limit; показывать экономию в рублях, не только %. Для горячих — специальный входной тариф (если он ограничен по доступности).
- **Пауза:** макс 1-3 мес; 60-80% паузеров возвращаются; авто-реактивация с предупреждением; прогресс/статус/достижения сохранять.
- **Даунгрейд тарифа:** младший план вместо отмены; что сохраняют (базовые функции) vs теряют (premium-функции, флагман, продвинутые сценарии); позиционировать как «подберём план под вас».
- **Разблокировка/продление функции:** открыть неиспробованную premium-функцию; для причины «мало ценности».
- **Личный контакт:** для топ-10-20% по MRR / B2B-когорт — маршрутизация в CRM на менеджера / личное письмо основателя.

### UI-принципы
Видимое «Продолжить отмену» на каждом шаге (без тёмных паттернов), один основной + один запасной оффер, конкретная экономия в рублях, имя/прогресс подписчика, мобайл-френдли.

Детали по типам бизнеса/интервалу/сегментам — `references/cancel-flow-patterns.md`.

## Прогноз оттока и проактивное удержание

Лучший save — до клика «Отменить». Особенно критично для **trial→churn**: предотвратить можно до конца trial (см. также `onboarding-cro-ru`).

### Сигналы риска
Падение частоты входов 50%+ (высокий, 2-4 нед); остановка ключевого действия (высокий); давно не запускал core-фичу; всплеск тикетов потом тишина; падение open rate писем; рост визитов на страницу биллинга (высокий, дни до отмены); NPS <6; trial-пользователь не активировался к дню 3.

### Health score (0-100)
```
Health = вход×0.30 + ключевое действие×0.25 + сентимент поддержки×0.15 + биллинг×0.15 + вовлечённость×0.15
```
80-100 здоров (апселл старших тарифов); 60-79 внимание (check-in); 40-59 риск (интервенция); 0-39 критично (личный контакт).

### Проактивные интервенции
Падение активности >50% за 2 нед → «Заметили, вы давно не заходили. Помочь продолжить?»; приближение к лимиту тарифа → апгрейд-нудж (не стена — это `paywall-cro-ru`); нет входа 14 дней → ре-вовлечение с новыми материалами/фичами; NPS-детрактор → личный follow-up за 24ч; годовое продление через 30 дней → recap ценности (что получено за год).

## Недобровольный отток: восстановление платежей

30-50% оттока, самый восстановимый.

### Dunning-стек
```
Pre-dunning → Умный ретрай → Dunning-письма → Grace-период → Hard cancel
```

### Pre-dunning
Алерты об истечении карты (30/15/7 дней); запрос резервного способа оплаты; **обновление карт:** проверить поддержку токенизации/обновления реквизитов на стороне платёжного провайдера; pre-billing уведомление за 3-5 дней для годовых.

### Умные ретраи
Soft-отказ (недостаточно средств, таймаут) → 3-5 ретраев за 7-10 дней; hard-отказ (карта закрыта/украдена) → не ретраить, просить новую; нужна аутентификация (3DS/СБП) → отправить обновить оплату.
Тайминг: ретрай в день месяца, когда платёж проходил раньше; после типичных дат зарплат (1, 15); не на выходных.

### Dunning-письма (4 шт за 10 дней)
День 0 (дружелюбный алерт) → День 3 (напоминание) → День 7 (срочность, «доступ приостановится через 3 дня») → День 10 (финал). Прямая ссылка на обновление оплаты, показать что потеряют (доступ, прогресс, данные), не обвинять, plain text работает лучше. Вёрстка — `html-email`, логика — `n8n`.

Полный плейбук + in-app dunning — `references/dunning-playbook.md`.

## Метрики

| Метрика | Таргет |
|---------|--------|
| Месячный churn | <5% B2C, <2% B2B-когорта |
| Revenue churn (net) | Отрицательный (net expansion за счёт апгрейдов) |
| Save rate cancel-флоу | 25-35% |
| Acceptance офферов | 15-25% |
| Реактивация после паузы | 60-80% |
| Recovery dunning | 50-60% |
| Trial→paid (косвенно churn) | См. onboarding-cro-ru |

**Когорты:** канал привлечения, тариф, tenure (когда отменяют — 30/60/90 дней или сразу после trial), причина, тип оффера. Данные — из вашей аналитики (`web-analytics`, Метрика/GA) и продуктовой БД. A/B cancel-флоу — `ab-testing-ru` (тест одной переменной: % скидки, длина паузы, порядок опрос/оффер, модалка/страница, тон).

## Частые ошибки

Нет cancel-флоу (даже опрос + 1 оффер спасает 10-15%); скрытая кнопка отмены (вредит репутации + закон требует лёгкой отмены); один оффер на все причины; слишком глубокие скидки (>50% приучают отменять-возвращаться); игнор недобровольного оттока; нет dunning-писем; копия с чувством вины; не трекать LTV «спасённых»; пауза >3 мес; нет пути возврата; игнор trial→churn (предотвращается активацией, не save-оффером).
