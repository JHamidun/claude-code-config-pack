# Мастер-промпт: JTBD-отчёт «конверсия воронки + возврат лидов»

> Источник: доска «Креативы и посадочные страницы», методология 8.0 (занятие
> 18.08.2026). Промпт снят с доски и **обезличен** — данные компании-участника
> заменены плейсхолдерами.
>
> Что это. Готовый промпт, который из сырья (выгрузка CRM + транскрипты звонков +
> переписки) собирает двухчастный отчёт: **Часть I** — сегментация по джобам и анализ
> конверсии воронки; **Часть II** — winback-разбор отвалившихся лидов с готовыми
> персональными сообщениями. Рассчитан на модель с доступом к файлам; на больших
> массивах запускать в Claude Code, чтобы сырьё читалось по частям.

## Зачем он нужен и когда его НЕ применять

Обычная «сегментация» кончается красивыми персонами, из которых ничего не следует.
Здесь конструкция другая: сегменты строятся **по джобам и критериям успеха**, сразу
кладутся на стадии воронки и заканчиваются либо гипотезой роста, либо конкретным
сообщением конкретному лиду. Отсюда и главная ценность — отчёт заканчивается
действиями, а не выводами.

Не применять, когда: нет выгрузки CRM со стадиями (тогда получится только сегментация,
и это надо честно сказать), меньше нескольких десятков лидов (кластеры не устоят), или
когда на руках только маркетинговые данные без голоса клиента — джоб из цифр не
вытащить.

## Железные правила работы с данными

Это ядро промпта, ради которого он и переносится. Без этих правил модель
«дорисовывает» проценты и цитаты:

1. **Ни одной выдуманной цифры.** Все проценты, доли и конверсии считаются из
   приложенных данных. Посчитать нельзя — пишем «нет данных», а не оценку. До текста
   отчёта строятся рабочие таблицы `лид → сегмент → стадии → когорта`.
2. **Каждый вывод опирается на доказательство:** цифру, цитату лида или паттерн из
   **N ≥ 3** случаев. Цитаты — дословно, в кавычках, с сохранением орфографии.
3. **Job формулируется как «хочу + глагол, чтобы + результат»**. Job — не демография и
   не проблема, а желаемый переход.
4. **Разные критерии успеха = разные сегменты.** Один и тот же желаемый результат, но
   разные барьеры (цена vs время vs доверие) — это разные сегменты.
5. **Уровень уверенности указывается честно** (high/medium/low по каждому лиду в
   части II; «нестабильность», «аномалия», «мало данных» — там, где выборка мала).
6. **Нет данных — раздел выпадает, а не заполняется.** В начале ответа перечисляется,
   какие разделы исключены и почему.

## Входные данные (заполнить перед запуском)

```
• Компания / продукт / гео: {{…}}
• Цена продукта и варианты оплаты: {{…}}
• Стадии воронки в CRM по порядку: {{контакт → интерес → счёт → рассрочка → оплата}}
• Текущая сегментация компании (если есть): {{список или «нет»}}
• Сырьё: выгрузка CRM (лиды, стадии, даты, когорты) · транскрипты и саммари звонков ·
  переписки в мессенджерах и почте · исследования и интервью
• Когорты: {{как делить — по месяцу захода / по потоку набора}}
• Для части II: {{какие когорты в winback, какая стадия = «отвалился»}}
• Имена менеджеров для сообщений: {{…}}
• Язык отчёта: {{русский}}
```

## Этапы

**1. Открытая сегментация.** По каждому лиду зафиксировать: формулировку Job · **Push**
(боли и триггеры, толкающие искать решение) · **Pull** (что притягивает в продукте) ·
**Anxieties** (тревоги, мешающие купить) · **Habits** (что удерживает на месте) ·
контекст. Кластеризовать по похожести Job и критериев успеха, **не задавая число
сегментов заранее** (обычно выходит 8–20). Устойчивый сегмент = встречается в нескольких
когортах или ≥3% выборки. Каждому — код `CS1…CSn`, название-метафора, доля, N, Won%,
описание, Push/Pull/Anxieties. Свести в 4–7 семейств, разделить на крупные (>10%),
средние (3–10%), мелкие (<3%).

**2. Маппинг на текущую сегментацию компании.** Карта «текущий сегмент → какие CS в него
попадают», что совпадает и что добавляет JTBD-анализ, какие сегменты упущены.
Ровно 3 ключевых изменения и таблица «было → стало». Тон: текущая модель **не
опровергается, а уточняется данными** — иначе отчёт не примут.

**3. Конверсия и динамика.** Прохождение каждой стадии по каждому сегменту + тренд.
Затем взять **одну когорту с самыми полными данными** и разобрать глубоко: как меняется
состав аудитории между соседними стадиями, какие сегменты усиливаются и отфильтровываются.
Из потерянных лидов вывести ~5 повторяющихся паттернов утечки (каждый:
`паттерн-цитата → JTBD-корень → почему уходят → что делать`) и 5 гипотез H1–H5 с
метриками и порядком тестирования. Матрица 2×2 (конверсия × объём): **Чемпионы /
Скрытые чемпионы / Потенциал / Мёртвые** — с директивой на каждый квадрант. Динамика по
когортам: таблица долей + 4–7 нарративов-трендов, каждый как `факт с цифрами → 2–3
возможные причины → рекомендация`.

**4. Гипотезы роста.** На каждый ключевой сегмент карточка: гипотеза одним предложением ·
обоснование **только реальными цифрами** · эффект в «+X–Y оплат/мес» **с показанной
логикой расчёта** · 2–4 конкретных действия, включая формулировки для A/B · риски.
Эффект оценивать консервативно и показывать, из чего он получен.

**5. Winback-классификация.** По каждому отвалившемуся лиду прочитать **всю** историю и
решить — дожимать или нет.

| Дожимать | Не дожимать |
|---|---|
| интерес сохраняется (нет категоричного отказа, просил перезвонить, называл сроки) | полный игнор (3+ попыток без ответа) |
| барьер **временный** — финансы, здоровье, занятость: может измениться за 1–3 месяца | категоричный отказ |
| был конструктивный диалог (вопросы, обсуждение рассрочки) | обстоятельства изменились: нашёл работу, выбрал конкурента |
| | негатив и агрессия; объективный форс-мажор |

Плюс сводки: по сегментам (% возвратных и приоритет), по типам барьеров (рецепт на
каждый), по точкам отвала. Для «не дожимать» — таблица причин и рекомендация по
CRM-гигиене (архив или nurturing, частота, триггер возврата).

**6. Персональные сообщения.** На каждого возвратного лида — карточка. Требования к
сообщению: обращение по имени и представление менеджера · **привязка к конкретной
истории лида** (его слова, даты, договорённости — «вы просили связаться ближе к весне»)
· конкретный оффер с цифрами (вариант рассрочки, дата группы, бронь) · мягкий выход без
давления · живой тон, 1–2 эмодзи, 3–6 предложений. Если лид называл срок — стартовать
с него; срок ещё не наступил — пометить карточку «отправить {{месяц}}». Плюс подсказка
для звонка (что спросить, что предложить, чего не делать) и один следующий шаг.

**7. План дожима и реестр.** Три волны по срочности (сейчас / через 1–2 мес / через 3–4
мес) с консервативными ожидаемыми конверсиями. 3–6 процессных гипотез (микро-рассрочка,
бронь, social-proof-видео, двухшаговое касание, автонёрчинг), каждая как
`проблема с цифрой → действие с параметрами → целевая метрика`. Полный реестр всех лидов
двумя таблицами с ID, когортой, сегментом, точкой отвала, confidence и обоснованием.

**8. Executive Summary — пишется ПОСЛЕДНИМ.** Вводный абзац, 4 KPI-плитки, ровно 5
ключевых выводов (`тезис + цифра + значение для бизнеса`), приоритеты на 4–8 недель
(3–5 строк `сегмент: барьер → рычаг (+эффект)`). **Summary не должен содержать ничего,
чего нет в теле отчёта.**

## Тон и формат

- Писать для владельца бизнеса и руководителя продаж, **не для аналитика**: каждый
  раздел открывается одним-двумя предложениями «что это и зачем читать».
- Методологию объяснять с нуля, на примерах этого же продукта.
- Рекомендации только операционные: не «улучшить коммуникацию», а «выдавать
  одностраничный план совмещения после первого контакта».
- Каждая таблица заканчивается выводом «что делать».
- **Не сглаживать плохие новости:** если сегмент мёртвый — так и писать, с ценой
  вопроса в часах менеджеров и деньгах.

Формат выдачи выбирается на входе: markdown по шаблону отчёта · `.docx` через скилл
`docx` · интерактивный HTML. Начинать с короткого плана работы: какие данные получены,
какие разделы заполняются, какие исключены и почему.
