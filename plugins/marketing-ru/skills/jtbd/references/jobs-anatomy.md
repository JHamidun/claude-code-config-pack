# Анатомия работы и карта работ: 8 элементов, уровни, типы, сегменты

Практический playbook для работы с «работой» (job) как единицей продуктового анализа. Здесь три инструмента, вложенных друг в друга как матрёшка:

1. **Карточка работы** — разбор одного клиента (интервью, отток, win/loss).
2. **Карта работ** (граф) — иерархия работ сегмента: откуда берётся ценность и куда двигаться.
3. **Карта сегментов** — за чьи работы конкурировать и почему победим.

**Определение.** Работа — это спецификация желаемого перехода клиента из текущего состояния (A) в желаемое (B) ради выполнения работы более высокого уровня. Продукт — лишь нанятое средство перехода. Клиенту не нужен продукт; ему нужно, чтобы работа была выполнена.

**Центральный тезис.** Каждое продуктовое решение — фича, тариф, заголовок, кампания — молча кодирует внутри себя выбор «чью работу какого сегмента мы улучшаем». Вопрос не в том, зашита ли работа (она зашита всегда), а в том, зашита ли *правильная* работа *правильного* сегмента осознанно. Ошибка на этом уровне — самая дорогая в продукте: всё ниже по течению (ценность, коммуникация, юнит-экономика, конверсия) после неё испорчено, и никакая оптимизация воронки это не чинит. Про саму воронку → skill `funnel-design-ru`.

| Задача | Вход | Инструмент отсюда | Выход |

| Спроектировать оффер, лендинг, скрипт продаж | Карточки L1 сегмента | §5: форматы L2/L3; §3.8 эмоции | One-liner, заголовки, скрипт |

| Выбрать целевой сегмент | Карта работ + экономика | §10: сегментация | Карта сегментов + решение «конкурировать/нет» |

## 1. Карточка работы — шаблон (копируй и заполняй)

Это формат Уровня 1 — источник истины. Всё остальное (брифы, заголовки, сегменты) выводится из него.

```markdown
## Карточка работы: {я хочу + глагол} — {сегмент/респондент}

### КОГДА (State A)
- Контекст (черты человека/компании/ситуации, которые ОБЪЯСНЯЮТ критерии):
  - …
  - …
- Негативные эмоции до результата (тревога/раздражение/стыд/страх — словами клиента):
  - «…»
- Триггер (конкретное событие во времени, после которого начал действовать):
  - {плановый/неожиданный} × {внешний/внутренний}: …
- Набор рассмотрения (что сравнивал в момент выбора):
  1. Способы, о которых знал: …
  2. Что каждый способ делает лучше/хуже (по каким критериям): …
  3. Конкретные продукты + первый шаг для каждого: …
  4. Страхи по каждой альтернативе и что их снижало: …

### Я ХОЧУ (State B — ядро)
- Ожидаемый исход: я хочу {инфинитив глагола + объект}
- Критерии успеха (направление + порог, конкретно, не прилагательные):
  1. {ось} — {порог}: …
  2. …
  3. …

### ЧТОБЫ (мотивация)
- Работа верхнего уровня: чтобы {исход большой работы}
- Позитивные эмоции после (как хотел себя чувствовать): «…»

### Экономика работы
- Частота: {раз в день/неделю/месяц/год/жизнь}
- Бюджет: {за раз} / {в год}
- Важность (1–10): …

### Нанятое решение (спутник карточки — заполняется ВСЕГДА)
- Что нанял в итоге: …
- Почему оно обошло альтернативы (какой критерий добило): …
- Что случилось после (доволен? налоговые работы? переключился?): …
```

Правила заполнения:
- Карточка без блока «Нанятое решение» — половина данных. Работа без решения называет пункт назначения, но не выбранный путь; решение без работы — выбор бренда без мотивации. Win/loss-анализ живёт именно на паре «набор рассмотрения + выбор»: почему их решение обошло наше, что было в наборе, чего мы не знали, в какой критерий победитель попал, а мы промахнулись.
- Набор рассмотрения — дорогой в раскопке блок; в потоковых интервью допустимо заполнять частично и докапывать под задачу (выбор сегментов, конкурентное позиционирование, win/loss).
- Заполняйте только тем, что клиент **реально делал** (платил деньгами, временем, энергией). Будущие намерения («стал бы», «планирую») — не данные, а сырьё для фейковых работ (§8.2).

## 2. Восемь элементов: зачем каждый нужен

Полная работа = 8 элементов, сгруппированных по шаблону:

> **Когда** ___, **я хочу** ___ (с такими-то критериями), **чтобы** ___.

В разговоре работу сжимают до «я хочу + глагол» — это ядро, но не вся работа. Источник истины — все восемь.

| # | Элемент | Блок | Что даёт продукту | Без него ломается |
|---|---|---|---|---|
| 1 | Контекст | Когда | Объясняет, почему именно эти критерии | Сегментация: разные контексты склеиваются в одну «работу» |
| 2 | Негативные эмоции (A) | Когда | Рычаг сообщений «от боли», мотивация действовать | Коммуникация говорит о фичах, а не о том, что гонит клиента |
| 3 | Набор рассмотрения | Когда | Реальное конкурентное поле + страхи для снятия | Позиционируетесь против выдуманных конкурентов |
| 4 | Триггер | Когда | Тайминг касания: когда сообщение приземляется | Реклама бьёт в стационарную привычку — впустую |
| 5 | Ожидаемый исход | Я хочу | Ядро работы, глагол мотивации | Работа превращается в ярлык категории |
| 6 | Критерии успеха | Я хочу | ТЗ на ценность → метрики активации | «Ценность» остаётся пожеланием, инженерить нечего |
| 7 | Работа верхнего уровня | Чтобы | Слой мотивации, язык коммуникации | Продукт присваивает чужой уровень → раздутые ожидания |
| 8 | Позитивные эмоции (B) | Чтобы | Образ для рекламы и заголовков | Лендинг перечисляет фичи вместо пункта назначения |

### 2.1. Контекст — причина критериев, а не фон

Диагностический тест на каждый кандидат в контекст: **влияет ли этот признак на исход или критерии?** Да → контекст. Нет → выбросить. «Была пятница» — не контекст, если пятничность не меняет ни одного критерия.

- B2C: психологическое состояние (тревожный/спокойный), прошлый опыт, задавший критерий, стадия жизни (родитель малышей, без машины), ситуация (пик цен в праздники).
- B2B: черты роли и её прошлый опыт («прошлый вендор упал на 100k rps» → критерий «держать продакшн-нагрузку»), черты компании (Series-B, нет своей ИБ), отрасль (регуляторика), ситуация (аудит через 30 дней, заморозка бюджета).
- Один исход в двух контекстах = **две работы**: «забронировать отель» в отпуске (близко к достопримечательностям, бассейн) и в командировке (Wi-Fi, тихий номер, скорость поиска) — разные работы.
- Вопрос интервью: «В каких ситуациях вы оказывались, когда решили использовать {решение}, чтобы получить {исход}?»

### 2.2. Негативные эмоции State A — топливо действия

Тревога, раздражение, сомнение, стыд, страх — сигнал мозга «я не там, где надо». Он срабатывает раньше рациональных надстроек; избегание негативной эмоции — самостоятельная сила, и весит она тяжелее стремления к B (асимметрия потерь; подробнее про loss aversion → `marketing-psychology-ru`).

- Устранение негативной эмоции — один из самых сильных рычагов ценности: страховка продаёт «сплю спокойно», а не «меньше взломов».
- Вопрос: «Пока вы не получили {исход}, были ли негативные эмоции?»
- **Ловушка недо-репорта:** плоское «нет, ничего не чувствовал» ≠ эмоций не было. Причины: эмоция слабая, нет доверия, респондент не понял вопрос, не владеет языком эмоций. Реакция — построить безопасность и дать пример («некоторые в такой ситуации злятся на себя…»), а не записать «эмоций нет».

### 2.3. Набор рассмотрения — знание клиента в момент выбора

То, что мозг сравнивает, выбирая способ выполнить работу верхнего уровня. Живёт внутри работы. Четыре слота:

1. Какие способы выполнить большую работу клиент вообще знает (включая «сделать самому» и «не делать»).
2. Сравнительная эффективность способов — по каким конкретным критериям каждый лучше/хуже.
3. Названные продукты **с точкой входа**: бренд + первый конкретный шаг (скачать, записаться на демо).
4. Страхи по каждой альтернативе + что эти страхи снижает.

Вопросы: «Между какими способами получить {исход большой работы} вы выбирали?» → «Что каждый делал лучше/хуже, и что победило?» → «Какие продукты держали в голове и знали ли, как начать?» → «Каких провалов боялись и что успокаивало?»

### 2.4. Триггер — граница между «думаю» и «делаю»

Событие во времени, переключающее из созерцания работы в трату энергии на неё. Клиент может месяцами жить в контексте с работой в голове — и не действовать до триггера.

Таксономия 2×2:

| | Внешний | Внутренний |
|---|---|---|
| **Плановый** | дедлайн аудита, дата продления, конец квартала | плановый пересмотр целей, ревизия своего стека |
| **Неожиданный** | новость о взломе, скачок цены, совет друга, одобрение руководителя | фрустрация перевалила порог, всплеск тревоги, вспышка любопытства |

Что с триггером можно делать (единственный элемент с игрой «до/в момент/после»):
- **Быть триггером** — сама коммуникация будит работу и запускает действие.
- **Ловить момент** — то же сообщение в момент контекстного давления бьёт в разы сильнее, чем в стационарной привычке.
- **Встраиваться через партнёров** — киоск проката у выдачи багажа; реклама там, где клиент уже в движении.
- **Строить ассоциацию триггер→бренд** (жара → конкретный напиток). Медленно, дорого, но копится годами.

Границы понятия: для регулярных работ триггер может быть неявным — его заменяет расписание. Необходимые условия («быть дома») — не триггер, это контекст; триггер живёт во времени. Вопрос: «В какой момент вы начали что-то делать ради {исхода}? Что было спусковым крючком?» Ответ должен быть конкретным моментом, а не «когда почувствовал готовность».

### 2.5. Ожидаемый исход — глагольное ядро

Формат: `я хочу + инфинитив глагола (+ объект)`.

- **Работа — глагольная фраза, не существительное.** «Управление арендой», «подача налогов» — ярлыки категорий, из которых выпал глагол. Глагол несёт мотивацию.
- Работа смотрит из настоящего в будущее: «хочу понимать» (состояние), а не «хочу разобраться однажды» (разовый прошлый результат).
- Каждый глагол — отдельная работа. Тот же глагол с другими критериями — **тоже другая работа**. Несколько глаголов в одном высказывании — стек, парсится до иерархии (§4.2).
- Минимально жизнеспособная запись: `я хочу {исход} с {главными критериями}`. Сжать сильнее нельзя: потеряется спецификация «достаточно хорошо», и работа станет непригодной для проектирования. Всё прочее в принципе восстановимо повторным интервью; критерии — нет.
- Вопрос: «Какой исход вы хотели получить, используя {решение}?» Если дали существительное — дожимать до глагола.

### 2.6. Критерии успеха — ТЗ на ценность

Измеримые условия клиента, по которым он судит «достигнуто достаточно хорошо». Не прилагательные, приятные команде.

Правило — **конкретность, не обязательно числовость**. Качественный критерий годится, если конкретен:

| ❌ Прилагательное | ✅ Критерий |
|---|---|
| «быстро» | «машина приехала меньше чем за 4 минуты» |
| «надёжно» | «платёж прошёл с первой попытки, каждый раз в этом месяце» |
| «качественно» | «в салоне чисто: нет запаха еды, нет липких сидений» |
| «безопасно» | «высадка от двери до двери, не идти одной ночью» |

У каждого критерия две компоненты — нужны обе:
- **Направление** — ось, на которой создаётся ценность (цена? комфорт пересадки? раскладка мест?). Говорит, куда вкладывать инженерию и какие оси игнорировать.
- **Уровень** — порог: выше — клиент чувствует ценность, ниже — проблему. «Меньше $1800»: за $1750 — ценность, за $1850 — проблема. Уровень задаёт знак ошибки прогноза в голове клиента.

Критерии переводятся прямо в метрики активации и доставки ценности. Если критерии сегмента нельзя чисто перевести в измеримые метрики — они недостаточно конкретны, назад в интервью. Вопрос: «Думая про {исход}, по каким конкретным признакам вы понимаете, что получили его достаточно хорошо?»

### 2.7. Работа верхнего уровня — слой «чтобы»

Работа, ради которой выполняется текущая. Выше живут причины, ниже — действия.

- **Ловушка присвоения:** не путать работу верхнего уровня с той, что делает *ваш* продукт. Продукт делает Core-работу; верхняя — на уровень-два выше. Обещать её как свою поставку = раздуть ожидания и породить искусственные проблемы.
- Техника — лестница «зачем?»: «Зачем вам {исход}?» → «А это — чтобы что?» → … Сигнал потолка: респондент перестаёт добавлять новое и **повторяет предыдущий ответ** — дошли до потребности, которая ниже сознательного доступа. Дальше не копать.

### 2.8. Позитивные эмоции State B — образ пункта назначения

Спокойствие, удовлетворение, гордость, облегчение — то, как мозг *представляет ценность* достижения B. Не надстройка над «рациональным».

- Это образ для рекламы: клиент спокоен за кухонным столом с одностраничной выпиской — «спокойствие», отрендеренное против большой работы.
- Якорь для заголовков: назвать эмоцию-пункт назначения сильнее, чем описать фичи. «Спите спокойно, зная, что данные защищены» > «сквозное шифрование».
- Не обещать эмоций, которые не доставите (та же ловушка, что с присвоением верхней работы).
- Вопрос: «Как вы хотели себя чувствовать после {исхода}?» Дожимать сквозь факты и метафоры до **названной** эмоции.

## 3. Worked-пример: разбор одной работы от сырой цитаты до карточки

Сырая цитата из интервью (владелец интернет-магазина, 34 года):

> «Я хотел наконец видеть реальные остатки и перестать продавать то, чего нет, чтобы не ловить возвраты и злые отзывы. У нас 1200 SKU на складе и два маркетплейса, я платил девочке 25 тысяч в месяц за сверки в экселе, и всё равно раз в неделю что-то продавалось в минус».

Шаг 1 — вытащить глаголы: «видеть остатки», «перестать продавать несуществующее», «не ловить возвраты». Это стек → парсим (§4.2): Core-кандидат «знать реальные остатки в каждый момент»; выше — «продавать без овер-селла»; ещё выше — «сохранять рейтинг магазина» (мотивация).

Шаг 2 — заполнить карточку:

```markdown
## Карточка: я хочу знать реальные остатки в каждый момент — e-com, 1000+ SKU, мультиканальный

### КОГДА
- Контекст: 1200 SKU; продажи в 2 маркетплейсах + свой сайт (остатки расходятся
  между каналами); нет штатного айтишника; уже платит 25 000 ₽/мес за ручные сверки.
  (Каждый пункт объясняет критерий ниже — тест пройден.)
- Негативные эмоции A: «стыдно перед покупателем, когда отменяю заказ»;
  страх «прилетит бан от маркетплейса за отмены».
- Триггер: неожиданный внешний — маркетплейс понизил рейтинг магазина после
  3 отмен за неделю (порог перейден — начал искать решение в тот же вечер).
- Набор рассмотрения:
  1. Способы: оставить экселе+человека / нанять второго человека / взять систему учёта.
  2. Сравнение: человек = гибко, но ошибки ~1 раз/нед; система = точно, но «страшно внедрять».
  3. Продукты: 2 названных системы; у одной знал первый шаг («у знакомого стоит, он покажет»).
  4. Страхи: «внедрение съест месяц», «сотрудники не осилят» — снижал отзыв знакомого.

### Я ХОЧУ
- Исход: я хочу знать реальные остатки по всем каналам в каждый момент
- Критерии:
  1. Точность — расхождение факт/система < 2% SKU при инвентаризации
  2. Свежесть — остаток на маркетплейсах обновляется ≤ 15 минут после продажи
  3. Стоимость владения — ≤ 25 000 ₽/мес (текущая цена ручного способа = якорь)
  4. Внедрение — ≤ 2 недель без программиста

### ЧТОБЫ
- Верхняя работа: чтобы продавать без овер-селла (→ чтобы сохранять рейтинг магазина)
- Позитивные эмоции B: «выдохнуть; не вздрагивать от уведомлений об отмене»

### Экономика
- Частота: работа непрерывная (проверка остатков — ежедневно)
- Бюджет: 25 000 ₽/мес ≈ 300 000 ₽/год (доказан реальной тратой)
- Важность: 9/10 (триггер — прямая угроза выручке)

### Нанятое решение
- Нанял: систему учёта Б (не А)
- Почему: попала в критерий 4 («настроили за 8 дней сами») — А требовала интегратора
- После: через месяц отмен нет; появилась налоговая работа «перебивать штрихкоды
  партии» (разрыв цепочки у поставщика) — кандидат на ход «снять работу с клиента»
```

Что дал разбор (проверка, что карточка «работает»):
- **Метрики активации** читаются из критериев: %, расхождения ≤2, лаг синка ≤15 мин, time-to-value ≤14 дней.
- **Заголовок лендинга** из эмоции B + верхней работы: «Продавайте без овер-селла. Остатки по всем каналам сходятся сами» — не «мощная система складского учёта».
- **Win/loss:** система А проиграла не по функциям, а по критерию внедрения — чинится не фичей, а онбордингом.
- **Якорь цены:** 25 000 ₽/мес — готовность платить, доказанная прошлой тратой, а не опросом.

## 4. Дисциплины формулировки (где чаще всего врут карточки)

### 4.1. Абстрактная работа → конкретная после найма

До выбора решения работа абстрактна: «хочу купить двушку» — нет района, застройщика, агента. После фиксации на решении работа конкретизируется, и под ней **появляется новый слой** нижних работ («встретиться с агентом», «посмотреть кв. 3Б в субботу», «получить одобрение ипотеки») — их не существовало, пока работа была абстрактной.
- Работа в интервью обычно абстрактна; работа в продуктовой аналитике — конкретна. Это разные стадии одной работы, не путать.
- Разные решения одной абстрактной работы дают **разные конкретные графы**. Считать их одной работой = схлопнуть две операционные реальности.

### 4.2. Парсинг многоглагольных высказываний

Высказывание с несколькими инфинитивами через «и / чтобы / так чтобы» — стек работ. Перед использованием распарсить до иерархии:

- ❌ «Сдавать дуплекс и получать предсказуемый ежемесячный доход» — два глагола, не одна работа.
- ✅ Супер-большая: «получать предсказуемый доход с недвижимости» ← большая: «сдавать дуплекс» (выполняется *чтобы*). Сквозные ограничения («не тратя вечера») уходят в критерии успеха, не в высказывание работы.

Непарсенный стек ломает сразу три вещи: сегментация по сходству графов схлопывается; таргетинг сообщений на уровень большой работы промахивается; проверка «чтобы что?» возвращает мусор — ответ уже сидит в исходной фразе.

### 4.3. Три «событийных» спутника, которых постоянно путают

| Понятие | Что это | Где во времени |
|---|---|---|
| **Набор рассмотрения** | Существующее знание, которое мозг сравнивает при выборе | В State A, ДО действия |
| **Триггер** | Событие, переключающее из созерцания в действие | Граница A / действие |
| **Момент «Ага»** | Позитивная ошибка прогноза при *личном* опыте продукта: «это лучше, чем я ждал» | ВНУТРИ действия, решение уже в руках |

Временная цепочка: рычаги выбора грузятся первыми (иногда за годы) и пишут в набор рассмотрения → срабатывает триггер → клиент действует → «Ага» происходит, когда продукт впервые бьёт прогноз. **Правило: триггер без загруженных рычагов выбора — шум.** Пуш «закажите уборку сейчас» не конвертит, если клиент ещё не знает, что существует лучший способ.

### 4.4. Жизненный цикл: четыре фазы перехода

- **State A** — контекст + прошлый опыт + набор рассмотрения + негативные эмоции + скрытый прогноз (мозг заранее предсказывает, как пройдёт). Прогноз — не девятый элемент: он уже живёт в критериях и наборе рассмотрения.
- **Триггер** — до него клиент созерцает работу, после — выполняет.
- **Действие** — клиент нанимает решение из набора; выбор устанавливает критическую цепочку нижних работ; мозг на каждом шаге сравнивает реальность с прогнозом.
- **State B** — исход + критерии + позитивные эмоции + верхняя работа, ради которой всё делалось.

## 5. Три формата записи: полный, средний, минимальный

| Формат | Содержимое | Куда идёт |
|---|---|---|
| **L1 — полный** | Все 8 элементов + частота/бюджет/важность + нанятое решение | Заметки после интервью, дизайн ценности, карта работ, карточки гипотез. Ничего не теряет |
| **L2 — предложение** | `Когда {контекст}+{триггер}, я хочу {исход} с {главными критериями}, чтобы {исход верхней работы}` | Дизайн-брифы, сравнение работ сегментов бок о бок, one-liner для скрипта продаж |
| **L3 — ярлык** | `Я хочу {исход} с {главными критериями}` | Заголовки лендинга, реклама, внутренние ярлыки, имя сегмента |

**L1 — источник истины; L2/L3 — производные.** Они должны ссылаться на L1 и пере-выводиться по требованию, а не жить самостоятельно; разошлись — артефакт «поплыл» и не заслуживает доверия. Заголовки и скрипты, написанные *из* L1, стабильно обыгрывают написанные без него — потому что L1 даёт конкретные критерии, контекст и рамку большой работы.

Пример всех трёх на работе из §3:
- L1 — карточка целиком (см. §3).
- L2 — «Когда у магазина 1000+ SKU в нескольких каналах и маркетплейс понизил рейтинг за отмены, владелец хочет знать реальные остатки (расхождение <2%, синк ≤15 мин, ≤25к ₽/мес, внедрение без программиста за 2 недели), чтобы продавать без овер-селла».
- L3 — «Знать реальные остатки по всем каналам — с точностью, за которую не штрафуют».

## 6. Карта работ (граф): устройство

**Карта работ — иерархия работ, которые сегмент выполняет ради своих верхних работ. Большинство стратегических ходов продукта — изменения в этом графе.** Каждый узел — работа (все 8 элементов на каждом уровне — граф фрактален). Рёбра двух видов:

- **Вертикальные** — рёбра «чтобы»: нижняя выполняется, чтобы выполнить верхнюю; мотивация течёт вверх. Ходят вверх вопросом «зачем? чтобы что?», вниз — «по шагам, что делал, чтобы выполнить эту?».
- **Горизонтальные** — между «братьями» под одной верхней: позиционные (Предыдущая → Следующая, когда порядок обязателен — критическая цепочка) и параллельные (независимые вклады в ту же родительскую).

**Это граф, а не дерево:** рёбра многие-ко-многим. Одна нижняя работа служит нескольким верхним; одно решение нанимается под несколько работ одного человека и разных людей. Дерево навязывает одного родителя — реальная мотивация так не устроена.

### 6.1. Пять уровней — относительно ВАШЕГО продукта

Названия уровней привязаны к позиции относительно Core-работы вашего продукта, а не к абсолютным позициям на жизненном графе клиента. Два продукта на соседних территориях пометят разные уровни как свой Core — и оба правы.

| Уровень | Определение | Тест принадлежности |
|---|---|---|
| **Супер-большая** | Уровень выше большой; близко к жизненной мотивации | — |
| **Большая** | Уровень выше Core; несёт мотивацию; продукт вносит вклад, но не выполняет целиком | Один набор Core обычно служит нескольким большим сразу |
| **Core** | Высшая работа, которую продукт выполняет **целиком**, выше которой не подняться при текущей форме | Большинство Micro под ней выполняются внутри продукта / вашей командой / вашей автоматизацией |
| **Small** | **Брат Core на том же уровне** под той же большой, который ваш продукт НЕ выполняет | Исполнитель-агностик (клиент, чужой продукт, партнёр, никто); единственный тест — выполняет ли её *наш* продукт |
| **Micro** | Уровень ниже Core и Small; зерно, где живёт клиентский опыт | — |

- У продукта нормально **несколько Core-работ** на одном уровне: один поверхностный глагол расщепляется по критериям («доехать» → «быстро» / «с собакой» / «с четырьмя чемоданами»).
- Полный граф клиента — 10+ уровней, от «нажать нужную клавишу» до «прожить жизнь, которой горжусь». Весь он не нужен никогда; нужен срез вокруг вашего Core.
- **Частая ошибка — ставить Small ПОД Core.** Small — брат, на одном уровне. Путаница Small↔Micro схлопывает два разных хода: кросс-продажа в соседнюю Core (рост) vs шлифовка мелкого UX (активация/удержание).

### 6.2. Тест подъёма: процедура постановки Core на правильный уровень

Ставить Core на правильный уровень — предпосылка любого решения на графе. Слишком высоко → продукт не выполнит заявленное, коммуникация родит проблему. Слишком низко → сегменты и ходы роста выйдут неверными.

1. Спросить **платящих** клиентов: «Какие задачи вы решаете нашим продуктом?» Ответы — кандидаты в Core. Рекрутировать только реально плативших и использовавших.
2. Для каждого кандидата — цикл из двух вопросов:
   - Q1: «Выполняет ли продукт эту работу *целиком*, каждую под-работу, от и до?» **Нет** → слишком высоко: спуститься на уровень, снова Q1.
   - Q2 (если Q1 = да): «Можем подняться на уровень выше и всё ещё выполнять целиком?» **Да** → подняться, снова Q1.
   - Стоп, когда Q1 = «да», Q2 = «нет». Это и есть Core.
3. Тянуться максимально вверх: каждый уровень выше — ближе к мотивации, рычагу коммуникации, широкой поверхности ценности. Правильный уровень — самый высокий *доступный сейчас*, не фиксированная позиция: по мере покрытия братьев-Small и убийства Micro Core поднимается.

### 6.3. Граф — гипотеза: создатель предлагает, клиент принимает или отвергает

Создатель в дизайне решения задаёт, какой граф клиент должен пройти. Клиент смотрит на предложенный граф (обычно неявно — через маркетинг, отзывы, триал) и принимает — или отвергает и берёт решение с более читаемым графом. Отказ выглядит как «не купили», вето невидимо до данных о конверсии. Спроектированный граф — **гипотеза** о том, что сегмент примет, не факт.

Пример: большая работа «подать налоги вовремя и корректно» — три решения, три графа, три сегмента:

| Решение | Граф под ним | Стоимость | Сегмент, который принимает |
|---|---|---|---|
| Сам на бумаге | 10+ Micro-работ в одиночку | $0 + вечер | «контроль прежде всего» |
| Пошаговый софт | 4 работы: войти → отвечать с авто-импортом → проверить → отправить | ~$100 + 1–2 часа | «скорость и точность» |
| Бухгалтер | 2 работы: отправить документы → подписать | $300–1500 + 30 мин | «сделайте за меня» |

### 6.4. Три градиента вдоль вертикали (что где размещать)

1. **Мотивация ↑ / механизм ↓.** Верхние работы — то, что клиент реально хочет; нижние — «неизбежное зло», которое терпят до появления более энергоэффективного способа (никто не хочет распутывать наушники и вводить пароли).
2. **Стабильность ↑ / смертность ↓.** «Добраться отсюда туда» — работа тысячелетиями; Micro-работы исчезают как класс (беспроводные наушники удалили «распутать провода», Face ID — «ввести пароль»). Команда на высокой большой работе наследует десятилетия стабильности; команда на Micro живёт на заёмном времени до следующего события удаления.
3. **Эмоция ↑ / продуктовая специфика ↓.** «Не подалась налоговая к понедельнику» трогает; кривая кнопка настроек — нет. Верхние работы говорятся языком клиента, нижние впитывают ваши глаголы и существительные. → **Коммуникация живёт на верхних работах, UX-детали — на нижних.**

## 7. Многие-ко-многим: откуда берутся ходы роста

### 7.1. Одна нижняя работа ← много верхних: суммарный апсайд

Когда работа служит нескольким верхним сразу, мотивация её выполнить растёт с каждой добавленной большой работой. «Освоить вайбкодинг» служит четырём большим («выкатить пет-проект», «отдать бойлерплейт ИИ на работе», «прототипировать за часы», «претендовать на роли с обязательной ИИ-грамотностью») → мозг взвешивает суммарный апсайд, вердикт сильнее. Ход: грузить рычаги выбора для тех больших работ, о которых клиент не знал, что они обслуживаются.

### 7.2. Одно решение → много работ: два пути роста

- **Работы одного человека** → LTV, средний чек, частота (доставка ужина → продукты → товары из магазина у дома: три Core, одно решение).
- **Работы разных людей** → размер рынка (добавленная работа есть у людей, которые никогда не были клиентами; начав её выполнять, начинаем за них конкурировать).

### 7.3. Реальные конкуренты — на уровне большой работы

- **Прямые** — делят вашу Core (тот же глагол, те же критерии, лоб в лоб).
- **Косвенные** — пересекаются по большим работам с *другими* Core: клиент решает ту же верхнюю работу другим классом решений.

Реальный набор = объединение, и косвенную часть недооценивают на порядок: матрас конкурирует с кофе, мелатонином, белым шумом и увольнением под большой работой «функционировать на недосыпе»; складской SaaS — с Excel и бумажным блокнотом под «знать, что на остатках»; уикенд-поездка — с Netflix под «сбежать из рутины».

### 7.4. DIY — полноценный конкурент

Часто нанятое решение — не продукт, а собственная активность клиента («погуглю, посмотрю ролик, сделаю сам»). Структурно это такой же граф. Три причины найма DIY: маленький бюджет; не знает об альтернативе (рычаги не долетели); знает, но не верит в ценность (видит цену, не может спрогнозировать эффективность). В исследовании картируйте DIY как конкурента.

## 8. Типы и свойства работ → доминирующий ход

Две разные оси, читаются вместе. **Свойства** — измерения, которые несёт каждая работа одновременно. **Тип** — категориальная роль: шесть взаимоисключающих, работа принадлежит ровно одному (по самой определяющей черте).

### 8.1. Свойства (у каждой работы — все три)

| Свойство | Что читать | Следствие для хода |
|---|---|---|
| **Участие в критической цепочке** | В какой цепочке, к какой верхней работе; выгода приземляется в КОНЦЕ цепочки — ранние работы чистая стоимость | Доминирующий ход на цепочечной работе — убить ранние звенья или подняться на уровень |
| **Частота** | Раз в день / год / жизнь; та же работа на другом срезе меняет частоту («переехать» — 3 раза/жизнь у человека, ~200 раз/год у корпоративного отдела релокации) | Задаёт юнит-экономику ($20×50 раз/год ≠ $200×3 раза/жизнь) и выбор среза сегментации |
| **Осознанность** | Может ли клиент назвать работу; статус, идентичность, контроль, безопасность видны в поведении раньше, чем в языке (повторяющиеся траты, избегание, противоречия, всплески эмоций) | Не просить назвать потребности — спрашивать про конкретное прошлое поведение; самоотчёт — один сигнал, не истина |

### 8.2. Таблица «тип работы → диагноз → ход»

| Тип | Как распознать | На какой вопрос бизнеса отвечает | Доминирующий ход |
|---|---|---|---|
| **Регулярная** | Плановая, добровольная, без конфликта в графе (помыть посуду, написать отчёт) | Где идёт стационарная доставка ценности? | Выполнять надёжно, чтобы работа ОСТАВАЛАСЬ регулярной |
| **Ориентационная** | Глаголы «понять/найти/выбрать/сравнить» — обновить набор рассмотрения | Когда маркетинг реально приземляется? | Тайминг касания в окно триггера; грузить рычаги выбора |
| **Налоговая** | Незапланированная, вынуждена тем, что нанятое решение провалило другую работу цепочки | Почему течёт удержание? | Выполнить сломанную работу: снять с клиента / починить / направить партнёру. НЕ извиняться вместо этого |
| **Фейковая** | Фантазия о будущем, ни разу не выполнялась («выучу испанский когда-нибудь») | Заплатит ли вообще кто-нибудь? | Рекрутить только плативших; подняться к реальной большой работе над фейком |
| **Виральная** | Выполняется ДЛЯ или ВМЕСТЕ с другим человеком (такси детям, слайды для класса) | Может ли продукт привлекать бесплатно? | Строить вокруг Core, выполняемого на глазах у аудитории |
| **Эмоциональная** | Исход — сдвиг эмоции («перестать тревожиться», «почувствовать спокойствие») | Какое сообщение конвертит сильнее всего? | Назвать эмоции A/B в коммуникации; удалить негативную в продукте |

Нюансы, которые легко упустить:
- **Ориентационная** — механизм роста графа под клиентом-новичком: каждое выбранное решение поднимается в большую работу, блокирует граф ниже, и под ним раскрывается новый слой ориентационных работ; рекурсия до Micro, которые клиент уже умеет.
- **Налоговая** — клиентское следствие разрыва критической цепочки. Токсична непропорционально размеру: негативное обучение быстрее позитивного, одна налоговая работа перечёркивает месяцы качественной. Одновременно это триггер смены поведения — клиент запускает ориентационную работу и становится восприимчив к рычагам конкурента. (В примере §3: «перебивать штрихкоды партии» — налоговая работа, кандидат на «снять с клиента».)
- **Фейковая** — самая дорогая ошибка: выглядит как реальный сегмент (интервью честно дают «хочу выучить испанский»), правдоподобно оценивается в market study, конвертит около нуля. Диагностика: «В прошлом вы что-нибудь делали ради {исход}? Платили деньгами/временем?» Нет → фейк с высокой вероятностью. Над фейковой часто есть реальная большая работа на другом уровне.
- **Виральная** операционно виральна, только если её выполнение одним человеком заставляет *дополнительных* людей начать свои работы с вашим решением. На входе в рынок приоритизируйте сегменты с максимумом виральных работ на высокой частоте: учителя, консультанты, агентства, контент-креаторы, инженерные менеджеры.
- **Эмоциональная** — единственный тип без верхней работы: терминальная вершина (выше — потребность, а потребность — не работа). Каждая полностью специфицированная работа указывает вверх на пару терминальных эмоциональных: избегающую («перестать тревожиться») и приближающую («почувствовать спокойствие»). Триаду «функциональное/социальное/эмоциональное» раскладывайте в граф, а не в прилагательные.

## 9. Ходы на карте + как копать и валидировать граф

### 9.1. Матрица стратегических ходов

**Направленные** (куда двигаться относительно текущего Core):

| Ход | Что делает | Когда выбирать |
|---|---|---|
| **Вверх — подняться на уровень** | Большая работа над Core становится новым Core; множество нижних работ умирает как класс | Самый мощный ход, когда достижим; после покрытия братьев-Small |
| **Вбок — захватить брата-Small** | Предыдущая в цепочке = привлечение/лидген; Следующая = удержание/средний чек; параллельный брат = третий вариант | Когда Core уже выполняется надёжно и нужен рост без смены уровня |
| **Наружу — связать с новой большой** | Создать ребро к большой работе, которого не было (премиум-вода связывает «утолить жажду» с «создать эстетику за столом») | Когда текущие большие работы исчерпаны как источник мотивации |

**Ненаправленные** (Core остаётся, структура меняется): убить работу как класс · снять работу с клиента (работа остаётся, выполняете вы) · начать выполнять работу, которую никто не делает хорошо (новый Core) · добавить ориентационные работы (документация, академия — вести процесс выбора) · направить работу партнёру · починить критическую цепочку (разрывы, передачи, циклы, временные дыры) · консолидировать (больше работ клиента в одном решении).

**Ходы вне графа** — на карте сегментов: вверх/вниз по рынку, соседний сегмент, B2B↔B2C; плюс изменение того, *как* выполняется Core без смены графа (цена ниже, одно измерение качества выше, минус негативная эмоция, минус когнитивная стоимость, гарантия результата).

Диагностика при затыке роста: какой ход из этого списка команда ещё **не рассматривала**? Дефолт большинства — точить существующий Core (фичи, улучшения), когда скачок живёт в другой клетке матрицы.

**Глубинный двигатель ценности — упрощение графа во времени.** Решение, доставляющее ту же большую работу через меньше нижних работ, энергоэффективнее по определению; мозг регистрирует упрощение как момент «Ага» (лифт vs лестница, навигатор vs бумажная карта, конструктор сайтов vs нанять разработчика). Граф при этом не пустеет: снизу работы удаляются, сверху рождаются новые большие («управлять цифровой идентичностью», «защитить данные от обучения ИИ»), которых поколение назад не было.

### 9.2. Шесть вопросов раскопки — все с якорем

**Изучайте работы через то, что клиент реально делал** (платил деньгами/временем/энергией). «Стали бы вы когда-нибудь делать X?» с трактовкой ответа как свидетельства — категориальная ошибка.

Якорь всех вопросов — исход работы **верхнего** уровня. Только «зачем?» (вверх) якорится на текущем узле; все остальные направления несут исход родителя в рамке — это и держит ответ внутри графа:

| Направление | Формула вопроса |
|---|---|
| Вверх, к родителю | «Зачем? Чтобы что?» |
| Вбок, Предыдущая | «По шагам: что делали ради {исход верхней} ДО того, как получили {исход текущей}?» |
| Вбок, Следующая | «По шагам: что делали ради {исход верхней} ПОСЛЕ того, как получили {исход текущей}?» |
| Вбок, братья вне цепочки | «Какие ещё задачи делаете ради {исход верхней}, кроме {исход текущей}?» |
| Вниз, последовательно | «По шагам: что делали, чтобы получить {исход текущей}?» |
| Вниз, параллельно | «Какие у вас обычные сценарии использования {решения}?» |

Режим провала — вопрос вбок/вниз **без** исхода в рамке: «Что делали до платформы?» приглашает дрейф («я пришёл в компанию два года назад»); якорная версия «…чтобы безопасно катить до платформы?» держит внутри графа.

Рекрутинг — по доказательству прошлого действия, не по намерению: «Когда последний раз платили за X? Сколько? Что сделали в результате?» — один проход отсеивает фейковые работы и низкомотивированных.

### 9.3. Валидация графа: процедура + чек-лист

Процедура: пройти «зачем? / чтобы что?» по **каждому** узлу подряд. Форма заставляет назвать следующую верхнюю работу вслух; ответ (или его отсутствие) вскрывает четыре режима провала — по убыванию частоты:

1. **Пропуск уровня** (самый частый) — «зачем?» возвращает несвязный ответ; формулирующий изобретает промежуточную работу на ходу → это и есть пропущенный уровень: вставить узел, переспросить оба соседних.
2. **Неверный родитель** — линия «чтобы» под давлением не мотивирует работу для этого сегмента; родитель выведен из головы, а не услышан в интервью → перепривязать ребро.
3. **Многоглагольный узел** — ответ на «зачем?» уже сидит внутри высказывания → распарсить (§4.2).
4. **Фейковая работа** — ответ фантазийный, без якоря на прошлое действие → вырезать или в бакет будущих гипотез; в рабочем графе не оставлять никогда.

**Чек-лист валидации графа (прогонять перед использованием в решениях):**

- [ ] Каждый узел — глагольная фраза «я хочу + инфинитив» (ни одного существительного-ярлыка).
- [ ] У каждого узла, кроме терминальных эмоциональных, есть родитель, и ребро «чтобы» читается вслух без натяжки.
- [ ] «Зачем?» на каждом узле даёт связный ответ = исход родителя (нет пропущенных уровней).
- [ ] Ни один узел не содержит двух и более глаголов (стеки распарсены).
- [ ] Каждый узел подтверждён прошлым действием респондента (платил деньгами/временем/энергией) — нет фейков.
- [ ] Small-работы стоят РЯДОМ с Core (братья), а не под ним; Micro — строго ниже.
- [ ] Core прошёл тест подъёма (§6.2): выполняем целиком = да; уровнем выше целиком = нет.
- [ ] Узлы с несколькими родителями отмечены как многие-ко-многим (не обрезаны до дерева).
- [ ] Критические цепочки размечены (где порядок обязателен), разрывы выписаны отдельным списком.
- [ ] Для спроектированного графа зафиксировано: это гипотеза; какие данные конверсии подтвердят/опровергнут принятие.

## 10. Сегментация по работам (не по демографии)

**Короткая форма стратегии:** решить, за какие Core-работы какого сегмента конкурировать и почему сможем победить. Всё ниже по течению следует из этого.

### 10.1. Корень: сходство Core-работ + критериев успеха

**Сегмент — группа людей, выполняющих похожие Core-работы с похожими главными критериями успеха.** Большие работы сверху уточняют сегмент и несут мотивацию, но не равноправный критерий (та же большая работа ≠ тот же сегмент).

Четыре правила, которые чаще всего нарушают:
- **Тот же поверхностный глагол ≠ тот же сегмент.** «Доехать дёшево» vs «доехать в тихой свежей машине» — разные Core, разные сегменты.
- **Те же критерии в другом порядке приоритета = разные сегменты.** «Скорость прежде всего» vs «без стресса прежде всего»; «контроль» vs «сделайте за меня» — список тот же, порядок инвертирован, продукты разные.
- **Один человек — ровно в одном сегменте.** Весь его граф работ помещает его в сегмент; утреннее такси на работу и вечернее в аэропорт — один представитель одного сегмента с обеими работами в графе. Граф эволюционирует — человек может перейти в другой сегмент, но в каждый момент он в одном.
- **Демография/фирмографика — никогда не первый срез.** Причинными становятся, только когда меняют Core-работы, критерии, маржу или спрос (клиент под отраслевой регуляторикой; организация на 200 инженеров с обязательным ИБ-ревью). Первым срезом они прячут кластеры Core-работ, которые надо увидеть.

### 10.2. Порядок построения: сначала широкий рынок, потом сегменты

1. Определить широкий рынок: не готовы менять форму продукта → все, кто платил (деньгами/временем/энергией) за текущие Core-работы во всех вариантах критериев; готовы менять → все, кто платил за большие работы над этими Core.
2. Качественное исследование внутри рынка → Core/большие работы, критерии, текущие решения, конкуренты, рычаги выбора, разрывы цепочек (сырьё для этого шага → `user-research-synthesis`).
3. Количественное → размеры кластеров, частота, бюджет, доли решений, удовлетворённость, топ-проблемы конкурентов.
4. Выход — **карта сегментов**: работы-сегменты вокруг больших работ + экономическая привлекательность каждой. НЕ заранее выбранная когорта с приклеенными потом работами.

**Ловушка последовательных фильтров:** каждый следующий критерий применяется только внутри среза от предыдущего — и большой привлекательный сегмент удаляется до начала исследования, его Core-работ никто не увидел. Классика: «проинтервьюируем отточенных и найдём их работы» сначала режет мир на «остались/отвалились/не платили» и ищет работы только в «отвалившихся». Дисциплина: **перед применением фильтра записать, что он удаляет**; если удаляемый срез может содержать плативших за нужные работы — фильтр слишком ранний. Диагностические когорты (отвалившиеся, не купившие, писавшие в поддержку) объясняют локальное состояние, но не определяют карту сегментов.

### 10.3. Причинные критерии vs фейковые

**Причинный критерий** — свойство клиента/компании/контекста, благодаря которому мы знаем, как создать добавленную ценность, заработать целевую маржу или создать спрос. Он *меняет* решение «конкурировать/нет».

**Фейковый критерий** называет срез, но оставляет все три решения пустыми — покупает ложное ощущение понимания. «Enterprise», «премиум», «родители», «отточенные», «high intent» не причинны сами по себе. Становятся причинными, только когда расшифрованы:

| Ярлык | Причинная расшифровка |
|---|---|
| «Enterprise» | SSO/SAML, аудит-логи, процесс закупок, ИБ-ревью + соответствующий бюджет |
| «Родители» | Дети до пяти → другой критерий, частота, канал, готовность платить |
| «Отточенные» | Только когда известно: отток внутри целевого сегмента + привязан к чинимой работе или разрыву цепочки |
| «Сэкономят $2000» | Это ценность, не критерий. Причинно: «40 полевых техников, каждый пропущенный визит рождает сверхурочные, диспетчер перегружен» |

Каждый причинный критерий должен становиться **наблюдаемым до дорогих усилий на лид**: вопрос квалификации, поле формы, поле CRM, событие использования, фирмографический прокси. Квалификация — точка, где сегментация перестаёт быть языком исследования и становится операционной инфраструктурой.

### 10.4. Решение «конкурировать / нет»: четыре вопроса

Описание сегмента полезно, только если позволяет ответить на все четыре — с минимумом доказательств:

| Вопрос | Минимум доказательств |
|---|---|
| Можем создать добавленную ценность для этих Core-работ? | Core-работы; критерии; текущие решения; доминирующие конкуренты в наборе рассмотрения |
| Можем заработать целевую маржу на единицу? | Бюджет работы; готовность платить; стоимость обслуживания; стоимость привлечения |
| Можем создать/захватить спрос? | Рычаги выбора; прокси каналов; модель продаж |
| Достаточно ли велика возможность? | Достижимое число клиентов; частота; совокупный бюджет сегмента |

Размер — проверка масштаба поверх: критерий может найти сегмент, где ценность/маржа/спрос сходятся, а сегмент всё равно слишком мал для фокуса.

### 10.5. Целевой сегмент, суб-сегменты, путь масштабирования

- **Целевой сегмент** — тот, чьи доказательства дают «да» на все четыре вопроса после сравнения карты. Не тот, что нравится / понятен / уже есть. Фокус = вычитание: не-фокусные Core-работы выводятся из зоны инвестиций, пока целевой не выигран.
- **Суб-сегмент** — та же Core и те же главные критерии, но более острый контекст добавляет критерии СВЕРХУ (payroll: одноштатный vs многоштатный, где контекст добавляет «налоги зарегистрированы и уплачены в каждом штате»). Не путать со Small-работой (брат Core, который продукт не делает).
- **Новый сегмент** — материально меняется Core, критерии или их порядок («опубликовать простой сайт» vs «headless-витрина на 10 000 SKU» — разные работы). Выход в соседний сегмент = заново прогнать дизайн ценности, коммуникацию, привлечение, юнит-экономику.
- **Путь масштабирования:** фокус → выиграть целевой сегмент суб-сегмент за суб-сегментом → добавить соседние. Прибыль с целевого финансирует экспансию. Первый ход внутри нового суб-сегмента обычно — починка разрыва критической цепочки: продукт уже создаёт ценность, но одна ссылка ломается в новом контексте (доступ в здание, формат данных, комплаенс, способ оплаты).

### 10.6. Действующий продукт: секвенирование через маржу × удовлетворённость

Если платящих уже достаточно — начинать с тех, кто валидировал допущения оплатой:
1. Разбить платящую базу по **марже на единицу × удовлетворённости**: A и B прибыльны и довольны настолько, что заслуживают ресурсов; C и D жгут ресурсы без замыкания экономики; X указывает вне текущих Core-работ.
2. Прогнать интервью **внутри A и B**, кластеризуя по Core-работам и критериям.
3. Перефокусировать продукт/привлечение/продажи/поддержку/цены на кластеры A+B.

Это не замена сегментации по работам, а её секвенирование. Не масштабируйтесь по работам без привязанной экономики: работы объясняют ценность, маржа на единицу решает, можете ли позволить себе выиграть сегмент.

### 10.7. B2B и внутренние продукты

- **B2B** — тот же корень (Core + критерии) плюс три обязательных поля: **цепочка ролей сделки** (одна поверхностная Core идёт через разные карты ролей — SMB / mid-market / enterprise-комитет); **процесс одобрения** (свайп карты / закупки / RFP / ИБ / legal / CFO — каждый рождает свой риск разрыва); **структура бюджета** (календарный / проектный / департаментский / аварийный / продления). Для сегментации покупки рекрутировать *принимающего решение*; на каждую роль картировать бизнес-работы И личные.
- **Внутренние продукты** — те же клиенты/работы/сегменты/юнит-экономика, меняется только валюта: бизнес решает финансировать, сотрудники решают, делает ли инструмент их работу энергоэффективнее (если внедрение не принудительное). Три повторяющихся сегмента: дорогие сотрудники (час экономии = высокая ценность), высокообъёмные роли (мелкий выигрыш × много людей), сервисы, критичные для прибыли. Принудительное внедрение портит сигнал удовлетворённости — минимальный критерий тогда не «выбрали нас», а «продукт не создаёт лишних налоговых работ».

### 10.8. Срок годности карты

Карта сегментов — эмпирическое знание со сроком годности; на быстрых рынках (ИИ, регуляторика, каналы) дрейфует за 3–6 месяцев. Триггер обновления — видимое изменение в решениях, бюджетах, каналах, регуляторике, процессах или самом графе. Нижние и Micro-работы меняются быстрее всего, большие — медленнее.

## 11. Частые ошибки → как избежать (сводная таблица)

| # | Ошибка | Симптом | Профилактика |
|---|---|---|---|
| 1 | Работа-существительное («управление арендой») | Из формулировки нельзя вывести ни критерии, ни мотивацию | Дожимать до «я хочу + инфинитив»; глагол обязателен |
| 2 | Критерии-прилагательные («быстро, удобно») | Метрики активации не выводятся | Требовать направление + порог для каждого критерия |
| 3 | Стек глаголов в одном узле | «Зачем?» возвращает ответ из самой фразы | Парсить до иерархии перед использованием (§4.2) |
| 4 | Small-работы под Core | Кросс-продажа и UX-шлифовка перепутаны как ходы | Small — брат Core на одном уровне; тест: «наш продукт её делает?» |
| 5 | Core не на своём уровне | Обещаем то, чего не делаем целиком / зажаты слишком низко | Тест подъёма (§6.2) на кандидатах от плативших клиентов |
| 6 | Фейковые работы в графе | Интервью красивые, конверсия около нуля | Рекрут по доказательству прошлой оплаты; «что вы уже делали ради этого?» |
| 7 | Работа без нанятого решения | Win/loss невозможен, конкуренты выдуманы | Карточка всегда парой: работа + что реально нанял и почему |
| 8 | Сегментация с демографии | Кластеры работ невидимы, «сегменты» не отличаются поведением | Первый срез — Core-работы + критерии; демография только как причинная расшифровка |
| 9 | Последовательные фильтры | Большой сегмент удалён до исследования | Перед каждым фильтром письменно: что он удаляет |
| 10 | Присвоение верхней работы | Маркетинг обещает то, на что продукт лишь влияет | Продукт коммуницирует вклад в большую работу, поставляет Core |
| 11 | Триггер-рассылка без рычагов выбора | Пуши/письма в моменте не конвертят | Сначала загрузить набор рассмотрения, потом ловить триггер |
| 12 | L3-ярлыки живут своей жизнью | Заголовки разошлись с данными интервью | L2/L3 пере-выводить из L1 по требованию, не редактировать напрямую |
| 13 | Извинения вместо починки налоговой работы | Отток «по необъяснимым причинам» | Снять сломанную работу с клиента / починить цепочку / отдать партнёру |
| 14 | Метрику чинят до проверки сегмента | Отток/конверсию оптимизируют по всей базе | Сначала: принадлежит ли метрика целевому сегменту? |
| 15 | Фича «для всех сегментов сразу» | Момент «Ага» не наступает ни у кого | «Какую Core-работу какого сегмента улучшает?» — ответ «всех» = нужна декомпозиция |

## 12. Итоговые чек-листы

**Карточка работы готова, если:**
- [ ] Исход — глагольная фраза, смотрит в будущее состояние.
- [ ] ≥2 критериев с направлением и порогом; каждый переводится в метрику.
- [ ] Каждый пункт контекста объясняет хотя бы один критерий.
- [ ] Триггер — конкретный момент времени, классифицирован по 2×2.
- [ ] Эмоции A и B названы словами клиента (не выведены).
- [ ] Верхняя работа получена лестницей «зачем?», не додумана.
- [ ] Нанятое решение записано + почему обошло альтернативы.
- [ ] Всё подтверждено прошлым действием (деньги/время/энергия).

**Перед стратегическим решением на карте:**
- [ ] Граф прошёл чек-лист валидации (§9.3).
- [ ] Core стоит на уровне по тесту подъёма.
- [ ] Рассмотрены ВСЕ клетки матрицы ходов (§9.1), а не только «точить Core».
- [ ] Косвенные конкуренты картированы на уровне большой работы (включая DIY и «не делать»).

**Перед выбором сегмента:**
- [ ] Сегменты нарезаны по Core-работам + критериям (порядок приоритета учтён).
- [ ] Все четыре вопроса «конкурировать/нет» отвечены доказательствами.
- [ ] Каждый критерий сегментации причинный и наблюдаемый в квалификации.
- [ ] У карты проставлена дата и триггер пересборки.
