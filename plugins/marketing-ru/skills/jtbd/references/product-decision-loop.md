# Цикл продуктовых решений — рабочий playbook

Практическое руководство по одному вопросу: **«что делать дальше с продуктом — и почему именно это»**. Внутри — один повторяющийся цикл (диагноз → сегмент+работа → тест допущений → доказательство ценности → операционка → снова диагноз) и четыре встроенных фильтра: тест самого рискованного допущения (RAT), ABCDX-сегментация платящей базы, гейт юнит-экономики и поиск узкого места (теория ограничений). Поверх всего — один мета-оператор: вычитание.

**Когда применять**
- Запуск нового продукта/фичи, вход на рынок, смена бизнес-модели.
- «Просела метрика — что делать» (конверсия, отток, CAC).
- Выбор целевого сегмента, приоритизация бэклога.
- Оценка чужого бизнеса как инвестиции (см. инвест-линзу в §10).
- Масштаб не важен: механики фрактальны — одна и та же логика работает на кнопке в интерфейсе и на выборе рынка (§12).

**Что на входе:** бизнес-цель (даже сырая), доступ к аналитике/базе клиентов/прошлым исследованиям, 2–6 недель календарного времени на оборот.

**Что на выходе:** выбранная стратегия — последовательность кросс-функциональных действий, заякоренная на ответе «за чьи работы и какие именно мы конкурируем, почему за эти и почему выиграем», плюс ранжированный список допущений, которые эту ставку могут убить, и план их дешёвой проверки.

**Смежные справочники:** граф работ, интервью о работах, механики ценности → skill `jtbd`; проектирование воронки под выбранный сегмент → `funnel-design-ru`; ментальные модели убеждения и ошибка предсказания → `marketing-psychology-ru`; синтез полевых интервью в кластеры → `user-research-synthesis`.

## 1. Пять несущих принципов

1. **Продукт — единый организм.** Discovery, разработка, маркетинг, продажи, поддержка, R&D и финансы работают на ОДИН целевой сегмент и говорят на одном языке — языке работ клиента. Три разные сегментации (продукт по работам, маркетинг по демографии, продажи по индустрии) = рассинхрон и утечка ценности.
2. **Ценность — это дельта, а не фича.** Мозг клиента оценивает каждое взаимодействие как инвестор: предсказанный результат против предсказанных издержек (деньги, время, усилия, когнитивная нагрузка, негативные эмоции). Поведение меняет **разница** между доставленным и ожидаемым: превысил ожидание → Aha-момент; совпал → сигнала нет; не дотянул → Проблема. Планка ожиданий растёт постоянно — вчерашний «вау» сегодня база. Фича — лишь грузовик, доставляющий изменение состояния клиента.
3. **Вычитание — мета-оператор.** Самый сильный ход обычно — удалить: работу из графа клиента, нецелевой сегмент, рискованное допущение, фичу, канал (§8).
4. **Это петля, не прогон.** Каждый оборот отдаёт рынку действие и забирает новые данные для следующего оборота.
5. **Два трека параллельно.** Локальный оптимум (улучшать текущий продукт/сегмент/модель): низкий риск, низкий потолок, делегируем вниз. Глобальный (сменить сегмент/модель/рынок/ключевую работу): высокий риск, мультипликативный апсайд, только владелец/C-level. Это не «или-или», а два фонда, финансируемые одновременно. Команда без глобального трека сползает в дилемму инноватора за 3–5 лет.

## 2. Диагностическая ось: цепочка причин прибыли

Хребет любой диагностики. Цепочка последовательна до ценности, затем ветвится на три условия, которые должны держаться **одновременно**, затем сходится в прибыль. Каждый узел наследует качество узла над собой → **диагностика всегда идёт сверху вниз**.

```
Рынок с деньгами
  → Сегмент + Работа            (одна аналитическая сущность, не два шага)
  → Добавленная ценность
  → ┌─ Юнит-экономика: положительная поштучная математика
    ├─ Спрос: привлечение при целевом CAC и качестве лидов
    └─ Масштабируемость: операции/поддержка без деградации качества
  → Экономика продолжает сходиться на масштабе (конверсия + удержание + повтор)
  → Целевая прибыль
```

Правила чтения цепочки:

| Правило | Что означает на практике |
|---|---|
| Рынок = сумма трат на работу | Не «рынок EdTech», а «сколько люди тратят, чтобы освоить навык ради смены карьеры» |
| Сегмент+Работа — одно целое | Сегмент = группа с похожими ключевыми работами и похожими критериями успеха. Демография — коррелят, не разрез |
| Три условия — параллельны | Тестируются одновременно, не по очереди |
| Сломанная метрика ≈ никогда не проблема самой метрики | Низкая конверсия / высокий CAC / отток — почти всегда выше: неверный Сегмент+Работа, ценность не бьёт альтернативы, или отказало одно из трёх условий. Сначала расследуй верхние узлы |

**Крупнейший единичный рычаг** — выбрать самую экономически ценную работу в сегменте с бюджетом. Скрин из четырёх измерений (все четыре сразу, выбор по одному — самая дорогая стратегическая ошибка):
1. Разрыв ценности работы против текущих решений клиента.
2. Бюджет сегмента на эту работу.
3. Размер и достижимость сегмента.
4. Доступность сегмента через известные тебе каналы.

## 3. Один оборот цикла: 3 фазы, 10 шагов

Стоимость шага растёт по фазам: Фаза I — часы (голова / эксперт / LLM), Фаза II — недели и реальные деньги на поле, Фаза III — самый большой спенд, разрешён только после убийства рискованных допущений и доказанной ценности.

```
 ┌─► ФАЗА I. РАМКА И ГИПОТЕЗЫ (дёшево, быстро)
 │     1. Оспорь бизнес-цель
 │     2. Диагностируй текущее состояние
 │     3. Собери слой: карта сегментов · граф работ · consideration-наборы
 │     4. Отбери кандидат-механики ценности
 │
 │   ФАЗА II. ПОЛЕ И ГЕНЕРАЦИЯ (реальное время и деньги)
 │     5. Полевое исследование, заданное механиками
 │     6. Примени выжившие механики к реальному графу работ
 │     7. Ранжируй по RICE + гейт юнит-экономики
 │
 │   ФАЗА III. СНЯТИЕ РИСКА И ОТГРУЗКА (крупнейший спенд)
 │     8. RAT — тест самого рискованного допущения
 │     9. Валидация ценности: продажи → UX 4/4
 └──── 10. Отгрузи топ-ставку → новые данные → к шагу 1
```

**Логика гейтов.** Каждый шаг — гейт: не подтвердился → пивот (смена набора допущений), дальше не идём. Нашёл на шаге N ложное допущение из шага N−K → вернись и пересобери от точки ошибки, не имитируй прогресс на сломанном верхнем узле.

### Шаг 1. Оспорь бизнес-цель
Выданная цель очень часто неверна («подними метрику», «отгрузи фичу»). Анализ пути к неверной цели — самая дорогая ранняя трата. Прогони 5 «почему» вверх: фича → конверсия → продажи → маржа → прибыль → стратегическая цель; на каждом уровне спроси, нет ли более эффективного способа достичь верхней цели. Явно выбери трек: локальный или глобальный оптимум.
**Выход:** фокус-цель на правильном уровне + выбор трека + отрезанные альтернативы с причинами.

### Шаг 2. Диагностируй текущее состояние
Не прыгай к решениям, не поняв ситуацию — главная ошибка стратега. Собери: карту сегментов и графы работ; принятые ранее решения по цели и их исход; владельца, ресурсы, конфликтующие цели, стейкхолдеров; исследования, фидбек, когорты, юнит-экономику. Определи контекст: новый продукт или существующий, стадия PMF (нет / слабый / сильный / «вырывают из рук»). Для существующего продукта — ABCDX по платящей базе (§6) + switch-интервью с оттоком; сначала «почему остаются?», потом «почему уходят?».
**Выход:** структурированная картина + явный контекст.

### Шаг 3. Собери слой — сначала данные, потом гипотеза
Стартуй с имеющихся структурированных данных (аналитика, прошлые исследования, отзывы), гипотезируй только пробелы; LLM быстро набрасывает гипотезные части. Цель — материал, достаточный чтобы **задать** исследование, не точность.
- 3.1 **Карта сегментов** — корень: похожие ключевые работы с похожими критериями (большая работа сверху — мотивационный контекст, не разрез).
- 3.2 **Граф работ целевого сегмента** — большая работа → ключевые → малые/микро + критическая цепочка (детали построения → skill `jtbd`).
- 3.3 **Consideration-набор на каждую ключевую работу** — 3–5 текущих решений, включая «сделать самому» и «ничего не делать» (оба — тоже графы работ), и чем наш граф отличается.

### Шаг 4. Отбери кандидат-механики
Пройди каталог механик создания ценности (→ `jtbd`) и отметь те, что теоретически бьют цель на этом слое. Оставь горстку самых верибельных.
**Выход:** шорт-лист механик, у каждой — список неизвестных для поля.

### Шаг 5. Полевое исследование, заданное механиками
**Отобранные механики — это ТЗ на исследование**, без них интервьюируешь вслепую:
- «Переход к предыдущей работе» → «проведи меня по шагам от появления большой работы до покупки текущего решения»;
- «Убей работу» → «что в текущем процессе ненавидишь или вечно откладываешь?»;
- «Сними страхи/барьеры» → «когда почти купил, но не купил — что остановило?».
Инструменты: интервью о работах, switch-интервью с оттоком, экспертные интервью, аналитика, количественный опрос для оценки размеров сегментов. **Рекрутируй только тех, кто уже платил** (за нас или конкурентов) — дешёвый фильтр против фейковых работ. Синтез интервью в кластеры → skill `user-research-synthesis`.

### Шаг 6. Примени выжившие механики к реальному графу
Каждая гипотеза = `сегмент × работа × механика → конкретное действие`. Реальная ценность обычно лежит **вне** текущих ключевых работ — в предыдущих/следующих работах, больших работах, соседних сегментах, эмоциональных работах, разрывах критической цепочки:
- *Убей работу* × онбординг → авто-импорт данных клиента: работа настройки исчезает.
- *Переход к предыдущей работе* × лидген → бесплатный калькулятор, которым пользуются ДО готовности купить: ловим раньше конкурентов.
- *Сними работу с клиента* → ведём процесс как услугу, клиент только одобряет.
- *Свяжи с новой большой работой* × статус → привяжи ключевую работу к «сигналить, кто я»: готовность платить растёт без изменения продукта.

Гипотеза засчитывается, только если делает **большую работу** лучше по собственным критериям успеха сегмента. Улучшение по критерию, который не поднимается к важному для клиента критерию большой работы, не вытянет переключение, каким бы истинным ни было.

### Шаг 7. Ранжируй по RICE + гейт экономики
- **R** — доля целевого сегмента, для которой гипотеза создаёт ценность.
- **I** — экспертная оценка добавленной ценности; шкала своя под каждую цель (конверсия ≠ удержание ≠ AOV).
- **C** — по иерархии доказательств: мнение < аналитика < опрос < интервью < MVP < продажи.
- **E** — усилия.

**Гейт юнит-экономики:** может ли гипотеза в принципе дать целевую маржу на паре сегмент/клиент? Нет — в корзину, какой бы красивой ни была. Запиши альтернативную стоимость: что отдаёшь, выбирая это вместо следующих гипотез.
**Выход:** ранжированный список + топ для теста.

### Шаг 8. RAT — тест самого рискованного допущения
Полностью — §5. Кратко: под топ-гипотезой — письменный список положительно сформулированных допущений; приоритизируй по формуле `(P × Стоимость провала) / Стоимость проверки`; убей смертельное и самое дешёвое первым. **Цель новой инициативы — убить или пивотнуть её, а не запустить.** Гейт: ключевое допущение опровергнуто → стоп и пивот.

### Шаг 9. Валидация ценности: продажи → UX 4/4
**Лучшая валидация — живые продажи.** Коммуницируй на уровне большой работы (там мотивация), обещай только то, что цепочка реально доставляет (сверх-обещание производит Проблему). Solution-интервью итерациями по 6. Пять итераций без продаж = фундаментальная ошибка в сегменте/работе/ценности → пивот (сегмент — самый рычажный), а не «ещё один круг».

После первых продаж — **UX-тесты по правилу 4/4**: четверо из четырёх выполняют ключевую работу без критических ошибок. Один провалился → чини → новая четвёрка, до 4/4. На каждом экране четыре вопроса: что видишь / о чём думаешь / что чувствуешь / что хочешь сделать. Aha-момент двигай максимально влево в критической цепочке — каждый шаг до него = окно оттока. Только после 4/4 продаж и 4/4 UX — полномасштабная разработка. (Дизайн шагов воронки под этот путь → `funnel-design-ru`.)

### Шаг 10. Отгрузи и зациклись
Отгрузи топ-ставку, забери данные рынка, вернись к шагу 1: пере-оспорь цель, обнови диагноз. Держи граф работ как **временной ряд** (какие работы умерли, какие появились, куда движется рынок) — ценность = упрощение графа во времени. Параллельно финансируй второй трек под глобальный ход.

### Контекстные ветки

| Контекст | Как меняется цикл |
|---|---|
| PMF = 0 | Главная цель — Go-to-Market: сначала найти платящие сегменты, потом доказывать ценность. Не масштабируй несуществующий продукт |
| PMF слабый | Расти ценностью, отстройся от альтернатив, дотяни маржу |
| PMF сильный | Масштаб, новые продукты, удержание, AOV, новые рискованные инициативы |
| Новый продукт | Полный цикл с шага 1. Главный риск — фейковая или редкая/низкочастотная работа |
| Существующий | Базовые риски снижены; старт с ABCDX + switch-интервью; ограничения — привычки клиентов, внутренняя политика, зона ответственности PM |

**Антипаттерн («сломанный процесс»):** придумали фичу → интервью «есть ли ценность?» → строить/не строить. Ломается трижды: (1) предвзятость подтверждения — ищешь «да»; (2) старт с фичи, а не с работы — слеп к остальному графу; (3) из 100+ механик случайно угадал одну.

## 5. RAT: тест самого рискованного допущения

Любая инициатива — стек допущений: кто клиент, за что платит, масштабируется ли канал, сходится ли экономика, разрешает ли регулятор. **Суть RAT: вскрыть все допущения, ранжировать по летальности, купить самое дешёвое доказательство против самого летального — первым, до билд-бюджета.**

### 5.1 Правила формулировки
- **Письменно.** Устный список — не список.
- **Положительно:** «сегмент платит по нашей цене», а не «клиенты могут не заплатить». Положительная форма говорит, что подтверждать, а не о чём тревожиться.
- **Фальсифицируемо одним экспериментом.** Лозунг — не допущение:
  - ❌ «Рынок растёт» → ✅ «Рынок X для [компаний до 50 сотрудников с оборотом < $1M/год] достаточен для бизнеса $100M ARR и рос ≥10%/год три года подряд».
  - ❌ «Сегмент купит» → ✅ «Среди [сегмент], при [интеграция 9 строк SDK по опубликованной цене], через [dev-каналы], доля покупки ≥10% на квалифицированного разработчика за 30 дней».
  - Абстрактная версия «ощущается верной» — именно поэтому большинство «валидированных» допущений никто не удосужился сделать конкретными.

### 5.2 Пять базовых рисков (+ шестой, который и убивает)
1. **Рынок** — существует, достаточно велик, растёт, нет блокирующего регулирования.
2. **Сегменты и работы** — люди с нужными ключевыми работами существуют, их достаточно, они достижимы; выбранные работы — самые привлекательные экономически. **Это корень: здесь умирает больше циклов, чем где-либо.** Ошибка каскадит вниз по всей цепочке; обратное неверно — сбой канала не отменяет верный выбор Сегмент+Работа. Сегментируй по ключевым работам и критериям успеха, НЕ по большим работам и НЕ по демографии: две группы с одинаковой демографией и одной большой работой могут иметь инвертированные наборы ключевых работ — это разные сегменты. **Критерии успеха = критерии сегментации.**
3. **Ценность** — клиенты из этих сегментов покупают наш продукт, чтобы выполнять эти работы.
4. **Юнит-экономика** — средняя маржа на платящего достигает цели.
5. **Каналы** — повторяемые каналы существуют, укладываются в бюджет экономики, масштабируются, поток предсказуем.
6. **Кастомные риски** — специфика механики ИМЕННО этого продукта: как поведут себя водители, поставщики, регуляторы, интеграции, дистрибьюторы в конкретной точке операционной модели. Невидимы с уровня категории, невидимы основателям до удара о стену, убивают после захода крупного капитала (классика: премиум-подписка на короткое видео; всегда включённая камера в публичных местах; дорогой аппарат, чью работу делали руки; «пользователи бросят Excel» — выжили те, кто дал иную первичную ценность, а не замену). Две практики инвентаризации: **поговори с продавцом конкурента до билда** (один эксперт убивает полугодовой план за 45-минутный звонок); **пройди операционную модель по каждому актору и шагу** — кастомные риски живут на стыках.

### 5.3 Формула приоритета
```
Приоритет риска = (P(риск сбудется) × Стоимость, если сбудется) / Стоимость проверки
```
Наверх всплывает допущение с высокой вероятностью ошибки, дорогими последствиями и дешёвым экспериментом. Задача формулы — **упорядочить**, не оценить точно. Следствия:
- Сегменты-и-Работы — наверх почти в каждом новом продукте (проверяются за 15–25 интервью до билд-бюджета).
- **Делегирование по уровню риска:** дорогие высоковероятные — топ-менеджмент; дешёвые низковероятные — вниз. Новые продукты запускают сеньоры, фичи отгружают джуны.
- Знаменатель меняет ответ: при равном риске первым идёт то, что дешевле проверить — отсюда преимущество concierge-MVP, fake-door, smoke-тестов и звонков партнёрам над билдом.
- Вопрос недели для любой команды: «Какое единственное самое рискованное допущение прямо сейчас — и какой самый дешёвый эксперимент его опровергнет?»

### 5.4 MVP — зонд, не продукт
«P» в MVP — самое вредное слово. MVP — **зонд** для проверки явно упакованных в него допущений, быстро и дёшево. Критерий успеха зонда — «проявился ли риск», а не «продалось ли»: зонд, ответивший «сегмента не существует», — успех (купил самое дорогое знание дёшево). Форма зонда диктуется формой риска: риск «не заплатят» → лендинг с ценой и кнопкой оплаты; риск «водители саботируют» → звонок водителю; риск «энтерпрайз не купит без сертификации» → интервью с покупателем, не аудит. **Зонд обязан поимённо перечислить допущения, которые тестирует** — иначе он сполз в «маленькую версию продукта».

### 5.5 Три исхода (по убыванию вероятности)
- **Убить** — сработал летальный риск. Это УСПЕШНЫЙ RAT: знание куплено дёшево, капитал перераспределён.
- **Пивот** — часть допущений выжила; меняем набор и продолжаем. Большинство продуктов до PMF пивотят несколько раз.
- **Пройти** — редкий лучший исход, на который не ставят.

Метрика скорости команды — доказательства-на-доллар против верхнего риска, не «фич за квартал». Команда проектирует **эксперименты, а не продукт**.

### 5.6 Пивот = смена набора допущений
Не копирайт/скин/цена/канал, а замена одного или нескольких допущений:

| Тип пивота | Что меняется | Пример |
|---|---|---|
| Одно-допущенческий | одно звено, остальное держим | тот же продукт → другой рынок |
| Много-допущенческий | 3–4 звена разом | новый сегмент + канал + модель |
| Полный | каждое звено | пересборка с нуля |

Принципы: меняй допущение с высшим приоритетом риска первым; предпочитай менять невалидированные, сохраняй оплаченные доказательствами (подтверждённый сегмент, рабочий канал, измеренный Aha); **пивот сегмент-работа — самый рычажный**, когда под вопросом и сегмент, и ценность (смена сегмента каскадит в ценность/коммуникацию/каналы/модель; обратно не каскадит); один набор за итерацию.

### 5.7 Цепь, не множество
Разрыв где-либо вверху обесценивает каждый доллар ниже. Неверный Сегмент+Работа → бессмысленны MVP, бренд, канал, воронка, команда. Неверная ценность → бессмысленны оптимизация, удержание, масштаб. Не сходится экономика → бессмысленен рост. Напиши цепочку → прогони формулу → валидируй верхнее → только потом трать вниз.

### 5.8 Риски множатся — вычитай их
Выживание мультипликативно: семь допущений с вероятностью выживания 60% каждое → 0.6⁷ ≈ 3% совместного выживания. Каждое добавленное допущение множит смертность; каждое снятое множит выживание на 1/p. **Самый рычажный ход — упражнение «что выбросить»** на кике и каждой вехе: какое допущение / интеграцию / партнёрство / найм / строку бюджета убрать целиком, не ломая суть? (Выбросить свою разработку → no-code MVP за 3 недели; выбросить маркетплейс-компонент → первые 50 сделок consierge-вручную; выбросить интеграции → первая когорта шлёт данные вручную.) Дефолт: **выбрасывай, пока не докажешь, что без этого продукт не существует.** Секвенирование: сначала шире и «на коленке», узкая версия строится на уже купленных доказательствах.

### 5.9 RAT-карточка (fill-in шаблон, одна карточка = одно допущение)

```markdown
### RAT-карточка №__ — [короткое имя допущения]

Допущение (положительно, конкретно, фальсифицируемо):
  «[сегмент] при [цена/продукт/условие] через [канал] делает [X] с частотой/долей [Y] за [срок]»

Тип: рынок / сегмент+работа / ценность / юнит-экономика / канал / КАСТОМНЫЙ
P(риск сбудется): __ %        ← честная оценка вероятности провала
Стоимость, если сбудется: __  ← что теряем (деньги/время/окно рынка)
Стоимость проверки: __        ← цена самого дешёвого зонда
ПРИОРИТЕТ = (P × Стоимость провала) / Стоимость проверки = __

Зонд (форма = форме риска, НЕ мини-версия продукта): ___
Что именно тестирует зонд (поимённо): 1) ___  2) ___
Критерий чтения: «риск проявился?» — порог: ___  (НЕ «продалось ли»)
Дедлайн зонда: ___
Исход: □ убить  □ пивот (меняем: ___)  □ пройти к следующему допущению
```

**Worked-мини-пример заполнения.** Продукт — ИИ-ассистент отчётности для маркетинговых агентств, цена 15 000 ₽/мес:

| Поле | Значение |
|---|---|
| Допущение | «Агентства 5–30 человек с ≥8 клиентами на ведении покупают автосборку клиентских отчётов за 15 000 ₽/мес через холодный Telegram-аутрич с конверсией ≥5% из демо в оплату за 30 дней» |
| Тип | сегмент+работа (и кусок канала) |
| P(сбудется) | 60% |
| Стоимость провала | ~1.2 млн ₽ (3 мес разработки × команда) + 3 мес окна |
| Стоимость проверки | ~40 000 ₽ (лендинг с ценой + 25 интервью + 3 concierge-сборки вручную) |
| Приоритет | (0.6 × 1 200 000) / 40 000 = **18** — выше всех остальных карточек |
| Зонд | лендинг с кнопкой оплаты + вручную собранный отчёт для 3 агентств |
| Критерий | ≥2 из 3 concierge-клиентов платят повторно за месяц 2; ≥5% демо→оплата |

## 6. ABCDX: сортировка платящей базы

Сортирует **платящих** клиентов по двум независимым осям — **поштучная маржа × удовлетворённость** — и перемещает ресурсы к тем, кого стоит держать. Это главный **локальный** ход: работы и бизнес-модель фиксированы, меняется **кого обслуживаем**. (Глобальные ходы иные: новый сегмент, работа уровнем выше, смена модели.)

### 6.1 Пять групп

| Группа | Маржа | Удовл. | Диагноз | Действие |
|---|---|---|---|---|
| **A** | высокая | высокая | тихо покупают, редко в поддержке, рекомендуют | **перераспределяй ресурсы сюда** |
| **B** | чуть ниже | неполная | продукт закрывает часть их работ, 1–2 вне досягаемости | закрой разрыв → B станет A; **самый дешёвый источник A следующего квартала** |
| **C** | номинально ок, с поддержкой ноль/минус | низкая | купили по ошибке: плохой фит под их работы; просят фичи, не нужные A/B | не слушать их фидбек; уволить или автоматизировать |
| **D** | низкая | низкая | балласт, поддержко-ёмкие | **уволь** или тариф с нулевой себестоимостью |
| **X** | — | — | коснулись продукта, но их работы вне текущего скоупа | **сигнал роста** — инструментируй и изучай |

Обе оси реальны и независимы: бывает несчастный высокомаржинальный (C по фиту) и любящий тебя убыточник (низкомаржинальный B). Ранжирование только по марже прячет первого; только по удовлетворённости (опрос «насколько расстроитесь без продукта», тест Шона Эллиса) — второго. **Равный вес обеим осям — весь вклад ABCDX.** Превращать B в A обычно выгоднее, чем тянуть A в A+ (планка предсказания растёт). C ≠ D: C иногда переходит в A/B при другом продукте/модели, D — почти никогда.

### 6.2 X — самое дешёвое рыночное исследование
Три типа: **пришли и ушли** (бросили воронку — их работы вне скоупа, это не C); **купили и вернули** (думали, работа совпадает — изнутри выглядит как C, на деле X); **платят, но используют для другого** (работа найма не из заявленных — тихий сигнал соседней работы с реальным спросом; самая действенная группа: назвав побочное применение первоклассной работой, часто открываешь новый сегмент без новой разработки). Тегируй X в CRM намеренно, интервьюируй выборку. Не пытайся конвертить X твиками воронки — несовпадение в работах, не в сообщении.

### 6.3 Порядок разрезов решает
Каждый критерий работает только на срезе, оставленном предыдущими; поменяй порядок — получишь другой сегмент и другую стратегию. Перед каждым разрезом три вопроса: почему этот критерий сейчас? какой срез отрезаю (не выбрасываю ли прибыльный сегмент)? какую ошибку беру (плохой ранний разрез тихо портит всё ниже)?
Классическая ловушка: «давайте проинтервьюируем отвалившихся» — это уже сегментация по критерию «заплатил и отвалился»; кластеризация даст работы среза уже-сжатого, возможно убыточного рынка. **Разверни порядок:** сначала сегментируй по похожести графа работ и экономической привлекательности → потом внутри прибыльного сегмента смотри, кто отвалился. Те же данные, другой порядок, другой ответ.

### 6.4 Реальные критерии — причины; фейковые — симптомы
Реальный критерий — свойство человека/ситуации, **причиняющее** поведение. Годный критерий проходит три вопроса: можем создать ценность? можем обслужить с целевой маржой? можем достучаться?

| Фейковые (симптомы — описывают группу задним числом) | Реальные (причины — говорят, что искать в новом лиде) |
|---|---|
| «потратил > 100 000 ₽ за полгода» | «готов делегировать проект целиком» |
| «> 2 заказов» | «бюджет $100K+ на объект» |
| «ноль жалоб», «NPS ≥ 9» | «живёт в другом городе — время дороже денег» |
| «активен в продукте ежедневно» | «ждёт $1M+ от проекта — наша комиссия для него погрешность» |

Скрытые критерии, пропускаемые на первом проходе: уровень тревоги, уверенность сделать самому, жёсткий дедлайн, ожидаемая выручка проекта, плохой прошлый опыт с конкурентом. Реальные критерии превращаются в **4–5 входящих квалифицирующих вопросов**, маршрутизирующих лид за минуту, и в конкретные отсечки в устье воронки («< 5000 SKU — не фит; ≥ 5000 — вот менеджер»). Внедрение отсечек в воронку → `funnel-design-ru`.

### 6.5 Границы применимости
- **ABCDX специфичен для пары клиент+продукт.** Один и тот же человек — A здесь и D там. Не импортируй ABCDX конкурента; прогоняй на своей базе.
- **Нужен паттерн, а не шум.** A-паттерн = свойство, разделяемое 10–15 клиентами, не тремя выбросами. Пороги: тесная однородная база — от 50–80 платящих; разнообразный энтерпрайз с китами — от 500+. Ниже порога ABCDX — гипотеза (визуальный паттерн A → критерий рекрутинга → иди найди ещё совпадений). Совсем нет паттерна = ищешь сегмент с нуля (глобальный трек: интервью тех, кто платил конкурентам).
- **Маркетплейс = два независимых ABCDX** (спрос и предложение). Стратегический вопрос — какой A одной стороны эффективнее всего обслуживает A другой; **начинай с дефицитной стороны**. A-спрос и A-предложение не пересекаются → маркетплейс не клирится в прибыльной точке: структурный дефект, не проблема привлечения.
- **Два пути по времени:** ABCDX — быстрый (~1–3 мес), лифт выручки за квартал, по построению локальный. Полное рыночное исследование — ~6+ мес, полная картина (мы/конкуренты/необслуженные), даёт право на глобальную ставку. Для нового продукта без платящих — сначала похожесть графа работ, ABCDX позже.

### 6.6 Что делать после разметки
1. Назови **причинные** критерии A/B → перенастрой привлечение, продажи, продукт под них.
2. **Перестань использовать фидбек C/D для решений** — их запросы тянут продукт прочь от фита A/B.
3. **Активно увольняй C/D** тремя механиками: отказ в устье воронки; автоматизация до near-zero себестоимости (self-serve/бот); поднятие цены (часть C станет B, остальные уйдут сами). Тест: «если построить идеальную версию продукта — станут ли они прибыльными?» Для реальных C/D ответ «нет»: несовпадение в типе работы, не в качестве.
4. Большую группу C/D иногда пере-маршрутизируют через **другой** продукт — но X обычно лучший старт для глобальной ставки, чем C/D.
5. Внутри A/B — второй разрез: кластеризация по графу работ через 15–25 интервью → выбор **целевого сегмента** (A/B были лишь способом быстро дойти до чистого сигнала). ABCDX без интервью — половина хода; интервью без ABCDX — риск гнаться за неплатящим сегментом.

### 6.7 Процедура (2–4 недели)
1. Возьми платящую базу за фиксированное окно (6/9/12 мес, не all-time — иначе перевес старых клиентов).
2. Ранжируй по поштучной марже: `выручка − переменная себестоимость − attributed CAC`. Нет данных — экспертно: продажи+поддержка ранжируют по памяти удивительно точно.
3. Кросс-ранжируй по удовлетворённости (NPS/CSAT/удержание/повтор/рекомендации/тикеты/каденс).
4. Кластеризуй в группы A/B/C/D; X — отдельным списком.
5. Найди причинные критерии каждой группы (§6.4).
6. Преврати в 4–5 квалифицирующих вопросов.
7. Внутри A/B — кластеризация по работам (§6.6 п.5).
8. Перестрой аллокацию: каналы/тарифы/онбординг/поддержка/цена в пользу A/B; C/D в self-serve; X под наблюдением. **Здесь глохнет большинство усилий: найти A легко, увести C/D тяжело операционно и эмоционально.**
9. Пере-прогоняй: при смене ключевых работ (обязательно), смене модели, сдвиге среды — и минимум раз в год (дважды в быстрых категориях). Рефреш дёшев.

## 7. Юнит-экономика — финансовый гейт цикла

Если поштучная математика не сходится — продукта нет, какими бы хорошими ни были работы.

- **Каждая работа связывается с маржой.** Гипотеза ценности проходит гейт шага 7: способна ли в принципе дать целевую маржу на паре сегмент/клиент.
- **Условие цепочки (§2):** LTV > CAC, окупаемость CAC < 12 мес, целевая contribution-маржа на юнит. Тестируется параллельно со спросом и масштабируемостью.
- **Считай на уровне сегмента, не в среднем.** Средняя экономика прячет структуру: клиент, выглядящий A по выручке, становится C по марже после пере-базирования CAC на его сегмент.
- **ABCDX работает на contribution-марже на клиента** (или заказ), не на марже компании.
- **Вычитание в экономике:** удаляй отрицательно-маржинальные юниты, каналы, транзакции, SKU (§8).

**Мини-калькулятор (worked):** сегмент «агентства 5–30 чел», цена 15 000 ₽/мес, gross churn 4%/мес → средний lifetime ≈ 25 мес; переменная себестоимость 3 000 ₽/мес (инференс+поддержка); CAC канала «холодный ТГ-аутрич» = 35 000 ₽.
- LTV(contribution) = (15 000 − 3 000) × 25 = 300 000 ₽ → LTV/CAC ≈ 8.6 ✅
- Окупаемость CAC = 35 000 / 12 000 ≈ 3 мес ✅
- Тот же продукт для сегмента «фрилансеры» при цене 3 000 ₽/мес и том же CAC: LTV = (3 000 − 1 500) × 15 = 22 500 ₽ → LTV/CAC = 0.64 ❌ — сегмент в корзину независимо от того, как сильно он «любит продукт». Это и есть гейт на уровне сегмента.

## 8. Теория ограничений: одно узкое место за раз

Пропускную способность системы задаёт **самое медленное звено**; узкое место **сдвигается** по мере изменения системы.

- **Критическая цепочка работ** — последовательность работ, которые должны завершиться, чтобы сложилась работа уровнем выше. Ценность реально доставляется (или проваливается) на прохождении этой цепочки.
- **Строй только ход, ломающий текущее ограничение.** Улучшение не-узкого звена не поднимает пропускную способность — это сожжённый ресурс. Найди одно узкое место (где рвётся цепочка, где отток, где очередь) — направь ход туда.
- После снятия ограничения — **пере-диагностируй**: узкое место сдвинулось, не улучшай по инерции старое звено.
- В параллельной секции цепочки (§2) спрашивай, **какое из трёх условий отказывает**, трактуя их как равноправных кандидатов.
- Для маркетплейса «начинай с дефицитной стороны» — та же логика.

## 9. Вычитание и фокус — один оператор

Под всеми фильтрами цикла — одна операция: **удаление того, что на первый взгляд обязано остаться.**

| Фильтр | Что вычитается | Инструмент | Кому больно |
|---|---|---|---|
| Работы клиента | работы из графа; целые нецелевые сегменты | «убей работу», «сделай за клиента», выбор целевого сегмента | конкуренты; команда, строившая под нецелевые сегменты |
| Юнит-экономика | отрицательно-маржинальные юниты/каналы/SKU | порог LTV/CAC, отсечка окупаемости, закрытие канала | команды, привязанные к объёму |
| RAT | допущения; гипотезы, провалившие тест | упражнение «что выбросить», пивот | авторы идеи (боль идентичности) |
| ABCDX | клиенты C/D, их фидбек, их нагрузка | отсечка в устье, автоматизация, цена | продажи (комиссия), поддержка |

**Почему ROI вычитания структурно бьёт добавление — четыре асимметрии:**
1. **Мозг любит «меньше потрачено».** Добавление просит клиента тратить больше (учиться, решать) ради выгоды потом; вычитание возвращает уже-тратимое немедленно, до кривой обучения. Беспроводные наушники не «добавили аудио» — убили распутывание проводов.
2. **Риск множится.** 7 допущений × 60% ≈ 3% выживания; снять одно → ×1.67; добавить даже надёжное (80%) → ×0.8. Добавление делает продукт МЕНЕЕ вероятным к отгрузке — арифметика, не вкус.
3. **Фокус не суммируется.** Каждое добавление крадёт внимание у каждого прежнего обязательства; вычитание возвращает его всему остальному.
4. **Неприятие потери ~2×.** Удаление трения/тревоги/разрыва регистрируется мозгом примерно вдвое сильнее эквивалентного добавления при той же стоимости билда (подробнее о механике — `marketing-psychology-ru`).

**Практика:** перед одобрением любой фичи — вопрос «что можно убрать из продукта/сегмента/каналов/стека допущений с сопоставимым или большим эффектом дешевле?» При выборе «добавить X с эффектом Y» vs «вычесть причину Проблемы с эффектом Y/2» — дефолт к вычитанию: асимметрии закроют разрыв.

**Предел вычитания — невидимый продукт:** работа выполнена, посредника не видно (проснулся — дом убран; налоги поданы — видел только подтверждение). Это асимптота, не пункт назначения: над каждой снятой цепочкой возникает большая работа уровнем выше. **Конкурента, движущегося к асимптоте, трактуй как экзистенциальную угрозу, не фиче-конкурента:** вопрос не «их фичи против наших», а «сколько графа работ клиента они вычли, что мы всё ещё требуем».

**Команды структурно смещены против вычитания.** Когнитивно: люди по умолчанию добавляют (в экспериментах 60–80% улучшают артефакт добавлением, даже когда вычитание сильнее; смещение снимается одной строкой-праймингом «убирать — бесплатно»); ИИ-инструменты тоже добавляют по умолчанию → смещённый оператор × смещённый инструмент = двойной дрейф. Институционально: добавление видимо (демо, слайд), вычитание — абзац в чейнджлоге; вычесть = признать ошибку; KPI платят за отгруженное; карьерный риск вычитания приватизирован, риск добавления социализирован.
**Противоядия:** вычитание — явный артефакт квартального ревью («что вычли и что это высвободило?»); прайминг в момент каждого решения; ответственность за вычитание — на самой авторитетной роли (глобальный оптимум субтрактивен и неделегируем); при найме на такие роли тестируй способность вычитать, не только строить.

**Фокус = управление вниманием = вычитание.** `направить(X) = вычесть(притязания-на-не-X)`: команда не добавляет внимание на фокус — она перестаёт тратить его на не-фокус. Фокус фрактален (внимание клиента в цепочке → компания → департамент → портфель → день сотрудника); масштабы вложены — клиентское внимание не управляется, если день сотрудника съеден процессами не для целевого сегмента. **Диагностируй масштаб до выбора механики.** Когда фокус «теряется» — смотри, какие притязания на внимание не были отклонены (громкий клиент вне сегмента, идея VP, новостной цикл конкурента): фокус не ослаб — вычитания не случились. Внимание сотрудника по умолчанию уходит на: клиентов перед глазами, KPI (измеряемое получает внимание), носителя власти, календарь основателя. KPI — явные инструкции, куда тратить внимание; увольнение C/D — внимательностная триажа. И держи оба трека: отказ на целевом сегменте + минимум один KPI, одна аллокация и один слот времени основателя в квартал на глобальный ход.

## 10. Диагностический чек-лист «сверху вниз» + инвест-линза

Провал пункта рвёт цепочку; расследуй верхние пробелы первыми.

1. Есть экономическая карта сегментов (размер, бюджет, частота, достижимость каждого)?
2. Целевой сегмент выбран по четырёхфакторному скрину (§2): самая ценная работа × сегмент с бюджетом под целевую маржу?
3. Известен граф работ целевого сегмента (большие, ключевые, малые, микро)?
4. Известны критерии успеха ключевой и большой работы?
5. Aha-момент вскрыт и сдвинут максимально влево в цепочке?
6. Ценностное предложение в форме `[сегмент] + [работа] + [насколько эффективнее] + [фичи]`?
7. Есть доказательство ценности (платят; пользуются; возвращаются)?
8. Держатся ли все три параллельных условия: (a) экономика сходится на уровне сегмента, не в среднем; (b) каналы смоделированы, протестированы, масштабируются; (c) операции масштабируемы без деградации качества?
9. Все функции выровнены вокруг одного целевого сегмента?
10. Конверсия+удержание держат сходимость экономики по мере роста потока?

**Инвест-линза (оценка чужого бизнеса):** есть ли выбранная стратегия («за чьи работы конкурируем, почему за эти, почему выиграем» — выбранная из видимого набора альтернатив)? Едина ли (продукт/маркетинг/продажи — одна стратегия в разных формах, не три документа)? Выровнены ли функции? Есть ли фокус (ресурсы на 1–2 сегмента, не размазаны на «всех»)? Цела ли цепочка причин-следствий насквозь? Отвечающая «да» компания компаундит; неспособная — жжёт капитал в сломанном узле и зовёт это «исполнением».

## 11. Worked-пример: один полный оборот цикла

Продукт: **B2B SaaS «Отчётный» — автосборка клиентских отчётов для маркетинговых агентств.** Существующий продукт, слабый PMF: 140 платящих, MRR 1.6 млн ₽, отток 6%/мес. Вводная от владельца: «конверсия из триала упала, нужен редизайн онбординга».

**Шаг 1 — оспорь цель.** 5 «почему»: редизайн → конверсия триала → продажи → маржа → прибыль. Раскоп показал: конверсия триала стабильна у агентств, упала у наплыва фрилансеров с нового канала. Фокус-цель: «рост прибыли через концентрацию на прибыльном сегменте», трек — локальный. Редизайн онбординга отрезан (лечил бы симптом).

**Шаг 2 — диагноз + ABCDX** (окно 9 мес, 140 платящих):

| Кластер | Клиентов | Маржа/мес на клиента | Удовл. | Группа |
|---|---|---|---|---|
| Агентства 10–30 чел, ≥8 клиентов на ведении | 24 | 11 200 ₽ | высокая (NPS 62, тикетов мало) | **A** |
| Агентства 5–10 чел | 31 | 8 400 ₽ | средняя («нет white-label PDF») | **B** |
| Инхаус-маркетологи | 38 | 2 900 ₽ | низкая (просят фичи «для себя», не для клиентов) | **C** |
| Фрилансеры | 47 | −600 ₽ (поддержка съедает) | низкая | **D** |
| X-список | 19 касаний | — | используют не для отчётов, а для **аудита подрядчика** перед наймом | **X** |

Причинные критерии A (не симптомы!): «отчёты — договорное обязательство перед клиентами агентства» + «≥8 клиентов → ручная сборка ≥16 ч/мес» + «есть аккаунт-менеджер, чьё время оцифровано». Квалифицирующий вопрос в устье: «Сколько клиентов у вас на ежемесячной отчётности?» — < 4 → self-serve тариф без поддержки.

**Шаги 3–4 — слой и механики.** Граф работ A-сегмента: большая работа «удержать клиента агентства» → ключевые: собрать данные → интерпретировать → оформить → защитить на встрече. Consideration: руками в таблицах (16 ч/мес), шаблоны BI (нужен аналитик), «ничего» (клиент уходит молча). Кандидат-механики: «убей работу» (сборка), «переход к следующей работе» (защита отчёта на встрече), «сними страх» (клиент агентства не понимает цифр).

**Шаг 5 — поле.** 18 интервью с A/B (только платящие). Находка: сборку продукт уже закрыл; боль сместилась в **следующую работу** — «объяснить клиенту, почему цифры такие»: аккаунты тратят 1–2 ч на подготовку к каждой защите, боятся вопросов.

**Шаг 6 — гипотезы.** Топ: `A-агентства × работа «защитить отчёт» × «переход к следующей работе» → ИИ-«тезисы для встречи»: по каждому отчёту готовые объяснения аномалий + 3 ответа на вероятные вопросы клиента`.

**Шаг 7 — RICE + гейт экономики.** R=0.8 (все A/B с регулярными встречами), I=высокий (закрывает верхний страх аккаунта), C=интервью, E=3 недели. Гейт: фича оправдывает апгрейд тарифа +5 000 ₽/мес → маржа A растёт до ~15 000 ₽/мес, LTV/CAC с 8.6 до ~11 ✅. Альтернативная стоимость: откладываем white-label PDF для B на квартал.

**Шаг 8 — RAT.** Верхняя карточка: «Аккаунт-менеджеры доверят ИИ-тезисы для живой встречи с клиентом (кастомный риск: страх опозориться перед клиентом сильнее экономии времени)». P=50%, провал = 3 недели разработки + подрыв доверия A-сегмента; проверка = 5 concierge-прогонов (тезисы пишет человек под видом фичи) за 3 дня. Приоритет — наверх. Результат зонда: 4/5 аккаунтов взяли тезисы на встречу, 3/5 попросили «ещё к следующей» → риск не проявился, проходим. (Второй зонд — fake-door апгрейда с ценой: 9 из 24 A кликнули «подключить» → сигнал платёжеспособного спроса.)

**Шаг 9 — валидация.** Продажи: 2 итерации по 6 solution-интервью → 7 предоплат апгрейда. UX: первая четвёрка — 3/4 (один не нашёл тезисы внутри отчёта) → перенесли блок на первый экран отчёта (Aha влево) → вторая четвёрка 4/4 ✅.

**Шаг 10 — отгрузка и петля.** Фича в проде для A/B; D-фрилансеры переведены на self-serve без поддержки (−47 клиентов, +80 ₽K/мес contribution за счёт снятой нагрузки); X-сигнал «аудит подрядчика» заведён в глобальный трек как кандидат на отдельный продукт следующего оборота (один KPI + слот времени основателя). Квартальное вычитание: убит канал, приводивший фрилансеров; убран тариф «Старт». Данные оборота: отток в A/B упал до 2.8%/мес → на следующем круге цель пере-оспаривается уже от новой базы.

Итог оборота в цифрах: MRR через квартал 1.9 млн ₽ при меньшем числе клиентов, поддержка −30% нагрузки, найден кандидат на глобальную ставку — без единого «редизайна онбординга», с которого всё началось.

## 12. Частые ошибки → как избежать

| Ошибка | Симптом | Противоядие |
|---|---|---|
| Приняли выданную цель как есть | «делаем редизайн, потому что попросили» | Шаг 1: 5 «почему» до уровня прибыли; письменно отрезать альтернативы |
| Чиним метрику на самой метрике | A/B-тесты кнопок при сломанном сегменте | Диагностика сверху вниз по цепочке §2 |
| Сегментация по демографии/индустрии | «наш клиент — компании 50–200 чел» | Сегмент = похожие ключевые работы + критерии успеха |
| Фича-first процесс | «есть идея — проверим, нравится ли» | Работа-first: цель → граф → механики → поле → гипотезы |
| Интервью с кем попало | инсайты от неплатящих | Рекрут только плативших (нам или конкурентам) |
| Абстрактные допущения | «рынок растёт», «клиенты хотят» | Конкретика: сегмент, цена, канал, порог, срок (§5.1) |
| MVP = маленький продукт | «урезанная версия за 3 месяца» | Зонд под форму риска; допущения перечислены поимённо |
| Валидация «нравится ли» | комплименты на демо, ноль денег | Продажи как критерий; 5 итераций без продаж = пивот |
| Средняя юнит-экономика | «в среднем LTV/CAC = 4» | Считать по сегментам; A по выручке бывает C по марже |
| Слушаем фидбек C/D | роадмап тянет прочь от фита A/B | После ABCDX фидбек C/D исключается из решений |
| Улучшаем не-узкое звено | «стало лучше, метрика не сдвинулась» | Одно ограничение за раз; после снятия — пере-диагноз |
| Только добавляем | скоуп-крип, риски множатся | Упражнение «что выбросить» на каждой вехе; квартальный артефакт вычитания |
| Один трек | либо дилемма инноватора, либо вечный поиск | Оба трека финансируются каждый квартал |
| Интервью отвалившихся до сегментации | стратегия под убыточный срез | Сначала разрез по работам и экономике, потом «кто отвалился» (§6.3) |
| ABCDX на 20 клиентах как истина | «паттерн» из трёх выбросов | Ниже порога — только гипотеза для рекрутинга |

## 13. Фрактальность: одна механика на всех уровнях

«Переход к следующей работе» — это и подсказка на кнопке в UI, и стратегия компании (дизайн → дизайн + ремонт). Уровень применения = масштаб: на большой работе это стратегия, на микро-работе — микрооптимизация. Освоив механики и цикл, применяешь их везде — от копирайтинга до выбора рынка. Именно поэтому чек-лист §4 гоняется и на фиче, и на продукте, и на портфеле — меняется только цена шага, не логика.
