# Промпты для AJTBD через Claude

> Практические промпты под аппарат Advanced JTBD, адаптированные под LLM-ассистента (например, Claude).
> Корми модель РЕАЛЬНЫМИ данными (транскрипты), не давай выдумывать факты — где данных нет, помечай `[НЕИЗВЕСТНО]`.

Перед использованием: возьми реальный контекст продукта и транскрипты интервью (синтез — через `user-research-synthesis`). Не давай Claude выдумывать факты — корми реальными данными.

---

## 1. Извлечь работы (Jobs) из транскрипта интервью

```text
Ты — исследователь по методологии Advanced Jobs To Be Done.
Вот транскрипт глубинного интервью с клиентом:
<<<
[вставь транскрипт]
>>>

Задачи:
1. Выпиши ВСЕ глаголы-кандидаты в «работы» (Jobs) из речи клиента.
2. Для каждой работы определи уровень в графе работ: low (micro) / mid / big / core.
3. Раздели работы на Functional / Emotional / Social.
4. Сформулируй главную Core Job клиента (настоящая мотивация: результат / статус / снижение риска).
Не выдумывай — опирайся только на слова клиента. Где данных не хватает — помечай [НЕИЗВЕСТНО].
```

---

## 2. Разложить решение по Forces of Progress

```text
По методологии Forces of Progress (Progress = (Push + Pull) − (Anxiety + Habit))
проанализируй это интервью о переключении клиента:
<<<
[транскрипт switch-интервью]
>>>

Для каждой из 4 сил выпиши конкретные цитаты клиента:
- PUSH (что не устраивало в текущем) →
- PULL (что привлекло в новом) →
- ANXIETY (чего боялся перед покупкой) →
- HABIT (почему не переключался раньше / что было жалко терять) →

Затем:
- Оцени, какие силы перевешивают и почему клиент в итоге переключился (или нет).
- Дай рекомендации: что усиливать в маркетинге (Push/Pull), что гасить в продукте (Anxiety/Habit).
Только цитаты и факты из интервью, без домыслов.
```

---

## 3. Провести Timeline-разбор пути решения

```text
Восстанови таймлайн принятия решения клиента по 5 стадиям AJTBD:
First thought → Passive looking → Active looking → Decision → Consumption.

Транскрипт:
<<<
[транскрипт]
>>>

Для каждой стадии укажи:
- что происходило (с привязкой к конкретным событиям/датам, если есть),
- триггерное событие перехода на следующую стадию,
- где возникали паузы/сомнения (там ищем Anxiety и Habit).
Помечай [НЕИЗВЕСТНО], где клиент не дал данных.
```

---

## 4. Сформулировать Job Stories

```text
На основе этих работ клиента:
<<<
[список работ / Core Job / контекст]
>>>

Сформулируй 5–7 Job Stories в формате:
"Когда [ситуация/контекст], я хочу [мотивация], чтобы [ожидаемый результат]."

Требования:
- ситуация конкретная и триггерная (есть момент «здесь и сейчас»);
- мотивация = глагол действия, НЕ название фичи;
- результат = прогресс/изменение состояния (functional + emotional + social);
- без упоминания конкретного продукта внутри истории.
```

---

## 5. Заполнить Job Story Canvas

```text
Заполни Job Story Canvas для этой работы клиента:
<<<
[описание работы + цитаты]
>>>

Поля:
- Functional job (что нужно сделать)
- Emotional job (что хочет чувствовать / перестать чувствовать)
- Social job (как хочет выглядеть в глазах других)
- Context (триггер, ситуация, место, время)
- Obstacles (Anxiety, switching costs, нехватка навыка)
- Success criteria (измеримый признак выполнения работы)
Опирайся на цитаты, помечай пробелы [НЕИЗВЕСТНО].
```

---

## 6. Приоритизировать работы через ODI

```text
По методу Outcome-Driven Innovation (Tony Ulwick) построй матрицу важность × удовлетворённость.

Вот desired outcomes клиента (с оценками 1–10, если есть; иначе оцени гипотетически и пометь это):
<<<
[список outcomes]
>>>

Для каждого outcome определи зону:
- UNDERSERVED (важно + плохо удовлетворено) — приоритет для продукта/messaging
- WELL-SERVED (важно + хорошо) — защищать
- OVERSERVED (неважно + переудовлетворено) — упростить / удешевить
- IGNORE (неважно + плохо)
Выдай отсортированный список underserved jobs — это главные зоны возможностей.
```

---

## 7. Сегментация по работам (не по демографии)

```text
У меня есть набор клиентских интервью с извлечёнными работами:
<<<
[работы по респондентам]
>>>

Сгруппируй респондентов в сегменты ПО РАБОТАМ (одинаковая Core Job + контекст),
а не по демографии (пол/возраст/должность).
Для каждого сегмента опиши:
- Core Job,
- контекст возникновения работы,
- Forces (что Push/Pull/Anxiety/Habit),
- кто реальный конкурент (включая non-consumption / «ничего не делал»),
- критерий успеха.
Покажи, как один и тот же продукт может обслуживать разные работы у разных сегментов.
```

---

## 8. Определить рынок как деньги на работу

```text
По AJTBD рынок — это совокупность денег, которые люди уже тратят на выполнение определённой работы
(а не «рынок продукта X» и не аудитория).

Продукт: [описание]
Гипотеза сегмента: [кто клиент]

1. Сформулируй рынок как «деньги, которые тратят, чтобы [работа]» — ШИРЕ, чем гипотеза сегмента.
2. Перечисли, на что эти деньги тратятся сейчас (конкуренты, включая non-consumption и «по-старинке»).
3. Покажи, куда продукт может двигаться вверх по графу работ (на какую более крупную работу претендовать).
```

---

## Чек-лист использования промптов

- [ ] Контекст продукта взят из реальных данных о продукте, не выдуман.
- [ ] На вход поданы реальные транскрипты (не синтетика), иначе результат = гипотеза, помечай как гипотезу.
- [ ] Claude помечает `[НЕИЗВЕСТНО]` там, где данных нет (anti-fabrication).
- [ ] Формулировки промптов адаптированы под твой продукт и данные.
- [ ] Выводы перепроверены на новых интервью (AJTBD = continuous discovery).
