# Unattended Loop Patterns — 7 продакшен-паттернов + safety

> Дистилляция [cobusgreyling/loop-engineering](https://github.com/cobusgreyling/loop-engineering) (7.8k⭐). Только паттерны и дисциплина — ничего не устанавливаем. Применять к своим петлям: `/loop`, `/schedule`, cron твоего бот-флота, cron на твоём сервере. Дополняет 9-частную анатомию из SKILL.md и `loop-guardrails-ru.md` — здесь то, чего там нет: rollout-модель L1→L3, loop-cost и чек-лист unattended-прогона.

## 7 паттернов (одной таблицей)

| # | Паттерн | Каденция | Токен-cost | Уровень | Суть | Твой аналог |
|---|---------|----------|-----------|---------|------|-----------|
| 1 | **Daily Triage** | 2ч–1д | низкий | L1 | Регулярный сбор + отчёт: что нового, что требует внимания | weekly marketing review (бот-аналитик), promise-tracker, daily-briefing |
| 2 | **PR Babysitter** | 5–15м | высокий | L2 | Мониторит открытые PR: ревью-комменты, конфликты, пинг при простое | бэбиситтер веток проекта; интеграция с /schedule |
| 3 | **CI Sweeper** | 5–15м | очень высокий | L2 | Реагирует на красный CI осторожными фиксами через verify-гейты | build-fix по расписанию; ТОЛЬКО с verification gate |
| 4 | **Dependency Sweeper** | 6ч–1д | средний | L2 | Обновления зависимостей patch-only, с прогоном тестов | dependency-auditor → updater по расписанию |
| 5 | **Changelog Drafter** | 1д / по тегу | низкий | L1 | Черновик release notes из мержей | changelog-generator; посты «что нового» для твоего продукта |
| 6 | **Post-Merge Cleanup** | 6ч–1д, off-peak | низкий | L1–L2 | Уборка после мержей: мёртвые ветки, worktree, TODO-хвосты | dead-code-hunter, чистка `_wt_*` (ТОЛЬКО `git worktree remove`!) |
| 7 | **Issue Triage** | 2ч–1д | низкий | L1 | Категоризация входящих issue + предложение решения | триаж лидов/заявок CRM (бот-обработчик), входящие упоминания бренда |

Правило из cost-модели: **токен-спенд ∝ частота каденции × глубина субагентов**. Петли 5–15м с verify-циклами = very high; 1д+ = low/medium. Прежде чем ускорять каденцию — посчитай (у тебя свои лимиты: число параллельных воркеров и квоты подписки/API).

## Rollout L1 → L3 — не запускай unattended сразу

| Уровень | Что делает | Гейт перехода выше |
|---------|-----------|--------------------|
| **L1 Report** | Только смотрит и пишет отчёт/драфт. Ничего не меняет. | ≥2 недели прогонов, по выходу реально действуют (не vanity) |
| **L2 Assisted** | Осторожные фиксы в узком скоупе (patch-only, allowlist путей) + верификация до каждого действия | 0 откатов руками за период, стабильные self-check'и |
| **L3 Unattended** | Полная автономия в границах гейтов | Только для low-cost паттернов с идемпотентностью и kill switch |

Правило поверх: **spend/publish/ПД — никогда не L3** (см. two-tier модель в `loop-guardrails-ru.md`) — авто-драфт ок, авто-публикация и авто-бюджет только через чекпоинт человека-оператора.

## Failure modes (что ломается в unattended)

1. **Token budget exhaustion** — петля выжирает лимит подписки/API, живые сессии голодают.
2. **Unattended mistakes** — тихие неправильные действия по расписанию, повторно, тем же людям.
3. **Comprehension debt** — вычищенный CI/смерженный код, который никто не понимает; «Build the loop like someone who intends to stay the engineer» — человек остаётся инженером системы, вердикты не делегируются.
4. Runaway-каденция — сверхчастые прогоны = busywork, выход начинают игнорировать (главный анти-паттерн из SKILL.md).

## Чек-лист безопасности unattended-прогона

Перед запуском ЛЮБОЙ петли без человека в цикле — все пункты «да»:

- [ ] **Stop-условия** явные: max итераций / дедлайн / условие успеха / error-halt (двойная ошибка подряд → петля отключает себя и пишет в тред/отчёт).
- [ ] **Cost-cap**: потолок токенов/итераций на прогон + circuit breaker на серию прогонов (аналог их `loop-context`); при достижении — halt, не деградация.
- [ ] **Idle-gate для тяжёлых локальных джобов**: только через ресурс-гард (реестр heavy-jobs) — никакого молчаливого крона на рабочей машине (векторизация, батч-генерация, рендеры).
- [ ] **Denylist/allowlist путей и действий**: петля трогает только свой скоуп (аналог их `gate.yaml`); деструктивное (`rm -rf`, DROP, force-push) — запрещено всегда.
- [ ] **Auto-merge / auto-act allowlist**: автономно — только заведомо безопасные классы изменений (patch-only deps, драфты, отчёты); остальное — в очередь на одобрение.
- [ ] **Изоляция**: код-петли — в worktree (чистка ТОЛЬКО `git worktree remove`), не в рабочем дереве основной сессии.
- [ ] **MCP/интеграции — минимальный скоуп**: у петли нет доступа к коннекторам, которые ей не нужны (особенно почта/мессенджер-рассылки/платежи).
- [ ] **State/идемпотентность**: dedupe-ключ + кулдаун — петля не сделает то же дважды (9-частная анатомия, часть 7).
- [ ] **Kill switch**: одно место, где петлю можно выключить мгновенно (`/schedule` delete, cron-коммент, флаг бота).
- [ ] **Выход читается**: назначен получатель отчёта; если 2+ цикла подряд по выходу никто не действует — петлю на удаление (vanity-петля).

## Как применять к каталогу

Каждой петле из `loop-catalog-ru.md` проставь **паттерн-родителя** (обычно Daily Triage или Issue Triage — маркетинговые петли почти все сенсорные) и **текущий уровень L1–L3**. Дефолт запуска — всегда L1 Report; повышение уровня — осознанное решение с гейтом, не дефолт.
