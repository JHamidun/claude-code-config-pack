# Cursor-OS — построение AI-сотрудника на Cursor

> Метод: Cursor (или Claude Code — терминальный аналог) держат не как чат, а как
> сотрудника с постоянной памятью и правилами. Практики, дошедшие до конца этой
> схемы, снимают ей 70-80% рутины команды. Цифра — ориентир, а не обещание:
> она получается только когда правила и контекст записаны, а не держатся в голове.

---

## 1. Философия: Cursor = сотрудник, а не чат

| ChatGPT | Cursor / Claude Code |
|---------|----------------------|
| Один запрос, нет памяти | Видит всю базу знаний компании |
| Не открывает файлы | Открывает / ищет / переписывает / обновляет файлы |
| Не выполняет код | Выполняет код, API-запросы, автоматизации |
| Разовый ответ | Работает как «ассистент отдела» |

Вы создаёте внутреннего **«ИИ-сотрудника»**, который знает структуру компании,
правила, шаблоны, стиль — и работает с ними стабильно, повторяя вашу логику.

---

## 2. 9-папочная структура

```
marketing-os/
├── rules.md           ← корневые правила (читаются ВСЕГДА)
├── Strategy/          ← позиционирование, ICP, цели, OKR, миссия
│   └── rules.md
├── Competitors/       ← досье конкурентов, summary-таблицы сравнений
│   └── rules.md
├── CRM/               ← выгрузки сделок, контакты, история переписок
│   └── rules.md
├── Marketing/         ← кампании, контент-планы, метрики, отчёты
│   └── rules.md
├── Sales/             ← офферы, КП, скрипты звонков, follow-up
│   └── rules.md
├── Operations/        ← процессы, чек-листы, регламенты, handbook
│   └── rules.md
├── Product/           ← фичи, roadmap, обратная связь, changelog
│   └── rules.md
├── Templates/         ← шаблоны офферов, писем, постов, анализов
│   └── rules.md
└── Tools/             ← скрипты, интеграции, API-обёртки (Perplexity, BI)
    └── rules.md
```

Cursor видит эти папки и работает с ними как живой сотрудник. Версионируй всё через
**Git** — так handbook и rules.md синхронизируются между членами команды.

## 3. rules.md — самообучающаяся система

### Корневой rules.md (минимальный набор)

```markdown
# rules.md (корень)

## Кто я / компания
[Имя, роль, чем занимается компания, продукт, ЦА]

## Что = «хороший результат»
[Критерии качества для каждого типа задачи: оффер, пост, анализ...]

## Структура папок
[Описание 9 папок и что в каждой лежит]

## Стиль коммуникации
[Тон, язык, длина, что нельзя — клише, канцелярит, эмодзи...]

## Принципы работы
- Всегда смотри в rules.md ПЕРЕД задачей
- Сначала верхний уровень контекста, потом конкретная задача
- После анализа конкурента — обновляй summary
- Если ошибся и я исправил — добавь правило в rules.md
- Не выдумывай цифры, ставь плейсхолдер [уточнить]
```

### rules.md внутри папки (пример — Competitors/)

```markdown
# rules.md (Competitors)

## Формат анализа конкурента
- Файл `<competitor>.md`: позиционирование, цены, оффер, каналы, слабые места
- В конце — summary-строка для общей таблицы `_summary.md`
- ПОСЛЕ каждого анализа — ОБЯЗАТЕЛЬНО обнови `_summary.md`

## Источники
- Perplexity API (см. Tools/perplexity.md)
- Сайт, лендинги, Meta Ads Library, отзывы

## Единый формат
- Всегда одни и те же поля → таблица сравнима по всем конкурентам
```

### Самообучающаяся цепочка

```
Агент ошибся
  → вы обычными словами: «Добавь в инструкции, что нужно обновлять
     summary после анализа конкурента»
  → агент САМ редактирует rules.md
  → ошибка больше не повторяется
  → система умнеет с каждым днём
```

Это главное отличие от разового промпта: **каждая ошибка = улучшение правил**.

## 4. Шесть use-cases автоматизации 70% рутины

### Use-case 1 — Анализ конкурентов

Cursor может: искать по Perplexity API, читать сайты/новости/лендинги, строить
таблицы сравнений, писать структурированный анализ, обновлять summary
автоматически, держать единый формат по всем конкурентам.

**Главное:** написать правила (`Competitors/rules.md`) + создать шаблон анализа в
`Templates/`. Запуск: «Обнови анализ конкурента DreamData по шаблону».

### Use-case 2 — Генерация офферов (20-30 секунд)

ИИ сам: читает прошлые офферы (`Sales/`), читает транскрипт звонка с клиентом,
подбирает структуру, пишет draft на нужном языке, вставляет плейсхолдеры для цен,
генерирует follow-up письма. В уроке ИИ сделал оффер **за 20-30 секунд**.

Запуск: «Подготовь оффер клиенту X на основе звонка `call-x.txt` по шаблону КП».

### Use-case 3 — PR / контент в стиле автора

ИИ умеет: собирать CRM/переписки/историю контактов, писать письма в вашем стиле,
анализировать запросы журналистов, составлять комментарии, посты, выступления.
Источник стиля — реальные тексты в `CRM/` и `Marketing/`.

Запуск: «Подготовь письмо клиенту в моём стиле» / «комментарий для журналиста по
теме Y».

### Use-case 4 — BI-аналитика + аномалии

ИИ подключается к БД, метрикам, рекламным кабинетам, BI и может: сравнивать недели/
периоды, находить просадки, искать аномалии, подсказывать что отключить, находить
«сжирающие бюджет» креативы. API-обёртки лежат в `Tools/`.

Запуск: «Сравни эту неделю с прошлой по кабинетам, покажи аномалии и что отключить».

### Use-case 5 — Документация / онбординг

ИИ может: обновлять документы сам, писать инструкции, формировать onboarding, вести
внутренний handbook, синхронизировать файлы команды, проверять изменения через Git.
Живёт в `Operations/`.

Запуск: «Обнови handbook раздел Y» / «сделай onboarding-чек-лист для нового SMM».

### Use-case 6 — Email-агент

Заменяет email-агентство одним Claude Code: собирает CRM + переписку → пишет draft
рассылок в стиле компании → follow-up цепочки. Кейс сообщества: «заменил
целое email-агентство одним Claude Code».

## 5. Антипаттерны (Gotchas)

| Антипаттерн | Последствие | Правильно |
|-------------|-------------|-----------|
| Нет правил / папок | ИИ теряется, сам придумывает структуру → хаос | Сначала 9 папок + rules.md |
| **«Всё в чат»** (грузить всё подряд) | галлюцинации | **Верхний уровень → конкретная задача** |
| Не давать агенту править rules.md | система не учится | Разрешить обновлять правила |
| Запрос без шаблона | непредсказуемый формат | Шаблон в `Templates/` → запрос «по шаблону» |
| Нет единого формата анализа | конкуренты несравнимы | Фиксированные поля в шаблоне |

> **Правило структурирования контекста:** иерархия и rules.md — выше, конкретная
> задача — ниже. ИИ должен «видеть» рабочую реальность.

## 6. Чек-лист настройки с нуля

- [ ] Создать `marketing-os/` + 9 директорий
- [ ] Написать корневой `rules.md` (кто / компания / хороший результат / структура / стиль / принципы)
- [ ] Создать `rules.md` в каждой папке (формат + источники + единый формат)
- [ ] Заполнить `Templates/` (оффер, письмо, анализ конкурента — минимум)
- [ ] Налить контекст в `Strategy/`, `Competitors/`, `CRM/`
- [ ] Подключить Perplexity API → `Tools/perplexity.md`
- [ ] Запустить первый use-case (анализ конкурента)
- [ ] После ошибок — «добавь в rules.md» (включить самообучение)
- [ ] Подключить MCP (Notion / Supabase / своя CRM) по мере роста
- [ ] Версионировать через Git (синхронизация команды)

## MCP-подключения для маркетинг-стека

| Источник | Зачем | Родной скилл |
|----------|-------|--------------|
| Perplexity | анализ конкурентов, research | `perplexity` |
| Notion | UI + дашборды, база знаний | cloud MCP |
| Supabase | БД для DWH / перелинковки | внешний |
| Apify | парсинг конкурентов | `apify-scraping` |
| CRM | CRM-данные | REST API твоей CRM (Битрикс24/amoCRM/HubSpot) |
| Tilda | публикация лендингов | `tilda` |
| local-gateway | low-cost LLM/image | `local-gateway` |

> Когда use-case вырастает в **продакшн-бот с деплоем** — переходи на
> agent-builder tooling (Hermes/OpenClaw). Cursor-OS — для одной команды на
> одной машине.
