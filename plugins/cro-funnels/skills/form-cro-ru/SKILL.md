# CRO форм (RU)

Максимизировать заполняемость форм вашего бизнеса, собирая только то, что реально нужно. Главная форма — **заявка на бесплатную консультацию** (вход B2B-воронки). Порт `cro/references/form.md` в самостоятельный скилл: принципы, поэлементная оптимизация и чеклисты сохранены, инструменты под RU-стек.

**Перед началом прочитай контекст:** `yourname-marketing-context` — `references/business.md`, `references/offerings.md` (CTA по сегментам), `references/funnel.md`. **Приоритет — закрыть дыру воронки: заявка на консультацию / запрос воркшопа — главные точки захвата B2B-лидов; лид-магниты и захват email на контент-ресурсах ведут в обучающий продукт.**

## Первичная оценка

1. **Тип формы:** заявка на бесплатную консультацию (главная, B2B), запрос формата воркшопа, скачивание лид-магнита, контактная, опрос/фидбэк, запрос корп-пакета academy.
2. **Текущее состояние:** сколько полей, текущая заполняемость, mobile vs desktop, где бросают.
3. **Бизнес-контекст:** куда падают заявки (→ ваша CRM, стадии new→interested→qualified→zoom_scheduled), какие поля реально используются в работе, требования 152-ФЗ.

## Базовые принципы

### 1. У каждого поля есть цена
Каждое поле снижает заполняемость. Ориентир: 3 поля — база; 4-6 — минус 10-25%; 7+ — минус 25-50%+. По каждому: нужно ли до того, как мы поможем? Можно ли получить иначе? Можно ли спросить позже (на самой консультации)?

### 2. Ценность > усилия
Чёткий value prop над формой («Бесплатная консультация: как внедрить ИИ в ваши процессы»), очевидно что получат, снизить воспринимаемое усилие (число полей, лейблы).

### 3. Снизить когнитивную нагрузку
Один вопрос на поле, разговорные лейблы, логичная группировка/порядок, умные дефолты.

## Поэлементная оптимизация

- **Email:** одно поле без подтверждения, inline-валидация, ловля опечаток, правильная мобильная клавиатура.
- **Имя:** одно «Имя» vs «Имя/Фамилия» — тестировать; делить только если нужно для персонализации.
- **Телефон:** для заявки на консультацию обычно нужен (бронь Zoom) — объяснить зачем, авто-формат, код страны (+7). RU: верификация через SMS Aero / SMSC.ru при необходимости.
- **Компания (B2B):** авто-подсказка; обогащение после сабмита (RU: Контур.Фокус / Rusprofile); вывод из email-домена.
- **Должность/роль:** дропдаун если категории важны (HR-директор/гендир/руководитель отдела), free text при большом разбросе, рассмотреть опциональность.
- **Сообщение / задача (free text):** опционально, ориентир по символам, расширять при фокусе («Какую задачу хотите решить с ИИ?»).
- **Дропдауны:** плейсхолдер «Выберите…», поиск при многих опциях, радио при <5, «Другое» + текст.
- **Чекбоксы:** параллельные лейблы, разумное число, «Выберите всё подходящее».

## Раскладка формы

- **Порядок полей:** лёгкие первыми (имя, email) → растить коммитмент → чувствительные последними (телефон, компания, задача) → группировка при многих полях.
- **Лейблы и плейсхолдеры:** лейбл всегда видимый (не только плейсхолдер — он исчезает при вводе); плейсхолдер = пример; help text только когда реально полезен.
- **Визуал:** достаточный интервал, чёткая иерархия, выделенная кнопка, тач-таргеты 44px+.
- **Одна колонка** почти всегда (выше заполняемость, мобайл-френдли); две — только для коротких связанных полей (Имя/Фамилия).

## Многошаговые формы

- **Когда:** >5-6 полей, логически разные секции, условные пути, сложные формы (запрос корп-пакета/воркшопа).
- **Практики:** прогресс-индикатор (шаг X из Y), лёгкие → чувствительные, одна тема на шаг, back-навигация, сохранение прогресса, чёткое required/optional.
- **Прогрессивный коммитмент:** (1) только email → (2) имя/компания → (3) квалифицирующие вопросы (задача, размер команды) → (4) контактные предпочтения + слот Zoom.

## Обработка ошибок

- **Inline-валидация:** при переходе к след. полю, не слишком агрессивно при вводе, чёткие индикаторы.
- **Сообщения:** конкретные, с подсказкой как исправить, у поля, не очищать ввод. Хорошо: «Введите корректный email (например, name@company.ru)». Плохо: «Неверный ввод».
- **На сабмит:** фокус на первой ошибке, сводка ошибок, сохранить все данные, не очищать форму.

## Кнопка отправки

- **Текст:** «[Действие] + [что получат]»: «Записаться на консультацию», «Выбрать формат воркшопа», «Скачать гайд», «Запросить корп-пакет».
- **Размещение:** сразу после последнего поля, по выравниванию с полями, достаточный размер/контраст, на мобайле sticky/видимая.
- **Пост-сабмит:** loading-состояние (disable + спиннер), подтверждение успеха (чёткий next step — «Свяжемся в течение X / выберите слот Zoom»), обработка ошибки.

## Доверие и снижение трения

- У формы: «Не передаём данные третьим лицам», регалии эксперта ([роль, компания]), отзыв/соцпруф, ожидаемое время ответа.
- Воспринимаемое усилие: «Займёт 30 секунд», индикатор числа полей, минимум визуального шума.
- Возражения: «Консультация бесплатна и ни к чему не обязывает», «Без спама», лид-магнит: «Скачивание мгновенно».
- **152-ФЗ:** согласие на обработку ПД (не пред-отмеченный чекбокс) + ссылка на политику — обязательно при сборе ПД.

## Формы по типам (кратко)

- **Заявка на бесплатную консультацию (главная B2B):** имя, email обязательны; телефон + компания + «какая задача» для квалификации; встроенный календарь Zoom или next-step бронь; заявка → `crm`, стадия new → qualified.
- **Запрос формата воркшопа:** имя, email, компания, размер команды/желаемый формат; вопрос «на каких задачах учить»; → `crm`, эскалация к владельцу для горячих enterprise.
- **Скачивание лид-магнита:** минимум полей (часто только email), чёткий value prop (название лид-магнита), мгновенная доставка + апсейл academy trial после сабмита.
- **Контактная:** email/имя + сообщение, телефон опц., ожидаемое время ответа, альтернативы (Sales-AI-агент/Telegram).
- **Запрос корп-пакета academy:** часто многошаговая, лёгкие вопросы → детали (размер команды, треки, SSO) позже, сохранение прогресса.
- **Опрос:** прогресс-бар, один вопрос на экран, skip-логика, стимул за завершение.

## Мобильная оптимизация

Тач-таргеты 44px+, правильные клавиатуры (email/tel/number), autofill, одна колонка, sticky-кнопка, минимум печати (дропдауны/кнопки).
