# CRO воронки регистрации (RU)

Снижение трения в регистрации/создании аккаунта ExampleProduct (trial 7 дней без карты) и захвате email на news.your-domain.com, подготовка к успешной активации. Порт `signup` из marketingskills: принципы и чеклисты сохранены, инструменты и примеры под подписочную AI-образовательную платформу (trial → платящий), оплату в рублях (ЮKassa) и Яндекс-стек.

**Перед началом опиши контекст продукта.** Заведи собственный навык-контекст (бизнес и позиционирование; продукты, тарифы и условия trial; механика захвата лидов в воронке) и читай его первым — в паке он не поставляется. Не дублируй позиционирование и метрики по файлам — держи их в одном месте.

## Первичная оценка

1. **Тип воронки:** trial-аккаунт academy 7 дней без карты (основное), захват email «YourName Weekly» на news, регистрация в боте @your_news_bot, мягкая web-регистрация. B2C-профи vs B2B-когорта.
2. **Текущее состояние:** сколько шагов/экранов, какие поля обязательны, текущий completion rate, где дропают (поэкранно).
3. **Бизнес-ограничения:** что реально нужно на старте, требования 152-ФЗ (согласие на обработку ПД + маркировка рассылки), что происходит сразу после регистрации (→ симулятор/AI-тьютор).

## Базовые принципы

### 1. Минимум обязательных полей
Каждое поле снижает конверсию. По каждому спроси: нужно ли это до начала работы, можно ли собрать позже (progressive profiling), можно ли вывести из других данных.
- **Обязательно (academy trial):** email (или соцавторизация), пароль.
- **Часто нужно:** имя.
- **Обычно откладываемо:** компания, роль, интересующий трек, телефон.
- **Email-захват на news:** только email — больше ничего.

### 2. Ценность до коммитмента
Что можно показать/дать до регистрации? Для academy — демо симулятора, превью трека, пример диалога с AI-тьютором, «доступ к множество моделей включён». Сначала ценность, потом регистрация. Для news — лента статей открыта, email только для дайджеста.

### 3. Снизить воспринимаемое усилие
Прогресс при мультишаге, группировка полей, умные дефолты, предзаполнение.

### 4. Убрать неопределённость
«7 дней бесплатно, без карты», показать, что будет после регистрации (→ первый трек/симулятор), без сюрпризов.

## Оптимизация по полям

### Email
- Одно поле (без подтверждения email), inline-валидация формата, ловля опечаток (gmial.com → gmail.com), понятные ошибки.

### Пароль
- Иконка «показать», требования заранее (не после ошибки), индикатор силы, разрешить вставку, рассмотреть passwordless/magic link.

### Имя
- Одно поле «Имя» vs «Имя/Фамилия» — тестировать. Требовать только если сразу используется (персонализация AI-тьютора, сертификат).

### Соцавторизация / SSO
- Размещать заметно (часто конвертит лучше email).
- **RU-контекст:** Яндекс ID, VK ID, Telegram, Google — релевантны для российской аудитории academy. Для B2B-когорт — корпоративный SSO (SAML/Google/Yandex).
- Чёткое визуальное отделение от email-регистрации.

### Телефон
- Откладывать, если не критично. RU: СМС через SMS Aero / SMSC.ru. Для academy trial обычно не нужен; если обязательно — объяснить зачем.

### Компания / роль / трек (для B2B-когорт)
- Откладывать в онбординг, авто-подсказка, вывод из email-домена. Если нужно на регистрации — один вопрос (интересующий трек).

## Один шаг vs мультишаг

- **Один шаг:** ≤3 поля, news email-захват, простой B2C trial, высокий интент (с рекламы/лид-магнита).
- **Мультишаг:** >3-4 полей, B2B-когорта с сегментацией, выбор трека.
- **Практики мультишага:** прогресс-индикатор, лёгкие вопросы первыми, тяжёлые позже (после псих-коммитмента), back-навигация, сохранение прогресса.
- **Паттерн прогрессивного коммитмента:** (1) только email → (2) пароль + имя → (3) выбор трека/цели (опционально).

## Доверие и снижение трения

- «Без привязки карты», «7 дней бесплатно», согласие 152-ФЗ + ссылка на политику ПД, бейджи безопасности, отзыв участника academy рядом с формой.
- Соцпруф автора: «[Регалии автора: должность, продукт с N+ юзеров] — ваш преподаватель».
- **Обработка ошибок:** inline-валидация, конкретные сообщения («Этот email уже зарегистрирован» + путь восстановления), не очищать форму, фокус на проблемном поле.
- **Микрокопия:** плейсхолдер = пример, не лейбл; лейбл всегда видимый.

## Мобильная регистрация

Тач-таргеты 44px+, правильные клавиатуры (email/tel), автозаполнение, меньше печати (соцавторизация/предзаполнение), одна колонка, липкий CTA. Большая доля трафика РФ — мобайл.

## После сабмита

- **Успех (academy):** понятное подтверждение, немедленный следующий шаг (→ первый трек/симулятор/AI-тьютор, см. `onboarding-cro-ru`).
- **Успех (news email):** подтверждение подписки + сразу мягкий CTA «Освоить системно → 7 дней academy бесплатно» (чинит дыру контент→продукт).
- **Верификация:** по возможности отложить; magic link как альтернатива паролю; дать исследовать продукт пока ждёт; простой ресенд. Email-захват news: `POST /api/portal/subscribe` → `newsletter_subscribers` + double opt-in `email_verifications`.

## 152-ФЗ (комплаенс)

- Явное согласие на обработку ПД (чекбокс, не пред-отмеченный) + ссылка на политику.
- Маркировка рассылки «YourName Weekly» + явная отписка.
- Для B2B-когорт — данные в российском контуре, проговорить при регистрации корп-аккаунта.

## Типовые паттерны воронок

- **B2C academy trial:** Яндекс/VK/Telegram/Google-авторизация ИЛИ email+пароль → trial 7 дней → первый трек → профиль/трек позже.
- **News email-захват:** только email → согласие 152-ФЗ → подтверждение → дайджест вс 09:00 МСК → CTA в academy.
- **TG-бот @your_news_bot:** `/start` → персональная лента → мягкий апсейл в academy/консультацию.
- **B2B-когорта:** email+SSO → имя+компания+трек (роль опц.) → онбординг когорты.
