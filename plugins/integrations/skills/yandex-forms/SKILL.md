# Yandex Forms — программное создание форм

Создаёт опросы в Яндекс Формах целиком из кода: блоки-заголовки, короткий/длинный текст,
один вариант (radio), несколько вариантов (checkbox), выпадающий список, шкалы 1–5,
обязательные поля. Публикует и отдаёт ссылку для заполнения.

## Когда использовать
- Нужно быстро собрать опрос/анкету (часто — входной опрос «ИИ-амбассадоры» под клиента).
- Нужно несколько форм одинакового формата под разные аудитории/компании.
- Нужна именно нативная Яндекс Форма (не Google Forms, не PDF, не Word).

## Эталонный формат «ИИ-амбассадоры» (7 блоков)
1. О себе (ФИО, email, должность, направление, роль)
2. Текущий уровень ИИ (частота, инструменты, самооценка-шкала, барьеры)
3. Рутина и задачи для ИИ (топ-задачи, часы рутины, «агент мечты», метрики)
4. Безопасность и границы ИИ (чувствительные данные, что НЕ доверять ИИ, важность фактчека)
5. Ожидания от программы (что получить, готовность в углублённый трек/амбассадорство)
6. Формат и время (часы, время суток, очно/онлайн/гибрид, самостоятельные задания)
7. Свободное (пожелания, опасения)

Под клиента меняются списки: `directions` (направления), `tools` (инструменты),
`tasks` (задачи), `metrics` (метрики). Текст блоков — постоянный.

## ПУТЬ 1 — Gateway через браузер (основной, работает)

Аутентификация — НЕ статический токен, а **сессия залогиненного браузера**
(cookies Яндекс 360) + CSRF-токен из `window.__DATA__.csrfToken`. Поэтому форма
строится через `chrome-devtools` MCP (`evaluate_script`) в Chrome, где выполнен вход
в аккаунт your-email@example.com.

### Шаги
1. Убедись, что в управляемом chrome-devtools Chrome выполнен вход на forms.yandex.ru
   (аккаунт your-email@example.com, Яндекс 360). Если нет — пользователь логинится вручную.
2. `navigate_page` → `https://forms.yandex.ru/admin/` (чтобы был свежий `window.__DATA__.csrfToken`).
3. Проверь сессию:
   ```js
   () => ({csrf: !!(window.__DATA__&&window.__DATA__.csrfToken), login: window.__DATA__.user&&window.__DATA__.user.login})
   ```
4. Запусти билдер из `scripts/yandex_form_builder.js` через `evaluate_script` — он целиком
   self-contained: создаёт форму, ставит имя, добавляет вопросы, публикует, возвращает
   `{surveyId, fill, ok, errs}`. Заполни массив `items` своим опросом (DSL ниже).

### DSL вопросов (массив `items`)
```
['S','Текст блока-заголовка ИЛИ интро']                 // секция (display-only)
['T','Вопрос', required?, 'подсказка?']                  // короткий текст
['P','Вопрос', required?, 'подсказка?']                  // абзац (длинный текст)
['R','Вопрос', ['опция1','опция2',...], required?]       // ОДИН вариант (radio)
['C','Вопрос', ['опция1','опция2',...], required?]       // НЕСКОЛЬКО вариантов (checkbox)
['SC','Вопрос','подпись-1','подпись-5', required?]       // шкала 1–5 (radio 1..5)
```
Для «Другое» просто добавь строку `'Другое'` в список опций.

### ГРАБЛЯ: «Другое» НЕ открывает поле для ввода
У Яндекс.Форм **нет** нативного инлайн-«Другое» с текстовым полем (в отличие от Google
Forms) — ни в конструкторе (кнопка «Добавить вариант "Другое"» отсутствует), ни в
gateway/официальной схеме (у опции только `{id,text,key,hidden}`, флага own-answer нет;
`modify_choices` — это сортировка natural/sort/shuffle, НЕ «свой ответ»). Опция `'Другое'`
остаётся обычным невводимым пунктом.
**Паттерн-обходка (проверено):** сразу ПОСЛЕ вопроса с «Другое» добавляй отдельное
необязательное короткое поле `['T','Если отметили «Другое» — впишите свой вариант', false]`.
Если нужен более чистый UX (поле появляется только при выборе «Другое») — это делается через
«Условия показа» вопроса, но их gateway-структура пока не реверсилась.

### КЛЮЧЕВАЯ ГРАБЛЯ (reverse-engineered)
- Тип вопроса задаётся полем `view`:
  - один вариант → `view:'radio',  widget:'radio'`
  - **несколько вариантов → `view:'checks', widget:'checkbox'`**  ← НЕ `'checkbox'`!
    Если послать `view:'checkbox'`, сервер молча коэрсит вопрос в `radio`.
  - выпадающий список → `view:'select'` (см. references)
- Секция-заголовок = обычный `type:'text', view:'textinput'`, но с ключом-префиксом
  `statement_…` (не `answer_short_text_…`). Именно префикс ключа делает его display-only.
- Короткий текст: ключ `answer_short_text_…`; абзац: `type:'text',view:'textarea'`, ключ
  `answer_long_text_…`; выбор: ключ `answer_choices_…`; опция: `{id, text, key}` где `key`
  — просто число-строка (без префикса).
- `id` — целые, `key` опций — 16-значные числовые строки. Генерируй уникально.

Полный список методов и схемы — в `references/gateway_api.md`.

## ПУТЬ 2 — Официальный REST API (если будет org id + scope)

База: `https://api.forms.yandex.net/v1` (57 методов, OpenApi сохранён в
`${WORKSPACE}/yandex_forms_ref/openapi_official.json`).
Нужно: OAuth-токен со scope `forms:write` + заголовок `X-Org-Id` (Яндекс 360) или
`X-Cloud-Org-Id` (Cloud). Текущий `YANDEX_OAUTH_TOKEN` отдаёт `/v1/users/me/`
(your-email@example.com, cloud_uid <ваш uid>), но без `forms:write`+orgId
создание форм возвращает 401/403. Когда токен будет — см. `references/official_api.md`.

## Доступ / креды
В `~/.claude/.credentials.master.env` (секция `# === YANDEX FORMS ===`):
- `YANDEX_OAUTH_TOKEN` — OAuth Яндекса (есть; для офиц. API нужен доп. scope forms:write).
- Метод Путь 1 описан там же: gateway-endpoint + auth через cookie-сессию браузера
  + `window.__DATA__.csrfToken`. Статического ключа для Путь 1 НЕТ — это by design.
