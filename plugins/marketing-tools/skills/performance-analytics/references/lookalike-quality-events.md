# Lookalike на качественных событиях — cross-platform паттерн

> Источник: экспертная методология (поток N) — VK Ads, Meta Ads, Яндекс/Google. Эталонные ориентиры из методологии курса.
>
> Это сводка одного приёма по всем платформам: «строй похожую аудиторию (lookalike) не на кликах, а на качественных событиях — оплатах и квал-лидах». Платформенные детали запуска — в `vk-ads-pro-ru`, `meta-ads-launch-ru`, `yandex-direct-pro-ru`, `google-ads-pro-ru`.

## Суть паттерна

Lookalike (LAL / «похожая аудитория») — алгоритм находит пользователей, похожих на загруженное «ядро». **Качество lookalike = качество ядра.** Если кормить алгоритм всеми кликами/лидами — он научится искать «кликающих». Если кормить **оплатами и квал-лидами** — научится искать платящих.

> Связь с full-funnel: дешёвые лиды плохо покупают, дорогие окупаются. Поэтому ядро LAL надо строить на дне воронки (оплата/квал-лид), а не на её верху (клик/лид). Подробно про когортную ценность — `full-funnel-analytics-ru`.

## Cross-platform таблица

| Платформа | Механизм похожей аудитории | Размеры / нюанс | На каких событиях строить ядро |
|-----------|----------------------------|-----------------|-------------------------------|
| **VK Ads** | **CS (Целевые сообщества)** — аналог LAL: загружаем ядро → находим 24000+ сообществ с концентрацией нашей ЦА | Часто находит нетривиальные сообщества; работает в связке с X-коэффициентом вовлечённости (X1-X6+) | Ядро из платящих / целевых подписчиков |
| **Meta** | **Lookalike Audience** | **1% / 1-3% / 3-5%** — оптимальные; выше 5% слишком широко | Лиды → квал-лиды → **оплаты** (чем глубже событие, тем лучше) |
| **Яндекс.Директ** | **Look-alike (Яндекс.Аудитории)** | Строится на сегменте Метрики / своих данных | Сегмент оплативших / квал-лидов, переданных в Метрику |
| **Google** | **Demand Gen / PMax LAL (похожие сегменты)** + Custom Segments | Аудитории = фактор №1 (8-9 случаев из 10 важнее креатива). В Search — в **наблюдение**, не в таргетинг | Сегмент конвертеров / Custom Segments по ключам в URL |

## Ключевые правила

1. **Глубина события важнее объёма.** Ядро из 200 оплат бьёт ядро из 5000 кликов. Если оплат мало — поднимаемся на шаг выше (квал-лиды), но не до «всех лидов».
2. **Meta-размеры 1% / 1-3% / 3-5%.** 1% — самый «похожий», но узкий; 3-5% — шире, но размывается. Выше 5% — уже почти широкая аудитория, смысл LAL теряется.
3. **VK: CS вместо классического LAL.** В экспертной методологии «похожая» строится через анализ целевых сообществ (CS) — загружаем ядро, находим сообщества с высокой концентрацией ЦА, часто нетривиальные. Дополняется X-коэффициентом: X2-X3 конвертят в оплату лучше, чем «горячий» X6+.
4. **Google: LAL-логика для медийки, не для Search.** Аудитории (включая похожие) на Search добавляют в **наблюдение** для сбора статистики, масштабируют — в Demand Gen / PMax / YouTube. В Search ключи ставятся вручную.
5. **Передавать оплаты обратно в кабинет.** Чтобы строить LAL на оплатах, эти оплаты должны попасть в платформу — через офлайн-конверсии (Яндекс по Client ID, Meta по External ID). См. `server-side-tracking-stack.md` и `capi-no-code-setup`.

## Анти-паттерн

- LAL на «всех, кто оставил заявку» без фильтра качества → алгоритм ищет таких же дешёвых нецелевых лидов.
- LAL шире 5% в Meta «чтобы охват больше» → теряется похожесть, CPA растёт.
- VK: попытка пересекать интересы внутри VK Ads (нельзя — только OR). Похожесть строится через CS, а не через пересечение интересов.
