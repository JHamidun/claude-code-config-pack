# Когда клиент ломается: симптом → причина → что делать

Симптом записан таким, каким его видно снаружи (по нему ищут), причина проверена на реальных сервисах. Источник у
части строк указан в скобках: файл карты или навыка. Цифры сроков и кодов — на дату замера; свои снимай
`doctor` и `harvest.py`. Платформо-специфичное остаётся в карте сервиса, здесь — повторяющиеся классы поломок.

## 1. Протухание сессии

| Симптом | Причина | Что делать |
|---|---|---|
| 401 на запросе, который вчера работал | сессия умерла по сроку: куки живут часы, токены сутки или месяц (`auth-map.md`) | `doctor`; если он говорит «session expired», `login`. Клиент сам делает один перелогин и один повтор, кроме сервисов с одной сессией на учётку |
| 302 на `/login…#error-session` или HTTP 200 со страницей входа вместо JSON | шлюз или SPA отвечает логином, а не ошибкой | то же. Признак живёт в `looks_expired()` клиента: редирект на login и форма с полем пароля вместо JSON |
| HTTP 200, а в теле `{"error": "RELOGIN"}` или `{"status": -419, …expired}` | протухание сообщено телом (Tilda: `tilda/references/auth.md`; Plaud: `status: -419` при HTTP 200) | внести маркер в `EXPIRED_BODY_MARKERS`; без него клиент принимает ошибку за успех и молча работает с пустым ответом |
| 401 или `RELOGIN` сразу после успешного входа | сессия на нескольких доменах не прогрета (Tilda: ленты оживают после обхода страниц проекта) либо не хватает заголовка, который SPA ставит сама (`x-device-id`, `Referer`, `Origin`) | прогреть в нужном порядке; сверить заголовки с `out/auth_hints.json` (`custom_headers`) |
| «alreadyused», «сеанс занят», `recovering: true` | один активный сеанс на учётку, его держит демон или вкладка | не входить. Ждать демона, ничего не нажимать на странице. Подробно — `auth-map.md`, раздел про одну сессию |
| В логе автообновления `redirected to login` | сессия умерла раньше, чем её продлили; headless-обновление бессильно (пример: сессия Google Studio) | войти руками в окне браузера, и только потом возвращать автообновление в планировщик |
| `doctor` пишет «token from session file» и код 4, а ты положил свежий токен в переменную | кэш `~/.claude/.sessions/<сервис>.json` записан после твоей правки переменной (клиент перелогинился сам), либо в переменную попал тот же токен, что был при записи кэша (`auth-map.md`, раздел «Откуда клиент берёт токен») | положи в переменную токен, которого там не было, или удали файл кэша (в нём только токен, время и отпечаток) и запусти `doctor` снова |
| В браузере данные есть, у клиента пусто или `null` | в сессии другой аккаунт, рабочая область или тенант; потерян заголовок тенанта | команда клиента, показывающая, чья это сессия; сверить заголовки с трафиком |

## 2. doctor: как читать и что он не делает

`doctor` проверяет конфигурацию и текущую сессию одним безопасным чтением. Он **не входит** в сервис и **ничего не
пишет**: вход у сервисов с одной сессией выбивает чужую, а проверка не должна иметь последствий.

| Код выхода | Что значит | Следующий шаг |
|---|---|---|
| 0 | конфигурация цела, чтение прошло, сессия жива | если команда всё равно падает, идти в разделы 3 и 4 |
| 3 | нет файла с секретами или переменной | отчёт называет, какое имя добавить в `~/.claude/.credentials.master.env` |
| 4 | чтение показало протухание | `login` (для сервисов с одной сессией — `login --yes`, убедившись, что никто другой её не держит) |
| 1 | сервис недоступен или `DOCTOR_PATH` отвечает ошибкой | проверить сеть и `BASE_URL`, затем путь по карте |

Зелёный `doctor` не значит, что работают все команды: он трогает один маршрут, а другой может отвечать 403 из-за плана
или роли. Не помечай клиент «проверено», пока `doctor` не прошёл вживую.

## 3. Съём трафика (`harvest.py`)

| Симптом | Причина | Что делать |
|---|---|---|
| JS-бандлы весят около сотни байт, `harvest.py bundles` пишет STUB | бот-защита отдаёт заглушку headless-браузеру; `page.request` из такого браузера тоже получает 401 | снимать в окне браузера, без `--headless`, на прогретом профиле |
| `capture` пишет «login was not completed» | форма входа без `/login` в адресе, либо вход не закончили за `--login-wait` | `--ready-selector` с элементом, который есть только после входа; поднять `--login-wait`; headless войти не может |
| Cloudflare или Turnstile не пускает управляемый браузер, галочка висит | проверка не проходит под управлением по CDP | клик делает человек в окне; другие движки — `--engine patchright` и `playwright-automation/references/stealth-scraping.md` |
| `curl` получает 403, браузер 200 | защита смотрит на набор заголовков: нужен полный набор браузерных (`User-Agent`, `Accept`, `Accept-Language`, `Sec-Ch-Ua*`, `Sec-Fetch-*`, `Upgrade-Insecure-Requests`), одного `User-Agent` мало | снять заголовки из `api_map.json` и повторить все; не получилось — запросы из страницы |
| В `api_map.json` пусто или слишком мало вызовов | адреса API не содержат `/api/` и других подсказок из `--include`, или API на другом хосте | `--all-xhr` и `--host` для нужных хостов; потом сузить |
| Разные маршруты показывают один и тот же текст | неверная база маршрутов SPA (рабочий маршрут `#/invoices-due/`, а не угаданный `#/due/`) | брать маршруты из меню: `--discover` или ответ эндпоинта меню |
| Нужное действие не снимается, кнопку не найти | интерфейс живёт в iframe (микрофронтенд); таблица рисует кнопки дважды, для десктопа и телефона, и первая из них скрыта; промо-окна глотают клики | искать по `page.frames`, фильтровать `:visible`, закрывать промо перед кликом. `harvest.py` ничего не кликает: клики — отдельный зонд на постоянном профиле |
| Платный запрос ни разу не прошёл в трафике | кнопку не нажимали, и правильно | прочитать запрос в бандле, не вызывая его: `harvest.py bundles <папка> --grep <слово>` показывает код рядом с `.put(`/`fetch(` |
| В выгрузке или логе оказался токен | `--keep-secrets` или `--save-session`, либо отладочная печать префикса | выгрузки по умолчанию маскируются; `out/` и профиль в `.gitignore`; значение токена не печатать, только длину и срок |

## 4. Запросы клиента

| Симптом | Причина | Что делать |
|---|---|---|
| 404 с HTML-страницей SPA вместо JSON | не хватает обязательного параметра запроса, а путь живой | сверить с картой: `harvest.py summarize` выделяет жирным параметры, бывшие во всех вызовах; подставить и проверить без каждого |
| 404 с XML `InvalidArgument … multipart/form-data` | запрос ушёл в облачное хранилище, а не в API | проверить хост и префикс пути; ссылки на файлы брать из ответов API |
| 404 на «правильном» пути | у каждого пути своя версия: `v4` нет, есть только `v3`; удвоенная версия в пути (`…/invoice/{id}/v2/recalc`) — не опечатка | копировать путь из трафика, а не достраивать по аналогии |
| 500 на запросе, собранном по карте | в тело ушло устаревшее поле из прошлого ответа или дата не в том формате (старое `due_date` вместо `recommended_date`, ISO вместо `DD/MM/YYYY`) | брать поля по карте; формат даты смотреть в трафике и записать в карту |
| Скачивание по ссылке даёт 403 или 404 | подписанная ссылка живёт минуты | запросить новую и качать сразу, без заголовков авторизации |
| Запрос 200, а в интерфейсе ничего не поменялось, или флаг в списке «не готово» | список отдаёт устаревшее поле (`is_trans` у Plaud) либо эндпоинт старый | проверять готовность по детальному эндпоинту; устаревший путь заменить, перезахватив трафик нужного экрана |
| 429, капча, бан | слишком частые запросы, параллельные сессии | не распараллеливать; капчу проходит человек, обхода здесь нет |

## 5. Вывод, платное и документация

| Симптом | Причина | Что делать |
|---|---|---|
| Вывод `api` обрезан и не разбирается | старый клиент резал строку по числу символов | шаблон режет списки по числу элементов, а очень длинные строки по числу знаков; остаётся валидный JSON и поле `truncated` с тем, что отрезано; `--limit 0` снимает оба ограничения и отдаёт всё |
| «Сухая» команда уже изменила состояние | перед проверкой цены выполнялся изменяющий запрос (команда пересчёта платежа: отметка «не оплачено» ставилась до чтения комиссии) | цену и последствия читать обычным GET **до** первого изменяющего запроса; в тестах проверять, что сухой режим не шлёт изменяющих вызовов |
| Код выхода 5 | платное или необратимое действие без `--yes` | прочитать план из сухого прогона и повторить с `--yes`, если владелец согласен |
| Таблица команд в документах не совпадает с кодом | таблица, написанная руками, расходится с парсером | `scripts/gen_commands.py <клиент.py>` после каждой правки парсера; `--strict` вернёт 4, если что-то не разобрано |
