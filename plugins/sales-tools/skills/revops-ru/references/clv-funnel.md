# CLV / CEV / CRV по стадиям воронки (RU, методология V. Instructor2 ценности клиента)

> **Что это.** Расчёт ценности клиента **по стадиям жизненного цикла** MQL → SQL → Customer → Advocate — чтобы оптимизировать воронку не на дешёвый лид, а на **итоговую денежную ценность** клиента и его «эффект сети» (рекомендации). Дополняет lifecycle-стадии (`lifecycle-ru.md`) денежным измерением.
>
> **Источники и честная атрибуция:**
> - **Из курса методология (что прямо звучало):** дерево метрик `CPM→CTR→CPC→CR1/CPL→CR2/CPA→LTV→CAC` (эксперт курса); «продукты со временем поднимаются вверх по графу работ», ценообразование от ценности прогресса, не cost-plus (эксперт курса, JTBD); полная когортная воронка `Расходы→…→Первая выручка→LTV→Маржинальность` и **Predict LTV = Zero Day Revenue × коэффициент**; «только CPL недостаточно — дешёвые лиды могут не покупать, дорогие окупаться».
> - **Аналитическая рамка CLV/CEV/CRV** (триада «3 ценности клиента») — это академическая модель **V. Instructor2** («Profitable Customer Engagement»), которой удобно структурировать ценность по стадиям. **Сама триада-аббревиатура в лекциях дословно не разбиралась** — это лупа поверх курсового материала, а не цитата. Поэтому конкретные ₽-цифры ниже бери из своих когорт (метод Predict LTV из курса), а не из лекций.
>
> **Граница:** дерево метрик и выбор типа воронки ДО CRM — `funnel-design-ru`; сквозная когортная аналитика/атрибуция — `full-funnel-analytics-ru`; здесь — **как считать ценность клиента по lifecycle-стадиям RevOps**.

## Три ценности клиента (триада Instructor2)

| Аббревиатура | Что измеряет | Простыми словами |
|---|---|---|
| **CLV** (Customer Lifetime Value) | Прямая денежная ценность от покупок клиента за всё время | Сколько денег клиент принесёт сам (= LTV из дерева метрик) |
| **CEV** (Customer Engagement / Equity Value) | Ценность вовлечённости: апсейлы, продления, расширение, частота | Сколько клиент добавит сверх первой покупки, оставаясь активным |
| **CRV** (Customer Referral Value) | Ценность рекомендаций: приведённые им новые клиенты | Сколько денег принесут те, кого он привёл (соцпруф, сарафан) |

> **Зачем в RevOps:** воронка, оптимизированная только на **CLV первой покупки**, недооценивает клиентов, которые продлевают (CEV) и приводят других (CRV). Для бизнеса типа «подписка + корп-воркшопы» это критично: довольный корп-клиент воркшопа → расширение на новые команды (CEV) + рекомендация другому HR-директору (CRV) часто дороже исходной сделки.

## Ценность по стадиям: MQL → SQL → Customer → Advocate

Логика: на каждой стадии у контакта **растёт реализованная ценность** и **снижается риск отвала**. RevOps считает на каждой стадии ожидаемую ценность = (ценность при конверсии) × (вероятность дойти до следующей стадии).

### 1. MQL — потенциальная ценность (ещё не деньги)
- **Что считаем:** ожидаемый CLV × вероятность MQL→SQL→…→оплата (по историческим конверсиям).
- **Курсовая привязка:** категория лида A/B/C/D (`lead-categorization-abcd.md`) — прокси ожидаемой ценности: A-лиды (бренд/email/SMM/органика) имеют выше ожидаемый CLV и выше вероятность конверсии, чем C.
- **Действие RevOps:** не лить бюджет на лиды с низким ожидаемым CLV; A-лиды → лучшим сейлзам («усиливать сильное»).
- **Пример:** B2B-MQL (HR-дир крупной компании, заявка на воркшоп) имеет несоизмеримо больший ожидаемый CLV, чем B2C-trial academy — отсюда разный приоритет скорости (SLA, см. `sla-perelidoz.md`).

### 2. SQL — квалифицированная ценность (подтверждён бюджет)
- **Что считаем:** ожидаемый размер сделки (ACV) × вероятность SQL→Сделка. Бюджет/полномочия подтверждены на консультации → оценка точнее.
- **Курсовая привязка:** эксперт курса о ценообразовании от ценности прогресса: если клиент переходит от дорогого ручного процесса к вашему решению, цена — «steal, не дорого». Это якорь для ACV.
- **Действие RevOps:** приоритизация сделок по ожидаемой ценности; крупный ACV → внимание основателя/старшего сейлза лично.

### 3. Customer — реализованный CLV (первая выручка)
- **Что считаем:** фактическая первая выручка (Zero Day Revenue) + **Predict LTV = Zero Day Revenue × коэффициент** (коэффициент из исторических когорт по сегменту/каналу).
- **Курсовая привязка:** полная воронка `…→Платящие→Первая выручка→LTV→Маржинальность`; ключевые метрики на 1 экран: AdSpend / Новые платящие / Zero Day Revenue / ROAS / LTV / Refunds / Predict LTV.
- **Действие RevOps:** сверять CLV с CAC по сегментам. Дешёвый лид с низким CLV может проигрывать дорогому лиду с высоким CLV — решает **CLV/CAC, а не CPL**.
- **Здесь начинается CEV:** академия → продление подписки, апсейл тарифа (базовый→средний→премиум); корп → расширение воркшопа на новые команды/форматы. Удержание — `churn-prevention-ru`.

### 4. Advocate — CRV (клиент приводит других)
- **Что считаем:** CRV = выручка от приведённых им клиентов (рефералы, рекомендации, кейс/отзыв как соцпруф).
- **Курсовая привязка:** отзывы с конкретными кейсами и цифрами работают лучше «роботизированных»; соцпруф/отзывы/кейсы как актив воронки (B2B-контент); фокус-группы и материалы-playbook отрабатывают возражения через истории клиентов.
- **Действие RevOps:** замкнуть петлю — довольный клиент (высокий CEV) → запрос кейса/реферала → новый MQL (источник категории A). Advocate-стадия питает верх воронки самыми качественными лидами.
- **Пример:** корп-клиент, прошедший воркшоп → кейс на news.your-domain.com / рекомендация коллеге-ЛПР → входящий A-лид. Это самый дешёвый и горячий канал.

## Формула воронки ценности (рабочая)

```
Ожидаемая ценность контакта на стадии =
    CLV (прямой)              ← покупки самого клиента (LTV)
  + CEV (вовлечённость)       ← продления/апсейлы/расширение
  + CRV (рекомендации)        ← выручка от приведённых
  × P(дойти до этой ценности) ← историческая конверсия по стадиям
```

- **CLV** ≈ LTV из дерева метрик или Predict LTV = Zero Day × коэффициент.
- **CEV** — из когорт продлений/апсейлов (academy Postgres + `product-analytics`; B2B — Your CRM повторные сделки).
- **CRV** — атрибуция приведённых (промокоды/реф-ссылки/«откуда узнали» + источник новых лидов).
- **P** — конверсии по стадиям из `lifecycle-ru.md`.

> **Главный вывод:** оптимизируй воронку на **полную ценность клиента (CLV+CEV+CRV) против CAC**, а не на дешёвый CPL. Дорогой лид, который продлевает и приводит других, бьёт дешёвый лид, который купил один раз и ушёл.

## Чеклист

- [ ] CLV (LTV / Predict LTV) считается по сегментам и сверяется с CAC (не только CPL)?
- [ ] CEV отслеживается: продления/апсейлы/расширение (academy + Your CRM)?
- [ ] CRV отслеживается: рефералы/рекомендации/кейсы атрибутированы к источнику?

- [ ] Advocate-петля замкнута: довольный клиент → кейс/реферал → новый A-лид?
- [ ] ₽-коэффициенты берутся из своих когорт (Predict LTV), не выдуманы?
