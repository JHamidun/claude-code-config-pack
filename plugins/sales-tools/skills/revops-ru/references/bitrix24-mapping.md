# Реализация RevOps через Your CRM + academy-CRM (маппинг процесс → API)

Этот скилл (`revops-ru`) задаёт **что** настроить в воронке. Реализацию **как** для B2B-сделок делает `crm` (REST API, 821 метод, 20 scopes: crm, bizproc, task, im и др.). Вход лидов и B2C-воронка живут в academy-CRM `yourname-sales-postgres` (Sales-AI-агент). Здесь — таблица «элемент RevOps → что вызвать».

> Правило: не писать API-клиенты здесь. Описать конфигурацию словами, передать `crm` (B2B) или логике Sales-AI-агента (вход/B2C) с конкретными полями/стадиями/триггерами.

## Объекты CRM

| RevOps-понятие | Your CRM-сущность | Scope / метод (через `crm`) |
|---|---|---|
| Подписчик / Лид | **Лид** (CRM Lead) | `crm.lead.add/update/list` |
| MQL → SQL конвертация | **Лид → Сделка + Контакт + Компания** | `crm.lead.add` → конвертация в `crm.deal.add` |
| Сделка | **Сделка** (CRM Deal) в воронке | `crm.deal.add/update/list`, `crm.dealcategory` (воронки) |
| Стадии сделки | **Стадии воронки** (deal stages) | `crm.dealcategory.stage.list`, `crm.status` |
| Компания (ИНН) | **Компания** (CRM Company) | `crm.company.add/update` |
| ЛПР | **Контакт** (CRM Contact) | `crm.contact.add/update` |

## Поля и скоринг

| Элемент | Как в Your CRM |
|---|---|
| Fit-скор / Engagement-скор | **пользовательские поля** (UF_) на Лиде/Сделке (число) — `crm.lead.userfield.add` |
| Источник лида + дата (152-ФЗ lineage) | стандартные `SOURCE_ID` + UF-поле «источник_URL», `DATE_CREATE` |
| Грейд (A/B/C/D) | UF-поле или вычисляется бизнес-процессом |
| Обязательные поля на стадию | проверка в **бизнес-процессе** на смене стадии (блокировать переход) |

## Хэндофф и SLA (бизнес-процессы)

| RevOps-механизм | Your CRM-реализация (scope `bizproc` / `im`) |
|---|---|
| MQL → мгновенный алёрт менеджеру | **Робот/бизнес-процесс** на достижении порога скора → уведомление в чат (`im.notify`) + создание задачи |
| Задача с SLA 4ч | `tasks.task.add` с дедлайном; робот на стадии MQL |
| Эскалация при просрочке | бизнес-процесс с таймером → уведомление руководителю при превышении SLA |
| Маршрутизация (round-robin/по сегменту) | правило назначения ответственного в роботе (по отрасли/размеру → старший менеджер для enterprise) |
| Recycling с кодом причины | смена стадии Лида на «Recycled» + UF «код_причины»; робот ставит в нуртур-сегмент |

## Уведомления и автоматизация

| Сценарий | Метод (через `crm`) |
|---|---|
| Уведомление о новом MQL | `im.notify.personal.add` или робот |
| Авто-смена стадии при условии | бизнес-процесс (`bizproc.*`) |
| Алёрт по застрявшей сделке | бизнес-процесс с таймером (2× средних дней стадии) |
| Дайджест активности по горячим лидам | задача/отчёт + `bizproc` по расписанию |

## Метрики (отчёты)

| Метрика | Источник в Your CRM |
|---|---|
| Конверсия по стадиям, win rate, скорость | встроенная **аналитика CRM** / `crm.deal.list` + агрегация |
| Speed-to-lead | разница `DATE_CREATE` Лида и первой активности |
| Воронка marketing→sales | отчёт по стадиям Лид→Сделка |
| free→trial→paid (B2C) | НЕ в Your CRM — academy Postgres + `product-analytics` (Яндекс Метрика) |
| контент→продукт-trial | academy Postgres (`newsletter_subscribers`→`leads`/trial) + `product-analytics` |

## Синхронизация входа лидов

- **Вход всех лидов = academy-CRM `yourname-sales-postgres`** (Sales-AI-агент `save_lead`, формы academy/workshop/services).
- Формы с сайта (Tilda) → лид в academy-CRM, при B2B-квалификации зеркалится в Your CRM-сделку. Webhook/интеграция — через `crm` или n8n как glue.
- Каждый лид несёт источник + дату + UTM (152-ФЗ lineage + атрибуция).
- Касания из `draft-outreach` (email/LinkedIn/Telegram) фиксируются как **активности**: academy `conversations` и/или Your CRM `crm.activity.add`.
- Бронь консультации — `zoom` → запись в academy `zoom_meetings`.

## Порядок внедрения

1. **Определить** (этот скилл): стадии, скоринг, SLA, коды отклонения — на бумаге.
2. **Согласовать** маркетинг ↔ продажи (определения MQL/SQL для обеих воронок).
3. **Вход** — academy-CRM (формы Tilda → `leads`, Sales-AI-агент). **B2B-сделки** — настроить в Your CRM (через `crm`): воронка + стадии → UF-поля скоринга → бизнес-процессы (алёрты, SLA-таймеры, recycling) → обязательные поля.
4. **Построить мостик** контент→продукт-trial nurture (главная дыра воронки).
5. **Дашборды**: Your CRM (B2B) + academy Postgres + `product-analytics` (B2C/news).
6. **Калибровать** скоринг квартально по выигранным сделкам и trial→paid конверсии.
