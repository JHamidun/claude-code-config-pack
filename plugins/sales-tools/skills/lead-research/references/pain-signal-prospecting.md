# Prospecting по публичным сигналам боли (signal-first / первые клиенты)

Дистилляция методики `codex-first-customer-finder` (Kappaemme-git) под наш стек. Дополняет — **не заменяет** — фирмографический prospecting (`qualification-ru.md` + `ru-data-sources.md`).

## Когда этот режим, а когда фирмографический

Два ортогональных подхода к поиску клиентов:

| | **Фирмографический (top-down)** — `qualification-ru.md` | **Signal-first (bottom-up)** — этот файл |
|---|---|---|
| Отправная точка | Есть проверенный ICP → фильтруешь компании по фирмографике → ищешь «почему сейчас» | Есть продукт/оффер → ищешь людей и компании, ПУБЛИЧНО выразивших боль → квалифицируешь |
| Прдукт идентифицирует | компания по признакам (отрасль/размер/ЛПР) | человек по выраженной боли (пост/жалоба/запрос) |
| Лучше для | зрелый оффер, известный ICP, массовый B2B-список | **запуск нового оффера, первые клиенты, design-партнёры, гипотеза ICP ещё не доказана** |
| Каждый лид держится на | ICP-fit + сигнал | **дате + ссылке на первоисточник с болью** (без цитаты → не в шортлист) |

Практика, где signal-first сильнее: запуск нового интенсива или курса, поиск первых клиентов под новый консалтинговый оффер, набор design-партнёров под фичу YourProduct/ClientProjectB. Можно комбинировать: signal-first находит «горящих», фирмографика добирает look-alike.

## Таксономия сигналов (что именно ищем)

Каждый прспект должен опираться минимум на 1 датированный публичный сигнал одного из типов:

1. **Явный запрос** — прямо просят инструмент/подрядчика/альтернативу («посоветуйте, кто внедряет AI-ботов», «ищу курс по нейросетям для команды»).
2. **Описание проблемы** — от первого лица описывают боль, которую наш оффер закрывает («тонем в ручной обработке заявок», «менеджеры не умеют в промпты»).
3. **Костыль / воркэраунд** — жалобы на ручной процесс или самопал вместо нормального решения (сигнал готовности платить за автоматизацию/обучение).
4. **Отток / переключение** — недовольство текущим вендором, обсуждение миграции, «ушли от X, ищем замену» (высокий intent).
5. **Триггер тайминга** — наём под задачу, запуск направления, расширение, новый CDO/директор трансформации, публичное заявление про AI (пересекается с «почему сейчас» из `qualification-ru.md`).

## Рубрика квалификации (5 измерений)

Скорь каждого прспекта; слабый по 2+ измерениям → в спекулятивные, не в шортлист.

| Измерение | Вопрос | Что проверяем |
|---|---|---|
| **Сила боли** | насколько остро и ясно выражена | острота формулировки, повторяемость, эмоция |
| **Product fit** | наш оффер реально закрывает эту боль | совпадение с core-результатом, не «смежно» |
| **Тайминг** | почему именно сейчас | свежесть сигнала (30 дн бьёт 6 мес), бизнес-момент |
| **Публичная достижимость** | можем ли выйти легитимным каналом | есть публичный рабочий контакт/канал (не личные ПДн) |
| **Качество доказательства** | сигнал сорсирован | ссылка + дата + оригинал (не пересказ, не агрегатор) |

Маппинг на наши грейды (`qualification-ru.md`): сильный по всем 5 → **Hot**; fit есть, тайминг/сила слабее → **Warm**; рыхло или контакт не подтверждён → **Cold**; нет цитируемого сигнала боли → **Skip** (спекулятивный, исключить). Уровни уверенности High/Medium/Low — как в `qualification-ru.md`.

## Режимы (scope)

| Режим | Объём | Фокус |
|---|---|---|
| **quick** | до 5 | только высшая уверенность |
| **standard** (деф) | до 10 | несколько типов источников |
| **deep** | до 20 | + карта повторяющихся паттернов боли |
| **design-partners** | готовые дать фидбек | итерация/тест, не продажа |
| **b2b** | сигналы на уровне компании | роли-ЛПР + бизнес-триггеры |
| **community** | публичные обсуждения | явные запросы на форумах/в чатах |

## Где мискать сигналы в RU (карта источников → исполняющий скилл)

Западные Reddit/HN/X заменяем/дополняем RU-площадками. Под каждым — готовый скилл, не реимплементировать.

| Тип площадки | RU-источники | Скилл |
|---|---|---|
| Проф-сообщества, комменты | Habr (посты+комменты), vc.ru, Пикабу, Яндекс Кью | `perplexity` / `deep-research`, WebSearch, `firecrawl` |
| Телеграм-чаты и каналы | проф-ТГ по AI/маркетингу/HR, чаты сообществ, комменты каналов | `social-intel`, `tg_client.py` (search/parse-comments), `last30days` |
| Соцсети | VK-группы и обсуждения, LinkedIn-посты ЛПР | `social-intel`, `linkedin`, ScraperVendor |
| Найм как сигнал боли | вакансии «нужен опыт с нейросетями», L&D-роли, «внедрить AI» | `headhunter` |
| Отзывы/переключение | отзовики, маркетплейс-ревью, обсуждения вендоров | `apify-scraping`, WebSearch |
| Западные (если ICP англоязычный) | Reddit, HN, X, форумы | `reddit-hn`, `last30days`, `tiktok-intel` |
| Тренд-мониторинг | что обсуждают за 30 дней | `last30days` |

Заметка из вашего региона: западные площадки (Reddit/X) иногда требуют аккуратности с доступом; RU-ядро (Habr/vc/ТГ/HH) работает без прокси. Платные ключи не обязательны — старт на WebSearch + `perplexity` + `tg_client`.

## Структура HTML-отчёта

Порядок разделов (генерация — через наши HTML-скиллы: `standalone-html` / `web-artifacts-builder` / `generate-report-header`; можно и Artifact):

1. **Вердикт** — достижимы ли сигналы первых клиентов; жизнеспособность гипотезы.
2. **ICP** — покупатель, «работа»/боль, триггер, дисквалификаторы.
3. **Топ-прспект** — сильнейшее доказательство + обоснование тайминга.
4. **Карточки шортлиста** — на каждого: URL-источник, цитата сигнала боли, дата, fit-скор, стадия, канал выхода, персональный опенер.
5. **Анализ паттернов** — повторяющиеся боли и бизнес-моменты (сырьё для позиционирования/оффера).
6. **7-дневный план касаний** — ручной, low-volume (ниже).
7. **Ограничения** — чего не хватает, что требует подтверждения, где данные устарели.

## 7-дневный план касаний (ручной, уважительный)

Никогда не автоотправка. План — гипотеза для валидации, не CRM-дамп.

- **Дни 1–2** — ресёрч публичных каналов, поиск тёплых интро/общих связей.
- **Дни 3–4** — черновики персональных опенеров на основе цитируемого источника (генерит `draft-outreach`; НЕ отправлять авто).
- **Дни 5–6** — тайминг фоллоу-апа, альтернативные каналы.
- **День 7** — рефлексия, квалификация тех, кто готов к глубокому разговору.

Передача: опенеры → `draft-outreach`; учёт лидов с lineage → `crm` / academy-CRM `yourname-sales-postgres`.

## Гардрейлы

- **Каждый прспект = ≥1 значимый публичный сигнал со ссылкой и датой.** Нет цитаты → Skip.
- **10 сильных совпадений лучше generic-списка** — планка качества выше объёма.
- **Неопределённость и устаревшие данные — показывать явно** (раздел «Ограничения»).
- **Персонализация только из цитируемого источника** — не додумывать контекст.
- **Касания только ручные**; шортлист = исследовательская гипотеза, не база для рассылки.
- **152-ФЗ** — только публичные рабочие каналы; источник + дата на каждый контакт; не хранить ПДн дольше нужного, не перепродавать (как в `qualification-ru.md`).

## Почему не ставим сам инструмент

`codex-first-customer-finder` — npm-пакет под фреймворк Codex-skills (Python+JS), запускается вне Claude Code и по составу дублирует то, что уже делают наши скиллы (`perplexity`, `social-intel`, `headhunter`, `reddit-hn`, `last30days`, `draft-outreach` + HTML-генераторы). Ценность — в методике (signal-first + evidence-backed + режимы + HTML-отчёт + 7-дневный план), она дистиллирована здесь. Инструмент как таковой не устанавливаем.
