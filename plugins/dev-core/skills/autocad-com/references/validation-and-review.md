# Проверка альбома: инварианты, красный прогон, независимое ревью

## Инварианты (`validator.py`, 25 проверок, PASS/FAIL/WARN/INFO)

Геометрия: помещения не пересекаются **внутренностями** (пересечение полигонов, не центроиды); дверь
помещения существует, лежит на контуре, есть в `walls[].openings` и замыкает обход; нумерация стен сплошная,
Σ цепочки = длина стены.
Мебель: позиции сквозные без пропусков и дублей; footprint **целиком** внутри помещения (углы + рёбра, не
центр); **исходные** секции из данных Σ = W (не после подгонки), флаг `fitted` = FAIL.
Данные: светильники внутри своих помещений, марки линий уникальны, ссылки линий на существующие
светильники; розетки/выводы/выключатели/терморегуляторы — на существующей (не открытой) стене, в пределах
длины, **не в проёме ниже его верха** (для всех настенных типов, не только розеток); типы пола/потолка —
ровно один на помещение и согласован с core; зоны тёплого пола внутри помещения; развёртки ссылаются на
существующие номера стен.
Newspaper1: все объёмы посчитаны и равны пересчёту по формуле; марки дверей уникальны и на существующих
стенах; символ и текст розетки из одного словаря; строк спецификации мебели = позиций.
Рендер (по тексту SVG, а не по реестру): адрес объекта на каждом полном штампе; «Листов» заполнено; ссылки
«на листе N / листы N–M / см. лист N» имеют число в диапазоне; десятичный разделитель — запятая (статический
белый список только `0.000`; иерархические позиции «1.1», марки линий «3.1», позиции мебели добавляются в
`allowed` из самой модели; составные обозначения вида «1.045.9-2.08» отсекает регэксп с lookaround на
`[\w/.-]`, а не список); масштаб в штампе = реестр; диапазоны стен в **отрисованных** заголовках развёрток =
модель; заглушек нет.

Правило конфликта устройства с проёмом различает окно и дверь: в окне — конфликт только при
`sill ≤ h ≤ sill + h_окна` (розетка 300 под подоконником 900 допустима); в двери/проёме — при `h ≤ высота
проёма`. Иначе ложные FAIL на каждой розетке под окном или пропуск выключателя в проёме. Устройство не на
стене (розетка в боковине острова) — `wall_ref: null` + `xy`, валидатор требует точку внутри полигона
своего помещения; ни того ни другого — FAIL.

Канал `project["_warnings"]`: модель и модули кладут туда «нехватка данных/места» (проём попадает на ребро
частично → ширина = длина пересечения + предупреждение, а не молчание), `run.py` печатает их в конце,
валидатор превращает список в WARN. Оговорка к «Σ цепочки = длина»: сумма слепа к перераспределению —
900+2700 и 780+2820 одинаково дают 3600; ширину проёма брать из пересечения, а не из данных.

Два известных слепых пятна геометрии (в красный прогон следующего валидатора): `polygons_overlap` не видит
вложенный полигон, все вершины которого лежат на рёбрах внешнего (дубликат помещения, «половина комнаты»);
`polygon_contains` для этого случая корректен — проверять оба.

`run.py` возвращает код 1 при любом FAIL; при полной сборке чистятся только `svg/png/dxf` и только без
`--only`; `album.pdf`, `specs.xlsx`, `viewer.html` не чистятся и не пересобираются, если шаг не заказан
(дефолт `--steps svg,png,dxf,validate`) — зелёный прогон оставляет старый PDF рядом со свежими SVG. Для
выдачи заказчику всегда `--steps svg,png,dxf,pdf,xlsx,3d,validate` с чистого `out/`.

## Красный прогон — обязателен до показа отчёта

`validator.py --break` портит копию данных, как портится ручной альбом: пропущенная позиция, шкаф в чужом
помещении, ссылка на несуществующую дверь, объём набит руками, розетка за концом стены, марка линии дважды.
Требование ≥ 4 FAIL; на демо 6. Валидатор, у которого нет красного прогона, не проверяет ничего — три
из четырёх слепых пятен ниже прошли бы зелёными без него.

## Слепые пятна, найденные независимым ревью (чек-лист для следующего валидатора)

Ревью: Codex CLI 0.153.4, `gpt-6-astra`, `model_reasoning_effort=xhigh`, полный доступ, четыре
команды-гейта в промпте; 16 минут, 141K токенов, 25 находок (16 S1). Сохранить как список того, что
проверять в любом валидаторе чертежей:

1. Проверка сравнивает **уже нормализованные** данные (подогнанные секции) — FAIL невозможен.
2. `… or True` — безусловная истина в условии.
3. Центроид вместо пересечения полигонов; центр footprint вместо вложенности.
4. Проверка «рендера» читает реестр, а не отрисованный текст.
5. Разные допуски в модели и валидаторе (250 vs 200) — объект есть в одном месте и отсутствует в другом при PASS.
6. Условие проёма только для части типов устройств; `virtual` стена принимается за существующую.
7. Рисуется только первая страница, хвост теряется (`pages[0]` в ведомости и таблице дверей, реестр всегда
   один лист) — валидатору проверять: отрисовано страниц = рассчитано.
8. Бесконечный цикл пагинации без сторожа продвижения.
9. Устаревшие файлы в выходе при зелёном отчёте; код возврата 0 при FAIL.
10. Два независимых расчёта одного числа (кол-во светильников: счёт записей vs Σ qty).
11. Свес прибавлен к габариту на чертеже, но не в спецификации.
12. Приоритет локального дубликата (h_clean в развёртках) над общей моделью (уровень потолка).
13. DXF молча теряет: заливки, цвет сущностей, тип штриховки, кривые Q/A.
14. Смещение проёмов при частичном демонтаже стены (at от исходного начала стены, не от участка).
15. Наружная дверь: дыра из existing, полотно из new_construction — разъезжаются.
16. 3D: отражение плоскости пола (знак координаты).
17. Vacuous PASS: проверка рендера на пустом входе (ни одного SVG) и на нераспознанном заголовке обязана
    падать; текст штампа («1:60», «34») читать только внутри `data-layer="STAMP"` — совпадение где угодно на
    листе не считается.

## Пробы: как писать (то, что оставил ревьюер в `review/probe_*.py`)

- **Холст-регистратор**: duck-typed класс с теми же методами (`set_layer/line/rect/polygon/arc/text`),
  который только копит точки. Функции компоновки (`draw_partitions`, `draw_outer_walls`, `draw_door_symbols`)
  дают числа — bbox сохранённых участков, дыры в полосе стены, координаты торцов — и сравниваются с ожиданием
  без рендера. Так поймались смещение проёма при частичном демонтаже и торцы двери внутри помещения.
- **Обратное чтение SVG**: рисовать в `sh.view(1, 0, H)` (масштаб 1:1 → координаты SVG = мм), затем
  `line` с `x1 == x2` — вертикальные членения, `H − y1` — отметки, `rect` с `height == worktop_t` — глубина
  столешницы; сравнивать с `build_item()` и спецификацией. Так нашлись 3×600 vs 4×450 и остров 1200 vs 900.
- **Порча данных в памяти**, не на диске: `copy.deepcopy(project)` → одно изменение → `validate()` → ожидание
  конкретного FAIL. Порча без FAIL = находка.

## Как организовать ревью

- Промпт с явным приоритетом: швы между модулями → слепые пятна валидатора (с минимальной порчей, которую
  он пропустит) → геометрия → DXF-потери → пагинация → дубли → кодировки. Формат: `[S1|S2|S3]`, файл:строка,
  воспроизведение, фикс; код не править; свои пробы класть в `review/`.
- Дать команды-гейты (`model.py`, `run.py --steps list`, `validator.py --break`, `run.py --strict`) — ревью без
  запуска = пересказ кода.
- Codex на Windows: `-s workspace-write` блокирует pwsh («blocked by policy») — нужен
  `-s danger-full-access -c approval_policy=never --ignore-user-config`, бэкап `engine/` рядом, `</dev/null`
  в фоне. Проверять, что процесс один (`Get-Process codex` — чужие сессии не трогать).
- Находки чинят **владельцы модулей** (воркеры с живым контекстом — `SendMessage` → resume), не ревьюер;
  после фиксов — пробы ревьюера зелёные, полная пересборка, красный прогон, глаза на изменённые листы.
