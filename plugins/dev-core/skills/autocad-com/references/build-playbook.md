## Что сработало

- **Данные раньше движка, контракт раньше данных.** SCHEMA.md + `python engine/model.py` (стены, проёмы,
  объёмы в консоль) — автор данных и воркеры читают одну распечатку.
- **Один файл — один владелец.** Данные разрезаны по JSON-файлам, код — по модулям; ни одного конфликта
  правок за ночь. Общие модули (`sheet/model/album`) правит только оркестратор; нужна функция — воркер
  пишет приватную и сообщает в отчёте (потом список «кандидаты на подъём» в ENGINE.md).
- **Заглушки вместо падений.** Реестр альбома подставляет лист «в разработке», если модуля нет или он
  упал: альбом собирается в любой момент, каждый воркер видит свои листы в общей нумерации.
- **Воркеры стартуют до данных** с дефолтами и подхватывают файлы по появлению (`ls` раз в 3–4 минуты, не
  дольше 25 мин) — критический путь не ждёт автора данных.
- **Промпт воркера = спецификация, а не понимание**: файлы-владения, разделы разбора эталона по номерам,
  эталонные PNG для глаз, гейт «рендер → Read PNG → сверка» после каждого листа, CRASH-SAFE протокол с
  прогресс-файлом, финальный ответ — что расходится с эталоном и чего не хватило в данных.
- **Глаза оркестратора на чужую работу** — 3–4 листа каждого модуля против эталонных PNG до приёмки; так
  нашлись полупустой A2 и служебная строка не на месте (торцы двери внутри помещения глаза на A2 при 150 dpi
  не увидели — их поймало ревью Codex пробой на координаты). Для плотных слоёв (розетки, свет, потолки)
  целый лист не годится — смотреть кроп фрагмента.
- **Ревью другой моделью после интеграции, не до** — швы между модулями видны только на собранном альбоме.
- **Фиксы чинят авторы**: `SendMessage` в завершённого воркера возобновляет его с контекстом; 25 находок
  разошлись по четырём воркерам и оркестратору за один ход.

## Что не сработало и как обойдено

- Нумерация стен изменилась после того, как автор данных на неё сослался → скрипт перенумерации по
  совпадению рёбер (115 ссылок), а не ручная правка; воркерам — сообщение «не кэшировать номера».
- Разовый `CronCreate` на время, которое прошло, пока сессия была занята, не сработает → периодический
  `*/20` на время роя, удалить по завершении.
- `cd` в Bash не переживает вызовы (cwd сбрасывается на домашнюю) → абсолютные пути или `cd … &&` в каждой
  команде.
- Codex в песочнице на Windows не выполняет команды → полный доступ + бэкап.
- Рабочую папку роя (`workflows-progress/<волна>/`) удалить не дали права — не страшно, там бэкапы.
- `json.dump(indent=2)` разворачивает координаты по строке на число → свой компактный дампер (объект в
  одну строку до 400 символов), иначе core.json нечитаем.

## Контрольный список перед отправкой заказчику/ученику

1. Полная пересборка с чистого `out/` и **всеми** шагами (`svg,png,dxf,pdf,xlsx,3d,validate`): SVG = PNG =
   DXF = число листов реестра, PDF страниц = листов; без заказанного шага старый `album.pdf` переживёт сборку.
2. `validation.md` без FAIL и WARN; красный прогон ≥ 4 FAIL. Числа FAIL/PASS/листов в compare/README —
   из вывода **этого** прогона, не из памяти (в первой версии compare.md стояло «7 FAIL» при фактических 6).
3. Глаза: лист каждой группы + все, что менялись после ревью.
4. Наружу — PDF-альбом, PDF документов (`md2pdf.py`), XLSX, PNG; DXF отдельным архивом с подписью «CAD».
5. Память: проект, грабли, фидбек; индекс в лимите (`memory_fit.py --check`).
