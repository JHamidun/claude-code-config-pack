## Что проверяли

1. Паспорт репозитория и npm без клонирования (метаданные, лицензия, мейнтейнеры, история).
2. Два статических сканера навыка `skill-manager` (личный на 36 правил и NVIDIA в локальном режиме без сети). Автоматический вердикт
   CAUTION: две находки WARN и десять статических. Разобраны по строкам: `prepublishOnly` срабатывает только при публикации пакета,
   `unref()` у таймера принят за «отвязанный процесс», три PE3 это строки `.env`/`.npmrc` в `.gitignore` и фраза в CONTRIBUTING
   «не копируйте токены», AE4 это `<p align="right">` языковой шапки, RP1 это совет README ставить через `npx ...@latest` (мы так не ставим).
3. Чтение всего исходного кода (1 215 строк) самим ассистентом.
4. Независимый рой из четырёх рецензентов. Каждый перед охотой подсаживал в копию заведомую находку своего класса (в том числе в
   замаскированном виде) и подтверждал, что его способ её ловит; найденное уровня medium и выше проверяли три опровергателя с разными
   линзами (цитата, достижимость, влияние). Линзы: цепочка поставок и установка; утечка данных и права (в роли атакующего);
   исполнение кода и разбор входа (в роли атакующего); MCP-поверхность, документы и целостность данных.

права файла сессии на Windows (биты режима не работают, защищает папка пользователя). Автоматические сканеры дали CAUTION: две находки WARN и
десять статических, разобраны по строкам (раздел выше): все ложные или принятые.

**Остаточные риски, которые нельзя закрыть кодом:**

1. **Чужой текст и режим без подтверждений.** Названия, продавцы, характеристики и отзывы пишут посторонние. Фасад вырезает типовые команды
   (русские и английские), полноширинную запись, невидимые теги, режет длины и подаёт всё под заголовком «ДАННЫЕ ИЗ OZON», но пересказ
   команды другими словами фильтр не поймает. Если сессия идёт в режиме `bypassPermissions` или с широкими `allow` (проверьте `permissions`
   в своём `settings.json`), удавшаяся инъекция исполнилась бы без вопроса. Это политика разрешений, а не дефект установки; снижает риск
   следующее: инструменты только на чтение, отзывы отдаются дайджестом, а не сырым текстом. Дальнейшая мера (по желанию): отдельный
   субагент, у которого из инструментов только `ozon_*`, чтобы чтение Ozon шло в изолированном контексте.
2. **Правила сайта.** Ozon не даёт покупателям публичного API; сервер читает внутренние адреса и скрывает признаки автоматизации
   (`--disable-blink-features=AutomationControlled`). Пользоваться интерактивно и понемногу, без массового сбора. Формат может измениться
   без предупреждения, тогда сработают предупреждения фасада, а не тихая пустота.
3. **Один мейнтейнер.** Репозиторий ведёт один человек (15 звёзд, одиннадцать issue и все от dependabot): исправлений уязвимостей ждать не от кого.
4. **Слепые зоны самого аудита.** Источники пяти рабочих зависимостей не читались построчно: они проверены по хэшу (сошёлся с реестром у
   120 из 120 пакетов) и по метаданным происхождения (у всех пяти рабочих пакетов trusted publisher и SLSA), но подмена внутри пакета с верным
   хэшем была бы невидима. Сканеры разбирают только .ts/.js/.mjs/.cjs; `package.json`, lock и README читались вручную и парсером Python.

## Установка с нуля (по шагам)

Нужны Node.js 22 или новее (проверялось на 22.15), git и Google Chrome; команды для Git Bash. Скачанное остаётся чужим кодом, поэтому
ставится только проверенный коммит и без скриптов установки. Сам upstream в этот набор не входит: его собирают локально по шагам ниже.

1. Скачать проверенный коммит: `git clone https://github.com/neosheps/ozon-shopping-mcp ~/.claude/tools/ozon-shopping-mcp`, затем
   `git -C ~/.claude/tools/ozon-shopping-mcp checkout 2ec1c7071ca44c8b8c44497c4e801158f26aeaa5`.
2. Патч P1 (зачем он, объяснено ниже): в `src/browser-session.ts` в объект параметров запуска браузера, рядом со строкой
   `args: ["--disable-blink-features=AutomationControlled"]`, добавить `chromiumSandbox: true,`.
3. В этой папке: `npm ci --ignore-scripts`, затем `node node_modules/typescript/bin/tsc -p tsconfig.json` (появится `dist/`; именно так
   собиралась проверенная сборка), затем `npm ci --omit=dev --ignore-scripts` (останутся только рабочие зависимости). Предупреждение npm
   про `engines` (нужен Node 24, а стоит 22) можно пропустить, `engine-strict` не включайте.
4. Убедиться, что патч попал в сборку: в `dist/browser-session.js` есть `chromiumSandbox: true`.
5. Подключить фасад из этого навыка, а не сам upstream:
   `claude mcp add --scope user ozon-shopping -- node ${HOME}/.claude/skills/ozon-shopping/server/ozon-safe-mcp.mjs`
   (на Windows путь должен получиться абсолютным; если `${HOME}` не раскрылся, подставьте полный путь).
6. В `settings.json` → `permissions.deny` добавить `Bash(*npx*ozon-shopping-mcp*)` и `Bash(*ozon-shopping-mcp@latest*)`.
7. Создать анонимную сессию (откроется окно Chrome, входить в аккаунт не нужно): `node ~/.claude/skills/ozon-shopping/scripts/ozon-audit.mjs setup`,
   затем `node ~/.claude/skills/ozon-shopping/scripts/ozon-audit.mjs health`.
8. Проверить сам навык: из его папки `node --test scripts/*.test.mjs server/*.test.mjs`. Перезапустить Claude Code, `/mcp` покажет `ozon-shopping`.
9. По желанию: положить в папку сборки `.audited.json` с источником, коммитом и патчем (метка происхождения для будущих обновлений), например
   `{"source": "https://github.com/neosheps/ozon-shopping-mcp", "commit": "2ec1c7071ca44c8b8c44497c4e801158f26aeaa5", "license": "MIT", "patches": ["P1: chromiumSandbox: true in browser-session.ts"]}`.

## Как собрано и подключено

Сборка из проверенного дерева, не из npm и не через `npx`:

1. Копия проверенного дерева (отпечаток сверен) в рабочую папку, `npm ci --ignore-scripts` (все 120 пакетов из lock-файла с проверкой хэшей, ни один скрипт не запускался), компиляция `tsc` из lock-файла, затем рабочая папка ставится заново только с рабочими зависимостями (`npm ci --omit=dev --ignore-scripts`, пять пакетов).
2. Один патч, P1: в параметры запуска Chrome в `browser-session.ts` добавлено `chromiumSandbox: true`. Без него Playwright запускает Chrome
   с `--no-sandbox` (в документации его типов: «по умолчанию false»), то есть без встроенной песочницы Windows, а страница ozon.ru исполняет
   чужой JavaScript от имени владельца. Рецензенты проверили патч сами: у процессов Chrome флаг пропал (рендереры получают низкий уровень
   целостности), всё остальное в командной строке браузера то же, Chrome стартует. Других правок в сборке нет.
3. Результат: `~/.claude/tools/ozon-shopping-mcp` (метка происхождения в `.audited.json`).
4. Зарегистрирован не upstream-сервер, а фасад этого навыка: `claude mcp add --scope user ozon-shopping -- node ${HOME}/.claude/skills/ozon-shopping/server/ozon-safe-mcp.mjs`.
5. В `settings.json` в `permissions.deny` нужны `Bash(*npx*ozon-shopping-mcp*)` и `Bash(*ozon-shopping-mcp@latest*)`: README и сообщения upstream-сервера советуют запускать его через `npx`, а без запрета (особенно при разрешённом `Bash(npx *)`) в сессию придёт непроверенная свежая версия.

## Что проверено после установки (12.10.2026)

- Тесты upstream на Node 22.15: 11 из 11 (в `engines` стоит 24 и выше, на 22.15 работает).
- Тесты навыка: `node --test scripts/*.test.mjs server/*.test.mjs`, 70 проверок на придуманных данных (разбор отзывов, представления, слой
  ввода-вывода на выдуманной сборке upstream, фасад на выдуманном клиенте).
- Настоящий протокол MCP по stdio с настоящим SDK и zod из сборки: `initialize`, `tools/list` (пять инструментов, у всех `readOnlyHint: true`),
  вызовы `ozon_status` и `ozon_reviews`. `claude mcp get ozon-shopping` показывает `Connected`.
- Живой Ozon (проверка из-за пределов РФ): `setup` отработал без ручной проверки Ozon; `search`, `product`, `reviews`, `compare` вернули данные
  (три реальных товара, сравнение целиком около 27 секунд при трёх выборках отзывов на товар).
- Что вскрыла живая проверка и чего не видели тесты на придуманных данных: (1) анонимной сессии Ozon отдаёт `purchased: false` всем отзывам,
  поэтому признак «покупка не подтверждена» учитывается только при смеси значений; (2) обычная выдача отзывов не «последние», а «новые и полезные»
  с перекосом к фото; (3) работают только сортировки `score_asc` и `score_desc`; (4) добавленные «новые пятёрки» по построению завышали
  среднюю оценку и давали ложное «слишком гладко» (у трёх разных товаров одинаковые «4,91»), оценки теперь считаются только по обычной выборке.

## Если меняешь сборку или фасад

- Фасад держится на одном внутреннем поле upstream: `client.session.requestJson` (`scripts/ozon-upstream.mjs`, сортировка отзывов). Если после
  обновления upstream оно исчезнет, дополнительные выборки отключатся с пометкой в ответе, а обычный разбор продолжит работать.
- Проверка после любой пересборки: у процессов Chrome нет `--no-sandbox`, `node --test` зелёный, `ozon-audit.mjs health`, затем `reviews <sku>`.

## Обновление

Никогда не `npx ozon-shopping-mcp@latest`. Новая версия это чужой код, которого никто не видел:

1. Скачать новый коммит в пустую папку (без запуска), сравнить его с проверенным (`git diff 2ec1c70..<новый>`), перечитать разницу и пройти сканеры `skill-manager`.
2. Если менялись зависимости, повторить проверку lock-файла (источники, хэши, скрипты установки, свежесть версий).
3. Пересобрать тем же порядком, обновить отпечаток и коммит в `.audited.json` и в этом файле.

## Откат и удаление

- Отключить: `claude mcp remove ozon-shopping -s user`.
- Убрать сессию: удалить папку состояния, в ней cookie анонимной сессии (`%APPDATA%\ozon-shopping-mcp` на Windows,
  `~/Library/Application Support/ozon-shopping-mcp` на macOS, `~/.config/ozon-shopping-mcp` на Linux).
- Убрать сборку: удалить `~/.claude/tools/ozon-shopping-mcp`.
- Откат правки `settings.json`: вернуть копию файла, сделанную перед правкой (перед любым изменением `permissions` делайте копию).

## Известные ограничения

- У Ozon нет публичного API для покупателей: сервер читает внутренние адреса сайта, формат и защита от автоматизации могут измениться без предупреждения.
- Сервер скрывает признаки автоматизации (`--disable-blink-features=AutomationControlled`), что идёт против духа правил сайта; пользоваться интерактивно и понемногу, без массового сбора.
- Из-за пределов РФ 12.10.2026 всё работало без прокси; если Ozon начнёт отказывать по адресу, нужен российский выход (в код сервера прокси не заложен).
- Ограничения отсева накрутки: `references/review-signals.md`.
