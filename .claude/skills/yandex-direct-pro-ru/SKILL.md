# Яндекс.Директ — Pro Playbook (RU)

Методология запуска и ведения контекстной рекламы в Яндекс.Директе из практики эксперта по контексту с сотнями проектов. Это **playbook по стратегии и оптимизации**, а не интерфейс к API.

> **Граница: методология vs API.** Этот скилл = МЕТОДОЛОГИЯ (что и почему делать в Директе/Метрике). Для **API-операций** — выгрузка статистики, создание целей, загрузка офлайн-конверсий, Wordstat через API, управление ставками — делай напрямую через API Яндекса (`api.direct.yandex.com`, `api-metrika.yandex.net`, OAuth). Принцип: здесь решаем «какую цель/стратегию/корректировку», там — «как технически записать».

## Когда использовать

- Запуск рекламной кампании в Директе с нуля (семантика → структура → цели → стратегия → объявления).
- Выбор автостратегии и модели оплаты под конкретную ситуацию (матрица выбора).
- Настройка обучения автостратегии и защита его от сброса.
- Еженедельный анализ и оптимизация (Поиск и РСЯ — разные чек-листы).
- Масштабирование работающей кампании в 3-5 раз без слома экономики.
- Передача квалифицированных лидов из CRM обратно в Метрику (офлайн-конверсии).

**НЕ использовать для:** Google/Meta/VK/Telegram Ads; SEO-семантики под органическую выдачу (→ `seo-machine-ru`); CRO лендинга; технических API-вызовов.

## Что нужно знать до запуска (фундамент)

1. **Контекст конвертирует готовый интерес в покупку.** Работает на этапе воронки, когда спрос уже сформирован. Не объясняем «зачем товар», объясняем «почему купить у нас».
2. **Два типа рекламы:** Поиск (ответ на запрос в Яндексе) и РСЯ (Рекламная сеть Яндекса — тысячи сайтов-партнёров, приложения, видеосети). Поиск и РСЯ — **всегда разные кампании**, у них разная логика объявлений, бенчмарки и стратегии.
3. **Аукцион.** Победитель и порядок показа определяются формулой: **ставка × CTR × коэффициент качества × прогноз CTR**. Аукцион проходит **каждый раз при загрузке страницы**, не один раз. Единственное, на что влияем напрямую, — ставка.
4. **Ставка ≠ списываемая цена.** Ставка — максимум, который готов платить. Списываемая цена всегда ниже (ставка 80 ₽ → спишется, например, 35 ₽).
5. **Персонализация.** Разным людям показываются разные объявления (демография, гео, устройство, история, интересы). **Поэтому проверять рекламу «вбил запрос — не вижу себя» бессмысленно** — оценивать только по статистике.
6. **Крипта** — технология Яндекса: анализирует 300+ характеристик пользователя (пол, возраст, профессия, доход, интересы, история, использование сервисов), объединяет в кластеры в реальном времени, **склеивает устройства одного человека и выделяет домохозяйства**. На ней работают автотаргетинг и обучение стратегий.
7. **Интерфейс — Direct Pro, режим эксперта** (не «мастер кампаний»). Один тип кампании — **ЕПК (единая performance-кампания)**, объединяет текстово-графические, графические, товарные объявления. Decision tree «мастер vs эксперт» и детали мест показа — `references/strategies-learning.md`.

## Workflow запуска кампании с нуля

```
1. СЕМАНТИКА      → собрать маски (базисы), развернуть в подзапросы,
                    отсеять холодные, кластеризовать          → references/semantics-wordstat.md
2. СТРУКТУРА      → бренд = отдельная РК; Поиск и РСЯ = разные РК;
                    1 группа = 1 список слов по 1 маске
3. ЦЕЛИ В МЕТРИКЕ → JS-события (не автоцели) на все макроконверсии
                    + микроконверсии (60/90 сек, скролл ≥70%) для обучения  → references/strategies-learning.md
4. ОБЪЯВЛЕНИЯ     → Поиск: заголовок1 ≤56, заголовок2 ≤30, текст ≤81,
                    быстрые ссылки, уточнения; РСЯ: конкретно, не тизер   → references/semantics-wordstat.md
5. СТРАТЕГИЯ      → выбрать по матрице (см. ниже); оплата за клики (90%);
                    атрибуция — Автоматическая                           → references/strategies-learning.md
6. UTM           → utm_source/medium/campaign/term/content + динам.параметры
                    (для Директ+Метрика метки НЕ обязательны — одна экосистема)
7. ОБУЧЕНИЕ      → НЕ трогать настройки 7-14 дней, ждать ≥10 конв/нед,
                    полное обучение 2-3 недели
8. ОПТИМИЗАЦИЯ   → еженедельный чек-лист (Поиск / РСЯ)                    → references/optimization-scaling.md
9. МАСШТАБ       → чистка → +10%/нед → расширение таргетингов            → references/optimization-scaling.md
```

## Матрица выбора автостратегии (быстрая)

| Ситуация | Стратегия | Ограничение |
|----------|-----------|-------------|
| Поиск + брендовая семантика | Максимум кликов | — |
| Поиск + горячая семантика | Максимум кликов | — |
| Поиск + любая другая семантика | Максимум конверсий | недельный бюджет или средняя цена |
| РСЯ | Максимум конверсий | недельный бюджет |
| Только запускаемся, данных нет | Максимум конверсий | недельный бюджет |
| Знаем целевой CPA, жёсткое ограничение | Максимум конверсий | средняя цена конверсии |
| Несколько целей разной ценности | Максимум конверсий | **целевая доля расходов 100%** (лайфхак) |

Подробно про каждую стратегию, модели оплаты и атрибуции — `references/strategies-learning.md`.

## Три приёма-сигнатуры методологии (не теряй)

1. **Целевая доля расходов (ЦДРР) 100%** — лайфхак для одновременной оптимизации на **микро + макроконверсии с разными ценностями**. Стратегия «Максимум конверсий» → ограничение «ЦДРР 100%» → в целевых действиях указываем не ценность, а **цену** каждого действия. Алгоритм обучается на бóльшем массиве данных (микро + макро), а не только на редких заявках. Расчёт и пример — `references/strategies-learning.md`. (Не для e-commerce с реальной ценностью заказа.)
2. **Корреляция Пирсона микро↔макро** в Excel: выгрузить по неделям/РК пары «микроконверсия» / «макроконверсия», посчитать корреляцию (0-1). **>0.7 → микро-цель валидна для обучения.** Корреляция может распадаться при смене настроек — перепроверять.
3. **Составная цель** — объединить в одну цель (один шаг, условие ИЛИ): отправка формы ИЛИ квиз ИЛИ страница «Спасибо» ИЛИ клик по телефону. Все лиды суммируются → стратегия обучается быстрее.

## Защита обучения (критический список)

**ПЕРЕЗАПУСКАЕТ обучение с нуля** (избегать после старта): смена стратегии · смена модели оплаты (клики↔конверсии) · смена типа ограничения расхода (бюджет/цена/доля) · смена модели атрибуции · добавление/удаление целей · остановка рекламы **>7 дней**.

**ВЛИЯЕТ, но НЕ сбрасывает:** изменение суммы бюджета или целевой цены · массовое добавление ключевых фраз · массовая переписка объявлений · смена расписания · смена гео · смена состава конкурентов · новые площадки РСЯ.

Полная таблица с пояснениями — `references/strategies-learning.md`.

## Принцип «работает — не трогай»

Если CPA ≤ KPI и количество лидов достаточное — **ничего не менять**. Лучшее — враг хорошего: изменения сбрасывают/портят обучение. Оптимизировать нужно только то, что вышло за бенчмарк.

## Бенчмарки (шпаргалка)

| Метрика | Поиск | РСЯ |
|---------|-------|-----|
| CTR | **> 5%** (хорошо) | **< 2%**, идеально < 1% (>2% = скликивание) |
| % отказов | < 30% | < 40-50% |

- **Минимум для выводов:** 100 кликов за период (неделя); 50 кликов для решений по площадке; 15-20 для решения по запросу. На 1-3 кликах решений не принимать.
- **Обучение:** ≥10 конверсий/неделю на РК; полное обучение 2-3 недели; вес данных — за последние 7 дней.
- **Погрешность алгоритма:** 25 конверсий → ±40% по цене; 400 → ~10%; 10 000 → почти нет.
- **Минимальный недельный бюджет = средняя цена конверсии × 10.** CPA 2000 ₽ → бюджет ≥ 20 000 ₽/нед.
- Приложения в РСЯ (`af://`, `id://`) с CTR 30-100% → скликивание, **отключать немедленно**.
- Полный список цифр и формул — `references/benchmarks.md`.
