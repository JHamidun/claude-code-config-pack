# Modo: setup — Первый запуск

Разворачивает рабочий каталог `~/career-ops/`. Запускается автоматически, если каталога
нет или в нём не хватает ключевых файлов, и вручную по `/career-ops setup`.

**Правило режима:** ничего не выдумывать за кандидата. Пустое поле лучше правдоподобного —
дальше по нему считаются все оценки, и выдуманная вилка молча испортит каждый отчёт.

## Шаг 1. Структура каталога

```bash
mkdir -p ~/career-ops/{config,data,reports,output,jds,interview-prep,batch/tracker-additions}
```

Скопировать шаблоны из навыка (они лежат рядом, менять их в навыке не нужно):

```bash
cp ~/.claude/skills/career-ops/config/profile.example.yml   ~/career-ops/config/profile.yml
cp ~/.claude/skills/career-ops/config/portals.example.yml   ~/career-ops/portals.yml
cp ~/.claude/skills/career-ops/templates/states.yml         ~/career-ops/config/states.yml
```

> Примеров конфигурации порталов два, и они разные.
> `config/portals.example.yml` — актуальный: 10 сканеров, тот, что читают `modes/scan-*.md`. Бери его.
> `templates/portals.example.yml` — апстримовый вариант «слежу за списком компаний»
> (`tracked_companies` + careers_url каждой). Пригодится, если ты целишься не в рынок вообще,
> а в 20 конкретных работодателей; секции можно склеить в один файл.

Создать пустые рабочие файлы:

```
~/career-ops/data/applications.md   # шапка таблицы из modes/tracker.md
~/career-ops/data/pipeline.md       # пустой список «- [ ] <url>»
~/career-ops/data/scan-history.tsv  # пустой
~/career-ops/interview-prep/story-bank.md
```

Добавить в `~/career-ops/.gitignore`: `output/`, `jds/`, `data/scan-history.tsv` —
это генерируемое и объёмное.

## Шаг 2. CV

Спросить у кандидата, откуда взять резюме, тремя вариантами по убыванию точности:

1. **Файл** — путь к docx/pdf/md. Разобрать (`pdf` / `docx` навыки), сохранить как `~/career-ops/cv.md`.
2. **Текстом** — попросить вставить.
3. **Наговорить** — задать 8 вопросов и собрать CV из ответов: последние 3 места,
   что делал, чем измеряется результат, стек, образование, языки, локация, чего хочет дальше.

`cv.md` — источник правды. **Никогда не править его без явного разрешения** (см. Ethical Rules).

## Шаг 3. `config/profile.yml`

Заполняется вместе с кандидатом, поле за полем. Что спросить и почему это важно:

| Блок | Вопрос | Зачем |
|---|---|---|
| `candidate` | имя, почта, город, LinkedIn, портфолио | подставляется в PDF и в письма |
| `target_roles.primary` | 2-4 роли, на которые целишься | вся оценка A-F считается относительно них |
| `target_roles.archetypes` | какая роль мечта, какая «пойдёт», какая стретч | веса в скоринге |
| `narrative.exit_story` | почему уходишь / что ищешь дальше | первый абзац любого отклика |
| `narrative.proof_points` | 2-5 проверяемых результатов с цифрой | из них собираются STAR-истории |
| `compensation` | целевая вилка, минимум, валюта | Block D сравнивает оффер с этим, а не с рынком вообще |
| `location` | страна, таймзона, виза, готовность к офису | Remote-измерение скоринга |

**Проверка на выдумку:** каждый пункт `proof_points` должен быть подтверждаем ссылкой,
публикацией или человеком, который это помнит. Агент будет вставлять их в публичные тексты.

## Шаг 4. Порталы

Открыть `~/career-ops/portals.yml` и пройтись по сканерам: какие включить (`enabled: true`),
какие поисковые запросы поставить. Запросы — формулировки твоей роли так, как её пишут
работодатели, а не так, как ты называешь себя. Не знаешь — сначала `/career-ops analyze-skills`.

Ключи, которые нужны только части сканеров:

| Сканер | Что нужно | Где взять |
|---|---|---|
| `adzuna` | `ADZUNA_APP_ID`, `ADZUNA_APP_KEY` | https://developer.adzuna.com — free tier 250 запросов/день |
| `linkedin` | залогиненный браузер (cookies) | обычный логин; без него деградирует до WebSearch |
| `hh` | ничего | публичный API |
| `remoteok`, `wwr`, `aijobs`, `startupjobs` | ничего | открытые JSON/RSS |

Ключи класть в переменные окружения или в свой `.credentials.master.env`
(шаблон — `~/.claude/templates/.credentials.master.env.example`), **не в `portals.yml`**:
конфиг порталов не секретный и его удобно держать в git.

## Шаг 5. Знакомство

Короткий разговор, 5-7 вопросов, ответы дописать в `config/profile.yml` → `narrative`:

- что в работе даёт энергию, а что выжигает;
- на что не согласишься ни за какие деньги (график, домен, тип компании);
- где потолок по переезду и офису;
- что в резюме выглядит слабым местом и как ты сам это объясняешь;
- срочность: «горит» или «смотрю рынок».

Это не анкета ради анкеты: Block C (уровень и стратегия) и Block G (черновики ответов)
без этих ответов выдают усреднённое.

## Шаг 6. Проверка

```bash
node ~/.claude/skills/career-ops/verify-pipeline.mjs
```

Должен подтвердить: каталог есть, `cv.md` не пустой, `profile.yml` заполнен, трекер читается.
После этого можно `/career-ops scan`.
