## Зачем вообще server-side

Браузерный пиксель теряет события (консенсус курса, + раздел E operational_knowledge):
- блокировщики рекламы режут клиентские теги;
- iOS 14.5+ ATT обрезает доступ к событиям;
- удаление cookies ломает атрибуцию;
- длинный цикл сделки — глубокие конверсии (оплата, LTV) происходят вне веб-сессии, в CRM.

**Консенсус экспертной методологии (раздел E):** server-side GTM подключать однозначно, особенно если есть события вне веб-части (purchase). Даже с учётом потерь после iOS 14.5 это не повод не строить — наоборот: **«больше данных = лучше почва»** для обучения алгоритмов.

## Decision matrix: чем собирать server-side

| Решение | Что это | Когда выбирать | Порог входа |
|---------|---------|----------------|-------------|
| **Stape.io** | Хостинг для server-side GTM (managed) | Нужен server-side GTM без своего сервера/DevOps; быстрый старт | Низкий — платный SaaS, без кода |
| **GTM Server (self-managed на своём хостинге)** | Серверный контейнер Google Tag Manager на собственном сервере (GCP/VPS) | Есть DevOps, нужен контроль и экономия на масштабе, кастомные теги | Высокий — нужен инженер (→ `senior-devops`) |
| **Яндекс SSP / server-side через API Метрики** | Передача офлайн-конверсий и серверных событий в Метрику по Client ID | Российский стек, основной канал — Директ, нужны офлайн-конверсии в Метрику | Средний — связка Client ID + API Метрики |
| **Self-hosted эндпоинт (свой код)** | Собственный серверный приёмник событий → раздаёт в кабинеты | Нестандартная логика, объём, полный контроль | Высокий — кастомная разработка (→ `senior-devops`) |
| **No-code (Zapier / Make / n8n / Albato)** | Связка `CRM → no-code → Conversions API` без серверного контейнера | Нет разработчика, надо быстро гнать глубокие события из CRM в кабинеты | Низкий — см. `capi-no-code-setup` |

> Практическое правило курса: если нет инженера — начинать с no-code (`capi-no-code-setup`) или managed Stape. Self-hosted GTM-контейнер и кастомный эндпоинт — это уже задача для `senior-devops`, в `capi-no-code-setup` они явно вынесены за скоуп.

## [AnalyticsCompany] — сквозная аналитика под ключ

**Что это:** B2B SaaS сквозной аналитики «под ключ» — собирает архитектуру с учётом всех сессий и многопоследовательности касаний. Цена — **от ~$1k/мес**. Команда «пару месяцев всё разрабатывает» под клиента (до этого команда «жила в гугл-таблицах»).

- Вендор также развивает направление AI-систем и full-funnel-аналитики.
- Класс инструмента: «сервис сквозной аналитики» — средний из трёх эволюционных уровней систем (ручной Google Sheets → сервис такого класса → собственный DWH + BI). Подробно про 3 уровня — в `full-funnel-analytics-ru`.

> Где такой сервис в общей картине: это **готовая платформа сборки сквозной воронки**, альтернатива самописному DWH. Методология анализа (когорты, Predict LTV, 9 шагов еженедельного анализа, выбор атрибуции) живёт в `full-funnel-analytics-ru` и не зависит от того, собираешь ли ты данные в такой платформе, в Google Sheets или в своём DWH. Сам же сбор серверных событий (источник данных для любой из этих систем) — этот файл + `capi-no-code-setup`.
