# Определения performance-метрик (RU) + UTM-структура

> Источник: экспертная методология (поток N) — «Вводные в performance», «Семантика + Wordstat», «Метрика», full-funnel. Эталонные определения из методологии курса.
>
> Это словарь метрик и разметки трафика на русском, под российский performance-стек (Директ/Метрика). Бенчмарки конкретных каналов — в `ad-benchmarks-ru` и `references/benchmarks.md` каждого канального скилла. Когортная воронка целиком — в `full-funnel-analytics-ru`.

## Дерево метрик (воронка performance)

Базовая цепочка, по которой раскладывается любая платная кампания:

```
Расходы → CPM → Показы → CTR → Клики → CPC → Лендинг
       → CR1 / CPL → Лиды → CR2 / CPA / CPO → Оплаты → LTV → CAC
```

## Словарь метрик

| Метрика | Расшифровка | Формула | Что показывает |
|---------|-------------|---------|----------------|
| **CPM** | Cost Per Mille | Расход / показы × 1000 | Стоимость 1000 показов (цена охвата) |
| **CTR** | Click-Through Rate | Клики / показы | Кликабельность объявления |
| **CPC** | Cost Per Click | Расход / клики | Стоимость клика |
| **CR1** | Conversion Rate 1 | Лиды / клики (или визиты) | Конверсия трафика в лид |
| **CPL** | Cost Per Lead | Расход / лиды | Стоимость лида |
| **CR2** | Conversion Rate 2 | Оплаты / лиды | Конверсия лида в оплату |
| **CPA** | Cost Per Action | Расход / целевые действия | Стоимость целевого действия |
| **CPO** | Cost Per Order | Расход / заказы | Стоимость заказа |
| **CPQL** | Cost Per Qualified Lead | Расход / квал-лиды | Стоимость квалифицированного лида |
| **AOV** | Average Order Value | Выручка / число заказов | Средний чек |
| **LTV** | Lifetime Value | Сумма выручки с клиента за всё время | Сколько денег приносит клиент |
| **CAC** | Customer Acquisition Cost | (Маркетинг + продажи) / новые клиенты | Стоимость привлечения клиента |
| **CPA vs CAC** | — | CPA = за действие; CAC = за оплатившего клиента | Не путать: CPA шире (любое действие), CAC = именно покупатель |
| **ROMI** | Return On Marketing Investment | (Выручка − Расход) / Расход × 100% | Окупаемость маркетинга (учитывает только маркетинг-затраты) |
| **ROAS** | Return On Ad Spend | Выручка / рекламный расход | Окупаемость именно рекламного бюджета |
| **CR** | Conversion Rate | Целевые действия / общее число | Конверсия любого шага |

### ROMI vs ROAS — в чём разница

- **ROAS** = выручка / рекламный расход. Считает «сколько рублей выручки на рубль рекламы». ROAS 3 = 300% = ₽3 на каждый ₽1 рекламы.
- **ROMI** = (выручка − все маркетинг-затраты) / маркетинг-затраты × 100%. Шире: включает не только рекламу, но и зарплаты, инструменты, сервисы. ROMI учитывает прибыль, а не только валовую выручку.

> Метрики оценки результата по типу бизнеса (по экспертной методологии / мастермайнду):
> - **E-com**: ROMI, ROAS, LTV, CAC, AOV, CR в оплату. Лучшая команда = низкий CAC + высокий ROMI/ROAS при объёмах.
> - **Лидген**: дополнительно CR из лида в квал-лид, CPQL.

## Поведение покупателя: касания

- **40-80+ рекламных касаний в день** получает каждый пользователь (экономика внимания). В разных уроках называется «80+», базовый ориентир — несколько десятков касаний в сутки.
- **5-7 касаний** требуется в среднем на одну покупку. Поэтому одноразовый показ почти не конвертит — нужна частотность и многоканальность.
- Следствие: оценивать канал по «последнему клику» в отрыве от цепочки касаний некорректно (см. `attribution-models-direct.md`).

## UTM-структура

Стандарт разметки ссылок. Пять обязательных параметров + динамические:

| Параметр | Назначение | Пример |
|----------|------------|--------|
| `utm_source` | Источник трафика | `yandex`, `google`, `vk`, `telegram` |
| `utm_medium` | Тип трафика / канал | `cpc`, `cpm`, `email`, `social` |
| `utm_campaign` | Название кампании | `spring_sale`, `academy_launch` |
| `utm_term` | Ключевая фраза | `kupit_kurs`, `{keyword}` |
| `utm_content` | Различение объявлений/креативов | `banner_a`, `text_v2`, `{ad_id}` |

### Динамические параметры (подстановки Яндекса)

Подставляются автоматически на лету — не нужно прописывать руками для каждого объявления:

| Параметр | Что подставляет |
|----------|-----------------|
| `{campaign_id}` | ID кампании |
| `{ad_id}` / `{banner_id}` | ID объявления |
| `{keyword}` | Ключевая фраза, по которой показалось |
| `{source}` | Площадка показа (в РСЯ — домен) |
| `{device_type}` | Тип устройства |
| `{region_name}` | Регион показа |
| `{phrase_id}` | ID фразы |

Использование динамических параметров в `utm_term`/`utm_content` позволяет в Метрике разрезать трафик по ключам, площадкам, устройствам и регионам без ручной разметки каждого объявления.

> UTM-метки склеиваются с **целями** Метрики (автоцели vs JS-события — см. `attribution-models-direct.md`), и именно на этой связке работает атрибуция и обучение автостратегий.
