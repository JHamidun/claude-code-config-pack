# План аналитики (RU) — события + цели под твою воронку

Порт `analytics` (event-library + tracking-plan) из marketingskills, переложенный на **Яндекс Метрику** (вместо GA4/GTM) под типовую воронку. Сначала опиши свою воронку (что и где захватывается) — какие точки входа, какие шаги прогрева, где деньги.

## Принцип

Меряем ради решений, не ради данных. Сначала вопрос («двигается ли человек из блога в продукт?»), потом событие. Имена консистентны: `object_action`, нижний регистр, подчёркивания (`trial_started`, `consultation_requested`). Без PII в параметрах (152-ФЗ).

## Свопы инструментов (Запад → RU)

| Запад | RU | Чем дёргать |
|-------|----|-------------|
| GA4 события | **Метрика: «достижение цели»** (тип JavaScript-событие `ym(ID,'reachGoal','goal_id')`) | `yandex` (Метрика API) |
| GA4 custom dimensions | **Параметры визита/пользователя** Метрики (`params`, `userParams`) | `yandex` |
| GTM | Метрика-счётчик + `reachGoal` в коде, либо GTM как контейнер (Метрика-тег) | — |
| UTM (utm_source/medium/...) | **те же UTM** — Метрика их парсит штатно | `yandex` |
| Conversions | **Цели Метрики** (помечаются в настройках счётчика) | `yandex` |
| Mixpanel/Amplitude product analytics | Метрика + собственные события в БД; mobile — AppMetrica | `yandex`, свой аналитический скрипт |

UTM-конвенции: нижний регистр, дефисы/подчёркивания консистентно, описательно (`blog_inline_cta`, не `cta1`). Реестр UTM — в таблице (`xlsx`/`gsheets`).

## Цели Метрики по воронке (что настроить)

Привязка к стадиям твоей воронки. Реализация целей и параметров — через `yandex`; сегменты (например, B2B-компании vs частные лица) и продуктовые воронки — через свой аналитический слой/дашборд.

### TOP (охват, контент/блог/лид-магниты)

| Цель (goal_id) | Что считает | Параметры | Триггер |
|----------------|-------------|-----------|---------|
| `newsletter_subscribed` | подписка на рассылку | `lang`, `source` | submit формы → `POST /api/subscribe` ок |
| `tg_bot_started` | старт твоего бота | `source` | переход + /start (трекать на стороне бота) |
| `lead_magnet_downloaded` | скачан лид-магнит | `magnet_name` | клик скачивания /materials |
| `blog_read` | дочитал статью блога | `slug`, `scroll>=75` | scroll-depth 75% |
| `content_to_product_click` | **клик сквозного CTA из контента в продукт** (закрывает главный разрыв воронки) | `placement` | клик CTA в блоге/контенте |

### MIDDLE (прогрев, продукт/консультация)

| Цель | Что считает | Параметры | Триггер |
|------|-------------|-----------|---------|
| `product_landing_viewed` | визит лендинга продукта | `source` | pageview |
| `trial_started` | старт trial (например, 7 дней без карты) | `plan`, `source` | успешная регистрация trial |
| `consultation_requested` | заявка на бесплатную консультацию (B2B) | `source` | submit формы /services /workshop |
| `call_scheduled` | назначен созвон | — | CRM-стадия call_scheduled |
| `workshop_lead` | заявка на формат воркшопа | `format` | submit формы /workshop |
| `webinar_subscribed` | запись на вебинар | `webinar` | submit |

### BOTTOM (деньги, платёжный провайдер)

| Цель | Что считает | Параметры | Триггер |
|------|-------------|-----------|---------|
| `plan_selected` | выбран тариф | `plan` (basic/plus/pro) | клик тарифа |
| `payment_completed` | оплата подписки/курса | `plan`, `value`, `currency=RUB` | webhook платёжного провайдера ок |
| `trial_converted` | trial → платная | `plan` | смена статуса в CRM/БД |
| `flagship_purchased` | покупка флагманского продукта | `tier` (solo/group/1to1) | оплата |
| `addon_added` | подключён доп. модуль/услуга | — | оплата add-on |
| `enterprise_handoff` | горячий enterprise → менеджеру | — | `handoff_to_sales` |

## Метрики воронки, которые реально важны (а не vanity)

| Стадия | Ключевая метрика | Где смотреть |
|--------|------------------|--------------|
| TOP | новые подписчики рассылки/бота; CTR из контента в продукт | БД контент-площадки (`newsletter_subscribers`,`users`) + Метрика |
| MIDDLE | trial-старты; заявки на консультацию; trial → paid % | продуктовая БД (`leads`,`meetings`) + Метрика цели |
| BOTTOM | оплаты, MRR, средний чек; конверсия лендинга продукта | БД продаж + платёжный провайдер + свой аналитический слой |
| Сквозное | стоимость лида по источнику; путь из контента в продукт | Метрика (UTM) + CRM-атрибуция |

North Star подбирай под продукт (для обучающего продукта — активные обучающиеся / завершённые треки; для SaaS — активные подписки; см. `metrics-tracking`). Бенчмарки каналов (email open/CTR, paid ROAS/CPA, SEO) — в основном SKILL.md этого скилла.

## Источники данных (НЕ дублировать — звать существующее)

| Нужно | Скилл / источник |
|------|------------------|
| Цели/параметры/трафик Метрики | `yandex` (Metrika API) |
| Сегменты (B2B/частные), воронки, дашборды | свой аналитический слой / BI |
| метрики контент-площадки (подписчики, бот, push) | БД контент-площадки (см. описание воронки) |
| продукт/продажи/CRM | продуктовая БД + твоя CRM (раздел «Учёт и аналитика» в `~/.claude/business-context.md`) |
| отчёт в таблицу | `xlsx`, `gsheets` |

## Чеклист валидации (на стеке Метрики)

- [ ] Цели срабатывают на нужном триггере (проверить в «Конверсии» Метрики)
- [ ] Параметры (`plan`, `source`, `lang`) приходят корректно
- [ ] Нет дублей событий (двойной счётчик / двойной reachGoal)
- [ ] Работает на мобайле (большая доля RU-трафика)
- [ ] UTM сохраняются и видны в Метрике
- [ ] Нет PII в параметрах (152-ФЗ); согласие на обработку получено

## Комплаенс (152-ФЗ / 38-ФЗ)

Согласие на обработку перс. данных, данные в РФ, маркировка рекламных коммуникаций (см. `ru-localization.md`). Не складывать email/телефон в параметры событий Метрики — только агрегаты и идентификаторы без PII.
