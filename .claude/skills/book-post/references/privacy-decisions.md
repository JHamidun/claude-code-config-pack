# PRIVACY DECISION TREE — шаблон

> **Что это.** Решения автора о том, что в книге можно называть своими именами, а что нельзя.
> Навык `book-post` читает этот файл перед каждой главой и сверяет с ним готовый текст.
>
> **Почему шаблон пустой.** Эти решения принимает человек, который отвечает за книгу.
> Модель их принять не может: она не знает, кто дал согласие, что уже опубликовано,
> что защищено договором и с кем автор ещё будет работать после выхода книги.
>
> **Когда заполнять.** До первой главы. Правки задним числом («уберём фамилию на вычитке»)
> не работают: к моменту вычитки текст уже прошёл через субагентов, логи и черновики.
>
> **Как пользоваться.** Файл не перезаписывается при обновлении пака только если лежит
> вне навыка. Заполненную версию держи рядом с книгой: `$BOOK_ROOT/PRIVACY.md`,
> а здесь оставь шаблон. Навык ищет сначала `$BOOK_ROOT/PRIVACY.md`, потом этот файл.

---

## 1. Кого можно называть прямо

Люди, которые **дали согласие** или чьё участие уже публично (публичное выступление,
их собственный пост, пресс-релиз). Для каждого — чем именно подтверждается.

| Имя | Роль в книге | Чем подтверждено согласие | Что о нём можно, что нельзя |
|---|---|---|---|
| [Имя Фамилия] | [соучредитель / коллега / герой сцены гл. N] | [устное согласие 00.00.0000 / публичный доклад / его пост] | [можно: роль и рабочий эпизод; нельзя: семья, здоровье, деньги] |
| | | | |

**Правило по умолчанию, если строки в таблице нет:** называть нельзя. Не «наверное, он не
против» — либо согласие есть и записано здесь, либо человек анонимизируется.

## 2. Кого анонимизировать и как именно

Замена должна быть **устойчивой**: один и тот же человек по всей книге называется одинаково,
иначе читатель считает их разными людьми, а внимательный — наоборот, вычислит по деталям.

| Кто | Как называем | Что снимаем помимо имени |
|---|---|---|
| [клиент, с которым NDA] | «крупный B2B-клиент из [отрасль]» | город, размер команды, срок проекта — по ним узнают |
| [коллега] | «коллега из соседней команды» | должность, если она в компании одна |
| | | |

**Деанонимизация по деталям — главная ошибка.** «Компания на 200 человек из Казани,
делающая доставку» — это адрес, а не анонимность. Проверка: убери имя и спроси себя,
сколько компаний подходит под остаток описания. Меньше пяти — описание всё ещё называет.

## 3. Клиенты и работодатели — блок-лист

Названия, которые не должны попасть в текст **ни в одной версии**, включая черновики
и промпты субагентов.

```
[ЗАПРЕЩЕНО НАЗЫВАТЬ]
- [Клиент А]
- [Клиент Б]
```

Разрешено называть (публичные кейсы, пресс-релизы, согласованные référence-истории):

```
[МОЖНО]
- [Компания] — основание: [ссылка на публичный кейс]
```

## 4. Цифры

Самая частая утечка в нон-фикшн — не имя, а цифра: по выручке и числу клиентов
восстанавливается всё остальное.

**Можно (публичные, названы самим автором или компанией публично):**

| Цифра | Где уже опубликована |
|---|---|
| [например: число пользователей продукта] | [ссылка/выступление] |

**Нельзя:**

- выручка, маржа, привлечённые инвестиции и оценки, если о них не объявляли публично;
- внутренние HR-цифры (зарплаты, увольнения, численность по отделам);
- цифры клиентов — даже без названия клиента, если клиент по ним узнаётся;
- слухи и «по ощущениям» — они выглядят как факт и опровергаются первым же читателем изнутри.

## 5. Автор и его семья

| Тема | Решение |
|---|---|
| Город / страна проживания | [называем прямо / только страна / не называем] |
| Дом, район, распорядок дня | [из ANCHORS.md или не пишем вовсе] |
| Дети — имена и возраст | [не называем / имя без возраста / с согласия] |
| Партнёр, родители | [решение] |
| Здоровье, финансы, конфликты | [обычно: не пишем] |

Про детей стоит помнить отдельно: имя плюс возраст плюс город — это идентификатор,
и он останется в книге на годы вперёд, когда ребёнок вырастет и не сможет это отозвать.

## 6. Что делать при сомнении

1. Не решать самостоятельно и не «смягчать формулировку» — спросить автора.
2. Пометить место в черновике `<!-- PRIVACY: нужно решение -->` — редактор не пропустит.
3. Пока решения нет — писать качественно, без имени и без цифры. Текст от этого
   почти не теряет: читателю важна механика, а не фамилия.
