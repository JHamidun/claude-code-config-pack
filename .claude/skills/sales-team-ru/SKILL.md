# Sales Team (RU) — отдел продаж под ключ + AI-разбор звонков

Исполняемый playbook **отдела продаж как команды**: найм продавцов, контроль эффективности, мотивация, AI-разбор звонков. Скилл не «рассказывает про продажи», а **производит артефакты**: план найма, отчёт аудита ОП, расчёт схемы мотивации, спецификацию AI-разбора.

**Чем этот скилл НЕ является (не дублировать):**
- `sales-enablement-ru` — sales-**материалы** (питч-деки, one-pager, демо-скрипты, battle-card). Здесь — **команда** и **процесс**, а не коллатерал.
- `revops-ru` — стратегия lead lifecycle, MQL/SQL, hand-off marketing→sales. Здесь — **ежедневная операционка ОП** (планёрки, нормативы, мотивация, ротация).
- `full-funnel-analytics-ru` — сквозная когортная аналитика, атрибуция, Predict LTV. Здесь — метрики **внутри ОП** (дозваниваемость, SLA, выработка, talk-to-listen).

## Когда использовать

- «Надо нанять сейлзов / построить отдел продаж с нуля / масштабировать ОП под план роста» → режим **A. Найм**.
- «Проверь наш отдел продаж / почему падает конверсия ОП / наведи порядок в продажах / у нас перелидоз» → режим **B. Аудит**.
- «Посчитай мотивацию сейлзов / РОПа, пересобери бонусную схему, сейлзы не бьются за план» → режим **C. Мотивация**.
- «Настрой AI-разбор звонков / оцени качество звонков / talk-to-listen / тренажёр для сейлзов» → режим **D. AI-разбор**.
- «Напиши/почини скрипт продаж, отработку возражений» → часть 3 + `references/scripts.md` (артефакт — скрипт по структуре B2C/B2B).

## Принципы (ядро методологии, не выдумывать)

- **«В сейлз всё начинается с найма».** Слабый менеджер ломает любую систему — скрипты, CRM, AI это не починят.
- **Найм продавца = маркетинг на кандидата.** Та же логика: кастдев ЦА → УТП → продающий лендинг → тест каналов трафика.
- **«Усиливать сильное»** (правило из го / Сунь-Цзы): лучшие лиды — лучшим сейлзам.
- **Опережающие метрики > конверсии.** Конверсия — **поздняя** метрика, когда месяц кончился — поздно. Управляй ролёвками, выработкой, SLA, talk-to-listen.
- **Армейская дисциплина.** ОП ближе всего к армии: ежедневные построения (планёрки), нормативы, публичное порицание, ротация.
- **Возражение «дорого» = недостаточная ценность.** Не скидка, а усиление ценности/якорь.
- **AI убирает рутину, не человека.** Финальное закрытие, доверие, сложные кейсы — за человеком.

## Процедура

**Шаг 0. Определи режим** по запросу пользователя:

| Запрос | Режим | Артефакт на выходе |
|---|---|---|
| Нанять / построить / масштабировать ОП | **A. Найм** | План найма ОП |
| Проверить / починить / «конверсия падает» | **B. Аудит** | Отчёт аудита ОП |
| Мотивация / бонусы / квоты | **C. Мотивация** | Расчёт схемы мотивации |
| AI-разбор / качество звонков / тренажёр | **D. AI-разбор** | Спецификация AI-пайплайна + шаблон отчёта по звонку |

**Шаг 1. Собери входы.** Продукт, чек, сегмент и экономика лежат в `~/.claude/business-context.md` (разделы «Продукт», «ICP», «Цены», «Экономика», «Воронка») — прочитай его первым. Файла нет — заведи из `~/.claude/templates/business-context.md`; без него нормативы и схема мотивации будут посчитаны от выдуманной маржи, а это прямой перерасход фонда оплаты. Чего в файле нет — спроси, не выдумывай:

- Продукт, средний чек, B2C или B2B, цикл сделки — из `business-context.md`.
- Текущая команда: сколько сейлзов, есть ли РОП(ы), CRM.
- Объём лидов/день и план выручки (месяц).
- Для режима B — доступные факты: конверсия, дозваниваемость, SLA, отток, как устроена мотивация сейчас.
- Для режима C — текущий фикс/бонус, план на сейлза, маржинальность (какой % выручки можно отдавать в бонус).

**Шаг 2. Примени framework из references** (по режиму):

- **A. Найм** → `references/hiring.md`: компании-доноры → лендинг вакансии → 2 канала трафика → групповое интервью (5 чел, ролёвка, 2 оценщика по баллам) → оплачиваемый тест 2 недели (цель — 2 оплаты) → онбординг (база знаний + тренер). Посчитай сроки от плана: цикл найма ~1 месяц → старт поиска = дата потребности − 1 мес.
- **B. Аудит** → `references/control-metrics.md`: пройди «чек-лист аудита ОП» (ниже) пункт за пунктом, для каждого зафиксируй факт vs норматив (120/120, дозваниваемость ≥40%, ≤12 лидов/день/сейлза, NPS ≥3.5, ротация 20%/мес и т.д.), пометь статус и напиши рекомендацию с приоритетом.
- **C. Мотивация** → `references/control-metrics.md` (раздел мотивации): недельные квоты (месячный план ÷ 4), прогрессивная шкала 3/5/9% (80–100% / 100% / 110%+ плана), выплаты сразу после закрытия недели, период вторник→понедельник, фикс/бонус 30/70, миксованная схема РОПа (недельные квоты + право догнать в месяце, премия при 80–100% плана команды), резерв «вертолётных денег». Подставь реальные цифры клиента и проверь юнит-экономику (бонусный фонд ≤ маржа).
- **D. AI-разбор** → `references/ai-call-analysis.md` + `references/scripts.md`: этапы звонка → 19 критериев → talk-to-listen (порог: менеджер >60% времени = плохо) → стек (Deepgram транскрипция → LLM-анализ → отчёт в CRM/мессенджер) → AI-симуляция клиента для тренировки слабого этапа.

**Шаг 3. Сгенерируй артефакт** по шаблону из раздела «Выход». Все цифры — либо из входов пользователя, либо нормативы методологии (тогда помечай «норматив»). Не смешивай факт и норматив без пометки.

**Шаг 4. Проверь по чек-листу качества** (внизу) и отдай артефакт. Если данных не хватило и есть допущения — вынеси их отдельным блоком «Допущения» в конце артефакта.

## Выход

### A. План найма ОП (шаблон)

```markdown
# План найма отдела продаж — [YourProduct]
Цель: N сейлзов к [дата] под план [X ₽/мес]. Старт поиска: [дата − 1 мес на цикл найма].

| # | Этап | Что делаем | Срок | Ответственный |
|---|------|-----------|------|---------------|
| 1 | Компании-доноры | Список 10–20 компаний ниши, где работают сильные сейлзы | нед. 1 | [эксперт]/HR |
| 2 | Оффер | Фикс+бонус на +15–20% выше рынка доноров + челлендж (рост/кейс) | нед. 1 | Фаундер |
| 3 | Лендинг вакансии | Продающая страница: УТП по болям кандидатов, миссия, упаковка выплат | нед. 1–2 | Маркетинг |
| 4 | Каналы | 2 канала (группы удалённой работы + платное промо в проф-сети), замер стоимости отклика | нед. 2+ | HR |
| 5 | Групповое интервью | 5 кандидатов: «60 сек о себе» + ролёвка ~7 мин с возражением; 2 оценщика, баллы по чек-листу | нед. 3+ | РОП + HR |
| 6 | Оплачиваемый тест | 2 недели на отказниках/старых лидах; цель — 2 оплаты (B2B — дольше) | нед. 4–5 | РОП |
| 7 | Онбординг | База знаний (CRM, продукт, FAQ) + тренер: ролёвки, совместная прослушка | с выхода | Тренер |

Воронка найма (план): откликов → интервью → тестовых → офферов → вышло.
Допущения: …
```

### C. Расчёт схемы мотивации (шаблон)

```markdown
# Схема мотивации ОП — [ClientCo]
Вход: план X ₽/мес на сейлза, чек Y ₽, фикс Z ₽ (правило 30/70: фикс ≈ 30% целевого дохода).

## Сейлз (недельная, период вт→пн, выплата сразу после закрытия недели)
Недельная квота = X ÷ 4 = … ₽.
| Выполнение недельной квоты | % от выручки | Бонус при квоте … ₽ |
|---|---|---|
| <80% | 0% | 0 ₽ |
| 80–100% | 3% | … ₽ |
| 100–110% | 5% | … ₽ |
| ≥110% | 9% | … ₽ |
Целевой доход сейлза при 100%: фикс + бонус = … ₽/мес. Проверка: бонусный фонд … % выручки ≤ маржа.

Премия при 80–100% плана команды; недельные квоты с правом «догнать» в месяце

## Резерв краткосрочной мотивации
«Вертолётные деньги»: ~$200–300/сейлз/мес заложено; РОП точечно объявляет спринты
(«N целевых действий сегодня → бонус/ужин»).
Допущения: …
```

### D. Спецификация AI-разбора звонков

Артефакт = спецификация пайплайна (стек, этапы, критерии, пороги TLT) + шаблон отчёта по звонку в карточку CRM. Скелет — в `references/ai-call-analysis.md`.

## Пример

**Вход:** «B2C-онлайн-школа, 8 сейлзов, чек 60 000 ₽, план 6 млн ₽/мес, конверсия из лида упала с 9% до 6%, лидов ~120/день. Проверь отдел». → Режим **B. Аудит**.

**Выход (фрагмент отчёта):**

| Блок | Норматив | Факт | Статус | Рекомендация |
|---|---|---|---|---|
| Перелидоз | ≤12 лидов/день/сейлза | 120/8 = **15** | 🔴 | P1: либо −20% лидов, либо +2 сейлза; дейлик маркетинг↔продажи, расписание линии на неделю |
| Мотивация | недельная 3/5/9% | месячная, 5% плоско | 🔴 | P1: перевести на недельные квоты 187,5К ₽ (750К÷4), шкала 3/5/9%, выплата после закрытия недели вт→пн |
| Дозваниваемость | ≥40% | не трекается | 🟡 | P2: включить трекинг + SLA от минуты заявки |

**Топ-проблема:** перелидоз (15 > 12) объясняет падение конверсии — у сейлза меньше времени на клиента. **Допущение:** конверсия по всем каналам однородна (нет данных по A/B/C-лидам).

Такой заполненный отчёт целиком = «готово».
