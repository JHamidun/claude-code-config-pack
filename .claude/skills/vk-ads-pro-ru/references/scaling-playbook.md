# Масштабирование и оптимизация VK Ads

Фреймворк системной работы на этапе оптимизации. Главная идея — не интуиция, а накопление достоверных **зацепок** и их применение ко всем новым сегментам.

**Главное правило:** дорогие срезы исключаем, дешёвые масштабируем (на другие возраст / пол / гео / креативы). Анализ на трёх уровнях: **кампания → группа → объявление**.

---

## Фреймворк системной оптимизации (6 шагов)

```
Шаг 1: Сбор зацепок после первого запуска
  — Сравнить группы МЦ и ПЦ на каждый сегмент
  — Выделить зелёным группы с результатом НИЖЕ KPI
  — Зафиксировать: какие сегменты / пересечения / возраста работают

Шаг 2: Проверка зацепок на других категориях
  — Прежде чем масштабировать — подтвердить зацепку на 2-3 разных категориях
  — Только после подтверждения → использовать как базовое правило для всех тестов

Шаг 3: Оптимизация по демографии
  — Статистика → Демография → Результат
  — Отключить возрасты с дорогим результатом (выше KPI более чем в 2 раза)
  — Добавить смежные возраста для теста

Шаг 4: Оптимизация ключевых фраз
  — Скачать отчёт по фразам в Excel
  — Сортировать по цене результата
  — Дорогие отключить, дешёвые масштабировать
  — Неочевидные искать Методом ИИ (см. creative-testing-methods.md)

Шаг 5: Выбор лучшего креатива
  — Определить победителя через метод четвёрок
  — (в группе ПЦ могут выиграть 2-3, в МЦ — 1-4)

Шаг 6: Масштабирование
  — Лучший сегмент × Лучший креатив → новые возраста
  — Лучший сегмент × Лучший креатив → новые ключевые фразы
  — Лучший сегмент × Лучший креатив → новые пересечения аудиторий
  — При исчерпании идей → пересоздать кампанию (см. лайфхаки)
```

## Способы масштабирования

### Через креативы
Несколько разных **групп креативов** на лучшие сегменты.

### Через возраст
Берём лучшую связку «аудитория + креатив», добавляем смежные возрастные группы (кейс: к лучшему 40-44 добавили 35-39).
- Результат **у KPI** → новый «ручеёк» лидов.
- Результат **выше KPI** → новая зацепка → тестируем дальше.

### Через время суток (времязависимые зацепки)
- Берём лучшую связку и тестируем на разное время.
- Кейс: GetCourse + **ночные часы (до 12:00)** = 122 ₽ при KPI ~100 ₽.
- Связка с «учётом местного времени» — `schedule-localtime.md`.

### Через другие аудиторные пересечения
Аудиторию-обогатитель (Сэндлер, GetCourse) пересекаем с разными приложениями/сегментами. Тройной тест `A∩B / A−B / B−A` для каждой связки.

### Через увеличение дневного лимита (ОСТОРОЖНО)
> ⚠️ Если в группе отключили плохие объявления, весь бюджет группы уходит на оставшееся → может **«сломать»** его.
- **Решение:** снизить лимит группы до **среднесуточного на одно объявление**, поднимать **постепенно**, наблюдая стабильность.

### Через вычерпывание ключевых фраз
- Аудитория по ключевым фразам обновляется через **7 дней** (цикл — понедельник).
- Ставь лимиты так, чтобы аудитория успевала **полностью вычерпаться** и обновиться к следующему циклу — иначе теряешь трафик.

### Лайфхак refresh: пересоздание кампании/группы
- Идентичная кампания в **другой день / время суток** обучается на другой доступной аудитории → другой результат от того же креатива+аудитории.
- Цитата: «Алгоритмы обучаются на той аудитории, которая доступна в данный момент. Создаёте даже одинаковую кампанию в другой день и время — она обучается на других данных и показывает другой аудитории».
- VK может не дать запустить **полные дубли** → меняй пару символов (знак препинания) → воспринимается как новое объявление.
- ⚠️ Перезапуск когда-либо остановленной кампании стартует **все группы и объявления, включая выключенные** — ревизия статусов перед стартом (`vk-bugs-2026.md`).

### Через плейсменты (во вторую очередь и по отдельности)
- Причина «только лента» техническая: **в кабинете нет разреза статистики по плейсментам** — смешав ленту с проектами VK и рекламной сетью, получишь неразделимую среднюю цену из дорогого и дешёвого и потеряешь рычаг сегментации.
- В других плейсментах объявления физически другие: длинные, узкие, нестандартной ширины, мелкий текст, перекрытие элементами интерфейса.
- ОК и партнёрскую сеть масштабировать **отдельными кампаниями**, каждую по отдельности. Цена клика и цена лида там не коррелируют — бывает и наоборот.

### Ритм масштабирования
- **Тест новых креативов идёт параллельно** масштабированию найденной связки, а не после её выгорания — к моменту выгорания уже должны быть наработки.
- Порядок при упоре в потолок: **сначала менять креатив, потом оффер**.

### Цель масштабирования — несколько ручейков, а не один (VK-3, авг. 2026)

Ответ на возражение «связка сломалась, а статистику собрать не успели»:

- Задача — **несколько параллельных связок**, диверсифицирующих трафик. «Даже если одна связка сломается, все сразу могут сломаться, только если ВКонтакте что-то сломает. Если говорить о поведении людей — все сразу, скорее всего, не сломаются».
- **Не выключать связку при первом же выходе за KPI.** «Если они пару дней выбиваются из KPI, можно потерпеть — средняя цена лида из-за этого сильно не вырастает, они потом часто, если хорошо собраны, возвращаются к своей предыдущей цене». Альтернатива выключению — «дать им просто ещё подышать» или починить/докрутить.
- Твёрдая связка = **три-четыре целевых свойства сразу**. Пример из разбора студии: отсечены ненужные возрасты + оставлен самый конверсионный 30–40 + геоточка + ключевые фразы. «Это люди не те, кто интересуется фастфудом. Они живут рядом и **прямо сейчас** начали интересоваться фитнесом».
- Против выгорания работают **обновляемые аудитории**: ключевые фразы (новая порция каждый понедельник) в первую очередь; категории интересов — тоже, но шире и грубее, поэтому их обязательно ограничивать возрастом, гео, полом и соцхарактеристиками.
- Отдельная ветка масштабирования победившей связки: **ретаргетинг на тех, кто кликал в других группах, но не сконвертил** — интерес проявили, форму не оставили.

## «Аудитория каждый раз собирается по-разному» — самый длинный разбор VK-3

Возражение практика с открутом **~1,5 млн ₽/мес** (корпусная мебель, кухни), занявшее треть занятия. Формулируется как тупик, и его стоит держать целиком, потому что каждый пункт возражения получил отдельный ответ.

**Что описывает практик:**

- одна и та же связка (текст, оффер, город, аудитория) то работает, то не работает;
- ВК «постоянно что-то оптимизирует»: то ключи отвалятся, то категории интересов, то всё сразу;
- ключи сужаешь — не запускается, расширяешь обратно — возвращается прежний разброс;
- один креатив тащит и людей с бюджетом на кухню 200 000, и с бюджетом 500 000 — «все замешаны в единый котёл»;
- **эксперимент не воспроизводится**: «мы не можем 2, 3, 4, 5 раз сделать одно и то же, чтобы оно дало такой результат» → нельзя доказать, что сработала именно введённая настройка;
- нашли «одну палочку» — набор креативов с повторяемым результатом, ниже рынка и конвертируемым, — но перенести его в другой такой же город не получается.

**Ответы эксперта, по порядку:**

| Пункт возражения | Ответ |
|---|---|
| «ВК пересобирает аудиторию» | «Мы с этим ничего поделать не можем — выносим за скобки». Работать с тем, что управляемо |
| «Один и тот же креатив то работает, то нет» | Это норма, а не поломка: «люди абсолютно разные, в разном состоянии увидели рекламу в разный момент: кто-то домой ехал, кто-то бежал, кто-то ругался». Отсюда — **всегда запускать по несколько креативов**: «в одном случае один работает, в другом другой, какими бы классными они ни были» |
| «Хочу, чтобы алгоритм отделил дорогие чеки от дешёвых» | Передавать **офлайн-конверсии / данные CRM** и оптимизировать по ним. Но: алгоритму на обучение нужно **10–15 конверсий**, а на кухнях за 500 000 это дорого — значит **отсекать руками**, а не ждать обучения (`bid-strategies.md`) |
| «Лид-форма = битый номер» | Три обхода, `lead-forms.md` |
| «Нельзя повторить результат → нельзя проверить гипотезу» | Сравнивать надо **не два запуска во времени, а две одновременные группы** с разными ID и одинаковыми креативами. Различие в результате и есть ответ; как разделилась аудитория внутри — не важно (`krestinin-methods.md` → соцхарактеристики) |
| «Аудитория выгорает раньше, чем накопится аналитика» | **Вечные (обновляемые) аудитории**: ключевые фразы с обновлением каждый понедельник в первую очередь; категории интересов — тоже, но обязательно ограниченные возрастом, гео, полом и соцхарактеристиками |
| «Куда бить, чтобы вылезти из этого» | Не в новую связку, а **вглубь сработавшей**: «дальше её копать» — заголовок, длина видео, плейсменты, форматы |

**Отдельная гипотеза под этот кейс (дословно у спикера — «навскидку»):** запустить **ретаргетинг на посетителей сайта, куда льётся Яндекс.Директ**, исходя из того, что Директ приводит людей с большими чеками, но закрываются не все — догревать их ВКонтакте. Оговорка тут же: «это правда, маленький объём будет».

**Честная граница ответа:** «Без конкретных цифр больше ничего не могу сказать» + «надо погружаться в проект, что вы делаете, что вы не делаете». Универсального рецепта на это возражение спикер не дал.

## Как выбирать между видео, когда лидов слишком мало

Из разбора кабинета: в лучшей группе осталось **одно** видео — таргетолог прогнал Видео 1 / 2 / 3, третье дало **первый** лид, и решение приняли по нему. Оценка эксперта: «по одному лиду, наверное, не совсем правильно делать выводы».

Чем добирать сигнал, пока конверсий мало, — вторичные метрики в той же таблице:

- **CTR** объявления;
- **начало просмотра** видео;
- **процент досмотра** (в кабинете есть настройка вывода процента просмотра).

То же правило и на старте работы с агентством: при почти нулевых конверсиях первым признаком «попал / не попал» служит CTR (`benchmarks.md` → тестовые бюджеты).

## Работа с Excel-отчётами

В кабинете VK анализ неудобен (плохая наглядность) → выгружаем в Excel/Sheets:

```
1. Скачать отчёт из кабинета VK Ads
2. Открыть в Excel / Google Sheets
3. Добавить столбец «Цена результата» = расход / количество результатов
4. Сортировать по: гео, возрасту, ключевым фразам
5. Топ-сегменты по цене → вынести в ОТДЕЛЬНЫЕ кампании
```

## Сравнение МЦ vs ПЦ

- Каждый сегмент тестируется в **двух группах**: минимальная цена (МЦ) и предельная цена (ПЦ).
- Нельзя заранее сказать, какая лучше — зависит от сегмента (для одних выигрывает ПЦ, для других МЦ).
- Это **первый шаг масштабирования**: дубль группы → разные стратегии → сравнить через 3-5 дней.

## Правила бюджета (сводка)

| Ситуация | Действие |
|----------|----------|
| Отключили плохие объявления в группе | снизить лимит до среднесуточного на 1 объявление, поднимать постепенно |
| Максимальное вычерпывание ключей | лимиты под 7-дневный цикл обновления |
| Топ-сегмент по гео/возрасту | вынести в отдельную кампанию |
| Идеи иссякли | пересоздать лучшую группу в другое время суток |

## Работа с агентством / подрядчиком

1. **Медиаплан — не опора, а формальность.** «Скорее всего, не будет выполнен». Повторение чужого кейса не работает в 95% случаев.
2. **Договориться на старте о ЕЖЕДНЕВНОЙ статистике на первых бюджетах** — там основной риск слива. Проговорить сразу, чтобы никого не раздражало, или автоматизировать.
3. Риск: агентство может долго не сообщать, что связка не найдена. Через 100–200 тыс ₽ выясняется, что связок нет — причём по банальным причинам (руководитель не досмотрел, таргетолог ушёл на выходные).
4. Когда связки найдены — контроль можно ослабить: дальше техническая оптимизация по проторенному пути.
5. Проверять не «связка найдена», а «связка конвертится в **деньги**» — дешёвые подписчики не равны полезным.

Тестовые бюджеты и первые признаки успеха — `benchmarks.md` («Тестовые бюджеты и KPI-модель»).

## NDA-напоминание

Цифры в кейсах — **иллюстративные** (крупные проекты под NDA). Методология применима к любому проекту, но **достоверные выводы — только на большой собственной статистике**. Не копируй чужие CPL как KPI.
