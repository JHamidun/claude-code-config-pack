# Tool search protocol

Claude Code (и Claude в целом) видит **частичный** список инструментов. MCP-коннекторы могут быть подключены, но не появиться в видимом списке до явного поиска.

## Правило

Если юзер просит сделать что-то с внешним сервисом (Slack, Google Drive, Linear, Notion, Jira, GitHub Issues, Asana и т.д.) — **до того как сказать "не могу"**, проверь:

1. Есть ли инструмент в среде — `ToolSearch` (в агентном контексте) или `claude mcp list`
   (в терминале). Точные формы — в разделе «Команды поиска» ниже.
2. Поищи по ключевым словам сервиса.
3. Если нашёлся — используй.
4. Если MCP не нашёлся — **это ещё не повод отказывать**. Отсутствие MCP-коннектора не
   значит отсутствие пути: у Slack/Drive/Linear/почты в этом конфиге чаще есть свой
   скрипт или CLI. Дальше по `rules/auto-learning.md` идут четыре источника —
   конфиг (`rules/routing.md` → `config/routing-ext.md` → списком `skills/`, `commands/`,
   `tools/`, `scripts/`), память (`memory_find.py` + `memory_vec.py`; если их нет в `scripts/` — `search_chats.py`), история чатов
   (`search_chats.py`), сама система (`.credentials.master.env`, `~/.ssh/config`,
   `pip list`). Отказ — только после всех четырёх и с парой «инструмент → результат»
   (`rules/try-before-refusing.md`).

## Антипаттерн

```
Юзер: "Запости в наш Slack #design"
Я:    "Извини, не могу — нет интеграции со Slack."
```

Это **до того**, как проверил.

## Правильный flow

```
Юзер: "Запости в наш Slack #design"
Я:    *проверяю tool_search "slack"*
       1) если найден slack_post — использую
       2) если не найден — "не вижу Slack-интеграции; добавь её в MCP и перезапусти, или вкинь сообщение сам"
```

## Команды поиска (проверено 22.08.2026)

- В терминале — **`claude mcp list`**. Печатает каждый сервер со статусом
  (`✔ Connected` / `Needs authentication` / `Failed to connect`) и внизу диагностику
  с путями конфигов. Голый `mcp list` — НЕ то: на PATH висит CLI питоновского MCP SDK,
  он отвечает `No such command 'list'`.
- Внутри агентного контекста инструмент называется **`ToolSearch`**, запрос вида
  `select:<name>[,<name>]` — он подгружает схему отложенного инструмента.
  Функций `tool_search` / `tool_search_tool_bm25` не существует.
- Где лежит конфигурация (по выводу `claude mcp list`): пользовательская —
  `~/.claude.json` → `mcpServers`; проектная — `~/.claude/.mcp.json` → `mcpServers`.
  Файл `~/.claude/mcp.json` (ключ верхнего уровня `servers`, VS Code-схема) Claude Code
  не читает — правка в нём ничего не включит.

## Что искать по ключевым словам

| Запрос упоминает | Поиск по |
|---|---|
| Slack | `slack`, `chat`, `message` |
| Notion | `notion`, `page`, `database` |
| Linear / Jira | `linear`, `jira`, `issue`, `ticket` |
| Google Drive | `drive`, `gdrive`, `gdocs` |
| Figma | `figma`, `design`, `frame` |
| GitHub | `github`, `repo`, `pr`, `pull request` |
| Email | `email`, `mail`, `smtp` |
| Calendar | `calendar`, `event` |
| Filesystem outside project | `file`, `bash`, `shell` |

## Не повторяй ошибку дважды

Если в одном чате уже искал и не нашёл — не зацикливайся: «не нашёл» один раз достаточно. Не делай tool_search на каждом сообщении.

## Когда никакого MCP нет

Сначала — четыре источника из шага 4 (в этом конфиге у почты, Drive, Telegram, Bitrix
и десятков сервисов путь не через MCP, а через свой скрипт в `tools/` или `skills/`).
И только если не нашлось нигде — спроси юзера: «Хочешь подключить MCP-сервер для X?
Минимальный путь: <ссылка/команда>». Это полезнее, чем отказ.

## Что MCP **обычно умеет**

- Чтение содержимого (страницы, тикеты, файлы).
- Создание/обновление сущностей.
- Поиск.

И **обычно не** умеет:
- Долгоживущие подписки на события.
- Сложные UI-актиш с кликами по конкретным кнопкам.
- Что-то требующее пользовательского OAuth-flow в моменте.
