# 6 шагов машинки контента — детально

Полная операционка цикла фабрики эксперта. Каждый шаг = что делаем, инструмент, артефакт, типовые ошибки. Креативное «мясо» (хук, декомпозиция, anti-AI-slop) делегируется в `ai-creative-factory-ru` — здесь именно конвейер.

```
1 ПУЛ → 2 РАДАР → 3 ТРЕНДВОТЧЕР → 4 ДЕКОМПОЗИЦИЯ → 5 AI-АГЕНТЫ → 6 АВТОВОРОНКИ
```

---

## Шаг 1. Пул мониторинга — 100-500 аккаунтов

**Идея.** Контент не придумывается из головы — он собирается из того, что уже работает. Первый шаг фабрики: собрать большой пул источников виральных форматов.

**Кого собираем (не только конкуренты):**
- конкуренты в нише,
- блогеры,
- эксперты,
- инфлюенсеры,
- аккаунты из **смежных ниш** (часто там рождаются форматы, которые ещё не пришли в твою).

**Что важно — НЕ размер аккаунта, а:**
- просмотры,
- вовлечённость (ER),
- **повторяемость форматов** (аккаунт стабильно выдаёт виралки → у него рабочая система, а не разовая удача).

**Размер пула:** **100-500 аккаунтов** на одну нишу + смежные.

**Инструменты:**
- **LiveDune** — первичный поиск по охватам/вовлечённости.
- Ручной ресёрч через подписки и рекомендации платформы.
- **Apify** — скрапинг IG/соцсетей для массового сбора (рецепт — в `apify-scraping`; Actor для Instagram упомянут в курсе).

**Артефакт — `monitoring_accounts.csv`:**

| handle | platform | niche | type | audience | avg_views | ER | last_viral | format |
|--------|----------|-------|------|----------|-----------|----|-----------|--------|
| @example | instagram | ниша | конкурент / блогер / эксперт / инфлюенсер | 120k | 80k | 4.2% | 2026-06 | подборка |

**Типовые ошибки:**
- брать только конкурентов → узкая лента, мало свежих форматов;
- гнаться за размером аккаунта → большие, но не виральные аккаунты бесполезны;
- собрать 20 и остановиться → пул из 100-500 нужен, чтобы радар-лента была насыщенной.

## Шаг 2. Аккаунт-радар

**Идея.** Создаётся **отдельный аккаунт только для анализа трендов** — analyzer-аккаунт.

**Как работает:**
1. Подписываешься с него на **все 100-500 аккаунтов** из пула.
2. Формируется «идеальная» лента — алгоритм платформы видит твои интересы и **сам подбрасывает новые тренды**.
3. Это твой **радар вирусного контента**: не ты ищешь виралки, а лента приносит их тебе.

**Гигиена радар-аккаунта (важно):**
- Заводить **отдельный** аккаунт, не личный и не бренд-аккаунт — иначе алгоритм смешает интересы и лента «загрязнится».
- Не лайкать/смотреть постороннее с него — чистота сигнала = качество радара.
- Один радар = одна ниша. Под другую нишу — другой радар.

**Артефакт:** работающий радар-аккаунт с насыщенной нишевой лентой.

## Шаг 3. Трендвотчинг

**Идея.** Поверх радара используется **отдельный инструмент (trendwatcher)**, который:
- анализирует **virality и engagement**,
- показывает лучшие ролики по: просмотрам / комментариям / вовлечённости,
- **декомпозирует видео** на: хук → сценарий → структуру.

**Критерий «виралки» (аномалия):** просмотры/лайки/комментарии **выше среднего по этому аккаунту** (не абсолют, а относительно собственного базлайна аккаунта).

**Критерий «годного аккаунта для отбора» (из:** актуален нише + ≥4 поста/неделю + хотя бы **1 виральный из 9**.

**Инструменты:**
- **[сервис]er** (trndwtch.com) — основная платформа.
- Аналоги: **virlo.ai**, **meedro.com**, **viralscope.io**.
- Свой vibe-code: **example.com/you/trendwatch-fork** (нужен собственный Apify-ключ — у пользователя есть).
- **VidIQ** — для YouTube.
- **Apify** — backbone для парсинга.

**Артефакт:** список виралок-кандидатов (URL + метрики) на декомпозицию.

> Связка→: трендвотчинг — отдельный урок эксперт, эксперт берёт этот стек и встраивает в более широкий business-layer фабрики.

## Шаг 4. Декомпозиция виралки

**Идея.** Мы **не копируем видео целиком**. Копируем **форму**, адаптируем **смысл**.

**Что копируем (форма):**
- хук (визуальный + текстовый),
- хронометраж,
- раскадровку,
- структуру подачи,
- дофаминовые триггеры.

**Что адаптируем (смысл):**
- тезисы и примеры → **под свой продукт**.

**5-слойная структура виральной единицы:**

| # | Слой | Что делает | Тайминг |
|---|------|-----------|---------|
| 1 | **Хук** | Ломает баннерную слепоту | **0-3 сек** |
| 2 | **Сеттинг** | Погружение в ситуацию/контекст | 3-7 сек |
| 3 | **Тезисы** | Факты, сторителлинг, конфликт | основа |
| 4 | **Дофаминовые всплески** | Каждые **3-5 сек** что-то меняется | сквозной |
| 5 | **CTA** | Комментарий / подписка / слово-триггер | финал |

**Хук-триггеры (каталог):**
- **Визуальные:** абсурд, резкий переход, крупный план, анимация, ASMR/слоп-контент, нестандартный ракурс.
- **Текстовые:** топы и списки, шок-факты, разрушение мифов, спорные утверждения, обращение «на ты», ограничение по времени, вопрос в кадре.
- **Формула:** **хук = атака на глаза + атака на уши.**

> Подробный разбор хука, 5-блочного канона и техник декомпозиции — **в `ai-creative-factory-ru`**. Здесь это краткий мост: на выходе шага 4 у каждого формата есть готовая «форма» для агента шага 5.

**Артефакт — таблица декомпозиции:**

| хук_визуал | хук_текст | хронометраж | раскадровка | структура | дофамин-триггеры | CTA |
|------------|-----------|-------------|-------------|-----------|------------------|-----|

## Шаг 5. AI-агенты — «1 формат = 1 агент»

**Ключевая идея эксперта:**

> **«Не увеличивать команду — увеличивать количество агентов.»**

**Как:**
1. Выявляются **форматы**, которые можно автоматизировать (по результатам шагов 3-4 видно, какие форматы рабочие).
2. Под каждый формат создаётся **AI-агент**: генерация сценариев / изображений / видео / каруселей.
3. **Один агент = один формат.**

**Почему это снимает бутылочное горлышко.** Главное ограничение фабрики — **объём контента**. Люди не масштабируются линейно и дорого. Агенты — масштабируются: чтобы удвоить выпуск формата, ты не нанимаешь человека, а запускаешь ещё инстансы агента / добавляешь формат-агента.

**Реестр форматов-агентов (артефакт):**

| Формат | Что генерит агент | Вход | Выход | Статус |
|--------|-------------------|------|-------|--------|
| Reels-нарезка | сценарий + раскадровка + монтажный план | таблица декомпозиции | сценарий + storyboard | active |
| Карусель-подборка | тексты слайдов + визуал-бриф | хук-форма | слайды | active |
| Говорящая голова | скрипт под аватар/съёмку | тезисы | скрипт | planned |
| Сторис-дайджест | серия сторис | тренд дня | сторис-сет | planned |

**Делегирование:**
- Сборку самих агентов как сущностей — в `ai-marketing-stack-ru` (мультиагентный стек) и `autonomous-agent-creator` (конкретный агент).
- Этот шаг отвечает за **архитектуру** (какие форматы → какие агенты), не за код агента.

**Anti-AI-slop (обязательно на выходе агента).** AI — инструмент, а не стиль. Чтобы контент «не палился»: менять кодек, апскейлить, заменять аудио, правильно монтировать, избегать AI-слопа. Техники — в `ai-creative-factory-ru`.

**Режиссёрский mindset.** Агент не делает видео «одним промтом». Пайплайн агента воспроизводит режиссёрский процесс: идея → сценарий → раскадровка → старт-фреймы → анимация → монтаж → ритм.

## Шаг 6. Автоворонки — контент как вход в воронку

**Идея.** Контент = **вход в воронку**, а не самоцель. Внимание конвертируется в лиды автоматизированно.

**Механика (ManyChat):**
```
комментарии        → автоворонки (ManyChat)
ключевые слова     → сообщения в директ (DM)
ценность           → прогрев → продажа
```

**Результат (бенчмарк эксперта):** даже с **10-15K подписчиков** десятки процентов лидов могут приходить из SMM — при работающей автоворонке.

**Инструменты:**
- **ManyChat** (~$20/мес) — comment-keyword → DM для IG/FB/TG.
- **n8n** — бэкенд-интеграции (ManyChat → CRM → продажа).

**Делегирование:** построение самих flow comment→DM→прогрев — в `manychat-funnel-ru` *(если есть; иначе опиши flow концептуально + `n8n` для backend)*. Этот шаг отвечает за **связку «какой пост = триггер какого flow»**, а не за конструктор воронки.

**Артефакт:** карта «контент → flow» (какой формат/хук запускает какую автоворонку) + ключевые слова-триггеры.

## Итог цикла

На выходе 6 шагов: радар приносит тренды → трендвотчер отбирает → декомпозиция даёт форму → агенты тиражируют форматы → автоворонки конвертируют в лиды. Метрика всего цикла — **лиды из SMM** (см. `operational-layer.md`).
