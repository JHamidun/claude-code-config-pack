## Правило (написано до прогона)

Вопрос остаётся включённым, только если одновременно:

- **ложные:** вероятность не ниже порога показа не больше чем на 5% живых абзацев владельца;
- **попадания:** вероятность не ниже порога не меньше чем на 60% машинных абзацев, в которых нужный паттерн есть
  (по разметке автора), и таких абзацев не меньше пяти.

Порог показа каждого вопроса лежит в `jev-questions.json` (`show_at`). Скрипт `jev_calibrate.py report --apply`
записывает в файл только `enabled` и `status`, пороги не трогает.

## Что показал разбор руками

- **Живые срабатывания** (первый прогон, 4 абзаца из 68): `p25` на «Но есть нюанс, который, мне кажется, у Зиновьева
  недоговорён…» и на «Вопрос не в том, касалась ли текста модель, а стоит ли за ним живой опыт…» (оба оборота подводят к
  мысли, то есть Jev увидел в живом тексте то, что вопрос описывает; по протоколу это ложные срабатывания, живой текст
  считается чистым); `p37` на ответ Анне про отторжение и привыкание (текст про чувства, то есть случай, который вопрос
  обещал не считать); `p09` на «это отличный разбор памяти».
- **Трудные отрицательные:** `p04` сработал на «Запрос отправлен, ответ пришёл через минуту» (нейтральный технический пассив,
  ровно то, что в `criteria.false`), `p25` — на «Если копнуть в логи, там видно…» (оборот в прямом смысле). Остальные
  граничные фразы вопросы пропустили. Выборка по две на паттерн: это сигнал смотреть, а не оценка.
- **Подсказки из вопросов:** дословных примеров из «да»-критериев в размеченных положительных абзацах нет, кроме четырёх
  абзацев `p04` («Считается, что», «Было принято решение»); без них `p04` попал 5 из 5.
- **Кальки (`p36`)** Jev ловит плохо: из семи размеченных абзацев сработал на три, а вероятности у «на регулярной
  основе» и «делает разницу» держатся около 0,2–0,6. Вопрос требует суждения о естественности русского сочетания, а
  русский не основной язык модели.
- **Соседние паттерны:** `p07` («раздувание значимости») и `p04` («пассив») срабатывают и на машинных абзацах с другими
  паттернами (в первом прогоне 23% и 18% «машинных без паттерна»): `p07` откликается на любую напыщенную похвалу,
  `p04` на безличные обороты вроде «напрашивается вывод». Для списка дефектов это допустимо, для названия паттерна нет.

## Как этим пользоваться

- Подсказка Jev означает «посмотри на этот абзац», а не «здесь ИИ». Одна подсказка без соседей не повод править.
- Включённые вопросы: p01, p02, p04, p07, p08, p09, p15, p16, p25, p28, p32, p35, p37. Выключен: p36; его паттерн (кальки) по-прежнему ловит чтение по
  `references/ai-writing-patterns.md`, раздел F.
- Модель закреплена (`jev-questions.json`, поле `model`); при другой модели `jev_audit.py` пишет предупреждение, что пороги
  откалиброваны на `jev-1.13.0`. Алиас `jev-latest` не использовать: вендор двигает его на новые сборки без предупреждения.

## Ограничения

- **Положительные примеры синтетические.** Их писал тот же автор, что и вопросы, в «типичной ИИ-манере»; формулировки
  примеров из вопросов обходил, но слепое пятно у автора общее. Попадания завышены; на настоящем ИИ-тексте из чужих рук
  не проверялось. Разметку паттернов делал автор по ходу, без второго разметчика.
- **Живая выборка мала:** 68 абзацев одного автора, в одном жанре (ответы в комментариях Telegram и Хабра). Для
  статей, постов с заголовками и длинных абзацев ничего не измерено; документные вопросы кандидата (№30, №38) не брались.
- **Русский не основной язык модели** (документация вендора); вопросы написаны по-английски, текст русский.
- **Недетерминизм** (раздел выше): расхождение до 0,17 между запусками.
- **Не измерено главное для владельца:** улучшает ли правка по подсказкам итоговый текст. Мерилось только то, насколько
  вопросы отличают его живые ответы от машинных.
- Пороги и правило выбраны до прогона и применены один раз; на других данных или другой модели результат может быть другим.

## Как пересчитать

```
python ~/.claude/skills/de-ai-ify/scripts/jev_calibrate.py report                       # пересчёт из сырых данных, без сети
python ~/.claude/skills/de-ai-ify/scripts/jev_calibrate.py report --raw ~/.claude/skills/de-ai-ify/references/jev-calibration-raw-run2.json
python ~/.claude/skills/de-ai-ify/scripts/jev_calibrate.py run --public --raw <новый файл>   # платно; другая модель или правка вопросов
python ~/.claude/skills/de-ai-ify/scripts/jev_calibrate.py report --raw <новый файл> --apply # записать enabled/status
```

Сырые файлы хранят вероятности и хеши текстов (текстов нет). `run` продолжает с того места, где остановился, и не смешивает
модели: для новой версии модели нужен новый `--raw`. Если `examples.md` или корпус изменились, `report` откажется считать
(хеши не совпадут). После правки формулировки вопроса, как и после смены модели, калибровку нужно повторять.
