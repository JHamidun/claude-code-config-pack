# Pixel + события + CAPI — полный setup-playbook

> ⚠️ Meta признана экстремистской в РФ. Раздел — для международных/СНГ-проектов.
> Пиксель, настройка событий, Events Manager и server-side (CAPI) — практика настройки.

Трекинг — **фундамент** Meta-рекламы. Без чистых данных алгоритму не на чём учиться: кампания не выйдет из learning phase, как бы хороши ни были креативы. Поэтому пиксель + CAPI настраиваем **до** запуска бюджета.

---

## 1. Facebook Pixel

**Что делает.** Фиксирует поведение пользователя на сайте после клика по рекламе:
- просмотр страниц;
- клики;
- отправку форм;
- добавление в корзину;
- покупки;
- движение по воронке после клика.

**Зачем.** Без пикселя система **не понимает, кто совершает важные действия** → невозможно корректно оптимизировать рекламу. Пиксель видит события **на сайте в реальном времени**.

### 4 способа установки пикселя

| Способ | Когда выбрать |
|--------|---------------|
| **Ручная вставка кода в `<head>`** | полный контроль, кастомный сайт |
| **Готовые интеграции платформ** (Tilda, Shopify) | no-code, конструктор сайтов / e-com платформа |
| **Google Tag Manager** | удобно, если много тегов и пикселей |
| **Event Setup Tool** | быстрый вариант для базовых событий (клик, форма) без кода |

> Если пиксель уже стоит на сайте от прошлого подрядчика — запроси доступ через BM. Если доступ не получить — ставь новый.

## 2. Стандартные события (6) — Meta их «понимает»

Meta использует эти события для **обучения алгоритмов** и классификации поведения всех пользователей в экосистеме:

```
PageView  →  ViewContent  →  AddToCart  →  InitiateCheckout  →  Purchase
                                                              →  Lead
```

| Событие | Что значит |
|---------|------------|
| `PageView` | просмотр страницы |
| `ViewContent` | просмотр конкретного контента/товара |
| `AddToCart` | добавление в корзину |
| `InitiateCheckout` | начало оформления заказа |
| `Purchase` | покупка |
| `Lead` | заявка / лид |

**Почему важны:** по стандартным событиям Meta классифицирует поведение **всех** пользователей и точнее находит тех, кто вероятнее совершит ценное действие. Meta знает поведение людей внутри своей экосистемы → умеет находить «похожих покупателей».

---

## 3. Кастомные конверсии — для глубины воронки

Создаются для **уникальных шагов**, которые нельзя описать стандартным событием:
- квалифицированный лид;
- внутренние статусы CRM;
- звонок;
- подтверждение сделки / этап сделки;
- оплата.

**Лучшие практики:**
- **максимально** использовать **стандартные** события (Meta их понимает лучше всего);
- **кастомные** — только для **глубоких этапов** (квал-лид, звонок, оплата);
- не дублировать стандартное событие кастомным без необходимости.

## 4. CAPI (Conversions API) — обязателен для длинного цикла

**Зачем.** Meta должна понимать **весь путь лида**, а не только клик по рекламе. CAPI передаёт **серверные** события, которые пиксель физически не видит (происходят вне браузера — в CRM, по телефону, при оплате):
- лид;
- квалификацию;
- звонки;
- продажи;
- LTV.

Особенно критичен при **длинном цикле сделки** (B2B): продажа происходит через недели после клика → пиксель её уже не свяжет с рекламой → без CAPI Meta оптимизируется «вслепую» на сырые лиды.

### 7 параметров матчинга (все нужны для качества)

Чем больше совпадений — тем точнее Meta «склеит» серверное событие с конкретным пользователем:

| Параметр | Что это |
|----------|---------|
| `email` | email лида (хэшируется) |
| `телефон` | телефон лида (хэшируется) |
| `страна`, `zip` | гео-привязка |
| `External ID` | внутренний ID пользователя/лида в твоей системе |
| `FBC` (Facebook Click ID) | ID клика по рекламе — связывает событие с конкретным объявлением |
| `FBP` (Facebook Browser ID) | ID браузера — связывает с сессией пользователя |

> **Принцип:** Meta должна знать, **какие лиды оказались качественными**, чтобы алгоритм оптимизировался на нужных людей. Чем больше и качественнее серверных событий → тем лучше работает оптимизация и lookalike.

### Способы внедрения CAPI

| Способ | Когда |
|--------|-------|
| **No-code: Zapier / Albato / Make / n8n** | нет разработчика; быстрый старт; **Albato** — российская альтернатива Zapier (важно для РФ-юрлица из-за санкций) |
| **Готовая интеграция CRM** (HubSpot, amoCRM, Битрикс24) | CRM имеет нативный коннектор к Meta CAPI |
| **Кастомная разработка** | сложная логика, высокая нагрузка, полный контроль |

**No-code пайплайн (логика для любого из инструментов):**
```
Триггер в CRM (новый лид / смена статуса / оплата)
   → нормализация полей (email, phone, country, zip, External ID, FBC, FBP)
   → отправка в Facebook Conversions API (event_name + event_time + event_id + user_data)
   → проверка в Events Manager → Test Events
```

> Готовый workflow в `n8n` (если есть скилл `n8n`). Если выделен отдельный скилл `capi-no-code-setup` — детальные blueprint'ы для Zapier/Make/n8n + deduplication (`event_id` + `event_time`) там.

## 5. Test Events — обязательная проверка после установки

Раздел **Events Manager**:
- **Overview** — список всех событий + воронка;
- **Test Events** — тестирование в реальном времени.

**Процедура проверки:**
1. открыть сайт через **тестовый режим** (Test Events);
2. пройти всю воронку (просмотр → форма → оплата);
3. убедиться, что события отбились корректно.

**Критерии корректной настройки:**
- ✅ **нет дублей** событий;
- ✅ события приходят **ровно один раз**;
- ✅ данные идут **стабильно и равномерно**;
- ✅ **веб-события + серверные события** (CAPI) отображаются корректно (и не задваиваются между собой).

> Дедупликация веб + сервер — частая боль: одно и то же событие может прийти и от пикселя (браузер), и от CAPI (сервер). Решается через общий `event_id` + `event_time` (Meta схлопывает дубли). Если видишь задвоение в Test Events — проверь `event_id`.

## 6. Стратегия запуска трекинга (порядок)

От точного к широкому — **не наоборот**:

```
1. Точный пиксель (4 способа установки)
2. Корректно настроенный CAPI (7 параметров матчинга)
3. Стандартные события
4. Качественные lookalike (на квал-лидах/оплатах)
5. Стабильные креативы
6. → потом расширение на широкую и Advantage+
```
