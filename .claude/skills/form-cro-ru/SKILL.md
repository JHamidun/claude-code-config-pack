# CRO форм захвата (RU)

Один навык на три подтипа формы: **заявка** (консультация, воркшоп, корп-пакет, контакт), **регистрация** (аккаунт/trial) и **лид-магнит/подписка**. Поля, лейблы, раскладка, обработка ошибок, мультишаг и мобайл у них совпадают — поэтому общая часть описана один раз, а различия собраны в разделе «Подтипы». Порт `cro/references/form.md` и `signup` из marketingskills: принципы и чеклисты сохранены, инструменты под RU-стек.

**Перед началом прочитай `~/.claude/business-context.md`** — разделы «Продукт», «Цены» (тарифы и условия пробного периода) и «Воронка» (где именно захватываются лиды). Файла нет — заведи из `~/.claude/templates/business-context.md`. Позиционирование и метрики держи только там: продублируешь по навыкам — разойдутся.

## Первичная оценка

1. **Подтип и цель:** заявка на бесплатную консультацию (вход B2B-воронки), запрос формата воркшопа, запрос корп-пакета academy, контактная форма; регистрация trial 7 дней без карты, регистрация в боте `@your_news_bot`; скачивание лид-магнита, захват email рассылки, опрос/фидбэк.
2. **Текущее состояние:** сколько полей и шагов, что обязательно, заполняемость / completion rate, где бросают — по полям и по экранам, mobile vs desktop.
3. **Бизнес-ограничения:** какие поля реально используются в работе и квалификации; куда падают данные (заявки → CRM, стадии new→interested→qualified→zoom_scheduled; регистрация → продукт); требования 152-ФЗ; что происходит сразу после сабмита.

## Базовые принципы

### 1. У каждого поля есть цена
Каждое поле снижает заполняемость. Ориентир: 3 поля — база; 4-6 — минус 10-25%; 7+ — минус 25-50%+. По каждому полю спроси: нужно ли это ДО того, как мы поможем (или человек начнёт работать)? Можно ли получить иначе — обогащением, из домена email? Можно ли спросить позже — на самой консультации или в онбординге (progressive profiling)?

### 2. Ценность до коммитмента
Показать ценность раньше, чем просить данные: «что вы получите на консультации» над формой; демо симулятора, превью трека, пример диалога с AI-тьютором — до регистрации; лента статей открыта, email нужен только для дайджеста. Форма без видимой ценности читается как чистое усилие, и её бросают на первом же поле.

### 3. Снизить когнитивную нагрузку
Один вопрос на поле, разговорные лейблы, логичная группировка и порядок, умные дефолты и предзаполнение, прогресс при мультишаге.

### 4. Убрать неопределённость
«7 дней бесплатно, без карты», «Займёт 30 секунд», «Свяжемся в течение X» — человек должен понимать, что будет после кнопки. Сюрприз после сабмита (внезапный запрос карты, письмо вместо доступа) стоит дороже, чем лишнее поле.

## Поля: общая часть

- **Email:** одно поле без подтверждения, inline-валидация формата, ловля опечаток (gmial.com → gmail.com), правильная мобильная клавиатура.
- **Имя:** одно «Имя» vs «Имя/Фамилия» — тестировать; делить только если нужно для персонализации (обращение, сертификат).
- **Телефон:** для заявки на консультацию обычно нужен — по нему бронируют Zoom; объяснить зачем, авто-формат, код страны (+7). Для регистрации trial обычно не нужен — откладывать. Верификация при необходимости — SMS Aero / SMSC.ru.
- **Компания (B2B):** авто-подсказка, вывод из email-домена, обогащение после сабмита (Контур.Фокус / Rusprofile) — это дешевле, чем ещё одно обязательное поле.
- **Должность / роль / трек:** дропдаун, если категории важны (HR-директор, гендир, руководитель отдела), free text при большом разбросе; на регистрации — откладывать в онбординг, на форме оставлять максимум один такой вопрос.
- **Сообщение / задача (free text):** опционально, ориентир по символам, расширять при фокусе («Какую задачу хотите решить с ИИ?»).
- **Дропдауны:** плейсхолдер «Выберите…», поиск при многих опциях, радио при <5 опций, «Другое» + текст.
- **Чекбоксы:** параллельные лейблы, разумное число, «Выберите всё подходящее».

## Поля только регистрации

- **Пароль:** иконка «показать», требования показывать заранее, а не после ошибки, индикатор силы, разрешить вставку — запрет вставки ломает менеджеры паролей. Рассмотреть passwordless / magic link: тогда поля нет вообще.
- **Соцавторизация и SSO:** размещать заметно — часто конвертит лучше пары email+пароль. RU-контекст: Яндекс ID, VK ID, Telegram, Google; для B2B-когорт — корпоративный SSO (SAML / Google / Yandex). Чётко отделять визуально от email-регистрации, иначе человек регистрируется дважды и получает «этот email уже занят».
- **Верификация email:** по возможности отложить и дать исследовать продукт, пока ждёт письма; magic link как альтернатива паролю; простой ресенд. Для рассылки — double opt-in (комплаенс) против single (конверсия), решать осознанно.

## Раскладка

- **Порядок полей:** лёгкие первыми (имя, email) → растить коммитмент → чувствительные последними (телефон, компания, задача) → группировка при многих полях.
- **Лейблы и плейсхолдеры:** лейбл всегда видимый — плейсхолдер исчезает при вводе, и человек перестаёт понимать, что он заполняет; плейсхолдер = пример; help text только когда реально полезен.
- **Визуал:** достаточный интервал, чёткая иерархия, выделенная кнопка, тач-таргеты 44px+.
- **Одна колонка** почти всегда (выше заполняемость, мобайл-френдли); две — только для коротких связанных полей (Имя/Фамилия).

## Один шаг vs мультишаг

- **Один шаг:** ≤3 поля, email-захват, простой B2C trial, высокий интент (переход с рекламы или лид-магнита).
- **Мультишаг:** >5-6 полей в заявке, >3-4 в регистрации; логически разные секции, условные пути, сложные случаи (корп-пакет, воркшоп, B2B-когорта с сегментацией).
- **Практики:** прогресс-индикатор (шаг X из Y), лёгкие вопросы первыми, тяжёлые позже — после психологического коммитмента, одна тема на шаг, back-навигация, сохранение прогресса, чёткое required/optional.
- **Прогрессивный коммитмент.** Заявка: (1) только email → (2) имя/компания → (3) квалифицирующие вопросы (задача, размер команды) → (4) контактные предпочтения + слот Zoom. Регистрация: (1) только email → (2) пароль + имя → (3) выбор трека/цели (опционально).

## Обработка ошибок

- **Inline-валидация:** при переходе к следующему полю, не слишком агрессивно во время ввода, чёткие индикаторы.
- **Сообщения:** конкретные, с подсказкой как исправить, у поля, не очищать ввод. Хорошо: «Введите корректный email (например, name@company.ru)», «Этот email уже зарегистрирован» + ссылка на восстановление пароля. Плохо: «Неверный ввод».
- **На сабмит:** фокус на первой ошибке, сводка ошибок, сохранить все данные, не очищать форму.

## Кнопка отправки

- **Текст:** «[Действие] + [что получат]»: «Записаться на консультацию», «Выбрать формат воркшопа», «Запросить корп-пакет», «Скачать гайд», «Начать обучение» / «7 дней бесплатно» (регистрация), «Подписаться».
- **Размещение:** сразу после последнего поля, по выравниванию с полями, достаточный размер и контраст, на мобайле sticky/видимая.
- **Пост-сабмит:** loading-состояние (disable + спиннер), подтверждение успеха с чётким следующим шагом, обработка ошибки без потери данных. Что именно за следующий шаг — см. «Подтипы».

## Доверие и снижение трения

- У формы: «Не передаём данные третьим лицам», регалии эксперта ([роль, компания]), отзыв или соцпруф, ожидаемое время ответа; для регистрации — «Без привязки карты», «7 дней бесплатно», бейджи безопасности и «данные в РФ».
- Воспринимаемое усилие: «Займёт 30 секунд», индикатор числа полей, минимум визуального шума.
- Возражения: «Консультация бесплатна и ни к чему не обязывает», «Без спама», «Скачивание мгновенно», «Отмена в один клик».
- **152-ФЗ:** явное согласие на обработку ПД — чекбокс, не пред-отмеченный, — плюс ссылка на политику; обязательно при любом сборе ПД. Для рассылки — маркировка и явная отписка. Для B2B-когорт данные держать в российском контуре и проговаривать это при регистрации корп-аккаунта.

## Подтипы

### Заявка (B2B, без аккаунта)

- **Бесплатная консультация (главная форма):** имя и email обязательны; телефон + компания + «какая задача» для квалификации; встроенный календарь Zoom или бронь следующим шагом; заявка → CRM, стадия new → qualified.
- **Запрос формата воркшопа:** имя, email, компания, размер команды / желаемый формат; вопрос «на каких задачах учить команду»; → CRM, эскалация к владельцу для горячих enterprise.
- **Запрос корп-пакета academy:** обычно многошаговая — лёгкие вопросы первыми, детали (размер команды, треки, SSO) позже, сохранение прогресса.
- **Контактная:** email/имя + сообщение, телефон опционально, ожидаемое время ответа, альтернативные каналы (Sales-AI-агент, Telegram).
- **После сабмита:** подтверждение + конкретный next step («Свяжемся в течение X» либо «Выберите слот Zoom»).

### Регистрация / trial

Регистрация в ExampleProduct (trial 7 дней без карты) и в боте — цель не «создать аккаунт», а довести до активации, поэтому лишние поля переносим в онбординг.

- **Обязательно:** email (или соцавторизация) + пароль. **Часто нужно:** имя. **Откладываемо:** компания, роль, трек, телефон.
- **B2C trial:** Яндекс / VK / Telegram / Google-авторизация ИЛИ email+пароль → trial 7 дней → первый трек → профиль и трек позже.
- **B2B-когорта:** email + SSO → имя + компания + трек (роль опционально) → онбординг когорты.
- **TG-бот `@your_news_bot`:** `/start` → персональная лента → мягкий апсейл в academy/консультацию.
- **После сабмита:** понятное подтверждение и немедленный следующий шаг (→ первый трек / симулятор / AI-тьютор, дальше `onboarding-cro-ru`); авто-логин вместо повторного входа; персонализированное приветствие по данным регистрации.

### Лид-магнит и подписка

- **Скачивание лид-магнита:** минимум полей — часто только email; чёткий value prop (название лид-магнита); мгновенная доставка, следом апсейл trial.
- **Email-захват рассылки (news.your-domain.com, «YourName Weekly»):** только email, больше ничего; согласие 152-ФЗ; `POST /api/portal/subscribe` → `newsletter_subscribers` + double opt-in `email_verifications`; подтверждение подписки → дайджест вс 09:00 МСК.
- **После сабмита:** подтверждение + сразу мягкий CTA «Освоить системно → 7 дней academy бесплатно» — иначе контент и продукт живут раздельно и подписчик не переходит в воронку.
- **Опрос / фидбэк:** прогресс-бар, один вопрос на экран, skip-логика, стимул за завершение.

## Мобильная оптимизация

Тач-таргеты 44px+, правильные клавиатуры (email/tel/number), autofill, одна колонка, sticky-кнопка, минимум печати (дропдауны, кнопки, соцавторизация). Большая доля трафика РФ — мобайл.

## Измерение

- Form start rate, completion rate, дроп по полям и шагам, доля ошибок по полям, время заполнения, mobile vs desktop, соцавторизация vs email, доля заявок, дошедших до qualified / zoom_scheduled.
- Где смотреть: твоя продуктовая аналитика (Amplitude / Mixpanel / своя БД) + Яндекс.Метрика с целями на фокус полей, шаги и сабмит; готового навыка в паке нет. Заявки и лиды — твоя CRM.
