# Sales Manager Audit — Аналитика продаж в Битрикс24

## Что делает скилл

Собирает и агрегирует данные из Битрикс24 Company (webhook `we.company.example`, admin-токен) в готовые отчёты для руководителя отдела продаж, головы sales, СЕО и других стейкхолдеров.

Отвечает на вопросы:
- «Как работает менеджер X?»
- «Кто в команде лучший по конверсии?»
- «Что не так с воронкой Y?»
- «Почему проигрываем сделки?»
- «Какой прогноз выручки?»
- «Кто ЛПР среди клиентов Z?»

## Когда вызывать

Триггерные фразы:
- «разбери менеджера X», «отчёт по X», «как работает X»
- «сравни X и Y», «X vs Y», «кто лучше»
- «аудит воронки», «здоровье воронки», «что не так с воронкой»
- «конверсия по этапам», «где теряем сделки»
- «причины отказов», «почему проигрываем»
- «pipeline», «прогноз выручки», «open opportunities»
- «динамика продаж», «сравни периоды»
- «кто ЛПР», «профиль клиентов X»
- «статистика звонков», «дозваниваемость»

## Основной workflow

### 1. Разбор одного менеджера

```bash
cd ~/.claude/skills/sales-manager-audit/scripts
python manager_report.py --manager "Захаров" --period 2026-04-07:2026-05-13 --format text
python manager_report.py --manager 3956 --period all --format xlsx --out ~/Downloads/zakharov.xlsx
```

Что даёт:
- Профиль (должность, email, отдел, дата регистрации)
- Все сделки за период (по всем воронкам)
- Разбивка по стадиям, WON/LOSE/Active
- Суммы выигранных, средний чек, средний цикл
- Статистика звонков (объём, дозвон, длительность, паттерны)
- TODO дисциплина
- Причины отказов (через парсинг timeline)
- Источники сделок
- Качество данных

### 2. Сравнение менеджеров

```bash
python compare_managers.py --managers "Ушаков,Захаров" --period 2026-04-07:2026-05-13
python compare_managers.py --managers 2813,3956,3910,3643,3341 --period 2026-Q2 --format md
```

### 3. Аудит воронки

```bash
python funnel_audit.py --funnel 43 --format text
python funnel_audit.py --funnel all --stale-days 90
```

### 4. Классификация причин отказов

```bash
python reasons_analyzer.py --funnel 43 --period 2026-05
python reasons_analyzer.py --funnel 4 --manager "Ушаков"
```

### 5. Конверсия по стадиям

```bash
python conversion_stages.py --funnel 4 --manager "Ушаков"
python conversion_stages.py --funnel 43 --team --compare-managers
```

### 6. Pipeline прогноз

```bash
python pipeline_forecast.py --funnel 5 --weighted
python pipeline_forecast.py --team --top 20
```

```
CRM_PROD_WEBHOOK_PATH=/rest/1303/{TOKEN}/
```

Клиент — `scripts/bx_client.py` — обрабатывает retry, throttling, пагинацию.

## Форматы отчётов

Ключ `--format`:
- `text` (по умолчанию) — моноширинный текст для чата/email, с сохранением табличной вёрстки
- `md` — markdown для встраивания в Notion/wiki
- `xlsx` — Excel с форматированием (headers, alt rows, цветовая разметка)
- `docx` — Word для формальных отчётов
- `json` — сырые данные для программной обработки
- `csv` — для последующего анализа

Ключ `--out` — путь файла (для xlsx/docx/csv/json). По умолчанию `~/Downloads/`.

## Структура ответов

Каждый отчёт для другого человека содержит:

1. **Шапка** — название, период, источник, дата генерации
2. **Ключевые цифры** — самое важное в 5-10 строках
3. **Детали** — разбивка по разделам
4. **Сравнение** — с нормой (командной / прошлым периодом)
5. **Выводы** — сильные / слабые / критичные
6. **Вопросы к разбору** — что обсудить на 1-на-1
7. **Рекомендации** — что делать дальше

## Ключевые нюансы (обязательно учитывать)

1. **Rate limit Битрикса: 2 req/sec** — обязательно `time.sleep(0.4-0.5)` между вызовами.

2. **Timeout 60-90 сек**, retry с exponential backoff на `ConnectionError` и `ReadTimeout`.

3. **Пагинация max 50 записей** — использовать `start` параметр.

4. **STAGE_ID формат**: для дефолтной воронки просто `WON`/`LOSE`, для остальных `C{ID}:WON` / `C{ID}:LOSE`.

5. **Поле «Причина отказа»** (`UF_REASON_FOR_REFUSAL`) **не заполняется** практически никогда — используем парсинг timeline через regex-словарь (см. references/reason_classifier.md).

6. **Импорт из AMO CRM** — сделки, закрытые в Q4 2024 за 0 дней, — это импорт, не реальные продажи. Учитывать в cycle time и win rate. Стадии с префиксом `AMO_*` — тоже импорт.

7. **Даты могут быть в будущем** при импорте — не полагаться на `DATE_CREATE` для «активных дней», лучше использовать даты звонков.

8. **95% сделок без компании** — системная проблема Company. При B2B аналитике учитывать.

9. **Windows encoding**: в начало Python-скриптов добавлять:
   ```python
   import sys
   sys.stdout.reconfigure(encoding='utf-8')
   ```

10. **Не выдавать голые цифры руководителю** — всегда с интерпретацией и выводами. Отчёт увидит не автор запроса, а другой человек.

## Anti-patterns

- ❌ Смешивать импортированные сделки с реальными продажами → искажение метрик
- ❌ Считать «активные дни» по DATE_CREATE сделок → используй даты звонков
- ❌ Полагаться на поле «Причина отказа» → парси timeline
- ❌ Ранжировать SDR и Closer в одном рейтинге → разные роли, разные метрики
- ❌ Выдавать метрики без указания периода
- ❌ Массовые запросы без throttling → упадёт на rate limit

## Расширения

Если нужно добавить новый тип отчёта:
1. Создать `scripts/{new_report}.py`
2. Использовать `bx_client.py` для API
3. Использовать `report_formatter.py` для вывода
4. Добавить триггеры в SKILL.md
