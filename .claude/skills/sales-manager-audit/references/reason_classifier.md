# Классификатор причин отказов

Поле `UF_REASON_FOR_REFUSAL` в Битриксе **не заполняется** практически никогда (0-5% сделок). Используем **парсинг timeline-комментариев** через regex-словарь.

## Актуальный словарь

Обновляется в `scripts/reasons_analyzer.py` (`CLASSIFIER_RULES`).

| Категория | Ключевые слова (случаи-совпадения любого) |
|-----------|-------------------------------------------|
| **Не удалось связаться** | `нд,` `нд ` `недоз` `некорректн` `нет контактов` `не берет` `не отвеча` `не дозвон` `номер не верн` |
| **Тест/дубль/свой сотрудник** | `тест ` `наш сотрудник` `дубл` `дбуль` `yourfirstname` `yourname` |
| **Не целевой (SMB/физлицо)** | `1 человек` `один человек` ` ип.` ` ип ` `самозанят` `физ.лиц` `физлиц` `для себя` `маленькая компан` `смотрит для себя` |
| **Сменил/покинул компанию** | `уволил` `уже не в` `сменил работ` `уволен` |
| **Есть своё решение** | `свои разработ` `внут.продук` `внутр` `своё реш` `своя платформ` `уже есть` `используют свои` |
| **Уже клиент Company** | `уже пользует` `уже клиент` `корп. библиотек` `пользуется платформ` |
| **Нет потребности** | `не интересно` `не готов` `не актуальн` `не надо` `не требует` `пропала потреб` |
| **Нет времени/приоритета** | `нет времени` `занят` `некогда` `не сейчас` `сброс после` `сброс ` `не хочет говор` |
| **Гос/нет бюджета** | `госку` `госзак` `мид` `нет бюджет` `бюджет не ` |
| **Выбрали другого** | `выбрали друг` `конкурент` `другой провайд` |
| **Дорого** | `дорого` `слишком доро` |
| **Прочее (есть коммент)** | fallback для содержательных комментариев |
| **Нет причины (только метаданные бота)** | fallback для пустых/шаблонных |

## Как расширять

Если появляются новые типовые формулировки:

1. Проверить через `python reasons_analyzer.py --funnel N --sample 100` — что попало в «Прочее»
2. Добавить ключевые слова в `CLASSIFIER_RULES` в `scripts/reasons_analyzer.py`
3. Прогнать заново

## Приоритет правил

Правила проверяются **по порядку** — первое совпадение выигрывает. Поэтому специфичные категории (Тест, Уже клиент) должны идти раньше общих (Нет потребности).

## Известные особенности

- Комментарии часто начинаются с `[BOT+SITE DATA]` — это автоматические метаданные регистрации, не содержательные
- HTML/BBcode нужно очищать перед парсингом (используй `clean_html()`)
- Некоторые менеджеры пишут кириллицей с ошибками (`нд` вместо `недозвон`) — учитывать в словаре
