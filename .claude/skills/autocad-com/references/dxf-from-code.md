# Путь A: DXF и SVG из кода без CAD

Проверено на `energetika-ai-demo` (однолинейные схемы, 07.2026) и `interior-ai-demo` (альбом на 34 листа,
09.2026). Канон холста — `${WORKSPACE}/interior-ai-demo/engine/sheet.py`, копия — `../scaffold/sheet.py`.

## Один API — два холста

```python
sh = Sheet("A2")          # SVG: копит элементы, viewBox в мм, Y вниз
dx = DxfCanvas("A2")      # DXF R12: те же методы, Y инвертируется при записи
for canvas in (sh, dx):
    draw_plan(canvas, project, ctx)     # одна функция компоновки
```

Методы: `line rect frect circle ellipse dot path poly polygon arc text text_lines tick image set_layer
hatch cross_hatch dots_pattern view(scale, ox, oy)`. Координаты — **мм страницы**, начало в левом верхнем углу.
`View` переводит мировые мм (Y вверх) в страничные: `X = ox + x/scale`, `Y = oy − y/scale`.

Слои задаются `set_layer("WALLS_NEW")` — в SVG попадают как `data-layer`, в DXF — как слой с цветом ACI.
Список слоёв и цветов — `DXF_LAYERS` в `sheet.py` (25 слоёв: 0, FRAME, STAMP, TEXT, DIMS, TABLE, LEGEND,
WALLS_EXIST 8, WALLS_NEW 5, DEMOLITION 1, DOORS, WINDOWS, GLASS 4, FURNITURE 8, FLOOR, CEILING, LIGHT 1,
POWER 5, OUTPUTS 1, HATCH 8, RISERS 1, LOGGIA 3, TILE 5, FINISH, SANITARY 4; без цифры — 7). Имя вне
списка `DxfCanvas.set_layer` **молча** сводит к слою `0` — новый слой сначала добавить в словарь.

## DXF R12 — что и как пишется

- `$ACADVER = AC1009`, `$DWGCODEPAGE = ANSI_1251`, файл пишется `encoding="cp1251", errors="replace",
  newline="\r\n"`. Символы вне cp1251 заменяются cp1251-безопасными аналогами в `_san()`: `≤→<=`, `≥→>=`,
  `×→x`, `Δ→D`, `— – ·→-`, `²→2`, `°→гр.`, `₽→руб`, `…→...`, `Ø→D`.
- Таблицы: `LTYPE` (CONTINUOUS, DASHED), `LAYER` (все из `DXF_LAYERS`), `STYLE` — `GOST` и `GOSTI`
  (наклон 15°, `isocpeur.ttf` по имени: CAD подставит свой шрифт, если этого нет).
- Сущности: `LINE`, `POLYLINE/VERTEX/SEQEND` (толстые линии ≥ 0,6 мм — полилиния с шириной 40/41),
  `CIRCLE`, `ARC` (углы 50/51, против часовой), `TEXT` (высота 40 = 0,72 × кегль SVG; выравнивание 72 +
  вторая точка 11/21; поворот 50 = −rot SVG). Цвет — код `62` с ближайшим ACI (`aci_color()`: палитра
  1 красный, 2 жёлтый, 3 зелёный, 4 cyan, 5 синий, 6 magenta, 7 чёрный/белый, 8 серый, 9 светло-серый,
  30 оранжевый, 33 коричневый, 41 бежевый — последние два ради типов потолка); чёрный и `None` — по слою.
- **Заливок в R12 нет.** `fill` сплошной пропадает. Следствие для компоновки: не рисовать «белую маску»
  поверх штриховки — вырезать зону вокруг мебели/проёмов до штриховки, тогда DXF = SVG.
- Штриховки-паттерны: SVG хранит `<pattern>` с линией; DXF рисует линии сканлайнами внутри полигона
  (`_hatch_lines`, поворот полигона → горизонтальные линии → обратно). Соответствие углов: SVG-паттерн —
  вертикальная линия, повёрнутая на θ по часовой (Y вниз) → **DXF-угол = 90 + θ**. Перекрёстная — два прохода
  135° и 45°; точечная — `CIRCLE` r = 0,12·шаг в узлах сетки внутри полигона. Проверять на квадрате 10×10:
  число линий/кругов и направление.
- `path`: поддержаны `M L H V Q A Z` (абсолютные и относительные). `Q` сплющивается на 8 отрезков; `A` — по
  endpoint-параметризации SVG 1.1 §F.6.5 на 16 отрезков (раньше дуга становилась хордой, а Q давал 0 сущностей).
  Для дуг открывания дверей лучше явный `arc()` → сущность `ARC`.
- Проверка DXF без CAD: пробой на сущности (`review/probe_dxf.py` в проекте: считает LINE/CIRCLE по типу
  узора, сравнивает entities для разных цветов, ищет линии HATCH внутри фасадов) и открыть в NanoCAD /
  онлайн-вьюере, глазами на кириллицу и слои.

## SVG → PNG / PDF

- PNG: headless Chrome/Edge/Chromium `--headless=new --screenshot --window-size=W,H` со страницей-обёрткой;
  размер берётся из атрибутов `width/height` SVG в мм (`render_png.svg_size_mm`), 150–200 dpi. Проверять
  сигнатуру PNG и размеры IHDR — старый или обрезанный файл не должен маскировать сбой браузера.
  `--allow-file-access-from-files`, если `@font-face` с локального TTF.
- PDF альбома: один HTML, каждый лист в `<div class="sheet pWxH">`, на каждый уникальный размер — именованная
  `@page pWxH { size: W H; margin: 0 }` и `.pWxH { page: pWxH }`; `--print-to-pdf --no-pdf-header-footer`.
  Число страниц проверять регэкспом `/Type /Page(?!s)` = число листов. Собирать по **явному списку**, не по
  `glob` папки — устаревшие файлы прошлой нумерации иначе попадут внутрь при зелёном отчёте.
- Шрифт: чертёжный ISOCPEUR / GOST type B на машине отсутствует; стек `FONT` в `sheet.py`:
  `'ISOCPEUR','GOST type B','GOST Type BU','PT Sans Narrow','Arial Narrow',Arial,Helvetica,sans-serif` —
  Chromium берёт первый установленный (Arial Narrow / Arial) курсивом, читается. Положить TTF в
  `engine/fonts/` — `album.font_face_css()` подключит (регистрирует только ISOCPEUR и GOST type B).

## XLSX без openpyxl

`xlsx_export.py` — OOXML на stdlib (zip + xml): вкладки по спецификациям, заголовок объединён по ширине
вкладки (`A1:<последняя колонка>1` — E для пятиколоночных, F для светильников, C для розеток), шапка,
группы жирным, числа числами. Гоча донора: заголовок в узкой колонке A с `wrapText` выглядит сломанным —
merge и без переноса. Проверять `openpyxl.load_workbook` (только для проверки, не для генерации).

## 3D из той же модели

`viewer3d.py` → один HTML с three.js (cdnjs r128): стены боксами с перемычками над проёмами и подоконными
частями, полы по типам, мебель W×D×H с номерами позиций, остекление лоджии, светильники. Проверка —
headless-скриншот с `--use-gl=angle --use-angle=swiftshader --enable-unsafe-swiftshader
--virtual-time-budget=6000`. Гоча: `Shape` в плоскости XY + `rotateX(−90°)` кладёт план так, что y → −z;
Shape с `−y` даёт зеркальные полы за фасадом — ловится только глазами на скриншоте.

## Проверки, без которых DXF «работает» только на словах

1. Открыть в CAD или вьюере хотя бы один лист каждой группы: кириллица, слои, толщины.
2. Пробой на узоры и цвета (см. выше) после любой правки `DxfCanvas`.
3. Сравнить число сущностей SVG и DXF на одном листе — расхождение указывает на молча пропущенный примитив
   (был случай: `Q` в `path` → 0 сущностей).
