# Плейбук dunning (RU)

Восстановление неудавшихся платежей ExampleProduct и снижение недобровольного оттока. Биллинг — **ЮKassa** (`webhooks/yukassa`).

## Зачем
Неудавшиеся платежи — 30-50% всего оттока подписок, большинство восстановимы. Эффективный dunning возвращает 50-60% неудавшихся платежей.

## Таймлайн
```
День -30…-7: Pre-dunning (предотвратить)
День 0:      Платёж не прошёл → Ретрай #1 + Письмо #1
День 1-3:    Ретрай #2 + Письмо #2
День 3-5:    Ретрай #3
День 5-7:    Ретрай #4 + Письмо #3
День 7-10:   Финальный ретрай + Письмо #4 (финал)
День 10-14:  Конец grace → Пауза/отмена
День 14+:    Win-back серия
```

## Pre-dunning

### Управление истечением карты
| Тайминг | Действие |
|---------|----------|
| За 30 дней | Письмо: «Карта •4242 истекает в след. месяце» |
| За 15 дней | «Обновите способ оплаты» |
| За 7 дней | «Карта истекает через 7 дней» |
| За 3 дня | In-app баннер в academy |

**Шаблон письма (истечение карты):**
```
Тема: Карта •4242 скоро истекает
Здравствуйте, [Имя]!
Карта, привязанная к подписке ExampleProduct, истекает [дата].
Обновите способ оплаты, чтобы не потерять доступ к трекам:
[Обновить способ оплаты →]
Это меньше 30 секунд.
— Команда ExampleProduct
```

### Обновление карт (RU)
В РФ нет Visa/Mastercard Account Updater программ в прежнем виде. Вместо этого:
- **СБП / привязка по подписке:** для рекуррентов через СБП обновление реквизитов на стороне банка.
- **Карты МИР + НСПК:** проверить поддержку токенизации/обновления у ЮKassa.
- **Резервный способ оплаты:** запрашивать после первого успешного платежа («Добавьте запасную карту»), лучший тайминг — после восстановления неудавшегося платежа.

### Pre-billing уведомления
Для годовых подписок (−20%) / высокоценных B2B-когорт: письмо за 7 дней с суммой и датой, ссылка на обновление оплаты, что входит в продление. Требуется офертной практикой для авто-продлений.

## Умные ретраи

### Классификация отказов
| Тип | Примеры | Ретрай? |
|-----|---------|---------|
| Soft | Недостаточно средств, таймаут, ошибка обработки | Да — 3-5 раз за 7-10 дней |
| Hard | Карта закрыта/украдена/истекла | Нет — запросить новую |
| Аутентификация | 3DS / подтверждение СБП | Отправить клиента подтвердить |

### Расписание (логику ретраев держим на своём бэкенде — ЮKassa не имеет smart retries)
| Ретрай | Тайминг |
|--------|---------|
| 1 | День 1 (24ч), утро, тот же день недели |
| 2 | День 3, другое время |
| 3 | День 5, после типичной зарплаты (1/15) |
| 4 | День 7, утро буднего дня |
| 5 (финал) | День 10, последняя попытка до конца grace |

Инсайты: ретрай в день месяца, когда платёж проходил; после дат зарплат (1, 15); не на выходных; утро (8-10 по местному) чуть лучше.

## Dunning-письма

### Письмо 1 — Платёж не прошёл (День 0). Тон: дружелюбный.
```
Тема: Нужно действие — платёж не прошёл
Здравствуйте, [Имя]!
Мы пытались списать оплату [тип карты] •[последние 4] за подписку ExampleProduct (XXX ₽), но не получилось. Обычно помогает обновление карты.
[Обновить способ оплаты →]
Доступ к трекам пока не затронут — мы повторим автоматически, но обновить карту быстрее.
— Команда ExampleProduct
```

### Письмо 2 — Напоминание (День 3). Тон: помогающий, чуть срочнее.
```
Тема: Напоминание — обновите оплату для ExampleProduct
Здравствуйте, [Имя]!
Мы всё ещё не смогли обработать платёж XXX ₽.
[Обновить способ оплаты →]
Ваш прогресс, XP и сертификаты в сохранности, но нужен рабочий способ оплаты.
— Команда ExampleProduct
```

### Письмо 3 — Срочность (День 7). Тон: прямой, последствия.
```
Тема: Доступ к ExampleProduct будет приостановлен через 3 дня
Здравствуйте, [Имя]!
Несколько попыток списания не прошли. Если не получим оплату до [дата], доступ будет приостановлен, и вы потеряете доступ к:
• трекам и урокам   • симуляторам с AI-тьютором   • прогрессу/XP
[Обновить способ оплаты →]
Данные не удаляются — реактивация в любой момент.
— Команда ExampleProduct
```

### Письмо 4 — Финал (День 10). Тон: финальный, без вины.
```
Тема: Последний шанс сохранить доступ к ExampleProduct
Здравствуйте, [Имя]!
Последнее напоминание. Платёж XXX ₽ просрочен, доступ будет приостановлен завтра ([дата]).
[Обновить способ оплаты →]
После паузы: прогресс хранится [90 дней], реактивация в любой момент.
Если вы хотели отменить — ничего делать не нужно.
— Команда ExampleProduct
```

Прямая ссылка на обновление (минимум кликов), показать что потеряют, не обвинять, plain text. Вёрстка — `html-email`, логика — `n8n`.

## Grace-период

| Настройка | Рекомендация |
|-----------|--------------|
| Длительность | 7-14 дней после финального ретрая |
| Доступ | Деградированный (read-only треки) или полный |
| Видимость | In-app баннер «Платёж просрочен» |
| Ретрай | Продолжать фоном |
| Коммуникация | Письма продолжаются |

Деградация: полный доступ (B2B-когорта — меньше трения, выше recovery); read-only (B2C — срочность без страха потери прогресса); мгновенный lockout (не рекомендуется).

После grace: пауза (не удаление); день 1 «Доступ приостановлен»; день 7 «Прогресс на месте»; день 30 win-back; день 90 предупреждение об удалении (с учётом 152-ФЗ).

## Настройка у провайдера (RU)

### ЮKassa
Рекуррентные платежи (автоплатежи) — настройка повторных списаний; webhook `payment.succeeded` / `payment.canceled` / `payment.waiting_for_capture`; кастомные ретраи через свой бэкенд (ЮKassa не имеет «smart retries» — логику ретраев и классификацию отказов держать у себя по расписанию выше). Промокоды и рефералка — на стороне academy.

## In-app dunning

### Баннер
```
⚠ Платёж XXX ₽ не прошёл. Обновите карту, чтобы не потерять доступ к трекам. [Обновить →] [Скрыть]
```
Показывать на каждой загрузке academy в период dunning; dismiss допустим (показывать снова в след. сессии); прямая ссылка; не блокировать продукт.

### Модалка (для финала)
```
Доступ к ExampleProduct будет приостановлен [дата]
Обновите способ оплаты, чтобы сохранить доступ к [N] трекам, прогрессу и сертификатам.
[Обновить способ оплаты]   [Напомнить позже]
```

## Метрики

| Метрика | Таргет |
|---------|--------|
| Recovery rate | 50-60% |
| Recovery по типу | Soft 70%+, Hard 40%+ |
| Время до восстановления | <5 дней |
| Pre-dunning prevention | 20-30% |
| Open rate dunning-писем | 60%+ |
| Click rate | 30%+ |

Данные — `product-analytics` / `yandex`; платежи — ЮKassa + Postgres `yourname_academy`. ROI: при ежемесячном неудавшемся MRR 10K ₽ рост recovery с 30% до 60% = +3K ₽/мес = +36K ₽/год при минимальных затратах на автоматизацию.
