# Batch research at scale — playbook

> Прогон Perplexity Max по 100+ сущностям без выгорания rate limits, кук и нервов.
> Основано на ~3000 запросов через `pplx-max.py` 5 мая 2026 (701 российская компания, досье на ЛПР).

---

## Кратко

| Параметр | Single query | Batch (5 в одном) | Speedup |
|----------|--------------|-------------------|---------|
| Время на сущность | ~30 сек | ~14 сек | 2× |
| С 3 workers | ~10 сек | ~4.5 сек | 6× от наивного |
| Rate-limit риск | низкий | средний (контролируется) | — |
| Качество | эталон | -10% (модель режет хвост) | приемлемо |

Если у тебя <50 сущностей — иди single queries. Если 50-100 — подумай. Если 100+ — batch обязателен.

## Паттерн

### 1. Один запрос — N сущностей с маркерами

В промпте — пронумерованный список и **строгая** структура ответа с маркером `## Тип N: ...`:

```
Подготовь краткие досье (по 150-200 слов) по этим 5 компаниям:

1. **крупный банк** — ИНН 7700000000
2. **Альфа-Банк** — ИНН 7728168971
3. ...

Для **каждой** в формате:

## Компания {N}: {Название} [{ИНН}]

**ЛПР:** ...
**Новости:** ...
**Триггеры:** ...

Со ссылками [1][2]. Не пропускай ни одну.
```

**Критично:**
- «Не пропускай ни одну» — без этой строки модель режет хвост батча на 1-2 элемента.
- Структура с `## Тип N:` — нужна для парсинга обратно.
- Слов на сущность — 100-200 (250+ срезает хвост, 50 — слишком плоско).
- Шаблон с `{N}` в синтаксисе ответа нужен, чтобы модель его держала.

### 2. Парсинг ответа

```python
import re

def parse_response(text, batch):
    """Split response into per-entity chunks by ## Type N: marker."""
    # Поддерживаем и кириллицу, и латиницу — модель иногда переключается
    chunks = re.split(r'\n(?=## ?(?:Компания|Company)\s*\d)', text)
    results = {}
    for chunk in chunks:
        chunk = chunk.strip()
        if not chunk: continue
        m = re.match(r'## ?(?:Компания|Company)\s*(\d+)[:.\s-]+(.+?)(?=\n)', chunk)
        if not m: continue
        n = int(m.group(1))
        if 1 <= n <= len(batch):
            results[batch[n - 1]['id']] = chunk
    return results
```

**Edge cases:**
- Модель пишет `## Компания` или `## Company` — поддерживай оба.
- Иногда `##Компания` без пробела — `## ?` в regex.
- Разделители после номера — `:`, `.`, ` -`, ` ` — `[:.\s-]+`.
- Иногда сущности 4 из 5 — `if 1 <= n <= len(batch)` отбрасывает мусор.
- Иногда модель путает порядок (3, 1, 2, 5, 4) — это ОК, парсер по номеру.

### 3. Idempotent execution

Для каждой сущности — отдельный `.md` файл:

```python
md_path = os.path.join(out_dir, f"{p['id']}.md")
if os.path.exists(md_path):
    content = open(md_path, encoding='utf-8').read()
    if len(content) > 300 and 'ERROR' not in content[:50]:
        continue  # skip — уже сделано
```

Если упал посередине — просто запусти снова, доделает хвост. Никаких state-файлов, никаких progress.json.

## Эмпирика rate limits (3000+ запросов, 5 мая 2026)

| Workers | Batch | Mode | Поведение |
|---------|-------|------|-----------|
| 6 | 5 | pro | ~30 батчей стабильно → потом массовые `NoneType` (cookies деградировали) |
| 3 | 5 | pro | ~50 батчей стабильно → редкий NoneType, продолжает |
| 1 | 5 | pro | стабильно 100+ батчей |
| 1 | 3 | auto + fallback pro | стабильно бесконечно |
| 1 | 3 | auto | быстро (~20 сек/батч) но хуже качество на cold-сущностях |

### Что значит «NoneType»

`pplx-max.py` возвращает `None` когда:
- Cookies устарели (внезапно после долгого прогона — Perplexity ротирует session token)
- Rate limit (НЕ HTTP 429, а молчаливый отказ от вызова инструмента поиска)
- Cold/obscure сущность — модели нечего сказать, она возвращает пустой ответ
- Капча в фоне (visible только если открыть Perplexity в браузере)

**Это не чинится наращиванием retries.** Нужен gentle-режим или ручной перевыпуск кук.

### Cold entities — отдельная боль

Компании со слабой публичной заметностью (региональные, B2B-нишевые, недавно созданные) дают NoneType **системно**. Не помогает:
- ❌ Retry 3x подряд
- ❌ `--mode "deep research"`
- ❌ Увеличение timeout

Помогает:
- ✅ Batch=3 (меньше нагрузка на сессию)
- ✅ `mode=auto` (модель сама решает не лезть в reasoning, отвечает базовое)
- ✅ Уменьшение объёма (50 слов вместо 150 — «если данных мало, кратко о бизнесе»)

## Fallback chain

```
pro → auto → batch=3 → 1 worker + sleep(1) → ручной перевыпуск cookies
```

**Правило:** когда срывается — **снижай агрессию**, не наращивай retries. Контринтуитивно, но это про rate-limiting в адаптивных системах.

### Скорости в каждом режиме

| Режим | Сек/батч | Сек/сущность (batch=5) | Сущностей/час |
|-------|----------|------------------------|---------------|
| 6 workers, pro, batch=5 | 70 | 14 | 1300 (пока живёт) |
| 3 workers, pro, batch=5 | 70 | 14 | 770 |
| 1 worker, auto, batch=3 | 20 | 7 | 540 (gentle, навсегда) |
| 1 worker, deep research | 120 | 24 | 150 (для критичных) |

## Три сценария

### Сценарий 1: «Быстрый прогон» (50-200 сущностей)

```bash
# batch=5, 3 workers, pro
WORKERS=3 BATCH=5 MODE_PRIMARY=pro python batch_research_template.py /work
```

Ожидание: 30-60 минут, 5-10% хвост недоделан → доделать gentle.

### Сценарий 2: «Массовый прогон» (200-1000 сущностей)

```bash
# Стартуем агрессивно, переключаемся при срыве
WORKERS=3 BATCH=5 MODE_PRIMARY=pro python batch_research_template.py /work
# через ~50 минут начнётся NoneType. Прерываем (Ctrl+C).
# Перезапускаем gentle на хвост (idempotent — пропустит готовое):
WORKERS=1 BATCH=3 MODE_PRIMARY=auto MODE_FALLBACK=pro python batch_research_template.py /work
```

### Сценарий 3: «Доделать хвост» (после срыва)

```bash
# Самый щадящий режим
WORKERS=1 BATCH=3 MODE_PRIMARY=auto MODE_FALLBACK=pro SLEEP=1 \
  python batch_research_template.py /work

# Если хвост всё равно NoneType — это cold entities, не rate limit.
# Перезапусти с promptом «если данных мало — 50 слов о бизнесе».
```

## Чеклист перед запуском

- [ ] **Cookies живые.** Открой Perplexity в браузере, проверь что залогинен.
- [ ] **`__Secure-next-auth.session-token`** в `.credentials.master.env` обновлён за последние 14 дней.
- [ ] **Сделал тестовый запрос** одной сущности через `pplx-max.py` — отвечает за 30 сек.
- [ ] **`queue.json` собран** — список `[{"id": ..., "name": ..., "context": ...}]`.
- [ ] **`out_dir` пустой или с предыдущими `.md`** (для idempotency).
- [ ] **`build_prompt` адаптирован** под юзкейс. Маркер `## ТипN:` совпадает с regex в `parse_response`.
- [ ] **Тестовый прогон 5 сущностей** (1 батч) — проверь что `.md` файлы создались по `id`, не по индексу.
- [ ] **Запуск в screen/tmux/nohup** для длинных прогонов (>15 минут).

## Юзкейсы и шаблоны промптов

### A. B2B-компании (досье на ЛПР)

```
Подготовь краткие досье (по 150-200 слов на каждую) для B2B-продаж по этим
{N} российским компаниям на 2026 год:

{numbered_list}

Для **каждой** компании дай ровно такую структуру:

## Компания {N}: {Название} [{ИНН}]

**ЛПР:** имя + должность (CDTO/CIO/CTO, HR/L&D-директор).
Если данных нет — "нет в открытых источниках".

**Свежие новости (2025-2026):** ключевые события, сделки, смена топов.

**Сигналы для {product}:** AI-инициативы, обучение, HR-tech.

**Триггеры для outreach:** что произошло за 3-6 месяцев.

Со ссылками [1][2]. Не пропускай ни одну компанию.
```

### B. Люди (досье для outreach)

```
Подготовь краткие профили (по 100-150 слов) этих {N} людей:

{numbered_list}

Для **каждого** в формате:

## Person {N}: {Имя} [{ID}]

**Текущая роль:** должность + компания + город.
**Бэкграунд:** ключевой опыт за последние 5 лет.
**Публичные сигналы:** LinkedIn-посты, статьи, выступления 2024-2026.
**Точки контакта:** что упомянуть в первом письме.

Со ссылками. Не пропускай никого. Если данных нет — "нет в открытых источниках".
```

### C. Темы / технологии / события

```
Подготовь краткие обзоры (по 200 слов) этих {N} тем на 2026 год:

{numbered_list}

Для **каждой** в формате:

## Topic {N}: {Название} [{ID}]

**Что это:** определение в 1 предложении.
**Состояние рынка:** ключевые игроки, объём, рост.
**Свежие события 2025-2026:** запуски, M&A, регулирование.
**Что почитать:** 2-3 ссылки на авторитетные источники.

Со ссылками. Не пропускай ни одну тему.
```

```
Кратко (по 80-100 слов) опиши эти {N} сайтов:

{numbered_list}

Для **каждого**:

**Что это за проект:** одно предложение.
**Аудитория и трафик:** оценка по открытым данным.
**Свежие изменения:** редизайн, релизы, новости проекта 2025-2026.
```

## Известные баги и обходы

| Симптом | Причина | Обход |
|---------|---------|-------|
| Все батчи возвращают `None` | Cookies протухли | Открой Perplexity в браузере → DevTools → Cookies → обнови `.credentials.master.env` |
| Парсер находит 3 из 5 | Модель срезала хвост | Уменьши batch до 3-4, добавь «не пропускай» жирным |
| `## Company 1:` вместо `## Компания 1:` | Модель переключилась | Regex `(?:Компания\|Company)` — поддерживает оба |
| `## Компания 0` или `## Компания 6` | Модель путает нумерацию | `if 1 <= n <= len(batch)` отбрасывает мусор |
| Время на батч 200+ сек | `deep research` mode случайно | Проверь `--mode` — должен быть `pro` или `auto` |
| Cold-entity вернула «нет данных» | Это нормально для obscure | Сохрани как есть, не ретраить |
| Subprocess зависает >300 сек | Cookies деградировали в фоне | `timeout=300`, не уходи в `timeout=600` |

---

## Когда НЕ применять batch

- **<30 сущностей** — overhead парсинга и регрессия качества не окупается.
- **Каждая сущность требует deep research** (часы, не минуты на каждую) — single + `--mode "deep research"`.
- **Сущности крайне разнородные** (компания, событие, человек в одном батче) — модель путается, парсинг ломается.
- **Нужны точные цифры с источниками для каждой** — batch съедает детали, single сохраняет.
- **Cookies в любую секунду могут протухнуть** (прод-сценарий) — лучше API ключ, sonar-pro, без cookies-зависимости.
