# ДНК карандашного стиля

Правила, по которым кадр узнаётся как «нарисовано карандашом», и числа, которыми они записаны в движке эталона
`<эталон>/`: `engine/core.js`, `engine/pencil.js`, `engine/hero.js`, `pencil/lib.js`,
`pencil/scenes.js` (прочитаны 05.10.2026).

Как читать:

- (с. N) — страница методички, выжимка в `methodology.md`.
- Числа без пометки взяты из кода эталона. «Проверено» значит, что кадры сняты `render/still.py` и сравнены
  попиксельно.
- Единица мира — 1 px кадра при zoom 1 (ширина кадра 1920 в 16:9 и 1080 в 9:16). Начало координат — центр кадра,
  ось y смотрит вниз.

Просьба «нарисуй карандашом» без этих приёмов даёт аккуратную векторную графику (с. 5). Рисованный вид держится на
трёх трюках классической анимации (двойки, кипящие линии, рваная линия с фактурой) и на звуке в кадр (с. 5–9).
Задача фактуры одна: как можно больше дефектов, которые оставил бы человек (с. 8). Звук описан в `workflow.md`,
раскадровка и стыки сцен — в `storyboard.md`.

## ДНК в десяти правилах

Методичка требует 6–10 правил, без которых стиль не узнаётся (с. 23). Вот они для этого стиля.

| № | Правило | Где в движке | Как проверить на кадрах | с. |
| --- | --- | --- | --- | --- |
| 1 | На двойках: видео 24 кадра/с, рисунок меняется 12 раз/с | всё от `tt = K.twos(t)`, номер рисунка `pen.d` | кадры 2n и 2n+1 совпадают до пикселя | 6, 23 |
| 2 | Линии кипят и в покое; случайность только с зерном | `K.rngOf(id, pen.d)`, `Math.random` нет | соседние рисунки отличаются по контурам, повторный рендер — те же пиксели | 7, 20, 23 |
| 3 | Штрих — лента с нажимом: сужение, разрывы, второй проход, перелёт | `pen.line` | на крупном плане концы тоньше, замкнутый контур заходит за старт | 8 |
| 4 | Тон — штриховкой, а не заливкой; на светлой бумаге штрихуется тень | `pen.hatch`, `pen.fill` | ровных заливок нет, кроме мелких тёмных пятен (`pen.solid`) | 8, 14 |
| 5 | Бумага потёртая, с клеткой и виньеткой | `makePaperTile`, `LIB.paperWorld`, `LIB.vignette` | видны зерно и волокна; клетка не кипит | 8, 14 |
| 6 | В начале сцены видны бледные строительные линии, потом гаснут | `pen.guides(items, k)` | на первом кадре они есть, к действию их уже нет | 8, 14 |
| 7 | Моушн-блюра нет; камера тоже движется на двойках | камера считается от `tt` | на кадрах нет смаза движения | 6, 14, 23 |
| 8 | Цветной карандаш и тёплая бумага — по умолчанию с первого кадра (выбор владельца 05.10); дуга методички «графит до поворота» — по заказу (`COLOR_FROM`) | `LIB.setTint`, `cfg.color`, `camera(cam, warm)` | лист кадров тёплый и цветной, графит — только там, где задуман | 17 |
| 9 | Текст пишется рукой: дрожь и проявление по буквам; кегль не ниже порога | `pen.text` | высота заглавной ≥ 48 px на 1080 px ширины | 18, 19 |
| 10 | Переходы камерой и формой; свечение — только у акцентов на тёмной бумаге | стыки в `storyboard.md`; в «тетради» свечения нет | простых склеек нет, на светлой бумаге нет ореолов | 14, 15 |

## 1. Время: двойки

```js
// core.js
const twos = t => Math.floor(t * 12 + 1e-6) / 12;
// pencil.js, class Pen
frame(t) { this.t = t; this.d = Math.floor(t * 12 + 1e-6); }   // d = drawing index = boil seed
// scenes.js
function renderAt(t) {
  pen.frame(t);
  const tt = K.twos(t);
  ctx.setTransform(1, 0, 0, 1, 0, 0);
  const sc = TIMING.scenes.find(s => t >= s.start && t < s.end) || TIMING.scenes[TIMING.scenes.length - 1];
  SCENES[sc.name](tt, t);
  LIB.vignette(ctx);
}
```

- Сцена — функция `sN(tt)`. От `tt` считаются позы, камера, проявление `p`, моргание `blinkAt(tt)`. Рот берёт
  `K.mouthAt(t)`, который сам округляет время до двоек.
- Сцену выбирают по сырому `t`, поэтому стык может прийтись на середину пары кадров. Это нормально.
- Кипение берёт номер рисунка `pen.d`: 12 новых рисунков в секунду (с. 7).
- Состояния между кадрами нет: любой кадр считается заново от `tt`, поэтому кадры можно рендерить по отдельности и
  в любом порядке, а повторный рендер даёт тот же ролик (с. 23). Кэши движка (`pen.pats`, `svgCache`) детерминированы
  и этому не мешают.
- Проверено (9:16, 05.10.2026): кадры 10,0 и 10,0417 с совпадают до пикселя, кадры 10,0833 и 10,125 с — тоже. Между
  10,0 и 10,0833 с отличаются 5,66 % пикселей: это кипят линии. Повторная загрузка страницы на 10,0 с даёт тот же md5.
- Время для `still.py` задавать точно, как номер кадра, делённый на 24. Строка `10.083333` даёт
  `floor(120.999996 + 1e-6) = 120`, то есть тот же рисунок, что на 10,0 с, и выглядит как «кипение сломалось». Запас
  `1e-6` в `twos` спасает только от погрешности деления `i / 24` в рендерере.

## 2. Кипение линий

```js
// pencil.js, Pen.line: one generator per stroke and drawing
const r = K.rngOf(o.id || 'l', this.d);
const ph1 = r() * 6.283, ph2 = r() * 6.283, ph3 = r() * 6.283,
      f1 = 0.010 + r() * 0.012, f2 = 0.035 + r() * 0.03;
// for every resampled point, s = arc length so far
const off = amp * (Math.sin(s * f1 + q1) * 0.65 + Math.sin(s * f2 + q2) * 0.35) + (rr() - 0.5) * 0.3 * amp;
```

- Точки штриха сдвигаются по нормали на сумму двух синусоид и мелкого шума ±0,15·amp. Длинная волна
  2π/f1 ≈ 285–630 ед., короткая 2π/f2 ≈ 97–180 ед. Фазы и частоты новые на каждом рисунке.
- Амплитуда `amp = o.boil × pen.boilAmp`, оба по умолчанию 1. Основной проход сдвигается до ±1,15 ед., второй — в
  1,6 раза сильнее.
- Где `boil` меняли: строительные линии 0,7, зачёркивания `crossOut` 1,4. Каракуль поверх «испорченной картинки»
  сделан штриховкой с `jitter: 6`.
- `id` — имя части объекта, одно и то же на всех кадрах: `'sheet'`, `id + 'outer'`.
  - Без `id` все штрихи берут общее зерно `'l'` (штриховка — `'h'`) и дрожат одинаково, как под копирку.
  - В `id` нельзя класть меняющиеся числа (координаты, прогресс): зерно станет новым на каждом кадре, и линия
    «поплывёт» вместо того, чтобы кипеть.
  - Исключение — намеренная смена рисунка: `'sunf' + o.sunColor` даёт новую штриховку солнца при смене цвета,
    `'n' + label` — новую цифру календаря.
- Две копии одного объекта в кадре получают разные `id`: герой `'hero'`, рассказчик в 9:16 `'narr'`, мини-герой
  `'mini'`, герои в миниатюрах `'th' + i + 'h'`.
- Случайная раскладка (звёзды, листы в стопке, пятна ластика) — свой генератор на каждый объект:
  `K.rngOf(id, 'sheet', k)`, `K.rngOf('eraser', k)`. Тогда появление и пропуск соседей ничего не сдвигают. Если
  генератор общий на цикл — сначала вытянуть все числа, потом пропускать невидимое (с. 20, 23).
- «Случайное» мигание тоже идёт на двойках: лампочки сервера горят при `K.rngOf(id, 'led', k, pen.d)() > 0.4`.

Заморозка — приём «больше ничего не изменилось» в сцене поворота (замер, что дерево не сдвинулось, — в
`storyboard.md`):

```js
// scenes.js, s4: the picture and the hero stop boiling after the click; only the captions keep boiling
const freeze = tt >= CLICK + 0.45 && tt < W('пиксель').e + 0.35;
const dSave = pen.d;
if (freeze) pen.d = Math.floor((CLICK + 0.45) * 12);
// ... landscape + hero with mouth: 0, blink: 0 while frozen ...
pen.d = dSave;
```

## 3. Штрих-лента: `pen.line(pts, o)`

Штрих — не линия `stroke()`, а залитая лента: левый и правый край строятся от центральной линии, полоса заливается
паттерном графита.

| Параметр | Значение по умолчанию | Что даёт |
| --- | --- | --- |
| `w` | 3, умножается на `pen.wMul = 1.2` → 3,6 ед. | толщина основного прохода |
| шаг ресэмплинга | `max(2.5, min(7, w × 1.4))` → 5,04 ед. при w 3,6 | гладкость и частота шума |
| сужение (`taper`) | первые 14 % и последние 20 % длины, smoothstep; кончик — 30 % ширины, но не тоньше 0,5 ед. | «нажал — отпустил» |
| нажим | `0.84 + 0.16 × sin(s × 0.027 + ph3)`: ширина 68–100 %, волна ≈ 233 ед. | неровная толщина по длине |
| второй проход | ширина ×0,42, прозрачность ×0,38, кипение ×1,6, своё зерно `(id, 'sk', d)`; только при `passes > 1` и w > 1,1 | набросочный след поверх |
| перелёт (`over`) | замкнутый контур продолжается за старт на 6 % точек; `over: false` выключает | контур «не попал в точку» |
| разрывы (`gaps`) | только на штрихах длиннее 140 ед.; без параметра — 0, 1 или 2 отрыва (в среднем 0,8): место 15–85 % длины, длина 2,5–7,5 шага, на каждом рисунке новые | карандаш оторвался от бумаги |
| `gaps: 0` / `gaps: n` | без разрывов / ровно n разрывов | глаза, мелочь — без разрывов; тело героя — 1, внутренний контур — 2 |
| `alpha` | 0,9 | |
| `p` | проявление 0..1: рисуется первая доля точек | штрих «рисуется» |
| текстура | лента заливается `pen.pattern(color)`: шум 256 px, непрозрачность пикселя 0,42–1,0 и 260 «зубцов» бумаги | зерно графита внутри линии |

```js
// pencil.js, Pen.line: pressure ribbon (u = 0..1 along the stroke)
const tp = o.taper === false ? 1 : K.smooth(Math.min(1, u / 0.14, (1 - u) / 0.2));
const press = 0.84 + 0.16 * Math.sin(s * 0.027 + ph3);
const hw = Math.max(0.25, w * wmul * (0.3 + 0.7 * tp) * press) / 2;
```

Толщины в эталоне (до умножения на 1,2):

- контуры предметов 3–3,6: `card` 3, `genBox` 3,6, сервер 3,4; контур героя 3,4, его внутренний контур 1,6;
- детали 1,6–2,6, строительные линии 1,6;
- пометки-акценты 4,5–7: красное кольцо 4,5–5, галочка 6, зачёркивание и лупа 7.

## 4. Штриховка вместо заливки, заслонение бумагой

`pen.hatch(region, bb, o)` штрихует область `Path2D` в пределах прямоугольника `bb`.

| Параметр | По умолчанию | Как работает |
| --- | --- | --- |
| `angle` | −0,9 рад (≈ −52°): штрих идёт снизу-слева вверх-вправо | направление рядов |
| `gap` | 7 | расстояние между рядами, каждый ряд ×0,75–1,25 |
| `len` | 70 | длина штриха ×0,45–1,35 |
| `dash` | 7 | промежуток между штрихами в ряду 0..`dash` |
| `w` | 1,6 | три толщины штрихов: ×0,7, ×1,0, ×1,3 |
| `alpha` | 0,7 | |
| `jitter` | 1 | концы кипят на ±0,8·jitter, изгиб ±2 постоянный и ±0,5·jitter кипящий |
| `cross` / `crossAngle` | нет / 1,25 рад | второй слой под углом, прозрачность ×0,8 |
| `p` | 1 | ряды появляются один за другим поперёк области |

```js
// pencil.js, Pen.hatch: the layout stays put, only the stroke ends boil
const rs = K.rngOf(o.id || 'h', 'stable'), rb = K.rngOf(o.id || 'h', this.d);
```

- Раскладка штрихов берётся из постоянного генератора, поэтому штриховка не прыгает, а только дрожит.
- `pen.fill(P, o)` — цветной карандаш, единственная «заливка» стиля: штриховка `gap 4.2, w 2.4, alpha 0.62, len 60`
  в два слоя с углом 0,5 рад.
- Тон в эталоне: штриховка цветом линии с прозрачностью 0,08 (лист программы) – 0,45 (берет), тень карточки 0,4;
  цветной карандаш `pen.fill` — 0,3–0,9.
- Свет — сверху слева, в обоих стилях одинаково:
  - тень карточки — многоугольник справа и снизу со сдвигом 12 ед. (`alpha 0.4, gap 4.5, angle -0.8`);
  - тень белка у героя — серп: белок минус его копия, сдвинутая на (−26, −16);
  - в 3D ключевой свет тоже стоит сверху слева (`dna-gloss3d.md`).
- На светлой бумаге штрихуют тень, на тёмной — свет (с. 8). Штриховка света на светлой бумаге даёт «негатив» (с. 20).
- `pen.paper(P)` заливает фигуру текстурой бумаги: передний предмет закрывает задний, а зерно остаётся.
  - Порядок для каждой части: `pen.paper` → тон → контур. Порядок вызовов — это порядок слоёв, дальнее рисуется
    первым.
  - `paper()` вызывать только когда часть уже проявляется (`p > 0`). Иначе «ластик» сотрёт задний план раньше, чем
    появится предмет (с. 20).
  - В `hero.js` ноги, лавр и руки проверяют своё окно проявления, а тело, тога, значок и глаза закрываются бумагой
    всегда. Пока `reveal = 1` (так во всём эталоне), этого не видно; если анимировать `reveal`, проверку нужно
    добавить.
- `pen.solid(P, color, alpha)` — плотное пятно графитом: зрачки, рот, прорезь автомата. Только для мелких тёмных
  мест.

## 5. Бумага, клетка, виньетка

- Плитка бумаги `makePaperTile(512, pal)`:
  - цвет `pal.paper` и шум на каждый пиксель ±4,5 уровня; у 1,2 % пикселей тёмная крапинка до −18; синий канал
    получает шум ×0,9, поэтому бумага чуть тёплая;
  - 70 волокон длиной 6–32 px и толщиной 0,6–1,2 px, цвета `rgba(120,100,70,0.10)` или `rgba(255,255,255,0.25)`;
    волокна рисуются с переносом через край, поэтому плитка повторяется без шва;
  - зерно задано `K.rngOf('paper', pal.name)`: у палитры с другим именем другое зерно.
- `LIB.paperWorld(pen, cam, warm)` — очистка кадра, её делает `camera()` первой в каждой сцене:
  - заливает видимую часть мира плюс 40 ед. запаса паттерном бумаги;
  - тёплый тон `'#F6D9A8'` с прозрачностью 0,22·warm;
  - клетка тетради шагом 48 ед., цвет `rgba(96,146,205,0.13)`, толщина `1.2 / cam.zoom`, то есть постоянная на
    экране. Клетка «напечатана»: она чёткая и не кипит.
- `LIB.vignette(ctx)` — радиальный градиент от 0,45·min(W, H) до 0,62·hypot(W, H), от `rgba(60,45,25,0)` до
  `rgba(60,45,25,0.16)`; рисуется в экранных координатах последним.
- Паттерны канвы подчиняются текущей трансформации: на наезде камеры зерно бумаги и графита крупнеет вместе с
  рисунком.
- Постоянных следов ластика и недотёртых призраков линий (с. 8) в эталоне нет. Есть только переход-ластик s1 → s2
  (раздел 9).

## 6. Строительные линии

```js
// pencil.js
guides(items, k, id = 'g') {
  if (k <= 0.01) return;
  for (let i = 0; i < items.length; i++)
    this.line(items[i], { w: 1.6, color: this.pal.guide, alpha: 0.85 * k, id: id + i, gaps: 0, passes: 1, boil: 0.7 });
}
// scenes.js, s1: the cover frame is a finished sketch over its construction (h = hero feet, h.s = scale)
const h = S1.hero, gk = 1 - tw(tt, 5.4, 1.4);   // visible from 0 s, gone by 6.8 s (the hero wakes at 6.95)
pen.guides([
  PEN.ellipse(h.x, h.y - 200 * h.s, 130 * h.s, 160 * h.s),                 // head volume
  [[h.x, h.y - 400 * h.s], [h.x, h.y + 20]],                              // vertical axis
  [[h.x - 230 * h.s, h.y + 4], [h.x + 230 * h.s, h.y + 4]],               // ground line
  PEN.ellipse(h.x - 43 * h.s, h.y - 235 * h.s, 36 * h.s, 36 * h.s),       // eye circles
  PEN.ellipse(h.x + 43 * h.s, h.y - 235 * h.s, 36 * h.s, 36 * h.s),
  [[h.x - 150 * h.s, h.y - 235 * h.s], [h.x + 150 * h.s, h.y - 235 * h.s]], // eye line
], gk, 's1g');
```

Направляющие — круги объёмов, оси и линия земли под тем, что сейчас нарисовано, цветом `pal.guide`. Они гаснут до
первого действия героя.

## 7. Цвет: графит → цветной карандаш, тёплая бумага

- У героя `cfg.color` от 0 до 1: графитовая штриховка тона слабеет как (1 − color), цветная перекрёстная растёт как
  color. При color > 0,5 контур тела становится коричневым (`COL.crispDark`), при color > 0,3 кайма тоги — золотой.
- `cfg.fills` от 0 до 1 — сколько штриховки тона уже положено. В s1 она растёт с 0,15 до 0,3 за 0–5,5 с и до 1 к
  6,9 с (`ioQ`).

```js
// hero.js: one tone helper for every part — graphite fades out as colored pencil fades in
const tone = (Pts, color, greyAlpha, o = {}) => {
  const path = P.toPath(Pts), bb = P.bbox(Pts);
  const p = Math.min(o.p == null ? 1 : o.p, fp);                       // fp = cfg.fills
  if (greyAlpha > 0 && col < 1) pen.hatch(path, bb, Object.assign({ color: g, alpha: greyAlpha * (1 - col), gap: o.gap || 5.5, w: 1.3, len: 50, id: id + (o.k || 't') + 'g', p }, o.grey || {}));
  if (col > 0 && color) pen.hatch(path, bb, { color, alpha: (o.alpha || 0.7) * col, gap: o.cgap || 3.6, w: o.cw || 2.4, len: 55, cross: true, crossAngle: 0.55, id: id + (o.k || 't') + 'c', angle: o.angle == null ? -0.9 : o.angle, p });
  return path;
};
```

**По умолчанию — цветной карандаш целиком.** Владелец посмотрел первую карандашную версию (графит до середины, цвет
с монтажки) и сказал: «мне понравился карандашный стиль, но когда он был цветным… вторая часть» (05.10). Поэтому:

- общий тон листа `LIB.setTint(T)` (0 — графит, 1 — цветной карандаш) — каждый рисунок библиотеки сам добавляет свою
  цветную штриховку пропорционально тону (палитра художника, генератор, терминал, команда, сервер, листы, календарь,
  лупа, пейзаж); сцены выставляют тон раз за кадр в `renderAt`;
- в шаблоне `COLOR_FROM = 0` — цветной с первого кадра; `COLOR_FROM = <слово>` — графитный набросок до этого момента и
  «заливка цветом» за 0,6 с (`ioQ`) — приём «оживания»;
- тёплая бумага идёт вместе с тоном: `camera(c, warm = TINT)`; внутри картинок, в которые ныряет камера, тот же тон
  (`pictureGround`, `pitfalls.md` № 120);
- герой — `cfg.color = TINT` через `heroBase`;
- акценты сюжета остаются акцентами: красный — ошибка, зелёный — «готово», синий — код; в цветном мире их держит
  насыщенность и обводка, а не то, что вокруг серо.

Эталон: `pencil_color_land_v1.mp4` — графит только у спящего героя до пробуждения (6,6–7,4 с), дальше цвет до конца;
солнце в s4 сразу жёлтое (голос говорит «не жёлтого, а зелёного»), на слове «солнце» его обводит оранжевый
карандаш, на щелчке — зелёное.

Первая (графитная) версия эталона для сравнения:

- s1–s4 — герой и реквизит графитовые, цвет только у акцентов (синий код, красные ошибки, зелёная галочка,
  солнце жёлтое → зелёное);
- s5, 37,95–38,7 с — `col = E.ioQ(inv(37.95, 38.7, tt))`: монтажка и герой становятся цветными, бумага теплеет;
- s6–s7 — цвет 1 и тёплая бумага 1.

Методичка: до поворота тихо, мелко и холодно, после — ярко, крупно и тепло; тёплый акцент бережём для развязки
(с. 17, 23). В эталоне поворот (щелчок) оказался на 52 % длины, вне окна 35–45 % (разбор — `storyboard.md`).
В 3D герой становится цветным уже при пробуждении (6,6–7,4 с) и остаётся цветным: графитовый стикер среди цветных
глянцевых игрушек смотрится чужим. Роли цветов и тёплый акцент — `palettes.md`.

## 8. Текст рукой: `pen.text(str, x, y, o)`

- Шрифты по ключу `o.font`: `hand` / `handb` — Segoe Print обычный и жирный, `code` / `codeb` — JetBrains Mono,
  `sans` — Manrope ExtraBold. Кегль по умолчанию 48, прозрачность 0,95, буквы заливаются паттерном графита.
- Каждая буква дрожит отдельно: по x ±1,25 % кегля, по y ±1,5 %, поворот ±0,02 рад, всё ×`boil`. Зерно —
  `K.rngOf(o.id || str, pen.d)`: если `id` не задан, им становится сама строка.
- `o.p` — проявление по буквам: буквы появляются по одной, текущая открывается шторкой слева направо.
- Мел на доске — та же строка дважды, вторая со сдвигом (+1,2; +0,8) и прозрачностью 0,85.
- Подчёркивание — отдельный `pen.line` толщиной 5–7, когда строка дописана (`p > 0.95`).
- Это заливка глифа шрифта, а не письмо по центральной линии пера, как в методичке (с. 19). Если делать письмо
  пером, брать шрифт с линией одной толщины (monoline), иначе буквы рвутся и двоятся (с. 20).

Кегль считается от порога высоты заглавной: подпись от 48–56 px, слоган от 64 px на 1080 px ширины кадра (с. 18,
23). Высота заглавной у шрифтов эталона (замер по контурам букв):

| Шрифт | Заглавная / кегль | Подпись 48 px → кегль | 56 px → кегль | Слоган 64 px → кегль |
| --- | --- | --- | --- | --- |
| Hand, HandB (Segoe Print) | 0,75 (H 0,747, Н 0,761) | ≥ 64 | ≥ 75 | ≥ 86 |
| Code (JetBrains Mono) | 0,73 | ≥ 66 | ≥ 77 | ≥ 88 |
| Sans (Manrope) | 0,72 | ≥ 67 | ≥ 78 | ≥ 89 |

- Поле `sCapHeight` в Segoe Print занижено (0,680): мерить по контурам букв, а не по полю шрифта.
- В 9:16 эталон держал порог у заголовков и плаката: «раньше» 72, строки плаката 92 (заглавная 69 — уровень
  слогана), «Example Academy» 110. Ниже порога были подписи 42–46, «0 px» 54, промпт 60 (Code), терминал 30,
  «здесь / там» 34, строка бренда на плакате 44. В новом ролике такие подписи увеличивать.
- Весь текст — выше линии 85 % высоты кадра: при камере (0, 0, zoom 1) это y < 378 в 16:9 и y < 672 в 9:16 (с. 18,
  23). Как пересчитывать порог для 16:9 — `frame-checks.md`.

## 9. Камера и переходы

```js
// core.js: world -> screen; zoom 1 = 1920 world units across a 16:9 frame (1080 across 9:16)
function applyCamera(ctx, W, H, cam, base) {
  ctx.setTransform(1, 0, 0, 1, 0, 0);
  ctx.translate(W / 2, H / 2);
  ctx.scale(base * cam.zoom, base * cam.zoom);
  if (cam.rot) ctx.rotate(cam.rot);
  ctx.translate(-cam.x, -cam.y);
}
```

- `camera(cam, warm)` — первый вызов каждой сцены. Он ставит камеру и рисует бумагу. `BASE = CW / 1920` в 16:9 и
  `CW / 1080` в 9:16; при родном размере кадра `BASE = 1`.
- `camKeys(tt, [[time, cam], ...], ease = E.ioC)` интерполирует ключи через `K.lerpCam`: зум — по логарифму, x, y и
  поворот — линейно.
- `camOnRect(cx, cy, w, h)` — камера, в кадр которой целиком входит прямоугольник мира: `zoom = min(1920 / w,
  1080 / h)` в 16:9.
- Камера считается от `tt`, поэтому и она движется на двойках. Плавного движения на 24 кадрах и смаза нет (с. 6).
- Пролёт сквозь кадр (миниатюра, экран) должен закончиться минимум за 2 кадра до стыка. В эталоне пролёты кончаются
  за 0,19 и 0,165 с.
- Запас на экран ноутбука при пролёте — `LP(1.04, 1.1)`, то есть 4 % в 16:9 и 10 % в 9:16.
- `K.lerpCam` на длинном пролёте ведёт цель вбок посередине пути. В 3D это заметили и заменили на `zoomTo` (формула
  в `dna-gloss3d.md`): там цель едет к центру кадра линейно в экранных координатах. Формула чисто двумерная
  (x, y, zoom) и годится для карандаша, но в карандашной версии эталона она не проверялась.
- Нарисовать целую сцену под другой камерой — крючок `window.__camOverride`: `camera()` берёт его вместо своей камеры.
  Так s6 рисуется во время пролёта в экран ноутбука.
- Переход-ластик s1 → s2 (7,57–8,25 с, `er = inv(7.57, 8.25, tt)`):
  - каракули s1 рисуются с прозрачностью 1 − er;
  - поверх появляются 7 пятен ластика `'#E9E3D6'` — эллипсы с полуосями 90 и 34 ед. Пятно k проявляется при
    er > k/9 и рисуется с прозрачностью 0,5·(1 − er);
  - места пятен заданы `K.rngOf('eraser', k)`;
  - герой в это время переезжает на место s2.
- Все шесть стыков эталона и правило выбора приёма — `storyboard.md`, раздел 5.

## 10. Свечение

Свечение бывает только у акцентов и только на тёмной бумаге (с. 14). В темах методички оно есть у «неона» и
«мистики», «чуть» — у «мела», слабое — у «синьки», а у «тетради» и «крафта» его нет (с. 15). Эталон сделан в
«тетради», поэтому модуля свечения в его движке нет, хотя методичка считает свечение одним из четырёх модулей
движка (с. 19). Роли палитр с флагом тёмной бумаги и уровнем свечения — `palettes.md`.

## 11. Герой: `HERO.draw(pen, cfg)`

Начало координат героя — между ступнями на земле. При `s = 1` рост ≈ 340 ед. Пропорции взяты из SVG-стикера в
квадрате 512: `L(x, y) = [x - 256, y - 430]`. Ключи `cfg` (недостающие берутся из `HERO.DEF`, руки сливаются
отдельно):

| Ключ | Значения | Что делает |
| --- | --- | --- |
| `x`, `y`, `s` | ед. мира, масштаб | где стоят ступни, размер |
| `dir` | ±1 | зеркально |
| `squash` | + сплющить / − вытянуть | `scale(1 + squash × 0.55, 1 - squash)`; в прыжке −0,08, на приземлении 0,15 на 0,15 с |
| `lean` | рад | наклон |
| `look` | [−1..1, −1..1] | взгляд: зрачок сдвигается до 9 / 8 ед. |
| `blink` | 0..1 | высота глаза ×(1 − 0,92·blink); от 0,75 — закрытая дуга |
| `brow` | −1..1 | брови −6·brow ед.; выше 0,5 — ещё на 3 выше |
| `mouth`, `shape`, `smile` | 0..1; `'smile'` `'grin'` `'o'` `'flat'`; лифт улыбки 12·smile | рот; `mouth` берётся из `K.mouthAt(t)` |
| `armL`, `armR` | `{sh, el}` — углы плеча и локтя, рад | рука из двух звеньев 46 и 42 ед.; по умолчанию L {−2,35; 0,35}, R {−0,25; −0,3} |
| `scroll`, `spatula`, `spatAng`, `laurel`, `airpods`, `scrollText` | вкл/выкл, угол, 3 строки | реквизит в руках и на голове |
| `legs` | [подъём левой, правой] | шаг, прыжок |
| `color`, `fills` | 0..1 | дуга цвета, раздел 7 |
| `reveal` | 0..1 | проявление: у каждой части своё окно `rv(a, b) = K.inv(a, b, reveal)` |
| `sleep`, `sweat` | 0..1 | летящие «z», капля пота |
| `id` | строка | префикс зёрен всех частей; у одновременных копий разный |

Каждая часть рисуется по одной схеме:

```js
// hero.js: the toga — paper (occlusion) -> tone (graphite or colored pencil) -> outline with its own seed and reveal window
const toga = S(D_TOGA, 5);
pen.paper(toga);
tone(toga, COL.toga, 0.1, { k: 'toga', p: rv(0.5, 0.65), alpha: 0.45 });
pen.shape(toga, { w: 2.8, id: id + 'toga', p: rv(0.32, 0.5), gaps: 1 });
```

- Порядок частей — порядок слоёв: тень на земле → ноги → тело (корочка, белок, тень белка) → тога → значок → лицо
  (румянец, брови, рот) → глаза → очки → наушники → лавр → руки с реквизитом → «z» и пот.
- Моргание: список `BLINKS` с моментами и треугольник `blinkAt(t)` шириной ±0,13 с. Рот — `K.mouthAt(t)`: огибающая
  громкости голоса по кадрам из `TIMING.mouth`, уже на двойках.
- Ходовые движения: пробуждение — рука по `E.outBack`; прыжок — `E.ioQ` по горизонтали плюс дуга
  `-sin(hop × π) × 120` по вертикали.
- Позиции кисти и кончика лопатки (`_handL`, `_handR`, `_spatTip`) пишутся во внутреннюю копию `cfg` и наружу не
  видны. Нужна точка кисти — возвращай её из `draw`.
- Герой эталона (яйцо-Сократ, маскот автора навыка) — проектный. В шаблоне он лежит образцом
  (`templates/engine/hero_egg.js`), а заготовка для своего героя — `templates/engine/hero_template.js`.

## 12. Новый герой из SVG

1. Нарисовать героя векторно в квадрате 512 (стикер, Inkscape, Figma). Каждая крупная часть — отдельный путь:
   внешний контур, внутренний контур, одежда, крупные детали. Исходник эталона — векторный стикер
   `handcraft_egg.svg` (у автора навыка).
2. Выбрать начало координат между ступнями на земле (у эталона `OX = 256, OY = 430`). Тогда `x, y` в сцене — место,
   где герой стоит, а рост при `s = 1` равен `OY` минус верх рисунка.
3. Скопировать строки `d` в константы и превращать их в точки через `PEN.svgPts`:

   ```js
   const OX = 256, OY = 430;
   const L = (x, y) => [x - OX, y - OY];
   const S = (d, step = 4) => P.svgPts(d, step).map(p => L(p[0], p[1]));   // SVG path -> local points
   ```

   `svgPts` проходит путь через скрытый `<svg>` в документе (`getTotalLength`, `getPointAtLength`), берёт
   `max(4, ceil(длина / step))` точек и кэширует их по `step|d`. Шага 4–5 ед. хватает. Работает только в странице с
   DOM.
4. Подвижные части — глаза, рот, брови, руки — строить кодом, а не брать из SVG: эллипсы, сплайны, рука из двух
   звеньев от точки плеча.
5. Цвета героя держать в одном объекте `COL`. Тон класть через `tone()`, тогда дуга «графит → цвет» работает сама.
6. Каждой части дать окно проявления `rv(a, b)`, а `pen.paper` части вызывать внутри того же окна.
7. Проверить на тестовой странице: `?scenes=test_hero.js&mouth=0.6` рисует героя рядом в графите и в цвете. Снять
   кадры `render/still.py` с этим запросом и посмотреть глазами.

## 13. Что ломает стиль

Коротко; полная таблица симптомов и лечения — `pitfalls.md`.

- `Math.random()`, `Date.now()` и любое состояние между кадрами: каждый рендер выходит другим (с. 20).
- `id` из меняющихся чисел: линии плывут вместо кипения.
- Движение от `t` вместо `tt`: плавно, «компьютерно» (с. 6).
- Ровные заливки, градиенты, тени CSS, моушн-блюр: картинка становится векторной (с. 6, 8, 14).
- Свечение на светлой бумаге, штриховка света на светлой бумаге (с. 14, 20).
- `pen.paper` до появления части: ластик раньше времени (с. 20).
- Кегль подписи ниже порога высоты заглавной, текст в нижних 15 % кадра (с. 18, 23).
