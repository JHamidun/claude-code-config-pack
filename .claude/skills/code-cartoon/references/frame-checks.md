# Проверка кадров

Методичка: агент сам снимает кадры и смотрит лист кадров до того, как показать человеку; перед показом — 8–12
ключевых кадров и лист; нашёл ошибку — исправь и сними снова, промежуточное не показывать (с. 4, 11, 16, 23).
Правильность кадра доказывает снимок и замер, а не чтение кода.

Два прохода:

1. стоп-кадры до полного рендера — ГЕЙТ 2 (`workflow.md`, этап 6);
2. готовый MP4 — перед критиком и превью (`workflow.md`, этапы 10–11).

Все команды ниже прогнаны на эталоне `<эталон>` 05.10.2026; числа эталона даны для сравнения.

## 1. Инструменты

Скрипты проекта (их копирует `scripts/new_project.py` из `templates/`) запускаются из корня проекта. QA-помощники
навыка лежат в `~/.claude/skills/code-cartoon/scripts/` и запускаются по полному пути; ниже путь
сокращён до `…/`. Справка — запуск без аргументов.

| Задача | Скрипт |
| --- | --- |
| стоп-кадры PNG; `--det` — проверка детерминизма | `render/still.py` |
| лист кадров из стоп-кадров | `render/sheet.py` |
| точное время кадра, пары у стыков, моменты рта | `…/qa_frames.py t`, `cuts`, `mouth` |
| что изменилось, пуст ли кадр, высота заглавной | `…/qa_frames.py diff`, `ink`, `cap` |
| линии 85 %, 5 % и 10 % поверх кадра; лист из кадров рендера | `…/qa_frames.py guides`, `fsheet` |
| звук в окне, слышен ли эффект, сдвиг удара, громкость, голос над музыкой | `…/qa_audio.py win`, `hit`, `onset`, `loud`, `vm` |
| звуки против сетки двоек | `…/qa_cues.py` |

```bash
python render/still.py <page.html> <out_prefix> <t1,t2,...> [land|port] [query] [--det] [--http] [--gpu|--no-gpu]
python render/sheet.py <out.png> <cols> <scale> <files...>
python …/qa_frames.py t 240,241,242,243
python …/qa_frames.py cuts timing/timing.json
python …/qa_frames.py mouth timing/timing.json
python …/qa_frames.py diff A.png B.png [x0,y0,x1,y1] [--thr 30] [--png map.png]
python …/qa_frames.py ink A.png
python …/qa_frames.py cap A.png x0,y0,x1,y1
python …/qa_frames.py guides A.png copy.png
python …/qa_frames.py fsheet out.jpg <cols> <tile_width> out/x.frames 739,740,907,908
python …/qa_audio.py win|hit|onset <media> <t> ...
python …/qa_audio.py loud <media>
python …/qa_audio.py vm timing/voice_final.wav sound/music.wav [--g 0.62]
python …/qa_cues.py out/<name>.cues.json [--tol 0.040]
```

Как снимать:

- Время кадра f — ровно `f / 24`. Округлённое `10.083333` попадает в предыдущий рисунок:
  `floor(10.083333 × 12 + 1e-6) = 120`, а кадр 242 — это рисунок 121. Времена печатает `qa_frames.py t` (10 знаков).
- `still.py --det` рисует каждый момент второй раз в обратном порядке и сравнивает пиксели: ловит `Math.random`,
  часы и состояние, перетекающее между кадрами.
- Подпись времени на листе стоит в полосе над кадром и не закрывает его угол: в углу бывает заголовок. Так делают
  `render/sheet.py` и `qa_frames.py fsheet`. Свою склейку с подписью внутри кадра не делать.
- Один формат на лист: `sheet.py` подгоняет все кадры под размер первого, и 9:16 рядом с 16:9 сплющится.
- Лист — не шире ~2000 px, чтобы смотреть его целиком: 16:9 в 4 колонки при масштабе 0,25 даёт 1960 px.
- `sheet.py` берёт подпись из имени после последнего `_`; для кадров рендера (`f00737.jpg`) нужен `fsheet`,
  он подписывает номер кадра и время.
- 3D: стоп-кадры по возрастанию времени, первый кадр страницы ждёт компиляции шейдеров. Много кадров подряд дешевле
  через `render.py gloss/index.html out/qa_g.mp4 --from 30 --to 31 --keep` и `fsheet` по `out/qa_g.frames/`.

## 2. Какие кадры снимать

- Лист сюжета, 8–12 кадров (с. 23): кадр 0, середина каждой сцены, поворот (через 2 кадра после удара), момент,
  когда дописан каждый слоган, последний кадр. Расчёт моментов из `timing.json` — `workflow.md`, этап 6.
- Лист стыков: на каждый стык пара — последний кадр до и первый после (`qa_frames.py cuts`). Лист в 4 колонки,
  пары стоят рядом.
- Оба формата и оба стиля — в одни и те же моменты; листы смотреть рядом. 9:16 — не повёрнутый 16:9
  (`storyboard.md`, раздел 8).

## 3. Чеклист стоп-кадров

### 3.1. История читается без звука (с. 18, 23)

Смотреть лист сюжета, не слушая. Каждая сцена держит одну мысль одним крупным словом или картинкой; поворот виден
без голоса: до него тихо, мелко и холодно, после — ярко, крупно и тепло (с. 17). Смысл держится только на голосе —
менять картинку.

### 3.2. Размер текста (с. 18, 23)

Порог методички: подпись — от 48–56 px высоты заглавной, слоган — от 64 px при ширине кадра 1080 px. Высота
заглавной — не кегль: `size` в `pen.text` и размер в `ctx.font` канвас-текстуры — это кегль.

| Формат | Подпись, высота заглавной | Слоган | Откуда порог |
| --- | --- | --- | --- |
| 9:16, 1080×1920 | ≥ 48 px, лучше 56 | ≥ 64 px | методичка |
| 1:1, 1080×1080 | ≥ 48 px, лучше 56 | ≥ 64 px | методичка: ширина та же |
| 16:9, 1920×1080 | ≥ 48 px — минимум; для ленты телефона ≥ 85 | ≥ 64; для ленты ≥ 114 | правило навыка |

Для 16:9 методичка порога не даёт. Минимум навыка — тот же порог по короткой стороне кадра. В ленте телефона
(Telegram, YouTube без поворота экрана) кадр 16:9 ужимается до ширины экрана в 1920 / 1080 = 1,78 раза сильнее, чем
9:16; чтобы текст на экране вышел того же размера, что в вертикальном ролике, порог умножается на 1,78: 85 и 114 px.
Эталон 16:9 стоит между: строки плаката — кегль 100, заглавная 76 px.

- Кегль из порога: высота заглавной на кадре = кегль × доля заглавной шрифта × zoom камеры (в карандаше на родном
  размере кадра мировая единица = пиксель). Доли шрифтов и готовые кегли — `dna-pencil.md`, раздел 8. В 3D
  перспектива меняет размер, там только замер.
- Замер на кадре — рамка вокруг одной заглавной буквы. Соседние строчные с петлями в рамку не брать: у Segoe Print
  «в», «б», «д» выше заглавных.

```bash
python …/qa_frames.py cap out/qa/story/land_065.58.png 1060,150,1112,245
```

Эталон, плакат 16:9, «И» в слове «Интенсив», кегль 70: `ink height 55 px`. Замер даёт полную высоту буквы с
хвостиком под строкой; у Segoe Print она на ~4 % больше высоты над строкой (0,79 против 0,76 кегля), для порога
это 2 px.

### 3.3. Нижние 15 % и поля по краям

- Нижние 15 % — без текста: там интерфейс Reels и Shorts (с. 18, 23). В 9:16 обязательно; эталон держал ту же линию
  и в 16:9. При камере (0, 0, zoom 1) это y < 378 в 16:9 и y < 672 в 9:16 в мировых координатах. Камера движется —
  координаты не помогают, проверять кадр.
- Поля по краям — правило навыка, методичка их не задаёт. Рамки — как в навыке `hyperframes-studio` (по умолчанию
  Premiere): весь текст внутри рамки 5 % от каждого края — это гейт; заголовки и CTA — внутри 10 %.
- В 9:16 сверху тоже интерфейс (название ленты, вкладки): заголовок не выше 10 % от верха. Справа внизу — колонка
  кнопок: подписи нижней половины кадра не прижимать к правому краю.

```bash
python …/qa_frames.py guides out/qa/story/port_064.00.png out/qa/guides_port.png
```

Красная линия — 85 % высоты, жёлтая рамка — 5 %, голубая — 10 %. Эталон 9:16, плакат: всё выше красной линии,
строка «поток N · старт <дата>» вышла за 10 % и стоит у рамки 5 % — проходит впритык.

### 3.4. Движение не наезжает на текст (с. 18, 23)

Снять кадры в моменты, когда движущееся проходит мимо текста: пролёт камеры, прыжок героя, улёт реквизита,
покачивание камеры в 3D. Ни на одном кадре текст не перекрыт. Декор — на фиксированных местах вне текстового блока
(`pitfalls.md`).

### 3.5. Первый кадр не пустой (с. 17, 23)

Кадр 0 — обложка автоплея в ленте. На нём уже рисунок, а не лист с одной линией.

```bash
python …/qa_frames.py ink out/qa/story/port_000.00.png
```

Ждём ≥ 1 %. Пустой лист (бумага, клетка, виньетка) даёт 0,00 %; эталон: карандаш 9:16 — 2,52 %, 3D 16:9 — 2,05 %
(спящий герой на листе и на стене).

### 3.6. Последние 3 с — плакат (с. 17, 18, 23)

- К началу последних 3 с весь текст дописан: кадр на границе и последний кадр несут один и тот же текст.
- Ничего быстрого не движется: разница «граница → последний кадр» не больше разницы двух соседних рисунков, то есть
  меняется только кипение. Граница — кадр `N = ceil((duration − 3) × 24)`, соседний рисунок — `N + 2`, последний
  кадр — `round(duration × 24) − 1`.
- В 3D покачивание камеры и декор замирают до границы (эталон: 62,3 и 62,0 с при границе 62,63 с).
- Последний кадр готового MP4 хорош как постер (раздел 4).

```bash
python …/qa_frames.py t 1504,1506,1574
python render/still.py pencil/index.html out/qa/end/land 62.6666666667,62.75,65.5833333333 land
python …/qa_frames.py diff out/qa/end/land_062.67.png out/qa/end/land_062.75.png
python …/qa_frames.py diff out/qa/end/land_062.67.png out/qa/end/land_065.58.png
```

Эталон: карандаш 16:9 — 2,59 % «граница → конец» против 2,47 % у соседних рисунков; 3D 16:9 (кадры 1504, 1506 и
1574 из `.frames`) — 1,09 % против 1,00 %, меняется только область героя-стикера.

### 3.7. Ничего не прыгает из того, что должно стоять (с. 18, 23)

Предмет, который по сюжету стоит, не меняет места и формы. Линии карандаша кипят всегда, поэтому разницу области
сравнивать с фоном кипения (те же два момента на другой стоящей области) или замораживать кипение кодом:
фиксированный `pen.d`, как на фразе «ни на пиксель» в эталоне.

```bash
python …/qa_frames.py diff out/qa/a_035.00.png out/qa/a_035.60.png 744,396,960,780 --png out/qa/tree_diff.png
```

Эталон, область дерева 16:9, 35,0 против 35,6 с: 0 px. К 36,3 с в той же рамке 403 px — карта показала, что это
метка «0 px», дописанная у верхнего края рамки, а не дерево. Карта `--png`: кадр B притушен, изменившиеся пиксели
красные.

### 3.8. Кипение есть и идёт на двойках (с. 6, 7, 23)

- Кадры 2k и 2k+1 совпадают до пикселя — 0 px, в 3D тоже. Не совпали — что-то рисуется от `t`, а не от `tt`:
  движение выходит плавным, «компьютерным». В 3D соседние кадры рисуют разные страницы рендера, и GPU даёт шум в
  единицы пикселей на 1–3 уровня яркости (эталон: 0–4 px); порог `--thr 30` его не видит, и это не нарушение.
- Кадры 2k+1 и 2k+2 различаются по всем линиям: эталон — 1,9–2,5 % кадра.
- Предмет, который между соседними рисунками не меняется совсем, не кипит: `boil: 0` или зерно без `pen.d`.
- Повторный рендер того же момента даёт те же пиксели: `still.py … --det`.

```bash
python …/qa_frames.py t 240,241,242,243
python render/still.py pencil/index.html out/qa/b/land 10.0000000000,10.0416666667,10.0833333333,10.1250000000 land --det
python …/qa_frames.py diff out/qa/b/land_010.00.png out/qa/b/land_010.04.png
python …/qa_frames.py diff out/qa/b/land_010.04.png out/qa/b/land_010.08.png
```

Первая разница — `changed px 0`, вторая — больше нуля (эталон: 50 291 px, 2,4 %).

### 3.9. Неон не пересвечен, кадр не перегружен (с. 14, 18, 23)

- Свечение только у акцентов и только на тёмной бумаге (с. 14). На тёмной палитре смотреть кроп акцента в 100 %:
  яркое пятно с ореолом, а не белая заливка всего акцента с выжженными краями.
- На листе в масштабе 0,25 главный предмет кадра читается сразу; мелочь не спорит с ним за взгляд.

### 3.10. Стыки — парами кадров (с. 17)

- На стыке совпадает всё, что видно: бумага и клетка (в 3D — стена), рамки, положение героя. Всё, что в сцепку не
  входит, уходит до стыка (`storyboard.md`, раздел 5).
- Пролёт камеры кончается минимум за 2 кадра до стыка (`K.lastTick(name) − 1/12`): последние кадры перед стыком
  отличаются только кипением.
- Карта изменений пары: кипение даёт тонкие красные нити по всем штрихам; целиком красные предметы, рамки и
  надписи — скачок.

```bash
python …/qa_frames.py cuts timing/timing.json
python render/still.py pencil/index.html out/qa/cuts/land <времена пар через запятую> land
python render/sheet.py out/qa/sheet_cuts_land.png 4 0.25 out/qa/cuts/land_*.png
python …/qa_frames.py diff out/qa/cuts/land_030.79.png out/qa/cuts/land_030.83.png --png out/qa/cut_s3s4.png
```

Эталон (стоп-кадры 05.10, 16:9): в 3D пары s3 → s4 и s4 → s5 почти одинаковы — на экране живой снимок следующей
сцены. В карандаше видны скачки: s3 → s4 — на последнем кадре пролёта видны рамка миниатюры и края красного круга
выделения, на первом кадре s4 их нет; s4 → s5 — пропадают подсказка и метки «0 px» и появляется тёмная рамка клипа;
s6 → s7 — на экране ноутбука не было клетки, после склейки она появилась. Разница пар 3,6–8 % против фона кипения
0,4–3,6 %: само число стык не судит, судят карта и глаза.

### 3.11. Рот двигается с голосом

```bash
python …/qa_frames.py mouth timing/timing.json
```

- Печатает моменты, где огибающая рта = 1 (рот открыт), и моменты внутри слов, где она < 0,05 (закрыт), и сверяет
  длину огибающей с `ceil(duration × 24)` (эталон 1576).
- Снять эти моменты, смотреть кроп головы: открыт и закрыт там, где сказано; в паузах рот закрыт.
- `timing/timing.json` новее `voice/voice.wav`: после переозвучки тайминг собирается заново, иначе рот и все события
  живут по старому голосу.

### 3.12. Артефакты 3D

| Что | Как выглядит | Как проверить |
| --- | --- | --- |
| выскакивание | предмет появляется или исчезает за один кадр без анимации | лист с шагом в рисунок вокруг появления; `show(o, k)` растит масштаб от нуля, голый `visible = true` — нет |
| срез | предмет режется краем кадра или камерой на самом крупном наезде | кадры самого крупного наезда; покачивание больше 0,16 выталкивает раскладку за край |
| z-fighting | грани в одной плоскости мерцают полосами | там, где покачивание 0, два соседних рисунка: вне стикера героя разница 0 px (эталон, плакат: меняется только область героя) |
| полосы на тенях | рябь-«ёлочка» на освещённых плоскостях | кроп 100 % стены и крупных граней; лечение — `bias −0.0004`, `normalBias 0.02` |
| пустые текстуры | белая или прозрачная грань вместо надписи, засечный шрифт, серая стена в миниатюре | стоп-кадр каждой надписи; `still.py --det`: текстура, нарисованная побочно прошлой сценой, на прямом кадре пустая |
| обрезанный стикер | у героя срезан край свитка или лопатки | крайние позы героя: руки вверх, предмет в вытянутой руке |
| тень героя | прямоугольник вместо силуэта | кадр героя у стены; `customDepthMaterial` с `alphaTest` |
| стык-снимок | миниатюра светлее или бледнее кадра, стена другого цвета | пара кадров у стыка, раздел 3.10 |

3D-подробности — `dna-gloss3d.md`, раздел 10; лечение — `pitfalls.md`, раздел 3.

## 4. Готовый MP4

| № | Проверка | Ждём |
| --- | --- | --- |
| 1 | потоки и длина | h264 1920×1080 или 1080×1920, `24/1`, `nb_frames` = round(длина × 24) (эталон 1575), aac 48000 Гц |
| 2 | последний кадр | плакат, весь текст на месте (с. 18, 23) |
| 3 | чёрные и застывшие куски | пустой вывод |
| 4 | громкость | −16…−14 LUFS, истинный пик ≤ −1 dBTP (с. 23) |
| 5 | голос над музыкой | не тише эталона: 14,0 дБ |

```bash
# 1 streams and length
ffprobe -v error -show_entries stream=codec_type,codec_name,width,height,r_frame_rate,nb_frames,sample_rate -show_entries format=duration -of compact out/x.mp4
# 2 last frame -> out/x.last.png (or add --last-frame to the render command)
ffmpeg -v error -y -sseof -1 -i out/x.mp4 -update 1 out/x.last.png
# 3 black or frozen stretches: no output expected
ffmpeg -hide_banner -nostats -i out/x.mp4 -vf "blackdetect=d=0.1:pix_th=0.10,freezedetect=n=0.0005:d=0.6" -an -f null - 2>&1 | grep -E "black_start|freeze_start"
# 4 loudness and true peak of the finished file
python …/qa_audio.py loud out/x.mp4
# 5 voice over music while the voice speaks
python …/qa_audio.py vm timing/voice_final.wav sound/music.wav
```

- `render.py` сам печатает строку `check:` по ffprobe и предупреждает, если длина разошлась больше чем на 0,05 с.
- `freezedetect` проверен на искусственном 2-секундном стоп-кадре — ловит; на эталонных роликах вывод пуст:
  кипение меняет кадр каждые 2 кадра.
- Громкость мерить на MP4, а не на WAV: AAC поднимает пики. Эталон: `mix_land.wav` — −15,0 LUFS и −1,0 dBTP,
  четыре MP4 версии v5 (AAC 192k) — −0,6 dBTP, у карандаша 16:9 и пик по отсчётам −0,7 dBFS; v6 — −0,8 dBTP. Всё
  выше предела методички. Проверенное лечение — `TP=-1.5` в `loudnorm` синтезатора: после AAC 192k −1,3 dBTP при тех
  же −15,0 LUFS.
- Стем музыки для `vm` пишет `sound/synth.py … --music-only sound/music.wav`; `vm` умножает его на 0,62 — множитель
  музыки в смеси эталона (`--g`, если в смеси другой). Без множителя эталон даёт 9,9 дБ.
- Музыка — это музыка, а не шум: `python ~/.claude/skills/sketch-course-video/templates/story-v3/tools/audio_check.py sound/music.wav --kind music`
  (эталон: `OK`, tonal 0,068). Его счётчик clipping на стерео с одинаковыми каналами врёт: скрипт сводит в моно
  через `-ac 1`, ffmpeg при этом поднимает одинаковые L/R на 3 дБ. Эталонный `mix_land.wav` с пиком −1,0 dBFS
  получает «clipping: 1403 samples».

### 4.1. Звук в кадр до 40 мс (с. 9, 23)

Звук и картинка берут одну константу (с. 16, 23), но на двойках картинка показывает событие на первом рисунке не
раньше константы: `ceil(T × 12) / 12`. Звук, поставленный ровно в `T`, приходит раньше картинки на величину до
83 мс.

1. Лист звуков против сетки двоек:

   ```bash
   python …/qa_cues.py out/pencil_land_v1.cues.json
   ```

   Ждём `0 lead the drawing by > 40 ms`. Эталон до правки: 39 из 92 событий раньше картинки больше чем на 40 мс,
   худшие на 80 мс (`snap` на 41,670 с: значок садится на рисунке 41,75 с). Лечение — `cue()` ставит время на сетку
   двоек (`pitfalls.md`, строка 66); после правки листы обоих стилей и форматов дают 0. Время сетки, округлённое
   `toFixed(3)` (71/12 → 5,917), скрипт считает стоящим на сетке.

2. Удар в готовом MP4 там, где нужно:

   ```bash
   python …/qa_audio.py onset out/pencil_land_v1.mp4 34.0
   ```

   Время брать из листа звуков (`out/<ролик>.cues.json`), не из головы. Ждём сдвиг от −40 до +40 мс. Эталон,
   щелчок поворота: в v6 стоит на 34,000 с — `+1 ms`, зелёное солнце впервые на кадре 816 (34,00 с); в v5 звучал в
   33,98 с, за 20 мс до рисунка.

3. Эффект слышен, а не утонул под голосом и музыкой:

   ```bash
   python …/qa_audio.py hit out/pencil_land_v1.mp4 41.67
   ```

   Окно эффекта (80 мс) громче 100 мс перед ним хотя бы на 3 дБ. Эталон: в версии v3a три щелчка `snap` дали −2,7,
   +0,9 и −3,7 дБ — утонули под голосом; после подъёма громкости эффектов в v4 — +4…+8 дБ.

4. Звук свежий: `timing/timing.json` → `out/<ролик>.cues.json` → `sound/mix.wav` → MP4 — каждый следующий файл новее
   предыдущего. Поменялись тайминг или сцены — лист звуков и звук пересобираются (с. 20).

## 5. Внешний критик

```bash
python render/critic.py out/pencil_land_v1.mp4 out/critic_pencil_land_v1.md [--model gemini-3.1-pro-preview] [--script SCRIPT_v1.md] [--style "..."] [--extra "..."]
```

Gemini смотрит ролик целиком со звуком по сценарию и возвращает таблицу «таймкод | что не так | насколько заметно |
как исправить» и три строки: лучшее, худшее, оценка 1–10. Вызов платный, ключ `GOOGLE_API_KEY` скрипт берёт из
`~/.claude/.credentials.master.env`. Для 3D — `--style "глянцевое 3D с рисованным героем-стикером, сделано кодом"`.

Где полезен: композиция, куда смотреть, пустой или перегруженный кадр, мелкий текст, рывки на стыках. Где врёт:
звук и «что-то шевелится». Поэтому каждое утверждение — в замер до правки: правка без замера чинит то, чего нет,
отказ без замера пропускает настоящий брак.

Как эталонный критик сверялся с замерами:

| Версия, таймкод | Критик | Замер | Итог |
| --- | --- | --- | --- |
| v3, 0:34,0 | «нет звукового акцента» на смене цвета солнца | пик в окне 33,9–34,1 с — −0,9 dBFS | неправда |
| v2 и v3, 0:34,5–0:37,0 | «дерево меняет форму кроны» | область дерева, 35,0 против 35,6 с — 0 px; к 36,3 с 403 px — это метка «0 px» у края рамки | неправда |
| v2 и v3, 0:41–0:43 | «звуковых эффектов нет» | в v3a окна трёх `snap` к 100 мс перед ними: −2,7, +0,9 и −3,7 дБ; на стемах пик эффекта −14,8 dB против пика голоса −8,1 dB в том же окне | правда по сути: эффекты тонули под голосом; громкость подняли, в v4 и v5 +4…+8 дБ |

Замеры по видам утверждений:

- «Нет звука», «эффект тихий» — пик и RMS в окне таймкода. Без Python:

  ```bash
  ffmpeg -hide_banner -nostats -ss 33.9 -t 0.2 -i out/x.mp4 -vn -af volumedetect -f null - 2>&1 | grep -E "max_volume|mean_volume"
  ffmpeg -hide_banner -nostats -ss 33.9 -t 0.2 -i out/x.mp4 -vn -af astats=measure_overall=Peak_level+RMS_level:measure_perchannel=none -f null - 2>&1 | grep -E "Peak level|RMS level"
  ```

  Эталон, окно щелчка: `max_volume: -1.1 dB`, `mean_volume: -16.3 dB`; `astats` — те же −1,11 и −16,29. Слышен ли
  эффект на фоне голоса — `qa_audio.py hit` (раздел 4.1).
- «Двигается», «прыгает», «обрезано» — два кадра вокруг таймкода и разница области. Без помощников, на PIL:

  ```python
  # region_diff.py A.png B.png x0 y0 x1 y1  -> changed pixels inside the box
  import sys
  import numpy as np
  from PIL import Image
  box = tuple(int(v) for v in sys.argv[3:7])
  a, b = (np.asarray(Image.open(p).convert('L').crop(box), dtype=np.int16) for p in sys.argv[1:3])
  print('changed px', int((np.abs(a - b) > 30).sum()), 'of', a.size)
  ```

  Скрипт сохранять файлом и запускать: heredoc в Git Bash ломается на кавычках. То же делает `qa_frames.py diff`.
- «Не совпадает с голосом» — время слова в `timing/timing.json` против первого кадра события на стоп-кадрах.
- «Мелкий текст», «текст внизу» — раздел 3.2 и `qa_frames.py guides`.

Подтвердилось — исправить и снять кадры заново. Не подтвердилось — записать рядом с ответом критика замер, которым
утверждение снято. Подтвердилась новая ошибка — строка в `pitfalls.md`.
