# book-polish-pipeline / scripts

Скрипты для финальной шлифовки книги. Обкатаны на реальном каскаде версий v8 → v13.2 —
номера в примерах оттуда, у твоей книги нумерация будет своя.

## build-book.py

Собирает EPUB + DOCX из глав. Подбирает наивысшую версию автоматически.

### Запуск

```bash
# По умолчанию (использует VERSION_TAG='v13.2')
python build-book.py

# Указать конкретную версию для имени файла
python build-book.py --version v14

# Переопределить пути через env
BOOK_ROOT=/path/to/my-book BOOK_OUTPUT_NAME=My-Book python build-book.py --version v1
```

### Environment variables

| Var | Default | Описание |
|---|---|---|
| `BOOK_ROOT` | — (**обязателен**) | Корень книги: папка с `chapters/` и `book.json` |
| `BOOK_OUT` | `$BOOK_ROOT/dist` | Куда складывать EPUB/DOCX |
| `BOOK_OUTPUT_NAME` | из `book.json` → `output_name` | Имя выходного файла без расширения |
| `BOOK_VERSION_TAG` | `v1` | Тег версии в имени файла |
| `BOOK_VERSION_PREFERENCE` | (см. в коде) | Порядок поиска версий по главам |

Всё остальное — название, автор, издатель, состав глав, сквозные термины — лежит
в `$BOOK_ROOT/book.json`, а не в переменных окружения и не в коде.
Образец с пояснениями: `../templates/book.example.json`.

### Внутри

- Strip frontmatter, `<!-- source-trace: -->`, EDIT-NOTES, PROOFREAD-NOTES
- Собирает по массиву `chapters` из `book.json` (порядок + заголовки частей + иллюстрации)
- EPUB: ebooklib + markdown2
- DOCX: python-docx
- Cover: путь из `book.json` → `cover`, ищется внутри `dist/`

### Адаптация под свою книгу

Ничего в коде не правится — всё берётся из `$BOOK_ROOT/book.json`:

1. `title`, `subtitle`, `cover_quote`, `author`, `publisher` — метаданные
2. `chapters` — список глав с заголовками частей и иллюстрациями
3. `cover` — путь к обложке относительно `dist/`
4. Иллюстрации — `dist/illustrations/`, имя файла указано в строке главы

Образец с пояснениями: `../templates/book.example.json`.

## cross_chapter_metrics.py

Проверяет плотность ключевых терминов, side-blocks, cliffhanger-стыки.

### Запуск

```bash
python cross_chapter_metrics.py --version v13.2
```

### Что проверяет

1. **F1. Плотность терминов** — таблица «глава × термин» по списку `metrics.key_terms` из `$BOOK_ROOT/book.json`
2. **F2. Side-block presence** — есть ли сквозная врезка (заголовок из `metrics.side_block`) в каждой содержательной главе
3. **F3. Cliffhanger → opening стыки** — выводит концовку главы N и зачин N+1 для визуальной проверки
4. **F4. Word count delta** — сравнение текущей версии с предыдущей по каждой главе

### Адаптация под свою книгу

Всё в секции `metrics` файла `$BOOK_ROOT/book.json` — код не трогается:

- `chapters_order` — slugs глав в порядке чтения
- `key_terms` — словарь терминов для проверки плотности (regex)
- `side_block` — regex заголовка сквозной врезки; пустая строка отключает проверку F2
- `side_block_required` — список глав, где врезка обязательна

## grep_suspicious_facts.sh

Bash-скрипт для поиска фабрикованных «личных» цифр и сцен после subagent-passes.

### Запуск

```bash
./grep_suspicious_facts.sh v13
# или
BOOK_ROOT=/path/to/book ./grep_suspicious_facts.sh v14
```

### 8 групп проверок

1. **Подозрительные «личные» числа** — «около 18 миллионов», «320 часов на развёртывание», «из 5 экспериментов»
2. **Синтетические сенсорные детали** — «ладони пахли», «свистит чайник», «гудел кондиционер»
3. **Манипулятивная срочность** (Pattern 21) — «потом будет поздно», «второго шанса не будет»
4. **Самопохвала читателю** (Pattern 22) — «ты знаешь больше N%», «опережаешь большинство»
5. **Гладкие проценты без базы** (Pattern 17) — «примерно 70%», «30% времени»
6. **Повторяющиеся авторские обороты** — задаются в `BOOK_REPEAT_PHRASES`
7. **Выдуманные исследования** — «MIT 2024», «Stanford 2025»
8. **Персонажи из отменённых версий книги** — задаются в `BOOK_BANNED_NAMES`

Группы 6 и 8 у каждой книги свои, поэтому вынесены в переменные окружения:

```bash
export BOOK_REPEAT_PHRASES='об этом редко говорят|как ни странно'
export BOOK_BANNED_NAMES='Имя Фамилия|Маша из регионального филиала'
```

Переменная не задана — группа честно печатает «пропущено», а не молча «нет совпадений».

### Как применять находки

Для каждой найденной строки:

1. Открыть указанный файл и строку
2. Проверить против `ANCHORS.md` / `SOURCES.md` этой главы
3. Если фабрикация → смягчить до качественного описания через Edit
4. Если реальный факт → добавить в `SOURCES.md` с атрибуцией

## Связь с предыдущим этапом

Скрипты этого навыка — **пост-FINAL**: они предполагают, что главы уже написаны
и доведены до `FINAL.md`. Базовый pipeline написания (writer / voice-pass / proofread /
fact-check / editor) — в навыке `book-post`, если он есть в паке.

Навыка нет — не блокер: эти шаги делаются субагентами по промптам из `../templates/`,
отдельного кода для них не требуется. Блокером было бы обратное: шлифовать текст,
который ещё не дописан.
