# Глоссарий, источники, кросс-главные метрики

Синхронизация глоссария и списка источников по всем главам плюс метрики, которые считаются поперёк книги. Читай перед сборкой версии, когда главы правились по отдельности.

## GLOSSARY + SOURCES SYNC

После каждого крупного content-апдейта (v9, v11, v13) — синхронизация back-matter.

### Glossary (`chapters/15-glossary/DRAFT.proofread.md`)

Прогнать grep по всем главам, найти термины которые автор использует, но не определяет.
Два класса, и пропускают обычно первый:

- **Авторские концепции и метафоры** — слова и обороты, которых до книги не существовало.
  Автору они кажутся самоочевидными (он их и придумал), а читатель встречает их
  в середине книги без определения
- **Профессиональные термины и англицизмы** — жаргон отрасли, который в глоссарий
  не попадает по обратной причине: кажется общеизвестным (enablement, governance, FTE, on-prem)

Каждый термин — короткое определение (3-5 строк), указание главы, где он вводится.

### Sources (`chapters/17-sources/DRAFT.proofread.md`)

Прогнать grep по всем главам на исследования/публикации, которых нет в источниках.
Пройти по классам, ни один не пропустить:

- **академические работы** — с номером (arxiv / NBER / DOI) и годом
- **отраслевые отчёты** консалтинга и вендоров — название отчёта, организация, квартал
- **опросы рынка и разработчиков** — название, год, размер выборки
- **публичные заявления компаний** — письмо акционерам, пресс-релиз, выступление CEO
- **локальные источники** своего рынка — забываются чаще всего

Атрибуция: имя/орг + название + платформа + дата. URL по возможности. Если URL неизвестен — оставить «требует ручной проверки автора».

См. `templates/glossary-sync-prompt.md` для полного промпта агента.

## CROSS-CHAPTER METRICS

Перед финальной сборкой — прогнать `scripts/cross_chapter_metrics.py`. Проверяет:

### F1. Плотность ключевых терминов

Свои термины пропиши в `scripts/cross_chapter_metrics.py` — словарь `TERMS` в начале файла.
Правило от книги не зависит: **термин концентрируется в главе, где вводится, и появляется
0-2 раза в остальных**. Если сквозной термин ровно размазан по всем главам — он перестал
быть термином и стал словом-паразитом.

Пример заполненной таблицы (строки под свою книгу пишешь сам):

| Термин | Норма |
|---|---|
| главный термин книги | концентрация в финальной главе + манифесте, 5-7 раз/глава максимум |
| термин-метафора | концентрация в главе, где вводится, 0-2 в остальных |
| название своего продукта | 2-4 раза в «рабочих» главах, ≤1 в личных |

### F2. Сквозная врезка

Если в книге есть повторяющаяся врезка — обращение ко второй аудитории, вставка
«прежде чем читать дальше», короткое резюме — она должна быть **во всех** содержательных
главах, а не в тех, где о ней вспомнили. Пропуск в одной главе читатель замечает: приём
уже стал ожиданием.

Заголовок врезки и список глав, где она обязательна, задаются в `book.json`
(`metrics.side_block` и `metrics.side_block_required`). Пустая строка отключает проверку.

### F3. Cliffhanger → opening стыки

Проверить, что концовка главы N логично переходит в зачин главы N+1.

Особенно после фикса (если cliffhanger перенаправлен) — что зачин следующей главы матчится с новой формулировкой.

### F4. 8 типов зачинов Зинсера (монотонность)

Все главы должны быть разными по типу:
- Нарративный (сцена с датой/именем)
- Вопрос
- Парадокс
- Цитата
- Факт-молот (статистика)
- Сцена
- Признание
- Прямое обращение

Если 5+ глав открываются одинаково (например, все нарративные) — нужно разнообразить.
