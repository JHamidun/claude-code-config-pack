## WAVE 7 — READER PERSONAS (3 призмы аудитории)

**Проблема:** generic reader-agent в WAVE 4-6 проверяет «читается ли», но не «читается ли *этой* аудитории». Foreword обещает 3 типа читателя — каждая глава должна работать минимум для одного.

**Персоны берутся из собственного foreword книги** — там автор уже пообещал, для кого пишет,
и каждое обещание надо проверить. Типовая тройка для делового нон-фикшн:

1. **Руководитель** — принимает решение за организацию. Проверка: читает организационные главы с интересом? Не теряется в технических?
2. **Индивидуальный профессионал** — применяет к своей работе, не к команде. Проверка: получает практическую отдачу из первой части? Не отпугивают ли его организационные главы?
3. **Отраслевой профессионал** — знает предмет лучше среднего читателя. Проверка: не скучно ли ему там, где объясняется базовое? Цепляют ли его самые спорные разделы книги?

Если foreword обещает другие три — брать их, а не эти. Смысл волны в том, чтобы обещание
из введения было проверено буквально, а не заменено удобным.

**Workflow:** 3 параллельных reader-агента на каждую главу, каждый в роли своей персоны. Метрика «engaged / neutral / lost» на каждый абзац. Глава должна быть **engaged** минимум для 1 из 3 (не для всех — это размывает голос), но не **lost** ни для одного.

## WAVE 8 — EMOTIONAL ARC TRACKING

**Проблема:** книга 200+ страниц = эмоциональное путешествие. Где читатель устанет? Где засомневается? Где захочет закрыть? Это не ловится reader-pass на одну главу.

**Workflow:** один opus-агент читает книгу подряд (или по 3 главы за раз), оценивает по шкале:

- **Tension curve** (0-10 на главу) — растёт к границе между частями, держит плато на операционных главах, спадает в финале (resolution). Ровная линия по всей книге — такой же дефект, как пила
- **Fatigue risk** — если 3 главы подряд одного регистра (только корпоративное / только техническое / только абстрактное) — FLAG
- **Memorability anchor** (1 на главу) — что читатель запомнит через неделю? Сцена / цифра / метафора. Если глава без anchor — FLAG

**Цель:** каждая глава оставляет 1 memorable image + варьирование регистра через каждые 2 главы.

## WAVE 9 — READABILITY METRICS (автоматические)

**Проблема:** ручное чтение вслух тест Безручко работает, но субъективно. Нужны числа.

**Чем считать.** Своего `scripts/readability.py` в этом навыке нет — писать его не надо:

```bash
python ~/.claude/skills/seo-machine-ru/scripts/readability_ru.py <file.md> [--json]
```

Скрипт считает по одному файлу — то есть по главе. Это даже удобнее, чем по всему
манускрипту: нужен разрез «какая глава тяжёлая», а не средняя температура по книге.
Прогони циклом по `chapters/*/DRAFT.v{N}.md` и сравни главы между собой.

Целевые диапазоны у разных инструментов разные (для научпопа встречается и 40-55).
Ниже — рабочие ориентиры; сверяй руками, а не принимай за норму:

- **Флеш-Оборнева** (русскоязычный индекс читаемости): целевой диапазон 50-70 (научпоп). <50 = тяжело, >70 = школьное.
- **Средняя длина предложения** по главам: 12-18 слов. >22 = вырезать. <8 = текст рваный.
- **Лексическая разнообразность** (type/token ratio): 0.4-0.6. <0.3 = повторы, >0.7 = снобизм.
- **Доля предложений длиннее 25 слов**: ≤15%.
- **Длина абзаца** (медиана): 3-5 предложений. >7 — стенка текста.

**Порог «когда чинить»:** одна глава вне диапазона — не повод, это разброс регистра.
Чинить, когда вне диапазона три главы подряд или медиана книги.

**Когда запускать:** после WAVE 5 (tightening), перед WAVE 6 (de-AI).

## WAVE 10 — CRITIQUE FROM ARCHETYPE (4 критика-персонажа)

**Проблема:** generic «editor» агент слишком вежлив. Нужны злые лупы.

**4 персонажа (каждый читает книгу со своей предвзятостью):**

| Персона | Что ищет | Что прощает |
|---|---|---|
| **Циничный CFO** | пафос без цифр, неоправданные суммы, эмоциональные обещания ROI | техническую сложность |
| **Технарь-скептик** | упрощения, hand-waving, «магия AI», ошибки в архитектуре | бизнес-clichés |
| **Начинающий менеджер** | непонятные термины без определения, перегруз jargon, отсутствие шагов | глубокие технические места |
| **Журналист индустрии** | плохие источники, неверифицируемые цифры, скрытую рекламу `<продукт автора>` | стилистические шероховатости |

Каждый — opus-агент, output: short report «что я бы вычеркнул / что вызвало сомнения / что я бы спросил автора». Использовать после WAVE 6 для финальной vetting.

## WAVE 11 — GLOSSARY DRIFT & TIMELINE CONSISTENCY

**Проблема:** при 200+ страницах термины «дрейфуют», временные маркеры расходятся.

### 11.1 Glossary drift check

Скрипта нет — дрейф ловит агент по шаблону промпта
`~/.claude/skills/book-polish-pipeline/templates/glossary-sync-prompt.md`
(он же дописывает недостающие термины). Проверка в промпте идёт по шагам:

1. Извлечь все термины из `15-glossary/`.
2. Для каждого термина — grep по всем главам.
3. Проверить: определение из глоссария = смысл в каждом использовании?
4. FLAG-пример: сквозной термин в первой главе определён как свойство человека («это состояние, а не должность»), а в поздней главе тем же словом называется тип компании. Разные определения одного слова = drift; чинится либо возвратом к первому определению, либо явной оговоркой в месте второго употребления.

### 11.2 Timeline consistency

**Автоматизации нет — делается руками** (или разовым grep'ом по главам, скрипта в
скилле не заводили). Порядок:

1. Извлечь все временные маркеры двух типов: относительные («три года назад», «с прошлой весны») и абсолютные («в марте 2025», «к концу года»).
2. Якорь книги = дата сдачи рукописи (из foreword `last_updated`). Относительные маркеры считаются от неё, а не от даты, когда глава писалась.
3. Проверить: все относительные маркеры согласованы с якорем?
4. FLAG-пример: в одной главе «пять лет назад», в другой про то же событие «четыре года назад» — один из маркеров неверен. Главы писались в разные месяцы, и «в прошлом году» уехало вместе с календарём.
5. Отдельно проверить маркеры, которые устареют к выходу книги: «в этом году», «сейчас», «на момент написания». Между сдачей рукописи и печатью проходят месяцы — заменять на абсолютные даты.

## WAVE 12 — PR-FRAGMENT EXTRACTION (после gold-standard)

**Цель:** после того как книга = print-ready, извлечь 15-20 «выгодных цитат» для PR-кампании: рецензии, анонсы, посты, обложечные blurbs.

**Workflow:** один opus-агент проходит финальную версию, ищет:

- **Pull-quote material** — короткие ударные фразы (1-2 предложения), которые работают вне контекста главы
- **Контр-интуитивные тезисы** — «не X, а Y» где X = общая ересь, Y = неожиданное
- **Конкретные числа с историей** — цифра, за которой сразу читается сюжет («$200 млн выручки командой меньше десяти человек»)
- **Авторские формулировки** — короткое определение сквозного термина книги в форме «X — это не A, а B»

Output: `PR-FRAGMENTS.md` — 15-20 фрагментов с указанием главы и контекста. Отдаётся маркетингу издательства либо используется самим автором в анонсах.

## WAVE 13 — TRANSLATION-READINESS REPORT

**Цель:** если планируется en/zh версия, заранее знать какие куски потребуют переписки.

**Что отмечать:**

- **Русские идиомы** без прямых аналогов («ни в зуб ногой», «на голубом глазу»)
- **Культурные референсы**, понятные только на локальном рынке (местные бренды, регуляторика, привычки) — нужны сноски-объяснения для en
- **Игра слов** на русском (рифмы, аллитерации, термины, построенные на созвучии)
- **Специфические единицы** (рубли, версты, метрические) — конвертация

Output: `TRANSLATION-NOTES.md` — список с предложением как адаптировать. Не блокер, а подготовка для будущих изданий.

## WAVE 15 — CONVERSION HOOK (первые 3 страницы)

**Проблема:** foreword + introduction + первая страница гл.1 решают купят / не купят дальше. Стандартный reader-pass проверяет общую читаемость, но не **conversion strength** этих первых страниц.

**Метрики hook strength:**

- **First sentence test** — первая фраза заинтриговывает / описывает / обещает? Лучше: интригует или сразу даёт неожиданный факт.
- **Time-to-payoff** — на какой странице читатель получает первую конкретную ценность (цифру / историю / тезис)? Целевая: ≤ страница 3.
- **First objection** — на какой странице читатель *может* подумать «зачем мне это»? Если в первых 2 страницах — есть проблема.
- **Promise specificity** — обещание книги конкретно («через 30 дней у вас будет AI-стек, который…») или абстрактно («научимся работать с AI»)?

**Workflow:** opus-агент в роли «потенциальный покупатель в книжном магазине, листает первые 5 страниц, решает покупать или нет». Output:

- Решение: BUY / SKIP / UNDECIDED
- Конкретные места которые тянут вниз
- Old → new для первых 3 страниц

Применяется **после WAVE 6 (voice)** — потому что conversion=голос + структура.

## WAVE 16 — CHAPTER → TG-POST EXTRACTION

**Проблема:** книга обязана работать как маркетинговый материал для твоего канала или блога. Каждая глава = семя для 2-3 промо-постов. Сейчас извлечение делается вручную.

**Workflow:** один opus-агент проходит главу, выделяет:

- **2-3 «atomic posts»** — короткие куски (200-500 символов) которые работают вне контекста главы как самостоятельный tg-пост. Должны: иметь крючок, конкретику, авторский голос (см. `~/.claude/skills/tg-post/SKILL.md`).
- **1 hook quote** — однострочный pull-quote для cover-картинки.
- **1 question for engagement** — спорный или открытый вопрос из главы, который можно превратить в reply-bait post.

Output: `chapters/<slug>/TG-EXTRACTS.md`:

```
## Post 1 (короткий тезис)
[текст 200-500 знаков]
**Источник:** гл.X, страница Y

## Post 2 (история-кейс)
[текст]

## Post 3 (контр-интуитивная мысль)
[текст]

## Cover quote
"[одна строка]"

## Engagement question
[открытый вопрос]
```

**Когда запускать:** после WAVE 12 (PR-fragment extraction). По сути — то же сырьё, но другой формат: PR-fragments для прессы, TG-posts для канала.

## WAVE 17 — A/B-TEST КАНДИДАТЫ ДЛЯ НАЗВАНИЙ И ПОДЗАГОЛОВКОВ ГЛАВ

**Проблема:** название книги и заголовки глав закрепляются на v8, но потом не пересматриваются. После 22 паттернов и WAVE 1-14 — содержание сместилось, заголовки могут быть subopt.

**Workflow:** opus-агент для каждой главы выдаёт:

- **3 альтернативных названия главы** — разной тональности (формальная / провокационная / нарративная)
- **3 альтернативных подзаголовка** для каждого подраздела

**Когда запускать:** перед WAVE 14 (publication checklist). Финальные названия закрепляются в TOC и manuscript только после.

## WAVE 18 — NEUROSYMBOLIC HOOK CHECK (memorable anchors)

**Проблема:** «человек запоминает не тезис, а образ» (Dan Heath, *Made to Stick*). Глава может быть структурно правильной, факты выверены, голос живой — но через неделю читатель ничего не вспомнит. Это смерть для non-fiction (которую читают и пересказывают коллегам).

**Workflow:** opus-агент читает главу как **«читатель через неделю после прочтения»**. Задача: какой ОДИН образ / сцена / метафора остаётся в памяти?

**Hook types (книга должна давать минимум 1 на главу):**

- **Образ** (visual) — конкретная сцена с сенсорной деталью («остывший чайник на столе в четыре утра», «партнёр разворачивает ноутбук экраном к команде»)
- **Метафора** (conceptual) — сквозная метафора книги, к которой возвращаешься в нескольких главах; работает, если она объясняет механизм, а не украшает абзац
- **Шок-цифра** (numeric) — соотношение, которое ломает ожидание («из двухсот купленных лицензий пользуются девятью»); запоминается пропорция, а не абсолютное число
- **Афоризм** (linguistic) — одна фраза, которую можно повторить дословно через неделю: короткая, с внутренним контрастом, без терминов
- **Контр-интуитивный тезис** (cognitive) — утверждение, спорящее с очевидным, с названным сроком или ценой («технология внедряется за квартал, привычки команды — за три года»)

**Output:** `MEMORABILITY-MAP.md` — таблица: глава × тип hook × конкретный hook × сила (1-5).

**FLAG:** если глава = 0 hooks силой 4-5 → переписать. Идеально: каждая глава = 1 hook силой 5 + 1-2 силой 3-4.

**Когда запускать:** после WAVE 8 (emotional arc) — синергия. Memorable anchor усиливает emotional peak главы.
