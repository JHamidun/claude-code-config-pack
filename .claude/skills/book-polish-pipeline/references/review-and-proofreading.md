## CROSS-MODEL REVIEW (Codex CLI как 2-я призма)

После того, как Claude-агенты прошли все 22 паттерна — запустить **Codex CLI (gpt-5.4)** на выборке из 3 глав: самая большая, одна операционная (там гуще цифры) и финальная. Codex даёт независимый взгляд и ловит то, что Claude-агенты пропускают.

### Команда

```bash
codex exec --model gpt-5.4 --skip-git-repo-check "Ты опытный non-fiction редактор...
[промпт из templates/codex-review-prompt.md]" > /tmp/codex-v13-review.log 2>&1 &
```

### Что искать

Codex регулярно ловит:
1. **Внутренние числовые конфликты** — «в 2,5-3,5 раза» и «на порядок» в соседних абзацах
2. **Манипулятивную срочность в финалах** — «второго шанса не будет», «встретимся по ту сторону»
3. **Самопохвалу читателю** — «ты уже опережаешь большинство коллег»
4. **Лакированную конкретику** — кейсы без единого сбоя/провала
5. **Жанровый сбой** — B2B-главу разрезает бытовая сцена
6. **Постановочные сценки** — «он отодвинул чашку и начал рисовать схему на салфетке»
7. **Длинный экскурс до основной развилки** — глава обещает «3 решения», 4 страницы юр-экскурса до них
8. **Гладкие цифры из питча** — 70% / 30% / «десятки» без базы наблюдения
9. **Самоопровержение в зачине** — нажимает на тезис, потом отмежёвывается
10. **Перегруз прогнозной арифметикой** — нумерология вместо прогноза

### Применение находок

- **CRITICAL (срочность/манипуляция/фабрикация)** — править руками сразу
- **STRUCTURAL (жанровый сбой, длинный экскурс)** — оставлять автору на финальную вычитку
- **MINOR (числовые расхождения)** — попасть в `book-v{N}-factcheck.md`

См. `templates/codex-review-prompt.md` для полного промпта.

## TRIPLE PROOFREADER PIPELINE

После всех content-правок — финальная корректура. **ВАЖНО:** запускать ПОСЛЕ всех editor-правок, иначе корректор перезапишет content-правки: он читает главу в состоянии на момент старта и в конце записывает её целиком, вместе с откатом всего, что появилось в файле по ходу.

### Распределение по 2 Sonnet-агентам

Делить по словам, а не по числу файлов: рамочные тексты втрое короче операционных глав,
и «поровну по главам» даёт одному агенту вдвое больше работы.

| Агент | Что получает | Объём |
|---|---|---|
| C-1 | первые главы + рамочные тексты | ~половина слов книги |
| C-2 | остальные главы + финал | ~половина слов книги |

### Тройной пайплайн внутри каждого агента

1. **Орфография** — опечатки, -тся/-ться, ё различительная, числительные
2. **Пунктуация** — запятые при оборотах и вводных, тире между подлежащим и сказуемым, двоеточие, прямая речь
3. **Типографика** — прямые кавычки `"..."` → ёлочки `«...»`, дефисы → тире `—` с NBSP, NBSP между числом и единицей (`1 234` → `1\xa0234`), многоточие `...` → `…`

### Что НЕ трогать корректору

- Frontmatter
- Source-trace HTML-комментарии в конце файла
- PROOFREAD-NOTES в конце
- Внешние цитаты на английском
- Манифест — только явные типографические правки (кавычки, NBSP), не пунктуация

### Чего ждать от прогона

- **Орфография и пунктуация — около нуля.** Их вычистили на этапе написания. Внезапные десятки орфографических правок означают, что корректор работает не с той версией файла
- **Типографика — десятки правок на партию**, почти вся про NBSP: на экране неразрывный пробел неотличим от обычного, поэтому автор его не видит ни при чтении вслух, ни при вычитке

**Insight:** орфография и пунктуация чистятся один раз и держатся. Типографика ломается заново на каждой версии, потому что правят её уже редактор и автор, а не корректор. Отсюда и правило: корректор запускается последним — и запускается заново после каждой волны.

## FACT-CHECK DISPATCH

После каскада версий и cross-model review — финальный факт-чек. Использовать спец-агент `book-fact-checker` (см. `~/.claude/agents/book-fact-checker.md`).

### Скоуп проверки

Конкретный список собирается из `chapters/*/SOURCES.md` и самих глав — он у каждой книги свой.
Разложен по четырём классам, у каждого своя типовая поломка:

1. **Цифры из исследований** — округление в свою пользу, цифра подгруппы, выданная за общую, потерянный размер выборки
2. **Цитаты внешних людей** (побуквенно) — привязка к не тому событию, сдвинутый год, авторский перевод, разошедшийся с оригиналом
3. **Цифры компаний** — здесь ломается не точность, а свежесть: ARR, оценки раундов, число клиентов, цены тарифов устаревают между сдачей рукописи и печатью
4. **Даты релизов**

### Источники для верификации

- **WebFetch** — для статей в открытом доступе
- **WebSearch** — для поиска первоисточников
- **Навык `perplexity`** — fact-check там, где WebFetch не справляется (Bloomberg / The Information за пейволом, McKinsey/HBR/Gartner с anti-bot защитой). Нужна своя подписка или `PERPLEXITY_API_KEY`.
- **YouTube API** — для цитат, упомянутых в <отраслевой видеоканал>

### Классификация результата

- **CRITICAL** — точно неверно, нужно исправить перед публикацией
- **WARNING** — расхождение в деталях (округление, дата) — сверить с автором
- **VERIFIED** — прошло факт-чек (краткий список без цитат)
- **UNKNOWN** — не удалось проверить (нужен URL/timestamp от автора)

### Что отделять от web-fact-check

- **Внутренние цифры своей компании** (выручка, число пользователей, объём базы) → всегда UNKNOWN с пометкой «требует подтверждения автора». Агент их проверить не может, а звучат они убедительно — и потому охотнее всего выдумываются
- **Личные истории автора** (сцены из практики, разговоры, эпизоды) → факт-чекеру не отдавать вообще; их единственный источник — `$BOOK_ROOT/ANCHORS.md`
- **Прогнозы** («через пять лет такая компания будет из двух человек») → не факт-чек, это авторская гипотеза

### Anti-pattern verification

Классический провал: fact-checker нашёл расхождения, оркестратор применил их руками — и **корректор, стартовавший до этого, перезаписал главу состоянием на момент своего старта**, вместе с откатом правок. Пропажа при этом тихая: файл валиден, версия правильная, отчёт корректора зелёный. Если применяешь content-правки параллельно с корректором — после возврата корректора **обязательно re-verify** через `grep` все critical-правки и переприменить через `Edit` / PowerShell `sed`. Поэтому правильный порядок:

```
1. craft pass (agents)
2. Self-read + manual content fixes (grep on suspicious facts)
3. Fact-checker dispatch (background)
4. Codex review (background, sample 3 chapters)
5. Apply CRITICAL fact + Codex fixes
6. Triple proofreader (background) — ВСЕГДА ПОСЛЕДНИМ
7. Re-verify content fixes survived
8. Build EPUB+DOCX
```
