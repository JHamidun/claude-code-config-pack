# Волны 1–5: bestseller-полировка (v8 → v10)

Пять волн содержательной правки: story-first и клиффхэнгеры, эпиграфы и сквозные герои, сшивка с компанией автора, систематизация читательских отзывов, уплотнение на 10–15%. Читай, когда запускаешь очередную волну из этой пятёрки.

## 5 ВОЛН BESTSELLER-ПОЛИРОВКИ (v8 → v10)

Применяются последовательно. Каждая волна = новая версия.

### Wave 1 (v8) — Story-first + Cliffhanger + Tweet-line

Цель: книга цепляет с первой страницы каждой главы и тянет в следующую.

1. **Story-first openings** для всех глав. Конкретная сцена с датой, местом, именем, репликой — **только из ANCHORS.md или extracted/stories/**. НЕ выдумывать.
2. **Cliffhanger endings** — мост в следующую главу, эмоциональный (не функциональный «дальше я разберу X»).
3. **Tweet-line** в конце каждой главы как pull-quote — короткая ударная фраза. Работают первые 8 глав, последние 4 обычно формульные — там пропускать.
4. **Sharp sentence** после Story-открытия — один разящий тезис, ставка всей главы.

### Wave 2 (v9) — Epigraphs + Recurring characters + Прямые зеркала

Цель: статусные сигналы + эмоциональное сопереживание + диалог с читателем.

1. **Внешние эпиграфы** к ключевым главам (с побуквенной верификацией первоисточника):
   - эпиграф ставится не ко всем главам, а к 4-6 опорным — иначе приём стирается
   - источник — публичная фигура отрасли, чьё имя читатель узнаёт без пояснения
   - к вводной главе работает не одна цитата, а трио разных по позиции голосов:
     оптимист, скептик и практик — рамка спора задаётся до первого абзаца
   - каждая цитата проверяется по первоисточнику побуквенно, с датой и площадкой;
     цитата «по памяти» — самый частый способ получить публичный разбор после выхода
2. **Recurring characters** (callbacks) — 2-3 живых человека из твоей практики; каждый
   возвращается в 2-3 главах и двигает одну сквозную линию. Пример раскладки:
   - герой А — линия «пользователь становится оператором»
   - герой Б — линия «обучение и наставничество»
   - герой В — линия «партнёрство»

   Считай не по главам, а по линиям: один герой — одна линия, и она должна за книгу
   куда-то прийти. Герой, который появляется дважды с одной и той же репликой, читается
   как декорация.

   Имена берутся ТОЛЬКО из твоего `$BOOK_ROOT/ANCHORS.md` и только с письменного
   разрешения самих людей. Нет разрешения — герой остаётся, имя уходит («партнёр»,
   «знакомый управленец»).
3. **Прямые зеркала к читателю** — раз в главу: «вы сейчас, скорее всего, думаете…», «у вас тоже есть момент, когда…».
4. **Manifest formulas** «не А, а Б» — оставлять только в Манифесте (разрешённое исключение Pattern 3 anti-ai-tells).

### Wave 3 (v10) — Сшивка со сквозным кейсом + отраслевые видеоинтервью

Цель: интегрировать сквозной кейс как сквозной кейс + добавить мировые голоса.

1. **Сшивка со сквозным кейсом** через главы (с privacy decision tree из `book-post`):
   - свой продукт упоминается 2-4 раза в «рабочих» главах, ≤1 в личных — иначе книга
     читается как расширенный пресс-релиз, и рецензент отметит это первым
   - **WHITELIST / BLACKLIST компаний заводится один раз до старта волны.**
     BLACKLIST — все, с кем есть NDA или чьё письменное разрешение не получено.
     WHITELIST — только публичные кейсы (пресс-релиз, публичное выступление, кейс на сайте).
     Оба списка держи в `~/.claude/author-profile.md` (раздел «О чём НЕ говорю») и
     продублируй в `$BOOK_ROOT/ANCHORS.md`. **Пустой BLACKLIST означает «не заполнил»,
     а не «называть можно всех»** — при пустом списке волна не запускается.
   - для всех из BLACKLIST — анонимизация по роли и отрасли:
     «крупный B2B-клиент из дистрибутивного бизнеса»
2. **10-12 встроек из отраслевых видеоинтервью** (анализ subtitles через YouTube API):
   - берутся публичные выступления фигур первого ряда твоей отрасли — тех, кого читатель
     узнаёт по фамилии; субтитры дают точную формулировку и таймкод
   - Атрибуция (c): в тексте «по интервью X» + сборная сноска в конце книги
   - Английский оригинал — только в 3 самых сильных местах
3. **Kahneman boxes** — врезки «Прежде чем читать дальше:» каждые 2-3 главы (всего 4 штуки)

### Wave 4 (v11) — Reader feedback systematization

Цель: точечные правки 3 читателей → системные паттерны.

1. **Собрать фидбек минимум от 3 разных читателей**, разных по профилю: технарь + бизнес + журналист (или редактор). Три одинаковых читателя дают одну и ту же правку трижды и создают ложное ощущение согласия.
2. **Из точечных правок вытащить системные паттерны**:
   - Триггер «2+ читателя независимо отметили одно и то же» = системный паттерн, в anti-ai-tells.md
   - Триггер «1 читатель + резонирует с принципом из 9 книг» = добавить в writing-craft-v2.md
3. **Применить системные паттерны ко всей книге** (через 5-agent parallel orchestration, см. ниже)
4. **Точечные правки фидбека** — отдельный список, применять руками (не агентами)

### Wave 5 (v12) — Tightening pass + структурный полиш

Цель: -10-15% объёма без потери содержания (Кинг + Зинсер).

1. **Скобочный метод Зинсера** по каждому абзацу: удалить всё, что не работает на смысл
2. **Стоп-слова Ильяхова** (90+ список из writing-craft-v2)
3. **Формула -10% Кинга** ко второму драфту
4. **Чтение вслух** (тест «второй вдох до точки» Безручко)
5. **Удалить служебные заголовки** разделов (главы идут непрерывным текстом)
6. **Мини-контракт** после story-first opening
7. **Конкретное действие в конце главы** (не «изучите», а «откройте, напишите, сделайте»)
