# Triple Proofreader Prompt — для 2 Sonnet-агентов

> Шаблон промпта для тройной корректуры (ortho → punct → typo). Запускать **ПОСЛЕДНИМ** в pipeline — после всех content-правок, иначе корректор перезапишет content-правки оркестратора.

## РАСПРЕДЕЛЕНИЕ ПО 2 АГЕНТАМ

Делить **по словам, а не по числу глав**: рамочные тексты втрое короче операционных,
и деление «поровну по файлам» даёт одному агенту вдвое больше работы.

| Агент | Что получает | Доля объёма |
|---|---|---|
| C-1 | первые главы + рамочные тексты | ~половина слов книги |
| C-2 | остальные главы + финал | ~половина слов книги |

Запуск через `Agent` tool с `subagent_type: general-purpose`, `model: sonnet`, `run_in_background: true`.

## ПРОМПТ ДЛЯ КАЖДОГО АГЕНТА

```
Ты редактор-корректор русского текста. Прогони тройной пайплайн ortho → punctuation → typography на {N} главах книги. Применяй правила Розенталя и Ильяхова, типографики artlebedev / Главреда.

ФАЙЛЫ:
{список путей к DRAFT.v{N}.md по главам этого агента}

ТРОЙНОЙ ПАЙПЛАЙН для каждого файла:

### 1. Орфография — проверь:
- Опечатки (буквенные пропуски, перестановки)
- -тся / -ться (инфинитив vs 3 лицо)
- Двойные и одиночные согласные (профессионализм vs профисионализм)
- Буква ё там, где нужна различительно («все» vs «всё»)
- Числительные прописью / цифрами

### 2. Пунктуация — проверь:
- Запятые при причастных и деепричастных оборотах
- Запятые при вводных словах
- Тире между подлежащим и сказуемым (если оба существительные)
- Двоеточие при перечислениях и пояснениях
- Прямая речь — кавычки + тире
- Авторская пунктуация (автор любит длинные предложения с тире — оставляй)

### 3. Типографика — поменяй:
- Прямые кавычки `"..."` → ёлочки `«...»` (внутренние — лапки `„..."`)
- Дефисы `-` между числами и в коротких связях → тире `—` (длинное)
- Перед тире — неразрывный пробел (NBSP, U+00A0)
- Между числом и единицей измерения — NBSP («12 узлов», «$3 млн»)
- Тысячные разделители: «1 234» (NBSP), «56 789» (NBSP)
- Многоточие `...` → `…` (один символ)

ПРАВКИ — В САМИХ ФАЙЛАХ DRAFT.v{N}.md (правь напрямую через Edit tool).

## ⛔ ВАЖНО — НЕ ТРОГАТЬ:

- Frontmatter в начале файла
- Source-trace в конце файла (HTML-комментарий `<!-- source-trace: -->`)
- PROOFREAD-NOTES в конце
- Внешние цитаты с указанием автора (если на английском — оставляй прямые кавычки)
- Английские термины в кавычках в авторском тексте
- ТОЛЬКО для Манифеста (если включён в твою партию): минимально — только явные типографические правки (кавычки, NBSP), НЕ пунктуация, ритм критичен

## ОТЧЁТ в конце:
- По каждой главе сколько правок какого типа (ortho / punct / typo)
- Финально — топ-5 систематических проблем, которые встретились во всех главах

Работай тщательно. Это финальный пас перед публикацией.
```

## ANTI-PATTERN — ВАЖНО

❌ **Корректор может откатить content-правки** если работает параллельно с editor-агентом. Классический случай: оркестратор руками применил CRITICAL fact-fixes (уточнил процент, снял неверную привязку цитаты к событию), а корректор, стартовавший до этого, читал главу в старом состоянии и записал её обратно поверх правок.

✅ **Решение:** ВСЕГДА запускать корректора ПОСЛЕДНИМ:

```
1. v{N} craft pass (5 Opus agents)        [60-90 мин]
2. Self-read + manual content fixes
3. Codex review (background, sample 3)    [60-90 мин]
4. Fact-check dispatch (background)       [30-60 мин]
5. Apply CRITICAL fixes
6. Triple proofreader (background)        [10-20 мин] ← ВСЕГДА ПОСЛЕДНИМ
7. Re-verify content fixes survived       [grep + переприменить через PowerShell sed]
```

После возврата корректора **обязательно re-verify** через grep все CRITICAL-правки. Если корректор откатил — переприменить через PowerShell `sed` (NBSP-aware):

```powershell
$f = "C:\path\to\DRAFT.v13.md"
$content = Get-Content $f -Raw -Encoding UTF8
$content = $content -replace "старая фраза", "новая фраза"
[System.IO.File]::WriteAllText($f, $content, [System.Text.UTF8Encoding]::new($false))
```

## ЧЕГО ЖДАТЬ ОТ ПРОГОНА

Профиль правок на книге, которая уже прошла корректуру на этапе написания:

- **Орфография и пунктуация — около нуля.** Это не повод считать прогон пустым:
  их вычистили раньше. Если корректор внезапно даёт десятки орфографических правок —
  он работает не с той версией файла.
- **Типографика — десятки правок на партию**, и почти вся она про NBSP. Это единственный
  класс, который не ловится ни автором при чтении вслух, ни предыдущими проходами:
  на экране неразрывный пробел выглядит как обычный.

### Топ-5 систематических проблем

Порядок устойчивый, от самой частой к более редкой:

1. **Число + млрд/млн без NBSP** — самая частая ошибка (`60,8 млрд`, `$2 млрд`)
2. **Число + часов/минут без NBSP** (`40 часов`, `11 минут`)
3. **Тысячи через обычный пробел** (`5 500`, `12 000`)
4. **Число + процентных пунктов/% без NBSP** (`40 процентных пунктов`, `30% времени`)
5. **Числовые диапазоны** (`9–10 миллиардов`, `10–100 раз`) — NBSP после диапазона

**Insight:** орфография и пунктуация чистятся один раз и держатся; типографика ломается
на каждой новой версии, потому что её правит уже не корректор, а редактор и автор.
Поэтому корректор и запускается последним — и запускается заново после каждой волны.
