# Codex CLI Review Prompt — Cross-Model 2-я призма

> Шаблон промпта для Codex CLI (gpt-5.4). Запускать после того, как Claude-агенты прошли все 22 паттерна. Codex даёт независимый взгляд и ловит то, что Claude-агенты систематически пропускают.

## КОМАНДА ЗАПУСКА

```bash
codex exec --model gpt-5.4 --skip-git-repo-check "$(cat <<'EOF'
Ты опытный non-fiction редактор. Прочитай 3 главы книги (название и автор —
из `$BOOK_ROOT/BOOK.md`). Найди то, что мог пропустить
предыдущий редактор:

1. $BOOK_ROOT/chapters/{slug-1}/DRAFT.v{N}.md
2. $BOOK_ROOT/chapters/{slug-2}/DRAFT.v{N}.md
3. $BOOK_ROOT/chapters/{slug-3}/DRAFT.v{N}.md

Контекст: книга прошла 22 прохода редактуры по 20+ паттернам AI-почерка,
9 книг по писательскому мастерству. Голос — первое лицо, уязвимость,
конкретные числа, скептический инсайдерский тон.

Ищи именно то, что СВЕЖИЙ глаз заметит, а уставший редактор пропустит:
- Внутренние противоречия (тезис в начале vs финал главы)
- Места, где автор говорит «у нас в компании», но конкретика звучит выдуманно
- Цифры/проценты, которые звучат подозрительно круглыми (70% / 30% / десятки)
- Слабые переходы между разделами
- Места, где читатель-CEO потеряет интерес
- Сцены, которые перегружены деталями (>4 сенсорных канала)
- Манипулятивные обороты, которые маскируются под «честность»
- Дублирующиеся идеи внутри главы
- Самоопровержение в зачине (нажимает на тезис → отмежёвывается)
- Числовые конфликты (одно число в одном месте, противоречащее в соседнем)
- Манипулятивная срочность в финалах («второго шанса не будет»)
- Самопохвала читателю («ты уже опережаешь большинство коллег»)

Отчёт: до 800 слов. По каждой главе 3-5 самых конкретных находок с цитатами
(номер строки или фрагмент) и предложением правки.

НЕ хвали книгу — нужна жёсткая критика. Если что-то отлично — пропусти,
не комментируй.

Формат каждой находки:
- **Цитата:** «текст из книги» (строка/контекст)
- **Проблема:** что не так
- **Правка:** что предложить
EOF
)" > /tmp/codex-v{N}-review.log 2>&1 &
```

## ВЫБОР 3 ГЛАВ ДЛЯ SAMPLE

Берётся не «первые три», а три разных по нагрузке:

- **1 самая большая глава** — там больше всего мест, где редактор устал
- **1 операционная глава** — где гуще всего цифры и выше риск фабрикации
- **1 финальная глава** — там концентрируются манипулятивная срочность и лесть читателю

Если книга малого объёма (<10 глав) — Codex по всем главам.

## ОБРАБОТКА РЕЗУЛЬТАТА

После завершения (60-90 минут на 3 главы):

```bash
# 1. Прочитать отчёт
cat /tmp/codex-v{N}-review.log | tail -200

# 2. Извлечь только finding-блоки (без процессного шума)
grep -A 3 "Цитата:\|Проблема:\|Правка:" /tmp/codex-v{N}-review.log
```

### Классификация находок Codex

| Категория | Действие |
|---|---|
| **CRITICAL** — манипулятивная срочность, лесть, выдуманные цифры | Править руками сразу |
| **STRUCTURAL** — жанровый сбой, длинный экскурс, перегрузка прогнозами | Оставить автору на финальную вычитку |
| **MINOR** — числовые расхождения, гладкие проценты без базы | Попасть в fact-checker отчёт |
| **STYLE** — постановочные сценки, лакированная конкретика | Применить к v{N+1} |

## ANTI-PATTERN — что Codex обычно НЕ ловит

- Точечные орфографические ошибки (это к корректору)
- Нарушения NBSP-конвенций (это к корректору)
- Выдуманные «личные» числа автора если они звучат правдоподобно (это к fact-checker)

## ПРИМЕР ФОРМАТА ОТЧЁТА

Ниже — вымышленный прогон, чтобы было видно нужную гранулярность. Порядок такой:
сначала CRITICAL с готовой заменой, потом STRUCTURAL списком без правок.

Типичный выход по трём главам — 10-15 находок, из них 3-5 CRITICAL.

**CRITICAL — применяются сразу, с явной заменой:**

1. ✅ Финальная глава: «второго шанса не будет» → «окно ещё открыто, но не бесконечно»
2. ✅ Финальная глава: «ты уже опережаешь большинство коллег» → «у тебя в голове сложилась рамка»
3. ✅ Финальная глава: «встретимся по ту сторону» → удалено
4. ✅ Операционная глава: «он отодвинул чашку и начал рисовать схему на салфетке» → удалено (постановочная кинодеталь)

**STRUCTURAL — уходят автору на финальную вычитку, агентом не правятся:**

- Самоопровержение в зачине: тезис заявлен и тут же смягчён
- Лакированная конкретика в кейсе: «сделали за два дня», ни одного сбоя
- Длинный отраслевой экскурс до основной развилки главы
- Бытовая сцена ломает жанр B2B-главы
- Числовой конфликт: «в 2,5-3,5 раза» и «на порядок» в соседних абзацах
- Нумерология в прогнозах вместо прогноза
- Раздутый инструментальный раздел отнимает фокус у тезиса
- Перегруз названиями продуктов в зачине
