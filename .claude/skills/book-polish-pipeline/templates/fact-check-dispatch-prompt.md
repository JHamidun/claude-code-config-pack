# Fact-Check Dispatch Prompt — для book-fact-checker агента

> Шаблон промпта для финального факт-чека всей книги. Использовать с агентом `book-fact-checker`.
> Общий фактчек статей — стадия 3 навыка `article-pipeline`
> (`~/.claude/skills/article-pipeline/references/stage-3-fact-checker.md`), но для книги он
> не подходит: там внутренние данные автора = FAIL, а в книге они UNKNOWN.

## ПРОМПТ

```
Ты фактчекер книги автора (название, издательство и год — из `$BOOK_ROOT/BOOK.md`). Прошла {N} проходов редактуры, нужен финальный факт-чек перед публикацией.

ВХОД: {N_chapters} глав v{N} в `$BOOK_ROOT/chapters/`:

{список путей к DRAFT.v{N}.md}

## ЧТО ПРОВЕРЯТЬ

Список конкретных фактов собери сам: пройди `chapters/*/SOURCES.md` и главы, выпиши
всё проверяемое. Ниже — четыре класса, по которым это раскладывается, и что в каждом ломается.

### 1. Цифры из исследований — реальны ли проценты

Выписывай в формате «организация + название отчёта + год: цифра, которую взял автор».
Чаще всего расходится:

- **процент округлён в свою пользу** — в тексте «+30%», в работе «+34%» по подгруппе
- **цифра из подгруппы выдана за общую** — эффект был у низкоквалифицированных,
  а в книге стоит как средний по выборке
- **размер выборки потерялся** — «исследование показало» на 16 участниках
- **знак результата перевёрнут** — работа зафиксировала субъективное ускорение
  при объективном замедлении, в пересказе осталась только приятная половина

### 2. Цитаты внешних людей — побуквенно ли с первоисточником

Для каждой цитаты нужны три вещи: точная формулировка, площадка, дата. Типовые провалы:

- **цитата приписана не тому событию** — сказано в подкасте, в книге стоит «на конференции»
- **год сдвинут** — фраза 2023 года подана как свежая
- **перевод сделан автором и разошёлся со смыслом оригинала** — сверять по оригиналу,
  а не по чужому переводу
- **цитата гуляет по интернету без первоисточника** — если первоисточник не находится,
  это UNKNOWN, а не VERIFIED

### 3. Цифры компаний

Выручка, ARR, оценка, число клиентов, сроки. Здесь главная беда — не ошибка, а **старение**:
цифра была верна в момент написания и разошлась к моменту выхода. Помечай всё, что
меняется быстрее чем раз в квартал (ARR стартапов, оценки раундов, звёзды на GitHub,
цены тарифов), отдельным флагом «проверить перед сдачей в печать».

### 4. Даты релизов и событий

## ИНСТРУМЕНТЫ ВЕРИФИКАЦИИ

- **WebFetch** — для статей в открытом доступе
- **WebSearch** — для поиска первоисточников
- **Perplexity Max** (если доступна, через cookies) — для платных источников
- **Grep** по локальным `chapters/*/SOURCES.md` — для проверки атрибуции в книге

## ⛔ ВАЖНО — ЧТО НЕ ПРОВЕРЯТЬ

Эти вещи НЕ верифицируются через web — это либо личные данные автора, либо качественные суждения:

- **Внутренние цифры компании автора** (выручка, число пользователей, объём базы, размер кодовой базы) → всегда UNKNOWN с «требует подтверждения автора»: проверить их снаружи нельзя, а звучат они убедительно
- **Личные истории автора** (сцены из практики, разговоры, эпизоды) → факт-чекеру не отдавать вообще; их источник — `$BOOK_ROOT/ANCHORS.md`
- **Прогнозы** («через пять лет такая компания будет из двух человек») → не факт-чек, это авторская гипотеза
- **Качественные суждения автора** («по моему опыту 65% людей боятся коллег») → пометить как UNKNOWN

## ВЫХОД

Создай файл `./work/book-v{N}-factcheck.md` со структурой:

# FACT-CHECK REPORT v{N}

## CRITICAL (нужно исправить перед публикацией)
[список с указанием главы, цитаты в книге, что не сходится, источник реальной информации]

## WARNINGS (проверить, возможно неточно)
[список с указанием главы, цитаты, что под сомнением]

## VERIFIED (прошло факт-чек)
[краткий список того, что подтвердилось — короткими строками, без цитат]

## UNKNOWN (не удалось проверить)
[список с указанием главы, цитаты, причина — нет источника или это внутренние данные автора]

Не комментируй то, что сходится — только проблемы.
ВРЕМЯ: до 30-60 минут на работу. Лучше быстрая выборка ключевых фактов, чем долгая обработка всех.
```

## ЧЕГО ЖДАТЬ ОТ ПРОГОНА

Порядок величин на книгу среднего объёма — чтобы отличить рабочий отчёт от халтуры:

- **CRITICAL — единицы.** Обычно это округление процента в свою пользу и цитата,
  привязанная не к тому событию. Каждая идёт с готовой заменой, иначе она бесполезна.
- **WARNING — несколько.** Расхождение в детали: год, площадка, знак после запятой.
  Их применяет автор, а не агент: тут нужно решение, а не правка.
- **VERIFIED — самая длинная секция**, и её надо держать короткой по форме:
  строка на источник, без цитат. Она нужна только чтобы видеть охват.
- **UNKNOWN — сопоставимо с VERIFIED, и это нормально.** Сюда падает всё за пейволом,
  цитаты без первоисточника, быстро стареющие числа и внутренние данные автора.
  Пустой UNKNOWN — признак, что агент выдавал правдоподобное за проверенное.
