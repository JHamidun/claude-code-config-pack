# Инструменты, таблицы закупа и сквозная аналитика

> Состояние сервисов, тарифы и промокоды — **весна 2026, проверять актуальность.** Часть сервисов с тех пор могла измениться или закрыться.

| Инструмент | Площадка | Для чего | Заметки |
|---|---|---|---|
| **TrendHero** `trendhero.io` | Instagram | вовлечённость, **гео, пол, интересы аудитории**, разбивка на реальные / подозрительные / массфолловеры / инфлюенсеры | аналог TGStat и Telemetr для Instagram. **Что из этого стоит денег.** TrendHero — отчёт по аккаунту платный (порядка нескольких
сотен рублей за отчёт, есть пакеты); Prizma.tools и Synapex — подписочные, тариф на сайте;
ViewStats и реестр ФАС — бесплатны; `@labelup_bot` — часть статистики бесплатно, полный
отчёт платный. Формулы и логика отбора работают и без этих сервисов, руками: платный
доступ экономит время, но не является условием работы. У сервисов бывают промо-условия
у партнёров — спрашивай при оплате, вшивать чужой промокод в навык смысла нет.

### Что из этого автоматизируется агентом

⚠️ Ниже — **эскиз агента**, а не работающий инструмент.
Он прямо расходится с практикой из раздела 2 («поиск делается руками»), поэтому приводится
как ориентир для сборки, а не как описание текущего процесса.

```
Проверка блогера
  при добавлении нового блогера агент шлёт запрос в сервис аналитики
  (Trendhero / LiveDune API) → подтягивает ER, географию аудитории,
  демографию (пол, возраст), охваты по постам и сторис
  → считает ПРОГНОЗНЫЕ CPV и CPL и сравнивает с внутренними бенчмарками
  → ставит тег «Брать» / «Не брать»

Автокоммуникация
  одобренным сразу уходит шаблонное сообщение
  (сценарии: предложение сотрудничества, обсуждение условий, подтверждение формата)

Генерация сценариев интеграций
  на основе трендвотчинга, с подстройкой под тематику блогера, его аудиторию,
  тренды ниши и цели кампании
  примеры: обзор продукта в Reels · трендовое видео с интеграцией ·
           серия сторис с CTA и промокодами

Аналитика
  собирает просмотры, клики, ER, CPL/CPA, сравнивает С ПРОГНОЗОМ,
  формирует отчёт по каждой интеграции и даёт рекомендации
  + организация доставки бартерных товаров

Стек: Trendhero API · LiveDune API · Supabase/PostgreSQL · OpenAI · Telegram Bot ·
      n8n · Make · Google Sheets
```

Ценная часть здесь не автоматическая рассылка, а **замкнутый контур «прогноз → факт»**:
агент сначала считает ожидаемые CPV и CPL по формулам (раздел `pricing-formulas.md`), а
после открутки сравнивает с реальностью. Именно это превращает разовые закупы в
накапливаемую статистику по бенчмаркам, и это можно вести даже в таблице, без агента.

К автоматической коммуникации стоит отнестись осторожнее: блогер, получивший явно
шаблонное сообщение, отвечает хуже, а на маленьком пуле кандидатов (а он почти всегда
маленький) экономия времени не окупает потерю тона.

## 2. Три уровня таблиц закупа

Поиск аккаунтов делается руками — автоматизации на этом этапе нет. Один человек ведёт цикл и постепенно дополняет данные, чтобы ничего не терялось.

**Уровень 1. Сбор кандидатов** (ведёт ассистент/аналитик)

| Колонка | Что пишем |
|---|---|
| Название аккаунта | |
| Ссылка | |
| Ключевой показатель | охват одной публикации за 24 ч (TG) либо комбинация множителей (IG) |
| Расчётный бюджет | плановый потолок из формулы: сколько готовы заплатить (→ `pricing-formulas.md`) |
| Ссылки на зашедшие креативы | референсы из «эффективности рекламы» / «рекламной отдачи» — что у них хорошо сработало |
| Вердикт | берём / дорого / мимо / **в резерв, если останется бюджет** |

**Уровень 2. Закуп** (тот же человек переходит в фазу закупа либо таблица уходит закупщику; данные частично дублируются)

Дата и время размещения · площадка · ссылка · админ/контакт · тематика · охваты под нужный формат · запрошенная цена · расчётный CPM · **кто делает маркировку — мы или они** · UTM-ссылка или отдельная пригласительная ссылка, которую им отдаём · кто делает креатив (бывают аккаунты, которые не отдают креатив на сторону) · оплачено/нет · фактический результат.

**Уровень 3. Аналитика креативов**

Позывной креатива × аккаунт → охваты, переходы, бюджет, цена подписчика/перехода. Накапливается пул боевых креативов — «горячий резерв» на случай, когда по аккаунту нет аналитики и копировать нечего (→ `echelons-and-creative.md`).

## 3. Prizma.tools — сквозная аналитика закупа

**Что не работает без неё.** Разместились в аккаунте — непонятно, сколько подписчиков пришло именно оттуда, сколько отвалилось через неделю и кто из них потом купил. Штатные пригласительные ссылки Telegram показывают только количество переходов: подписался человек или просто заглянул — неизвестно.

**Как устроено.** Бот добавляется в канал и **UTM-ит каждый переход** по сгенерированной пригласительной ссылке. Пример разметки:

| Параметр | Что кладём | Пример |
|---|---|---|
| `source` | где размещаем — площадка/тип трафика | посевы vs Telegram Ads |
| `medium` | имя подрядчика, который занимался размещением | |
| `campaign` | локальная гипотеза | закупы с аудиторией >10К vs авторские <10К |

Ссылки при этом могут вести и с внешних источников — видно, кто перешёл и подписался ли потом.

**Что это даёт:**

1. **Отток по каждому источнику.** В сводке видно «пришло 1500 — осталось 190», то есть удержалось 13%, а по другому каналу «пришло 11 — осталось 11». Аккаунты, из которых аудитория остаётся, и аккаунты, из которых она осыпается, различаются в разы — это критерий для долгосрочной работы, которого нет ни в одном сервисе аналитики.
2. **Выгрузка ников** с указанием, по какой ссылке человек пришёл. Выгрузка периодически сверяется с продажами в CRM (запросить телеграм-ник в отделе продаж несложно) → видно **цикл прогрева до покупки** и то, какие аккаунты дают реальных клиентов, а не подписчиков.
3. **Правильный look-alike.** Расширяться нужно от аккаунтов, которые дали продажи, а не от всех подряд.

> «Работа с отсроченными когортами, особенно в social media, где всё сливается со всем, — суперважно.»

## 4. Synapex — полуавтоматизация маркировки

Актуально при **большом количестве размещений** (паблики пачками); при точечной работе с авторскими аккаунтами избыточно.

Закрываемая цепочка, статусами по шагам — что сделано, что нет:

```
бронь размещения → добавление издателя по ИНН → шаблон договора → подписание
→ отправка в ОРД → получение токена → выставление и отправка счёта
→ приём креатива через бота → вставка маркировки в креатив → публикация
→ удаление креатива на стороне канала → акт по договору → отправка статистики
```

Часть шагов автоматизирована (получение токена, подача статистики). Смысл — держать в порядке большой поток закупа и не терять документы.

**Статус на весну 2026:** развитие продукта приостановлено — VK забирает этот функционал на себя. Если сервис отвалится, ищется аналог; сама цепочка шагов от этого не меняется и остаётся чек-листом.

## 5. Роли в команде

**Закупом занимается не SMM-щик.** Отдельный человек ведёт рутину: шерстит аккаунты, ведёт переписку, договаривается о датах и условиях, собирает статистику. SMM-щик подключается **после** договорённости — получает референсы, договорённости и собранную статистику и решает, как именно размещение будет реализовано.

Разделение существенно: поиск и переговоры — это объём рутины, который съедает SMM-щика целиком и вытесняет его основную работу.

## 6. Смежные замеры

Падение конверсии при уходе на внешний ресурс замеряется прокси-ссылками: на каждый клик фиксируется, кто кликнул (client id внутри бота), и потом сверяется, оставил ли он заявку. Так получена цифра «на внешнем ресурсе заявок примерно вдвое меньше» (→ `pricing-formulas.md`).

Сверка получившихся CPM/CPL/CPA с рыночными бенчмарками РФ и проверка подрядчика на ботовода → `ad-benchmarks-ru`.
