# Большие данные у агента: sandbox + grep вместо контекста

Как отдать агенту объём, который не влезает в контекст: файлы в песочнице, поиск по ним инструментами, а не чтением. Читай, когда агенту нужны каталоги, выгрузки, длинные логи.

## Работа с большими данными (sandbox + grep вместо контекста)

Правило: **большой артефакт не попадает в контекст никогда**. Он монтируется в песочницу агента, агент грепает/скриптует по нему и возвращает наружу только агрегат.

### Как это устроено

1. Файл (лог на десятки тысяч строк, выгрузка CSV, JSONL) кладётся в рабочий каталог агента / монтируется в сессию.
2. В системном промпте прямо сказано: где лежит, что он большой, и что читать его целиком нельзя — только `grep`/`python`.
3. Агент сам сужает выборку точечными запросами: сначала окно по времени/ключу, потом детали найденного.
4. Наружу уходят десятки строк, а не десятки тысяч.

Формулировка в промпте (переносимая):

```
Лог примонтирован по пути <path> (большой; анализируй grep/python, НЕ читай целиком).
Локальные инструменты <...> отдают те же данные, что видит дашборд.
Сопоставь свидетельства и изложи вывод кратко.
```

### Разделение: песочница vs локальные инструменты

- **В песочницу** — тяжёлые статичные данные (логи, дампы, выгрузки). Там же агент пишет и запускает скрипты.
- **Локальными инструментами** (исполняются на твоей стороне, агент дёргает их через поток событий) — доступ к живым/закрытым системам: метрики, деплои, CRM, БД. Замена мок-JSON на реального клиента превращает демо в прод, ничего не меняя в агенте.
- Каркас минимального агента с песочницей — это ~7 функций: создать агента, создать окружение, загрузить файл, открыть сессию, прокачать поток событий, обработать вызов локального инструмента, закрыть сессию. Всё остальное — промпт, схемы инструментов и UI.

### Массовые операции

Для любой операции, затрагивающей больше ~5 сущностей: не листай вызовами инструментов, а **напиши скрипт**, который читает файлы и печатает компактный JSON. Батч-скрипты живут ВМЕСТЕ со скиллом (скилл = инструкции + исполняемые файлы рядом), и в скилле явно написано: «для свипа по многим SKU запускай batch-скрипт, а не цикл вызовов».

Эффект измеряется в транскрипте: 100+ вызовов инструментов и минуты стены превращаются в 2-3 запуска скриптов.

### Sinks для побочных эффектов

Записи (заказы, исходящие сообщения, апдейты ERP) — в append-only JSONL, по одному JSON-объекту на строку, с обязательными полями-идентификаторами. Это одновременно аудит и то, что читает грейдер `action_taken` при эвале.

### Перенос на наш стек

- **Hermes:** тяжёлые данные — в workspace-volume контейнера, доступ через `terminal`-тулсет; батч-скрипты — рядом со скиллом/плагином. Инструментам плагина запрещено возвращать «портянки»: плагин считает и отдаёт агрегат. Клиентским ботам `terminal` не давать — им большие данные и не нужны.
- **OpenClaw:** тот же приём через sandbox-браузер/воркспейс, лимиты на размер ответа инструмента в extension.
- **Общее:** ставь жёсткий потолок на размер ответа любого инструмента (ориентир ~2k токенов). Инструмент, регулярно упирающийся в потолок, — кандидат на переезд в code-exec.
