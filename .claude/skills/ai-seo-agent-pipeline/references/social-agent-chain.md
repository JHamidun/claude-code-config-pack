# Агентская цепочка для соцсетей: сначала research, потом продакшн

Вторая половина метода эксперт, зеркальная программатическому SEO. Логика одна: выигрывает не
лучшая единица контента, а система, которая закрывает объём — но **вход в систему не там, где
кажется**.

> Главное правило блока, повторённое трижды: **первым делом автоматизируется исследование, а не
> продакшн.** «Просто начать создавать 100-200-300 видео, которые не несут ценности» — тупик;
> статьи и ролики мёртвым пластом валяются. Обязательное условие любого объёма: под контент должна
> существовать аудитория и спрос. Иначе генерация — это производство мусора в промышленных
> масштабах.

Причина однотипности контента на рынке: все используют одни и те же шаблоны и одинаковых
AI-аватаров (Higgsfield и подобные). Отличие даёт не инструмент генерации, а качество отбора того,
что генерировать.

---

## 1. Воронка трендвотчинга — цифры, которые всё объясняют

Весна 2026, проверить актуальность:

| Этап | Объём |
|------|-------|
| Аккаунтов в мониторинге | **300+** |
| Роликов, которые они выпускают за неделю | **более 10 000** |
| Из них реально виральных, способных дать результат | **~100** |

Процент рабочих единиц крайне низкий — около 1%. Отсюда два вывода:

1. **Один-два аккаунта в мониторинге бессмысленны.** Про это обычно умалчивают, когда рассказывают
   про «анализ конкурентов»: при пуле в 2-3 аккаунта в неделю попадается ноль-один пригодный
   образец, и агент-сценарист начинает фантазировать.
2. Пул строится из ниши **и смежных ниш** — хук из соседней тематики переносится лучше, чем
   пятидесятый пересказ своей.

Кросс-проверка: в `content-machine-instructor2-ru` пул задан как 100-500 аккаунтов — 300 это рабочая
середина от второго независимого источника, и приведённая воронка объясняет, зачем так много.

## 2. Метрика виральности

Собственная формула скоринга у автора метода — secret sauce, не раскрывается. Рабочая замена для
старта, которую он даёт прямо:

**Сравнивать просмотры ролика с медианой этого же аккаунта.**

Если аккаунт обычно собирает ~1000 просмотров, а конкретный ролик набрал в разы больше — он
виральный **относительно своего контекста**. Абсолютные просмотры для этой задачи бесполезны: у
крупного аккаунта проходной ролик наберёт больше, чем прорывной у мелкого, и отбор скатится в
«лучшие ролики самых больших аккаунтов».

Практическая формулировка: `virality = views / median(views последних N роликов этого аккаунта)`,
отбирать по порогу и сортировать по убыванию.

## 3. Цепочка из пяти агентов

```
[1 Сборщик] → [2 Сценарист] → [3 Генерация] → [4 Публикатор] → [5 Аналитик]
                    ▲                                                │
                    └──────────── обратная связь по метрикам ────────┘
```

**1. Агент-сборщик.** Обходит все аккаунты пула, складывает ролики с метриками в таблицу:
просмотры, лайки, комментарии, share, save, хэштеги, ник аккаунта, число подписчиков, дата.
Источник данных — акторы Apify либо готовый датасет (§5).

**2. Агент-сценарист.** Берёт лучшие ~100 роликов за неделю, разбирает **хуки и покадровую
структуру** и пишет новые сценарии. Принципиальное отличие от «напиши сценарий для рилса»: он **не
фантазирует, а строит на роликах, которые уже принесли результат конкурентам**. В таблицу
складываются caption, топик, хук, ценность, структура, «почему сработало» и рекомендации.

**3. Генерация.** Идея → визуалы → сборка ролика. Сборка — через сервис с API (в источнике назван
на слух как «криотомат», по описанию это сервис программной сборки видео по API,
вероятно **Creatomate** `[?]`); визуалы — Fal.ai или свой image/video-стек. В экосистеме пользователя
генерация идёт через разрешённые модели (`skills/video-generation`, `skills/image-generation`,
правило `dont-do`).

**4. Агент-публикатор.** Берёт готовые ролики из таблицы, скачивает видео и обложку, публикует
через API площадки (в источнике — Instagram API), обновляет статусы строк.

**5. Агент-аналитик.** Подтягивает список опубликованного, снимает свежие метрики, показывает, что
зашло. **Это замыкает петлю:** видно, какие типы сценариев искать дальше, и порог отбора на шаге 2
пересобирается по своим данным, а не по чужим.

## 4. Анатомия агента (проектная рамка)

Агент — не сервис, а автономная система из четырёх частей:

| Часть | Что подставляется |
|-------|-------------------|
| **Модель** | ChatGPT / Claude / Gemini |
| **Контекст** | CRM, Notion, база знаний, база данных — куда сохраняется найденное |
| **Логика и интеграции** | Оркестрация: n8n / Gumloop / Relevance или код |
| **Интерфейс** | Как с ним взаимодействуют: форма, чат, панель, таблица |

Практическая развилка «где строить»:

- **Claude Code** — когда нужен полноценный интерфейс. У автора метода это панель, где ролики
  сортируются по метрике виральности и по каждому видно caption, топик, хук, ценность, структуру,
  почему сработало и рекомендации.
- **n8n / Gumloop / Relevance** — когда достаточно таблицы на выходе.

## 5. Источники данных

| Сервис | Что даёт |
|--------|----------|
| **Apify** | Store с акторами: Facebook, Google Maps, Twitter, TikTok, YouTube. Формулировка автора: «актор — это как скилл, который вы даёте агенту» — доступ к площадке без своего скрапера. Скилл `apify-scraping` |
| **Bright Data** | Прямая покупка готовых датасетов, например по LinkedIn |
| **Influencer Club** | Данные по инфлюенсерам |
| **Датасет-сервисы под агентов** (новый класс) | Продают данные специально для агентов. Названный пример — сервис по коротким видео (в записи на слух `shop.ai` `[?]`, название проверить): **100+ млн проиндексированных видео, 200+ полей** на видео — просмотры, лайки, комментарии, share, save, хэштеги, никнеймы, число подписчиков, гео, саунды. Покупается готовым вместо своего скрапинга |
| **Fal.ai** | Генерация контента (визуалы) |

Своя разведка по TikTok/Reels без покупки датасетов → скиллы `tiktok-intel`, `trend-engine`.

## 6. Порядок внедрения (что делать по шагам)

1. Собрать пул **300+ аккаунтов** в нише и смежных.
2. Автоматизировать сбор всех их роликов с метриками (Apify-акторы либо готовый датасет).
3. Отскорить виральность: просмотры ролика против медианы этого же аккаунта.
4. Отобрать сотню лучших за неделю, разобрать хуки и покадровую структуру.
5. Агент-сценарист пишет новые сценарии строго на базе отобранных, не «из головы».
6. Собрать ролик: визуалы + сборка через сервис с API.
7. Опубликовать через API, обновить статусы в таблице.
8. Снять свежие метрики агентом-аналитиком и вернуть выводы в шаг 3.

**Шаги 1-4 автоматизируются первыми. Шаги 5-7 — только после того, как отбор заработал.**
