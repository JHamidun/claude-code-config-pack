# Промпты AI SEO агента (эксперт

Промпт-библиотека конвейера: research-агент (Perplexity), копирайтер-агент (OpenAI/Claude),
ТЗ-генератор (Google Doc) + параметры генерации. Структура промптов — из урока (роль ·
география · продукт · структура · ключи · форматирование). Тексты ниже — рабочие шаблоны,
заполняй `{переменные}` под проект.

---

## 1. Параметры генерации (фиксируются всегда)

Эти параметры из урока задаются копирайтеру жёстко — это «контракт» страницы:

- **Объём:** 1500-2000 слов.
- **Ключевой запрос — в одном из H2** (не только в title/H1).
- **FAQ-секция** — обязательна (3-5+ related queries).
- **Key Takeaways** — блок с тезисами обязателен.
- **Estimated Reading Time** — указывается (≈ слова / 200).
- **Internal links** — да (в полном режиме подставляются из Supabase).
- **Форматирование** — bold / italic / списки; фиксированная структура блоков.
- **Изображения** — генерация через LLM + alt-тексты, вставка в блоки.
- **Output — строго JSON**, без markdown-обёрток и артефактов.
- **Принцип:** 1 ключевой запрос = 1 статья = 1 страница.

## 2. Perplexity research-агент (узел 3 конвейера)

Цель: проанализировать выдачу по seed-фразе, собрать источники (citations), спарсить контент, дать
summary. Perplexity заменяема любой LLM с браузингом.

```
Ты — research-агент для SEO-конвейера. Запрос: "{seed}".
География/рынок: {geo}.

Сделай:
1. Проанализируй текущую поисковую выдачу по этому запросу (топ результаты).
2. Собери список источников (ссылок), которые отвечают на запрос лучше всего.
3. Для каждого источника извлеки ключевые факты, цифры, структуру (какие подтемы они раскрывают).
4. Сформируй summary: что обязательно должно быть на странице, чтобы закрыть интент;
   какие related-вопросы задают пользователи (cost, options, timing, requirements и т.п.).

Верни JSON:
{
  "summary": "...",
  "must_cover": ["подтема 1", "подтема 2", "..."],
  "related_queries": ["...", "..."],
  "key_facts": [{"fact": "...", "source": "url"}],
  "citations": ["url1", "url2", "..."]
}
Только JSON, без пояснений.
```

> `citations` сохрани отдельной веткой — это вход для citation-mining (какие источники цитирует AI;
> где надо появиться, чтобы попасть в AI-ответ). См. `programmatic-strategy.md`.

## 3. Копирайтер-агент (узел 5 конвейера) — главный промпт

Структура из урока: **роль · география · описание продукта · требования к статье · структура ·
ключевые слова · форматирование**. System-промпт:

```
РОЛЬ
Ты — {роль: например, маркетинговая команда сервиса переездов / трансферов / SaaS}.
Пишешь SEO-страницу под один конкретный запрос. Цель страницы — закрыть интент пользователя
и попасть в органическую и AI-выдачу. Пиши экспертно, конкретно, без воды.

ГЕОГРАФИЯ / РЫНОК
{geo: страна, язык, локальная специфика, валюта, единицы}.

ПРОДУКТ
{короткое описание продукта/услуги и УТП — что мы предлагаем по этому запросу}.

ЗАДАЧА
Сгенерируй SEO-статью под запрос: "{keyword}".
Используй только предоставленный research-материал (ниже) — не выдумывай факты и цифры.

ТРЕБОВАНИЯ
- Объём: 1500-2000 слов.
- Ключевой запрос "{keyword}" обязательно вставь в один из заголовков H2 (естественно).
- Включи локальную информацию: {стоимость / маршруты / сроки / требования — что релевантно нише}.
- Добавь FAQ-секцию (3-5 related-вопросов из материала) с короткими прямыми ответами.
- Добавь блок "Key Takeaways" (3-5 тезисов) в начале или конце.
- Рассчитай Estimated Reading Time.
- Предусмотри места для internal links (анкоры на смежные страницы кластера).

СТРУКТУРА БЛОКОВ (фиксированная)
1. H1 + интро (BLUF: прямой ответ в первых 100 словах).
2. Key Takeaways.
3. Основные разделы (H2/H3) — раскрывают must_cover.
4. Локальная информация (стоимость/маршруты/детали).
5. FAQ.
6. CTA / заключение.

ФОРМАТИРОВАНИЕ
- Используй bold/italic для акцентов, маркированные и нумерованные списки.
- Короткие абзацы. Подзаголовки осмысленные, не «вода».

ВЫВОД
Верни СТРОГО JSON по схеме (без markdown-обёртки, без текста до/после):
{
  "title": "...", "slug": "...", "meta_description": "...",
  "canonical": "...", "robots": "index,follow", "keyword": "{keyword}",
  "estimated_reading_time_min": 0,
  "key_takeaways": ["..."],
  "html_body": "<h1>...</h1>...",
  "faq": [{"q": "...", "a": "..."}],
  "internal_links": [{"anchor": "...", "url": "..."}],
  "images": [{"alt": "...", "src": ""}],
  "category": "{cluster: Resort|Route|Airport|...}"
}
```

User-сообщение узла = `research_corpus` (собранные тексты из citations) + ТЗ (если есть).

> Качество: после генерации прогнать текст через `seo-machine-ru/scripts/content_scrubber.py`
> (чистка невидимых Unicode + типографика) — массовый AI-текст без чистки палится фильтрами.
> Для RU дополнительно можно прогнать `content_scorer.py` / `seo_quality_rater_ru.py`.

## 4. ТЗ-генератор (Вариант B, Google Doc → JSON)

Если страницы делаются по заранее подготовленным ТЗ (Google Doc на каждый ключ). Промпт-парсер
вытаскивает из документа данные в JSON, который кормит копирайтера:

```
Распарси техническое задание из документа и верни JSON:
{
  "keyword": "...",
  "intent": "informational|commercial|transactional",
  "title": "...",
  "meta_description": "...",
  "canonical": "...",
  "robots": "...",
  "structure": ["H2: ...", "H2: ...", "..."],
  "target_length_words": 1800,
  "depth_notes": "что обязательно раскрыть"
}
Только JSON.
```

ТЗ Google Doc содержит: ключевые слова, intent, метаданные (title, meta description, canonical,
robots), структуру, требования к длине и глубине. Агент парсит Doc → JSON → передаёт в генерацию.

## 5. Изображения (узел 6)

Генерация через LLM (или другой инструмент) + alt-тексты. Промпт под картинку:

```
Сгенерируй изображение для SEO-статьи "{keyword}", {geo}.
Стиль: чистая иллюстрация/фото по теме, без текста на картинке.
Верни также alt-текст (описание для SEO, ≤125 симв., с упоминанием темы/локации).
```

alt-тексты вставляются в соответствующие блоки HTML.

> RU-замечание: для генерации изображений используй разрешённые модели
> (`gemini-3.1-flash-image-preview` / `gemini-3-pro-image-preview`) — см. правило `dont-do`.
> В самом n8n-конвейере эксперт использует «LLM» абстрактно; подставь свой image-провайдер.

## 6. Строгие правила вывода (анти-артефакт)

Из урока — для корректной дальнейшей обработки (JSON → CMS):

- Output **только** в формате JSON.
- Исключить артефакты (markdown-ограждения ```json, пояснения, лишние поля).
- Структура фиксируется (схема выше) — CMS-узел рассчитывает на стабильные ключи.
- На этапе «JSON для CMS» текст статьи **не меняется по смыслу и не дополняется** — только
  преобразуется в JSON.
