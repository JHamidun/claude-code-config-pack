# Операторы Wordstat для SEO

> Операторы Wordstat: как заставить сервис показать то, что нужно, а не всё подряд.
> Здесь — **методология операторов и того, как Яндекс трактует запрос**. Реальный программный
> съём частот (internal API getTable, логин, анти-завис) — в `wordstat-real-recipe.md`. Сборка
> ядра из масок — в `keyword-mapping.md`. Различия сбора для рекламы и SEO — в `perf-vs-seo-semantics.md`.

Для SEO Wordstat нужен, чтобы понять **реальный спрос** и форму запроса: какие фразы люди вправду
ищут, в какой формулировке, с какой частотой и сезонностью. Без операторов цифры завышены
(широкое соответствие складывает все вложенные запросы).

---

## 1. Что Яндекс НЕ учитывает в запросе

Система отбрасывает окончания и работает с **корнями слов**. По умолчанию **НЕ учитываются**:

- **Род, число, падеж, лицо.** «Стол», «столы», «столом» — для системы одно и то же слово.
- **Порядок слов** (если не зафиксирован скобками `[ ]`).
- **Предлоги и частицы** (если не закреплены оператором `+`) — «вода на дом» и «вода дом» Wordstat
  смешивает.
- **Стоп-слова** (служебные части речи) — игнорируются, пока не закреплены `+`.

Учитываются только **3 части речи**: существительное, прилагательное, глагол.

> Для SEO это важно вдвойне: семантическое ядро строится по корням, поэтому одна нормализованная
> маска покрывает все словоформы. Но **точную форму** (мн.ч., падеж) для заголовка/URL/H1 проверяй
> оператором `!`, иначе оценка частоты по форме будет неверной.

## 2. Четыре оператора Wordstat

| Оператор | Назначение | Пример | Зачем в SEO |
|----------|-----------|--------|-------------|
| `+` | обязательное вхождение **предлога/частицы** (Яндекс по умолчанию их игнорирует) | `вода +на дом` | отделить запрос с предлогом, если он меняет интент («доставка воды на дом») |
| `!` | **фиксация формы** слова (род, число, падеж) | `!кий` — не «Киев», не «Kia» | проверить частоту именно той словоформы, что пойдёт в H1/title/URL |
| `" "` | показы **только по словам в кавычках**, без дополнительных слов (отсечение хвоста) | `"пластиковые окна"` | узнать «чистую» частоту фразы без вложенных запросов — оценить, тянет ли пиллар сам по себе |
| `[ ]` | **фиксация порядка** слов | `[лечение при осложнениях]` | разделить запросы, где порядок меняет смысл и интент |

Операторы **комбинируются**: `"!купить !окна"` — точная форма обоих слов и без хвоста.

### Как операторы меняют цифру

- **Без операторов** (широкое): `пластиковые окна` → 1 200 000 показов — это сумма всех вложенных
  («пластиковые окна цена», «пластиковые окна купить» и т.д.). Завышено для оценки одной страницы.
- **В кавычках** `"пластиковые окна"` → 60 000 — только сам запрос, без хвоста. Это и есть спрос на
  пиллар-фразу.
- **С `!` и кавычками** `"!пластиковые !окна"` → ещё меньше — конкретная словоформа.

Правило: **для приоритизации страниц снимай частоту в кавычках** (без хвоста), иначе ВЧ-маски
выглядят гигантскими, а реальный спрос на конкретную фразу — на порядок ниже.

## 3. Интерфейс и сезонность

- **`old.wordstat.yandex.ru` (старый интерфейс) — удобнее** для анализа, чем новый.
- Показывает: частоту за **предыдущий месяц**, разбивку по **регионам**, **историю и сезонность
  за 2 года**.
- **Сезонность**: спрос может различаться в **2-3 раза** лето/зима. Для SEO это влияет на план
  публикаций — сезонные кластеры готовить заранее, до пика.
- **Правая колонка** («что ещё искали» / похожие запросы) — источник расширения ядра, особенно
  информационных запросов длинного хвоста (для SEO это ценно, см. `perf-vs-seo-semantics.md`).

## 4. Связка с пайплайном

- Снять **реальные частоты** программно (по списку фраз сразу) → `wordstat-real-recipe.md`
  (`scripts/wordstat_fetch.py` / internal API на куках). Direct API v4 часто заблокирован (error 58).
- Реальные частоты с операторами кладутся в `keywords.json` (поле `volume`) → `opportunity_scorer.py`
  приоритизирует страницы.
- Снять частоту можно и через скилл `yandex` (Wordstat-методы).

> **Не доверяй оценочным тирам** (по ширине suggest) — они завышают в 5-10×. Всегда снимай реальный
> Wordstat **с операторами** перед приоритизацией кластеров.
