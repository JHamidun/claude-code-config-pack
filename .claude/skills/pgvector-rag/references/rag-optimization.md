# RAG-оптимизация: латентность + качество ретрива

> Паттерны из практики продакшн-RAG (LlamaIndex/Milvus/Qdrant-стек). Применять, когда базовый «эмбеддинг → top-k → LLM» уже работает, но (а) медленный, (б) тащит нерелевантное, (в) галлюцинирует на пробелах.

## Латентность (цель — sub-50ms ретрив)
- **Вектор-БД под нагрузку**: Milvus/Qdrant с HNSW (`ef_search` 40→200 — компромисс recall/скорость), а не brute-force pgvector на больших корпусах. pgvector ок до ~1M векторов с `ivfflat`/`hnsw`-индексом; выше — выделенная вектор-БД.
- **Быстрый инференс эмбеддингов**: батчинг запросов; локальная модель (e5-small/bge через ONNX) вместо API-роундтрипа; кэш эмбеддингов частых запросов.
- **Groq/SambaNova-класс инференс** для генерации, если LLM-шаг — узкое место (sub-15ms retrieval бессмысленен при 3с генерации).

## Качество ретрива
- **Corrective RAG (CRAG)**: после ретрива — grader оценивает релевантность top-k; если ниже порога → веб-fallback или расширение запроса. Убирает «ретрив ни о чём → уверенная галлюцинация».
- **Agentic RAG**: LLM решает *когда* искать и *чем* (внутренняя БД vs веб vs несколько под-запросов), а не всегда top-k. Для сложных вопросов — декомпозиция на под-запросы.
- **ColBERT / late interaction**: token-level матчинг вместо single-vector — заметно лучше на точных терминах/кодах; дороже по хранению, окупается на технических корпусах.
- **Reranking**: bi-encoder (быстрый) для top-100 → cross-encoder reranker для top-10. Дешёвый способ поднять precision.
- **Context engineering**: не пихать все top-k, а собирать компактный контекст (dedupe, суммаризация длинных чанков, memory-слой для многоходовых сессий — паттерн Zep/mem0).

## Чанкинг (фундамент качества)
- Structure-aware (по заголовкам/секциям), а не фикс-окно; overlap 10-15%.
- Для структурированных PDF (договоры, отчёты) — layout-parsing (vectorless/reasoning-RAG типа PageIndex) вместо наивного split.

## Диагностика «RAG плохой»
| Симптом | Узел | Фикс |
|---|---|---|
| Медленно | вектор-БД / эмбеддинг | HNSW-индекс, локальные эмбеддинги, батчинг |
| Тащит нерелевантное | ретрив/чанкинг | reranker, structure-aware чанки, CRAG-grader |
| Галлюцинирует на пробелах | нет fallback | CRAG веб-fallback, «не знаю» при low-score |
| Путает точные термины | single-vector | ColBERT / late interaction |
