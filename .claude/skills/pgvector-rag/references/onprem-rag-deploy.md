# On-prem / приватный RAG: развёртывание без облака

> Когда данные НЕ должны покидать периметр (юр/финдоки, ПД, корп-политика). Приватный RAG-API на своём железе. Актуально для DLP-совместимых внедрений и enterprise, где облачный LLM запрещён.

## Стек (полностью локальный)
- **LLM-серверинг**: Ollama (быстрый старт, GGUF-модели) или vLLM (продакшн-throughput, батчинг). Модели под задачу: qwen3-30b-a3b / qwen3-32b (сильные RU/код), gemma3-12b (лёгкая), llama3.x — по VRAM.
- **Эмбеддинги**: локальные (e5/bge через ONNX/vLLM) — никакого API.
- **Вектор-БД**: Qdrant/Milvus/pgvector в контейнере рядом.
- **API-обёртка**: LitServe или FastAPI — приватный inference-эндпоинт, который дёргает retrieval + локальный LLM. Контейнеризация (Docker), `--read-only`, `--no-new-privileges` для untrusted-нагрузки.

## Архитектура (референс)
```
[клиент] → [LitServe/FastAPI: /ask]
              ├─ embed(query)         → локальная эмбеддинг-модель
              ├─ search(top-k)        → Qdrant/pgvector (в периметре)
              ├─ rerank + context     → cross-encoder (локально)
              └─ generate(prompt+ctx) → Ollama/vLLM (локальная LLM)
   всё в одной приватной сети, наружу — 0 запросов
```

## Гибрид «обезличивание + облако» (когда on-prem GPU не окупается)
Для малых команд (≤20 чел) выделенный GPU часто дороже пользы. Альтернатива: **DLP/обезличивание на входе** (вырезать ПД/секреты локальной моделью — см. `privacy-filter`) → безопасный облачный LLM → результат. Данные-идентификаторы не уходят, тяжёлый инференс — в облаке.

## Экономика (грубая прикидка перед КП)
- On-prem имеет смысл при: жёстком требовании «данные в периметре» ИЛИ высоком постоянном объёме (тогда амортизация GPU бьёт per-token облако).
- Для 20 пользователей нерегулярной нагрузки — GPU обычно НЕ окупается → гибрид (обезличивание + облако) дешевле.
- В КП разнести: единоразово (железо/внедрение) + ежемесячно (поддержка/обновление моделей).

## Гочи
- Прод Node/PHP-контейнер = только компилят → индексируй ИСХОДНИК на хосте, не в контейнере.
- Модели тянут VRAM: 30B ≈ 20-40GB (квантизация Q4/Q5 спасает); проверь до обещаний в КП.
- Оценка качества локальной LLM на доменных вопросах — ДО внедрения (не «поставили qwen и ок»): прогон на реальных кейсах клиента.
