# Самодостаточный HTML-дашборд

Один файл, который открывается двойным кликом и работает офлайн: KPI-карточки, фильтры,
графики, сортируемая таблица. Не BI-система, а срез на момент времени, который можно
отправить человеку файлом.

Чарты рисуются приёмами из SKILL.md — здесь только то, чего там нет:
каркас, KPI, фильтры, таблица, выбор типа графика и пороги по объёму данных.

## Ограничение: никаких внешних загрузок

Артефакты на claude.ai закрыты строгим CSP — `<script src="https://cdn...">` не загрузится,
и дашборд молча останется пустым. То же самое при отправке файла человеку без интернета.

Поэтому: **весь JS и CSS инлайном, данные вшиты в HTML как JS-переменная, шрифты системные,
картинки — data: URI**. Если нужен d3 — вставить его тело в `<script>` (~280 КБ) либо
обойтись обычным SVG: столбики, линии и площади рисуются десятком строк без библиотеки.
Проверка на самодостаточность одной командой:

```bash
grep -nE '<(script|link)[^>]+(src|href)="https?://' dashboard.html   # пусто = самодостаточен
```

## Каркас

```
┌──────────────────────────────────────────────────┐
│  Заголовок                          [Фильтры ▼]  │
├────────────┬────────────┬────────────┬───────────┤
│  KPI       │  KPI       │  KPI       │  KPI      │   2–4 карточки, главные числа
├────────────┴────────────┼────────────┴───────────┤
│   Главный график        │   Второй график        │   1–3 графика: тренд + разрезы
├─────────────────────────┴────────────────────────┤
│   Таблица деталей (сортируемая)                  │   опционально, для «провалиться вглубь»
└──────────────────────────────────────────────────┘
```

Единый источник правды — состояние фильтров. Любое изменение фильтра пересчитывает
`filteredData` и перерисовывает **все** секции; секции сами данные не фильтруют.

```html
<script>
const DATA = [ /* вшитые строки или предагрегаты */ ];

const dash = {
  raw: DATA, filtered: DATA, charts: {},
  init()  { this.buildFilters(); this.renderAll(); },
  apply() {                                       // единственная точка фильтрации
    const region = pick('f-region'), from = val('f-from'), to = val('f-to');
    this.filtered = this.raw.filter(r =>
      (!region || r.region === region) &&
      (!from   || r.date >= from) &&               // ISO-строки сравниваются лексикографически
      (!to     || r.date <= to));
    this.renderAll();
  },
  renderAll() { this.renderKPIs(); this.updateCharts(); this.renderTable(); }
};
const val  = id => document.getElementById(id).value;
const pick = id => { const v = val(id); return v === 'all' ? null : v; };
dash.init();
</script>
```

Значения фильтров собираются из самих данных, а не хардкодятся — иначе при подмене датасета
в списке останутся мёртвые опции:

```js
function fillFilter(id, rows, field) {
  const sel = document.getElementById(id);
  [...new Set(rows.map(r => r[field]))].sort().forEach(v => {
    const o = document.createElement('option'); o.value = o.textContent = v; sel.appendChild(o);
  });
}
```

## KPI-карточки

Карточка = метка + число + изменение к прошлому периоду. Без сравнения число не читается:
«выручка 1.2 млн» ничего не говорит, «1.2 млн, +18% к прошлому месяцу» говорит.

```html
<div class="kpi"><div class="kpi-label">Выручка</div>
  <div class="kpi-value" id="k-rev">—</div>
  <div class="kpi-delta" id="k-rev-d"></div></div>
```

```js
function fmt(v, kind = 'number') {
  const a = Math.abs(v), s = kind === 'currency' ? '₽' : '';
  if (kind === 'percent') return v.toFixed(1) + '%';
  if (a >= 1e9) return s + (v / 1e9).toFixed(1) + ' млрд';
  if (a >= 1e6) return s + (v / 1e6).toFixed(1) + ' млн';
  if (a >= 1e3) return s + (v / 1e3).toFixed(1) + ' тыс.';
  return s + v.toLocaleString('ru-RU');
}

function renderKPI(id, value, prev, kind = 'number', higherIsBetter = true) {
  document.getElementById(id).textContent = fmt(value, kind);
  const d = document.getElementById(id + '-d');
  if (!prev) { d.textContent = ''; return; }              // без базы — не выдумываем дельту
  const pct = (value - prev) / Math.abs(prev) * 100;
  d.textContent = (pct >= 0 ? '+' : '') + pct.toFixed(1) + '% к прошлому периоду';
  d.className = 'kpi-delta ' + ((pct >= 0) === higherIsBetter ? 'good' : 'bad');
}
```

`higherIsBetter` обязателен: у оттока и времени ответа рост — это плохо, а зелёная стрелка
вверх на карточке оттока прямо вводит в заблуждение.

```css
.kpi-row { display: grid; grid-template-columns: repeat(auto-fit, minmax(200px, 1fr)); gap: 16px; }
.kpi { background: var(--card); border-radius: 8px; padding: 20px 24px; box-shadow: 0 1px 3px #0001; }
.kpi-label { font-size: 13px; color: var(--muted); text-transform: uppercase; letter-spacing: .5px; }
.kpi-value { font-size: 28px; font-weight: 700; margin: 4px 0; }
.kpi-delta.good { color: #28a745; } .kpi-delta.bad { color: #dc3545; }
@media (max-width: 768px) { .kpi-row { grid-template-columns: repeat(2, 1fr); } }
@media print { .filters { display: none; } .chart { break-inside: avoid; } }
```

Печатный `@media print` стоит дёшево: дашборды регулярно уезжают в PDF для встречи.

## Сортируемая таблица

```js
function renderTable(el, rows, cols, state = { by: null, dir: 'desc' }) {
  const sorted = state.by
    ? [...rows].sort((a, b) => {
        const x = a[state.by], y = b[state.by];
        const c = typeof x === 'number' ? x - y : String(x).localeCompare(String(y), 'ru');
        return state.dir === 'asc' ? c : -c;
      })
    : rows;
  el.innerHTML = `<table class="dt"><thead><tr>${cols.map(c =>
      `<th data-f="${c.field}">${c.label}${state.by === c.field ? (state.dir === 'asc' ? ' ▲' : ' ▼') : ''}</th>`
    ).join('')}</tr></thead><tbody>${sorted.slice(0, 200).map(r =>
      `<tr>${cols.map(c => `<td>${c.format ? fmt(r[c.field], c.format) : r[c.field]}</td>`).join('')}</tr>`
    ).join('')}</tbody></table>`;
  el.querySelectorAll('th').forEach(th => th.onclick = () => {
    const f = th.dataset.f;
    renderTable(el, rows, cols, { by: f, dir: state.by === f && state.dir === 'desc' ? 'asc' : 'desc' });
  });
}
```

`localeCompare(..., 'ru')` — иначе кириллица сортируется по кодам и «Ё» улетает в конец.
`.slice(0, 200)` не косметика: выше начинает тормозить перерисовка на каждом фильтре;
больше — постранично, с подписью «показано 1–200 из 2 340».

## Сколько данных вшивать

| Объём | Что делать |
|---|---|
| < 1 000 строк | Вшить как есть, считать в браузере |
| 1 000 – 10 000 | Вшить, но графики строить по предагрегатам |
| 10 000 – 100 000 | Вшивать **только** агрегаты, сырьё оставить в источнике |
| > 100 000 | Не клиентский дашборд: BI-инструмент или постраничная выдача |

```js
// ❌ 50 000 сырых строк в файле — многомегабайтный HTML, который тормозит на каждом фильтре
const RAW = [/* 50 000 */];

// ✅ то, что реально нужно графикам
const AGG = {
  monthly: [{ month: '2026-01', revenue: 150000, orders: 1200 }, /* 12 строк */],
  top:     [{ name: 'Продукт А', revenue: 45000 }, /* 10 строк */],
  kpi:     { revenue: 1980000, orders: 15600, aov: 127 }
};
```

Предагрегация меняет и логику фильтров: разрез, по которому пользователь фильтрует,
обязан остаться измерением в агрегате, иначе фильтр окажется нерабочим.

Пределы отрисовки: линия — до ~500 точек на серию (дальше прореживать, глаз всё равно
не различает), столбики — до ~50 категорий, точечная диаграмма — до ~1000 точек.
При множестве графиков отключай анимацию и перерисовывай без переходов.

## Какой график ставить

| Что показываем | График | Чем заменить |
|---|---|---|
| Динамика во времени | Линия | Площадь (если важен накопленный объём) |
| Сравнение категорий | Столбики | Горизонтальные при длинных подписях / многих категориях |
| Рейтинг | Горизонтальные столбики | Точечный график, slope-график для двух периодов |
| Состав целого | Столбики с накоплением | Treemap для иерархии |
| Состав во времени | Площади с накоплением | 100%-накопление, если важны доли |
| Распределение | Гистограмма | Box plot для сравнения групп |
| Связь двух величин | Точечная | Пузырьковая (третья величина — размер) |
| Матрица связей | Тепловая карта | Парные графики |
| Последовательные этапы | Воронка | Sankey для ветвлений |
| Много метрик сразу | Малые кратные | Отдельные графики в сетке |

Чего не делать: **круговая диаграмма** — только если категорий меньше 6 и точность не важна
(углы человек сравнивает плохо); **3D** — никогда, искажает и не добавляет информации;
**две оси Y** — осторожно, подразумевает связь, которой может не быть, обе оси подписывать;
**накопление с множеством категорий** — средние сегменты не сравнить, брать малые кратные.

## Точность подачи

- Столбики начинаются с нуля. Всегда. Полоска от 95 до 100 превращает 5% в «двукратный рост».
- У линии база может быть не нулевой — если диапазон колебаний осмысленный.
- В сравниваемых панелях одинаковая шкала, иначе сравнение визуально ложное.
- Заголовок формулирует вывод: «Выручка выросла на 23% год к году», а не «Выручка по месяцам».
- Подзаголовок — период, фильтры, источник. Без него график нельзя перепроверить.
- Цвет кодирует данные, а не украшает: главную серию — акцентным, остальное — серым.
- Категории сортируются по значению, не по алфавиту (кроме естественного порядка: месяцы, этапы).
- Не полагаться на цвет в одиночку: разный тип линии, прямые подписи, паттерны заливки.
  Красный/зелёный как единственный различитель не работает для ~8% мужчин.
- Показывать неопределённость там, где она есть: интервал, диапазон, усы.
