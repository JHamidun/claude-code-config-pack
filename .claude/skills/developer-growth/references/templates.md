# Шаблоны — developer-growth

Полные копируемые шаблоны для workflow A/C/D и менторских сессий. Русский — для текста, английский — для кода/терминов. Все имена/компании — плейсхолдеры.

## 1. Матрица навыков (Workflow A)

Шкала оценки:

```
1 = Beginner   (изучаю, нужен постоянный надзор)
2 = Junior     (делаю с подсказками/ревью)
3 = Mid        (самостоятельная работа)
4 = Senior     (могу учить других, задаю стандарт)
5 = Expert     (признанная экспертиза за пределами команды)
```

Скелет (блоки и строки подгоняй под реальный стек пользователя — не выдавай список как есть):

```markdown
## Матрица навыков: [Имя] · [дата]

### Languages
| Skill | Current | Target | Gap |

| TypeScript | [X] | [Y] | [Y-X] |
```

```markdown
| Metric | Value | Target |
```

## 3. Полный PDP (Workflow C)

```markdown
# План развития: [Имя]
**Период:** [квартал] · **Роль:** [текущая] → **Цель:** [целевая] · **Бюджет времени:** [X ч/нед]

## Топ-3 gap (из матрицы навыков)
| # | Навык | Сейчас | Цель | Почему важно для целевой роли |
|---|-------|--------|------|-------------------------------|
| 1 | [...] | [X] | [Y] | [...] |

## Цели (SMART, ≤3)
### Цель 1: [навык X→Y]
- Текущее состояние: [конкретно, чем подтверждается]
- Целевое состояние: [конкретно]
- Действия:
  ① практика в рабочих задачах: [что именно взять]
  ② учебный ресурс: [конкретная публичная книга/курс, главы]
  ③ learning in public: [доклад / статья / OSS-вклад]
- Критерий успеха: [измеримый: «2 принятых design doc», не «стал лучше»]

### Цель 2 / Цель 3: [аналогично]

## План по неделям
| Недели | Фокус | Milestone |
|--------|-------|-----------|
| 1-4 | [...] | [ ] [...] |
| 5-8 | [...] | [ ] [...] |
| 9-12 | [...] | [ ] [...] |

## Чекпоинты
- Еженедельно: саморефлексия (что узнал / где застрял)
- Раз в 2 недели: 1:1 с ментором (если есть)
- Ежемесячно: обзор прогресса, корректировка
- Конец периода: повторная матрица навыков (v2), сравнение

## Ресурсы
- Ментор/бадди: [имя или «нет — найти»]
- Бюджет на обучение: [если есть]
```

## 4. Карьерная лестница IC (Workflow D, дефолтная)

Используй, если у компании пользователя нет своей. Каждый чекбокс требует подтверждающего примера работы.

```markdown
## Individual Contributor Levels

### Junior Engineer (L1) — scope: задача
- [ ] Пишет чистый работающий код
- [ ] Следует стандартам команды
- [ ] Доводит поставленные задачи до конца
- [ ] Вовремя просит помощи, когда застрял

### Mid Engineer (L2) — scope: фича
- [ ] Проектирует и реализует фичи самостоятельно
- [ ] Пишет тесты как норму, не по требованию
- [ ] Делает содержательные код-ревью
- [ ] Помогает джунам (онбординг, парная работа)

### Senior Engineer (L3) — scope: проект
- [ ] Ведёт технические проекты end-to-end
- [ ] Принимает архитектурные решения и отвечает за них
- [ ] Влияет на практики команды (стандарты, процессы)
- [ ] Дебажит сложные/распределённые проблемы

### Staff Engineer (L4) — scope: организация
- [ ] Задаёт техническое направление нескольким командам
- [ ] Решает кросс-командные проблемы
- [ ] Драйвит крупные инициативы (миграции, платформы)
- [ ] Менторит сеньоров

### Principal Engineer (L5) — scope: компания
- [ ] Экспертиза, признанная за пределами компании
- [ ] Формирует техстратегию компании
- [ ] Внешнее thought leadership (доклады, статьи, стандарты)
```

Таблица готовности к грейду:

```markdown
## Готовность к [L_]: [Имя] · [дата]
| Критерий | Статус | Пример-подтверждение |
|----------|--------|----------------------|
| [...] | ✅ / 🟡 / ❌ | [ссылка на PR / design doc / проект — обязательна для ✅] |

**Закрыто:** [X]/[N] ([%]) · **Приоритеты для роста:** [список ❌ и 🟡]
```

```markdown
# 1:1: [ментор] × [подопечный] · [дата]

## С прошлой встречи

- Узнал: [...]
- Застрял на: [...]

## Темы для обсуждения
1. [...]

## Фидбек
- Что идёт хорошо:
- Зоны роста:
- Какая нужна поддержка:

## Action items
- [ ] [действие] — срок [дата] — [чей]
```

## Принципы (для любого артефакта)

1. Мерить одно и то же, регулярно — иначе тренд не виден.
2. Качество > количество: LOC не продуктивность.
3. SMART-цели: измеримый критерий обязателен.
4. Learning in public ускоряет рост: блог, доклад, OSS.
5. Фидбек запрашивать конкретный («что убрать из моих ревью?»), не общий.
