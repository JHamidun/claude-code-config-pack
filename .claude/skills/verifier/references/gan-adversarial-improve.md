# GAN-паттерн: мутатор-vs-судья + двусторонний pairwise против position bias

> Источник: `crimeacs/auto-improve` (GAN-style self-improvement loop; вдохновлён karpathy/autoresearch + RLAIF).
> Дистилляция паттерна, НЕ установка тула. Сам тул завязан на `GEMINI_API_KEY` (Gemini API) —
> нам он не нужен: паттерн переносится 1:1 на связку Opus-оркестратор + Fable-воркеры (0 внешних токенов).
> Применять в: **verifier** (проверка чужой работы, кросс-чек) и в **adversarial-review Workflow**
> (наш паттерн-замена мёртвого Codex — finder-агенты vs скептик-верификатор, см. память
> `phoenix-softdelete-dedup-adversarial-2026-07-19`).

## Ядро: разведи генерацию и оценку, не верь самооценке

Главная идея — **генератор никогда не оценивает свою же работу**, а «лучше» доказывается
не самоотчётной цифрой, а слепым попарным сравнением. Три роли, три РАЗНЫХ контекста:

1. **MUTATE** (генератор) — best-of-N мелких хирургических правок, каждая целит в СВО�ё слабое
   измерение. Высокая температура (~0.9) ради разнообразия. Диффы find/replace, НЕ переписывание целиком.
2. **SCORE** (оценщик) — отдельный вызов, строгий, детерминированный (temp=0), усреднён по N прогонов
   для стабильности. Якоря: `50 = средне, 70 = хорошо, 90 = исключительно, НЕ инфлировать`.
3. **DECIDE** (судья) — pairwise: лучший кандидат против чемпиона. **Правило keep — НЕ `score>current`**,
   а победа в двустороннем голосовании (ниже). Проиграл → откат в git.

`git`-ветка = лог улучшений; каждый коммит = проверенный выигрыш, а не «уверенная, но худшая» правка.

## Приём №1 (главный для нас): двусторонний pairwise против position bias

LLM-судья систематически предпочитает первый вариант. Лечение — **прогнать оба порядка**
`[Candidate, Champion]` и `[Champion, Candidate]`, и держать кандидата ТОЛЬКО если он набирает
больше голосов. Один прогон → тай-брейк по позиции, а не по качеству.

```
голос_кандидата = (порядок1: победил B) + (порядок2: победил A)
голос_чемпиона  = (порядок1: победил A) + (порядок2: победил B)
keep := голос_кандидата > голос_чемпиона     # строго больше; ничья → чемпион держится
margin := "clear" если 2:0, иначе "slight"
```

Промпт судьи (temp=0), дословно суть из тула — переносим в наши ревью:

```
You are a strict judge. Read TWO versions of the same artifact (version A then version B)
and a RUBRIC. Decide which is genuinely BETTER against the rubric. Judge quality only;
do not favor a version because it appears first. If equivalent, answer tie.
Return ONLY JSON: {"winner":"A"|"B"|"tie","margin":"clear"|"slight","why":"<=15 words"}
```

Обобщение для **любого** LLM-as-judge у нас (выбор из 2 вариантов копирайта/дизайна/КП/ответа,
A/B рецензий, «какой фикс лучше»): всегда спрашивай ОБА порядка, keep только при 2:0 или чистом
перевесе. Одиночный вызов судьи = скрытый position bias.

## Приём №2: скептик-оценщик по умолчанию отвергает (совпадает с нашим adversarial-review)

- SCORE строгий: «50 — средне», явный запрет инфляции; усреднение N прогонов, флаг `spread>10 → noisy`.
- Наш adversarial-review уже так и работает: finder находит → верификатор с default REFUTED проверяет
  КАЖДУЮ находку. GAN добавляет к этому: (а) генератор ≠ судья по контексту, (б) двусторонний pairwise
  на финальном «оставить/откатить», (в) решение по голосам, а не по самоотчётной цифре.

## Приём №3: crash-proof apply ladder (правка не портит файл)

Правку применяем по лестнице, кривой find НИКОГДА не рушит файл — кандидат просто дропается:

1. **exact** — точное вхождение `find` в тексте.
2. **canon** — NFKC + кудрявые кавычки→прямые, тире(–—−)→дефис, юникод-пробелы→ascii, `…`→`...`,
   схлопнуть пробелы; матч канонизированного, но сплайс по СЫРЫМ офсетам (байт-точно).
3. **fuzzy** — скользящее окно по словам, `SequenceMatcher.ratio() >= 0.8` (ранний выход при 0.97).
4. Не нашли → `(None, reason)`, кандидат отброшен. Плюс защита: не вклеивать разделитель-маркер,
   которого не было в исходнике (иначе разметка кандидатов порушит артефакт).

Мораль для наших пайплайнов правок (skill-патчи, КП patch+build, book-polish): любой авто-diff
применяй через ladder с деградацией, а не одним `str.replace` — иначе одна кривая правка бьёт файл.

## Рубрика (если оцениваем текст рубрикой)

Markdown, 5-7 измерений, сумма весов ровно 100, якоря 50/70/90, reward-framed («дай N баллов, когда X»),
специфична под ЭТОТ артефакт, не boilerplate. Нет рубрики → генератор пишет её из артефакта (+ `--goal`).

## Когда тянуть (у нас, без внешних тулов)

- **verifier / кросс-чек**: выбор лучшего из 2+ результатов воркеров → двусторонний pairwise-судья.
- **adversarial-review**: finder-агенты (mutate/find) отдельно от скептик-верификатора (score/decide);
  финальное keep — через pairwise, не через самооценку автора.
- **Итеративный полиш артефакта** (email/лендинг/промпт/README/КП): best-of-N мелких диффов →
  строгий оценщик → pairwise-гейт → коммит только победителя. Движок — Fable-воркеры, оркестратор Opus.

## Опционально: запустить сам тул (Gemini-keyed, НЕ обязательно)

```bash
export GEMINI_API_KEY=...   # или GOOGLE_API_KEY (у нас есть)
python3 improve.py --artifact path/to/file.md --tag v1 --max-iterations 8 [--criteria rubric.md]
# результат на ветке improve/<tag>; git diff main improve/v1 -- <file>
```
Клон: `${WORKSPACE}/temp-clones/auto-improve/`. Из вашего региона Gemini API доступен (тот же GOOGLE_API_KEY,
что и для image-моделей). Но для нас ценность — паттерн, а не тул: гоняем на Claude-подписке за 0 токенов API.
