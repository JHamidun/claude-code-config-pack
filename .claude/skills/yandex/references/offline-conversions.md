# Офлайн-конверсии в Метрику — передача квалифицированных лидов из CRM

> **Граница навыков:** ЗАЧЕМ и КОГДА передавать офлайн-конверсии — методология в `yandex-direct-pro-ru`.
> ЗДЕСЬ — техническая реализация API-вызова из навыка `yandex`. Источник Client ID и факта
> квалификации — твоя CRM (Битрикс24 / amoCRM / HubSpot — у всех есть REST API).
> Server-side передача без правок кода — см. `capi-no-code-setup`.

## Зачем

По умолчанию Директ оптимизируется на «все лиды» (заявки), включая спам и нецелевые обращения.
Офлайн-конверсии позволяют оптимизировать на **квалифицированные лиды** и **продажи** — то есть на
реально ценные для бизнеса действия, которые происходят уже в CRM, а не на сайте.

- Видно, какие площадки/запросы дают спам, а какие — качественный трафик.
- Автостратегии обучаются на более ценных конверсиях → выше отдача бюджета.
- Особенно критично в B2B и нишах с длинным циклом сделки, где «заявка ≠ деньги».
- Это **приоритет №1** для роста эффективности кампании (частая рекомендация практиков Директа).

> «Лиды — это уже не оптимальный показатель. В идеале нужно видеть хотя бы квалифицированные лиды
> или продажи.» — мнение практиков Директа

## Как работает

Технология работает на основе **Client ID** — уникального идентификатора пользователя в Метрике
(на базе cookies: браузер + устройство + ОС). Логика передачи:

1. На сайте получаем Client ID пользователя и сохраняем его в CRM вместе с заявкой.
2. Когда лид квалифицирован (или совершена продажа) — отправляем событие обратно в Метрику
   по этому Client ID на специальный endpoint.
3. В Метрике появляется цель «квалифицированный лид» / «продажа» с привязкой к источнику
   (кампания, площадка, запрос).
4. В Директе указываем эту цель в автостратегии вместо «оставили заявку».

**Готовые коннекторы:** AmoCRM, Битрикс24 (через интеграторов). Настройка ~1 неделя + участие
программиста.

## 6-шаговая инструкция

### Шаг 1. Получить Client ID на сайте

Добавить на сайт код, который читает Client ID из счётчика Метрики:

```javascript
// COUNTER_ID — номер вашего счётчика Метрики
var clientID = ym(COUNTER_ID, 'getClientID');
// Сохранить clientID в скрытое поле формы → передать в CRM вместе с заявкой
```

### Шаг 2. Хранить Client ID в CRM (AmoCRM / Битрикс24)

- Создать кастомное поле, например `Metrika Client ID`.
- При создании лида записывать в него Client ID из скрытого поля формы.

### Шаг 3. Создать цели в Метрике

- Цель «Квалифицированный лид» (тип: JavaScript-событие или составная цель — см.
  `references/metrika-goals-setup.md`).
- При необходимости — отдельная цель «Продажа».

### Шаг 4. При квалификации/продаже отправить событие обратно в Метрику

Когда менеджер квалифицировал лид или закрыл сделку в CRM — отправляем HTTP-запрос на endpoint
загрузки офлайн-конверсий:

```
POST https://api-metrika.yandex.net/management/v1/counter/{COUNTER_ID}/offline_conversions/upload
```

Передаём: ID цели («квалифицированный лид» / «продажа»), Client ID, дату/время конверсии.

### Шаг 5. Указать цель в автостратегии Директа

В стратегии «Максимум конверсий» выбрать цель «Квалифицированный лид» вместо «Оставили заявку».
Алгоритм начнёт оптимизировать на качество, а не на объём.

### Шаг 6. Использовать в отчётах

В Мастере отчётов Директа и в Метрике выбирать данные по цели «Квалифицированный лид» —
для оценки реальной эффективности площадок и запросов.

## Пример API-запроса (технический)

Endpoint принимает CSV-загрузку. Привязка по `client_id`. Формат `text/csv`:

```python
import requests, os
from dotenv import load_dotenv

load_dotenv(os.path.expanduser("~/.claude/.credentials.master.env"))  # заведи из templates/.credentials.master.env.example

TOKEN      = os.getenv("YANDEX_OAUTH_TOKEN")
COUNTER_ID = os.getenv("YANDEX_METRIKA_COUNTER_ID")

url = f"https://api-metrika.yandex.net/management/v1/counter/{COUNTER_ID}/offline_conversions/upload"

# CSV: ClientId,Target,DateTime,Price,Currency  (DateTime — Unix timestamp в секундах)
csv_body = (
    "ClientId,Target,DateTime\n"
    "123456789,qualified_lead,1737888000\n"   # квалифицированный лид
    "987654321,sale,1737974400\n"             # продажа
)

resp = requests.post(
    url,
    headers={"Authorization": f"OAuth {TOKEN}"},
    params={"client_id_type": "CLIENT_ID"},   # привязка по Метрика Client ID
    files={"file": ("conversions.csv", csv_body, "text/csv")},
)
print(resp.status_code, resp.json())
```

**Поля CSV:**
- `ClientId` — Метрика Client ID (из CRM). Альтернативно — `UserId`/`Yclid` при другом `client_id_type`.
- `Target` — идентификатор цели (`identifier` цели в Метрике).
- `DateTime` — Unix-таймстамп конверсии (секунды).
- `Price`, `Currency` — опционально, для передачи ценности (например, суммы продажи).

**Заметки:**
- Загрузка асинхронная — статус проверяется отдельным GET по `/offline_conversions/uploadings`.
- Для server-side передачи событий без правок фронтенда (через CRM-вебхуки / прокси) см.
  `capi-no-code-setup`.
- Сам факт квалификации и сумма продажи берутся из твоей CRM: нужна выгрузка сделок плюс
  кастомное поле, в котором лежит Client ID. У Битрикс24, amoCRM и HubSpot это делается
  входящим вебхуком / REST-методом списка сделок.
