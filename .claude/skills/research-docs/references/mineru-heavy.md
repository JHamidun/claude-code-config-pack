# MinerU — тяжёлый локальный парсер сложных документов (heavy-job, под ресурс-гард)

> Третий движок парсинга research-docs, **дополняет** LiteParse (дефолт) и PageIndex (длинные структурированные PDF).
> Источник: https://github.com/opendatalab/MinerU · лицензия: MinerU Open Source License (на базе Apache 2.0, коммерческое использование разрешено).
> Статус на 2026-07-19: **НЕ установлен**. Установка/скачивание весов — heavy-job, реестр `ваше локальное хранилище памяти` #8.

## Что это и зачем (вердикт: ДОПОЛНЕНИЕ, не дубль)

MinerU — VLM+OCR парсер документов в Markdown/JSON для RAG/LLM. Двойной движок:
- **pipeline** (CPU-совместим, точность ~86.5) — быстрый, без GPU;
- **vlm / hybrid** (GPU, точность ~95.3) — распознаёт **сканы, рукописный текст, многоколоночную вёрстку, формулы→LaTeX, таблицы→HTML**, 109-язычный OCR, авто-удаление колонтитулов, восстановление порядка чтения.

**Ниша, которую НЕ закрывают наши движки:**

| Движок | Формат | GPU | Стоимость | Сильная сторона | Слабое место |
|--------|--------|-----|-----------|-----------------|--------------|
| **LiteParse** (дефолт) | PDF/DOCX/PPTX/XLSX/img | нет | бесплатно | bounding-box → visual citations, быстро | плохо на сканах/рукописях/формулах/сложных таблицах |
| **PageIndex** | длинные PDF/MD | нет | OpenAI $ (~$0.01/стр build) | reasoning-навигация по дереву 50+ стр. | платно, нет OCR, текстовый слой обязателен |
| **MinerU** (этот файл) | PDF/DOCX/PPTX/XLSX/img/сканы | да (vlm) | **бесплатно локально** | сканы, рукопись, формулы, таблицы, 109 языков, мультиколонка | тяжёлый: 20GB диск, 8GB VRAM, скачивание весов |

**Когда звать MinerU (а не LiteParse):**
- Скан/фото документа без текстового слоя (PDF из сканера, снимок договора).
- Рукописный или смешанный текст, восточные языки, арабский (109-язычный OCR).
- Плотные научные/финансовые таблицы и формулы, где LiteParse отдаёт кашу.
- Многоколоночная вёрстка (газеты, journal-верстка), где ломается порядок чтения.

Для обычных цифровых PDF/DOCX/XLSX с текстовым слоем — **остаётся LiteParse** (быстрее, даёт visual citations). MinerU не заменяет основной flow скилла, а подключается точечно на «трудных» файлах.

## Ресурсы (почему heavy)

- **VRAM:** 4GB (pipeline) → 8GB (vlm/hybrid). Видеокарта с 16 ГБ VRAM тянет vlm с запасом.
- **RAM:** 16GB минимум, 32GB и выше — комфортно.
- **Диск:** ≥20GB (веса моделей + кэш), SSD.
- **Python:** 3.10–3.13. **Ставить ТОЛЬКО в отдельный venv** (не в базовый), чтобы не тащить torch/vllm в общее окружение.

## Установка (heavy — НЕ запускать вслепую, только под ресурс-гардом)

> Прогон установки и первого скачивания весов = heavy-job. Перед стартом: idle-check (владелец не за компом), GPU-check (`nvidia-smi` — чужой VRAM ниже порога), TG-нотификация старт/финиш. Кирпичи гарда — `ваше локальное хранилище памяти`.

```bash
# 1. Отдельный venv (uv быстрее)
VENV=${HOME}/.claude/mcps/mineru/.venv
python -m venv "$VENV"

# Интерпретатор внутри venv называется по-разному: Windows кладёт его в
# Scripts/python.exe, macOS и Linux — в bin/python. Жёстко записанный
# Scripts/python.exe давал на *nix «No such file or directory» сразу после
# успешно созданного venv. Берём тот, который есть:
PY="$VENV/bin/python"; [ -x "$PY" ] || PY="$VENV/Scripts/python.exe"

"$PY" -m pip install --upgrade pip uv
"$PY" -m uv pip install -U "mineru[all]"

# 2. Источник весов. Из вашего региона HuggingFace доступен напрямую → предпочтителен.
#    ModelScope (CN) может тормозить/резаться — брать только если HF недоступен.
export MINERU_MODEL_SOURCE=huggingface   # варианты: huggingface | modelscope | local

# 3. Первый прогон сам скачает веса (несколько ГБ) в кэш. Это и есть тяжёлая часть —
#    запускать под ресурс-гардом (idle+GPU-check), не в фоне молча.
```

Offline/локальные веса и точная конфигурация: https://opendatalab.github.io/MinerU/usage/model_source/

## Запуск (CLI)

```bash
VENV=${HOME}/.claude/mcps/mineru/.venv
# Windows: Scripts/…(.exe) · macOS и Linux: bin/… — берём существующее
PY="$VENV/bin/python";  [ -x "$PY" ]     || PY="$VENV/Scripts/python.exe"
MINERU="$VENV/bin/mineru"; [ -x "$MINERU" ] || MINERU="$VENV/Scripts/mineru.exe"

# CPU-режим (без GPU, для цифровых PDF со слоем текста или когда GPU занят):
"$MINERU" -p input.pdf -o out_dir/ -b pipeline

# VLM (GPU) — сканы/рукопись/формулы, максимальная точность:
"$MINERU" -p scan.pdf -o out_dir/ -b vlm-transformers
# hybrid — компромисс точность/скорость:
"$MINERU" -p doc.pdf -o out_dir/ -b hybrid
```

Бэкенды VLM: `vlm-transformers` (прямой inference), `vlm-vllm-engine` (быстрее через vLLM, больше VRAM), `vlm-http-client` (клиент к поднятому серверу). Серверный режим (эндпоинты `POST /file_parse`, `POST /tasks`) и точные флаги клиента — сверять по докам, интерфейс версионируется: https://opendatalab.github.io/MinerU/usage/

Вывод: папка с `*.md` (Markdown), `*_content_list.json` (структура + координаты), картинками вырезанных таблиц/формул.

## Встраивание в flow research-docs

MinerU — **пре-процессор перед Step 2** скилла, когда файл «трудный»:

1. Прогнать трудные файлы через MinerU → получить `.md` в `out_dir/`.
2. Положить полученные `.md` рядом с остальными документами (папка `$0`).
3. Дальше обычный flow скилла: LiteParse/read подхватят `.md` как plaintext (`page: 0`), и Step 3 отвечает с цитатами по этому тексту.

Ограничение: visual citations с bounding-box работают у LiteParse по исходным PDF-страницам. MinerU-Markdown цитируется как plaintext (`page: 0`) — точный highlight на изображении страницы для него недоступен. Если нужны именно visual citations — сначала пробуй LiteParse; MinerU бери, когда LiteParse не вытянул содержимое вообще (скан/рукопись).

## Альтернатива без установки (fallback)

Онлайн MinerU: https://mineru.net + Web UI/Gradio + REST API — если разовая задача и не хочется ставить тяжёлый локальный стек. Но это уже не «локально на 4090» и требует загрузки документа наружу — для конфиденциальных финдоков/KYC (portfolio-review) НЕ использовать, только локальный режим.
