# Граф работ + ODI + Сегментация по работам

> Структурный аппарат по методологии AJTBD: как разложить работы в граф, как найти underserved jobs через ODI Тони Алвика, как сегментировать рынок по работам, а не по демографии.

## Граф работ (low / mid / big / core)

Работы **не существуют по отдельности** — они связаны в граф. Снизу вверх:

| Уровень | Название | Суть | Мотивация / готовность платить |
|---|---|---|---|
| **low** | micro jobs | вынужденные шаги, «надо сделать, чтобы…» | низкая (это не цель, а издержки) |
| **mid** | промежуточные работы | связующие задачи | средняя |
| **big** | Big Jobs | крупная задача, ради которой всё затевалось | высокая |
| **core** | Core Jobs | настоящая глубинная мотивация (результат/статус/риск) | максимальная |

### Пример графа (контент-мейкер)

```text
core:  зарабатывать деньги / расти как автор
  ▲
big:   получить охваты
  ▲
mid:   выложить ролик
  ▲
mid:   снять ролик
  ▲
low:   написать сценарий          ← micro job, вынужденный шаг
```

> 👉 Чем выше уровень работы — тем выше мотивация, ценность и готовность платить. **Люди не покупают micro jobs.** Они покупают результат, продвижение по жизни, снижение рисков, сохранение статуса.

### Стратегический закон: продукты поднимаются вверх по графу

> **«Все продукты со временем поднимаются вверх по графу работ.»**

Почему: мозг стремится к энергоэффективности — люди хотят **меньше шагов → больше результата**. Продукт, который убирает вынужденные micro jobs, выигрывает.

| Продукт | Какие micro jobs убрал | Обслуживаемая Big/Core Job |
|---|---|---|
| **Такси** | покупка авто, парковка, заправка, ТО | доехать без владения машиной |
| **Zoom** | поездка, билеты, гостиница, дорога | провести встречу |
| **ChatGPT** | писать самому, искать формулировки, редактировать | получить готовый результат |

### Как использовать граф на практике

1. Выпиши все **глаголы** из речи клиента — кандидаты в работы.
2. Разложи их по уровням low → core. Найди **Big/Core Job** — это настоящая мотивация (туда бьёт messaging).
3. Найди **вынужденные micro jobs** клиента — их твой продукт может убрать (туда бьёт продукт).
4. Реши, **куда двигать продукт вверх по графу** — это карта роста и расширения оффера.

> Продукты ниже — учебные, придуманы под демонстрацию разбора по уровням. Свой продукт
> раскладывай сам, из интервью, а не по аналогии с этими строчками.

- **ExampleProduct (условный B2C, обучение работе с ИИ-ассистентом):** low «посмотреть урок» → mid «освоить приём в Claude Code» → big «реально внедрить ИИ в свою работу» → core «вырасти в карьере / зарабатывать больше как ИИ-практик, не отстать». Двигать вверх: от «обучения» к «результату на работе» (проекты, портфолио, трудоустройство).
- **YourProduct (условный B2B, корпоративный доступ к ИИ):** low «дать доступ к инструментам» → mid «команда начала пользоваться» → big «повысилась эффективность процессов» → core «снизились риски / выросла прибыль бизнеса». Двигать вверх: от «доступ к инструментам» к «измеримый бизнес-результат + безопасность данных».
- **AI-воркшоп (условный формат корпобучения):** low «провести 2 часа обучения» → big «команда решает реальные задачи ИИ» → core «руководитель выглядит прогрессивным и получил отдачу от бюджета».

## ODI — Outcome-Driven Innovation (Тони Алвик / Anthony Ulwick)

Количественный метод поверх качественной глубины интервью. Превращает работы в **приоритизированный список** зон для продукта.

### Шаги ODI

1. **Собрать desired outcomes** — желаемые результаты выполнения работы, в формате «[направление: минимизировать/увеличить] + [метрика] + [объект] + [контекст]». Пример: «минимизировать время, нужное, чтобы получить рабочий промпт под задачу».
2. **Оценить каждый по двум шкалам** (опрос, 1–10 или 1–5):
   - **Важность** — насколько важен этот результат.
   - **Удовлетворённость** — насколько текущие решения его обеспечивают.
3. **Найти разрыв** — высокая важность + низкая удовлетворённость = **underserved job** (зона возможностей).

### Матрица важность × удовлетворённость

```text
                    Удовлетворённость
                 низкая            высокая
важность  ┌──────────────────┬──────────────────┐
высокая   │   UNDERSERVED     │  well-served     │
          │  (бей сюда —      │  (защищай —      │
          │   приоритет!)     │   твоё преимущ.) │
          ├──────────────────┼──────────────────┤
низкая    │  игнорируй        │  OVERSERVED      │
          │  (не тратить силы)│  (упрости/режь   │
          │                   │   цену/убери)    │
          └──────────────────┴──────────────────┘
```

- **Underserved** (важно, но плохо удовлетворено) → главные кандидаты для новых фич, messaging, нового оффера.
- **Overserved** (неважно, но переудовлетворено) → перегруз; упрости, удешеви или убери — здесь конкурент может зайти снизу (disruption).
- **Well-served** → твоё конкурентное преимущество, защищай.

### Пример ODI-таблицы (ExampleProduct, эскиз)

| Desired outcome | Важность | Удовлетв. | Зона |
|---|---|---|---|
| Минимизировать время до первого полезного результата с ИИ | 9 | 4 | **underserved** |
| Не выглядеть отстающим перед коллегами/руководством | 8 | 3 | **underserved** |
| Снизить страх «я не разберусь в этом» | 8 | 4 | **underserved** |
| Получить максимально широкий теоретический обзор всех ИИ | 4 | 8 | overserved |

> Underserved-строки → прямо в Job Stories и в заголовки лендинга/писем. Overserved («полный теоретический обзор») — сигнал, что рынок перекормлен теорией; дифференцируйся практикой.

## Сегментация по работам, а не по демографии

### Почему демография не работает

> **«Демография — это изучение людей, которые ничего общего не имеют, кроме года рождения. Jobs — это изучение людей, которые делают одно и то же, несмотря на разный возраст.»**

Классическая (ошибочная) сегментация: пол / возраст / должность / география. Два человека с **одинаковой должностью** могут иметь **разные ключевые работы** и покупать **разные решения**. И наоборот — люди разного возраста/профессий с **одинаковой работой** ведут себя одинаково и покупают одно и то же.

### Как сегментировать по работам

1. Собери работы из интервью (граф работ для каждого респондента).
2. **Сгруппируй людей по одинаковому набору ключевых работ** (особенно по Core Job + контексту).
3. Для каждого сегмента-работы опиши: контекст, Forces (что Push/Pull/Anxiety/Habit), конкурент (часто non-consumption), критерий успеха.
4. Проверь, что **рынок шире гипотезы сегмента**: рынок = деньги на работу, сегмент = конкретная группа с этой работой.

### Пример: один продукт — разные работы (условный B2B-продукт)

| Сегмент по работе | Core Job | Что нанимает |
|---|---|---|
| HR/L&D корпорации | «команда начала пользоваться ИИ, есть видимый результат» | обучение + платформа + безопасность данных |
| Руководитель отдела | «ускорить процессы своего отдела, отчитаться наверх» | быстрые кейсы + метрики экономии времени |
| Аналитик-практик | «делать свою работу быстрее, не светить данные вовне» | доступ к инструментам + приватность + оплата в локальной валюте |

Один и тот же продукт, **три разные работы** → три разных messaging и три разных оффера. Демографически это могут быть «сотрудники крупных компаний 30–45», что ничего не объясняет.
