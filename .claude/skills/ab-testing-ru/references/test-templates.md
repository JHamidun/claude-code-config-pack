# Шаблоны A/B-тестов

Шаблоны для планирования, документирования и анализа экспериментов. Примеры — под типовой бизнес эксперта (курс, воркшоп, услуги, контент-сайт, email).

## Содержание
- План теста
- Документация результатов
- Запись в реестр тестов
- Краткий бриф теста
- Стейкхолдер-апдейт
- ICE-скоркарта приоритизации
- Бэклог гипотез

## План теста

```markdown
# A/B-тест: [Название]

## Обзор
- Владелец: [имя]
- Страница/фича: [что тестим — напр. hero /services, subject дайджеста]
- Даты: [старт] — [конец]
- Инструмент: [Метрика-эксперименты / PostHog / ручной split в Tilda / разные subject в рассылке]

## Гипотеза
Так как [наблюдение/данные],
мы считаем, что [изменение]
приведёт к [результат]
для [аудитория].
Подтвердим, если [метрика].

## Дизайн
| Элемент | Значение |
|---------|----------|
| Тип | A/B / A/B/n |
| Длительность | X недель |
| Выборка | X на вариант |
| Распределение | 50/50 |
| Реализация | client-side / server-side / редактор Tilda |

## Варианты
### Контроль (A)
[скрин] — текущий опыт.
### Вариант (B)
[скрин/макет] — [изменение]. Обоснование: [почему должно выиграть].

## Метрики
- Первичная: [метрика], база [X%], MDE [X%].
- Вторичные: [...].
- Guardrail: [что не должно ухудшиться — отписки, отток trial, lead quality].

## Сегменты для анализа
Мобайл/десктоп · B2B/B2C · источник трафика (Директ/TG/рассылка/Habr).

## Критерии успеха
Победа: первичная +X% при 95% (или байес-вероятность ≥ N%). Проигрыш: значимое падение. Неопределённо: [что делаем].

## Чеклист перед запуском
- [ ] Гипотеза задокументирована
- [ ] Первичная метрика трекается (`yandex` / продуктовая аналитика)
- [ ] Выборка посчитана, длительность оценена
- [ ] Варианты собраны и проверены (QA)
- [ ] Дата анализа в календаре
```

## Документация результатов

```markdown
# Результаты: [Название]

| | |
|---|---|
| Даты | [старт]—[конец] |
| Длительность | X дней |
| Результат | Победитель / Проигравший / Неопределённо |
| Решение | [что делаем] |

## Первичная метрика: [имя]
| Вариант | Значение | 95% ДИ | vs контроль |
|---------|----------|--------|-------------|
| Контроль | X% | [X%, Y%] | — |
| Вариант | X% | [X%, Y%] | +X% |

Стат: p = X.XX (значимо / нет) — или байес: вероятность, что B>A = N%.
Практическая значимость: [эффект в деньгах/лидах].

## Вторичные и guardrail
| Метрика | Контроль | Вариант | Δ | Значимо/Тревога? |
|---------|----------|---------|---|------------------|

## Сегменты
Мобайл vs десктоп; B2B vs B2C — lift по каждому.

## Интерпретация
Что произошло (просто) · почему думаем, что так · оговорки/внешние факторы.

## Решение и выводы
Победитель: [A/B]. Действие: [внедрить/оставить/перетест]. Выводы: [инсайты]. Что тестим дальше: [идеи]. Эффект на бизнес: [проекция].
```

## Запись в реестр тестов

```markdown
| ID | Название | Страница | Даты | Первичная метрика | Результат | Lift |
|----|----------|----------|------|-------------------|-----------|------|
| 001 | Hero /services | services | 1–15.06 | заявки на консультацию | Победа | +12% |
| 002 | Subject дайджеста | рассылка | 10–24.06 | open rate | Проигрыш | -5% |
```

## Краткий бриф (для простых тестов)

```markdown
## [Название]
Что: [одно предложение]
Зачем: [гипотеза в одну строку]
Метрика: [первичная]
Длительность: [X недель]
Результат: [TBD / ...]
Вывод: [главное]
```

## Стейкхолдер-апдейт

```markdown
## Апдейт по тесту: [Название]
Статус: Идёт / Завершён · Дней осталось: X · Выборка: X% от цели.
Предварительные наблюдения (без решений): [...]
Следующие шаги: [дата анализа → решение → внедрение].
```

## ICE-скоркарта приоритизации

| Гипотеза | Impact (1-10) | Confidence (1-10) | Ease (1-10) | ICE = ср. |
|----------|---------------|-------------------|-------------|-----------|
| Вынос CTA «Консультация» в hero /services | | | | |
| Founding-оффер X ₽ на лендинге курса | | | | |
| Соцпруф «[должность] в [компании]» у CTA | | | | |
| Сквозной CTA контент-сайт → trial продукта | | | | |

ICE = (Impact + Confidence + Ease) / 3. Сначала — наибольший. Пересмотр раз в месяц.

## Бэклог гипотез

```markdown
| ID | Зона | Наблюдение | Гипотеза | Потенциал | Статус |
|----|------|------------|----------|-----------|--------|
| H1 | контент-сайт | трафик не идёт в продукт | сквозной CTA повысит trial-старты | Высокий | Тест |
| H2 | курс | drop на тарифах | founding-оффер повысит оплату | Высокий | Бэклог |
| H3 | рассылка | низкий open | имя+цифра в subject повысит open | Средний | Бэклог |
```

## Плейбук (победитель → паттерн)

При выигрыше документируй не только правку, а **переиспользуемый паттерн**:

```markdown
## [Эксперимент]
Гипотеза: [...] · Выборка: [n/вариант] · Результат: +X% (95% ДИ [..], p=..).
Guardrail: [исход]. Сегменты: [где сильнее].
Почему сработало: [анализ].
Паттерн: [инсайт — напр. «соцпруф Company у CTA повышает заявки B2B»].
Применить к: [другие страницы/потоки].
Статус: внедрено / в очереди на масштабирование.
```
