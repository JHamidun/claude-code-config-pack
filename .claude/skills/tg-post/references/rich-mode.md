# Режим RICH — большие посты через бота

Формат RICH: таблицы, раскрывашки, цитаты, гифки, лимит 32768 знаков, отправка через бота. Читай, когда пост большой или требует вёрстки сложнее обычного текста.

## РЕЖИМ RICH — основной формат для больших постов (август 2026)

> Обычный пост в Telegram упирается в 4096 символов и не умеет ни таблиц, ни раскрывашек.
> **Rich-сообщение через бота снимает оба ограничения: лимит 32 768 символов, таблицы, спойлеры-раскрывашки, цитаты, картинки и гифки внутри текста.** В канале публикуется от имени канала, подписи автора не видно.
> Проверено на постах 989 (взлом Hugging Face), 990 (разбор сайтов) — оба собраны так.

### Когда rich, а когда обычный пост

| Rich | Обычный пост |
|---|---|
| Есть хронология, сравнение, «что почём» → просится таблица | Одна мысль, одна история |
| Есть техническая часть, нужная не всем → в раскрывашку | Всё одинаково важно |
| Больше 4096 знаков | Короткий личный пост (лучший формат по ER) |
| Есть живая гифка или схема | Одно фото или вовсе без медиа |

**Не гнаться за rich.** Лучший пост месяца — 1546 знаков обычным текстом, ER 11,94%. Rich нужен там, где содержание реально требует структуры, а не ради красоты.

### Что умеет rich-markdown

```
H2 «## Заголовок»     → крупнее жирного, один на пост
**жир**  *курсив*  `код`
> цитата              → блок цитаты
| a | b |             → таблица (киллер-фича, обычный пост так не умеет)
|---|---|
<details><summary>**Заголовок** — тизер что внутри</summary> … </details>
![alt](https://url)   → картинка ИЛИ гифка прямо в тексте
---                   → горизонтальная линия-разделитель
[текст](url)          → инлайн-ссылка
```

### Грабли rich (все пойманы вживую)

**Одиночный перенос строки схлопывается.** Голосовалка из трёх строк слипается в одну сплошную. Между строками реакций — пустая строка, всегда.

**Картинки только по URL.** Локальный файл вставить нельзя: заливать на `your-site.example.com/images/`, оттуда `![](https://your-site.example.com/images/name.gif)`.

**Telegram кеширует картинку по адресу.** Перезаписал файл под тем же именем — в посте останется старая версия, сколько ни переотправляй. **Обновлённая картинка = новое имя файла** (`name_v2.gif`, `name-20260812.png`).

**Заголовок раскрывашки должен обещать содержимое.** Свёрнутый блок выглядит как строка со стрелкой, и непонятно, стоит ли открывать. Не «Технические детали», а «Как именно добрались до Hugging Face — датасет, чужие ключи, тринадцать часов до администратора».

**Три раскрывашки — потолок.** Дальше пост превращается в оглавление.

**Формулы `$$…$$` внутри `<details>` роняют Telegram Desktop.** Не смешивать.

**Rich трудно скопировать как обычный текст** — для постов это нормально, для инструкций хуже.

### Команда

```bash
python ~/.claude/tools/tg_bot.py --token TG_BOT_TOKEN rich \
  --to @your_channel --md-file post.md
```

Тест всегда сначала в личку: `--to <твой user_id>`.
