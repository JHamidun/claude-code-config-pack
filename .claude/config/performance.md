# Производительность: почему сессия столько стоит и как сделать дешевле

> Замерено на живой машине: 18 параллельных сессий Claude Code.

## Из чего складывается цена одной сессии

Сам Claude Code занимает примерно полгигабайта. Всё остальное — MCP-серверы,
и их оказывается **вдвое больше по весу, чем самой программы**. При восемнадцати
сессиях это 507 процессов операционной системы и 31 гигабайт.

Главная причина в том, как объявлен сервер. Запись вида `"command": "npx"`
разворачивается в **пять процессов**:

    cmd → node (загрузчик npx) → cmd → node (сам сервер) → conhost

Прямой запуск того же сервера даёт два. Разница — три лишних процесса на каждый
сервер в каждой сессии.

## Что даёт наибольший выигрыш

**Прямой путь вместо npx.** Замер до и после на одной машине: 28 процессов на
сессию стали 12, память с 1,73 до 0,87 гигабайта. Чтобы так стало, пакеты должны
лежать локально:

    npm install --prefix ~/.claude

После этого в объявлении сервера меняется команда — вместо `npx` пишется прямой
путь к файлу входа:

```json
"filesystem": {
  "command": "node",
  "args": ["${HOME}/.claude/node_modules/@modelcontextprotocol/server-filesystem/dist/index.js", "."]
}
```

Пакеты перечислены в `~/.claude/package.json`. Без установки всё продолжает
работать через `npx` — просто дороже.

**Осторожно с плагинными серверами.** Их объявления живут в собственных
`.mcp.json` внутри папки плагина, и править надо ТАМ, а не переносом в
`settings.json`. Причина: имя инструмента складывается из места объявления —
`mcp__plugin_playwright_playwright__*` против `mcp__playwright__*`. Навыки зовут
первое имя, и после переноса перестанут находить инструмент. Плата за правку на
месте: путь содержит версию плагина, после обновления правку надо повторить.

## Хуки: платим за запуск, а не за работу

Каждый хук на событии `PreToolUse` — это запуск процесса на **каждый** вызов
инструмента. Замер: два хука по 75 и 72 миллисекунды, при этом сама их логика
занимает около трёх. Остальное — рождение процесса.

Отсюда правило: **один хук вместо нескольких**. Объединённый `guard.js` разбирает
имя инструмента внутри себя и применяет нужный набор правил — поведение то же,
запуск один.

Отдельно про звук завершения ответа. Команда через PowerShell стоила **2613
миллисекунд на каждый ответ**: 1453 из них — холодный старт PowerShell, который
ничего не делает, и ещё 390 — сами гудки, они блокирующие. Для сравнения `node`
стартует за 303 миллисекунды. В этом паке звукового хука нет.

## Таймаут подключения

`MCP_TIMEOUT` по умолчанию 30 секунд. Значение 120 когда-то ставили, чтобы
пережить медленный `npx`; после перехода на прямые пути оно только вредит —
неудачный старт сервера держит сессию вчетверо дольше.

## Антивирус

Windows Defender проверяет каждый читаемый файл. При старте сессии Claude Code
читает около 950 файлов плагинов, и замер даёт **6 секунд** только на проверку.
Исключение папки `~/.claude` в настройках Defender снижает это до 176
миллисекунд — в тридцать четыре раза.

Размен честный: исключённая папка не проверяется, включая плагины из
маркетплейса. Кто ставит чужие плагины, может исключить только
`~/.claude/plugins`, оставив под наблюдением `hooks`, `scripts` и `tools` — там
исполняемое.

## Главное, что не чинится настройками

Субагенты внутри одной сессии делят MCP-серверы с родителем. Пятьдесят
субагентов стоят примерно как одна сессия. Пятьдесят отдельных сессий — это
пятьдесят полных комплектов серверов.

Если работа расходится на много параллельных задач, дешевле держать её внутри
одной сессии, чем открывать сессию под каждую.

## Чем измерить у себя

    python ~/.claude/scripts/session_cost.py            # что происходит сейчас
    python ~/.claude/scripts/session_cost.py --save     # запомнить как точку отсчёта
    python ~/.claude/scripts/session_cost.py --compare  # сравнить после правок

Считает вместе с `conhost`: без него цифра занижается почти вдвое.

## Режим обхода разрешений навязывал работу через Bash

Пока стоит `bypassPermissions`, Claude Code подмешивает в сессию указание
предпочитать `Bash` (cat, grep, sed) вместо `Read`, `Edit` и `Write`. Каждый
такой вызов — это запуск процесса операционной системы, тогда как встроенные
инструменты выполняются внутри уже запущенного. На машине с несколькими
параллельными сессиями разница заметна.

Указание выключается отдельно от самого режима: автономность и отсутствие
запросов на подтверждение сохраняются, меняется только выбор инструментов.

```json
"env": { "CLAUDE_CODE_THRIFTY_SONIC": "false" }
```

Переменные окружения читаются при старте процесса — правка действует со
следующей сессии, не с текущей.
