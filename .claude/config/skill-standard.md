# СТАНДАРТ НАВЫКА (SKILL.md)

> Основание: официальная документация Claude Code, спецификация Agent Skills,
> платформенный гайд Anthropic, репозиторий anthropics/skills. Ссылки — в конце.
> Файл — рабочий чеклист для агентов, правящих навыки. Критерии бинарные:
> по каждому выносится «да / нет», а не «в целом неплохо».

## 0. Механика, из которой следует всё остальное

1. В промпт при старте грузятся ТОЛЬКО `name` + `description` всех навыков (листинг).
2. Тело SKILL.md грузится при вызове и **остаётся в контексте до конца сессии**
   («the rendered SKILL.md content enters the conversation as a single message and
   stays there for the rest of the session»). Каждая строка тела — повторяющаяся трата.
3. Файл повторно НЕ перечитывается: то, что должно действовать всю задачу, пиши
   постоянными указаниями, а не одноразовыми шагами.
4. Вложенные файлы (`references/`, `assets/`) не стоят ничего, пока их не прочитали.
   `scripts/` не стоят ничего вообще, если их запускают, а не читают.
5. После авто-компакта у каждого вызванного навыка сохраняются первые **5 000 токенов**,
   общий бюджет на все навыки — **25 000 токенов**, заполняется от свежих к старым.
   Что не влезло — теряется молча.

**Отсюда приоритет правок:** `description` (всегда в контексте, у ВСЕХ навыков) →
тело часто вызываемых навыков → тело редких. Резать редкий навык на 20 КБ — почти
бесполезно; сократить его описание на 200 знаков — полезно всегда.

## 1. Жёсткие лимиты (нарушение = дефект)

| Что | Лимит | Источник |
|---|---|---|
| `name` | ≤64 знака, только `a-z0-9-`, не начинается/кончается дефисом, без `--`, совпадает с именем папки | spec |
| `description` | ≤1024 знака, непустое, без XML-тегов | spec (hard), platform docs |
| `description` + `when_to_use` в листинге | обрезаются на **1536 знаках** → ключевой сценарий ставить ПЕРВЫМ | Claude Code docs |
| Бюджет всего листинга | 1% контекстного окна модели; при переполнении описания срезаются, начиная с редко вызываемых навыков | Claude Code docs |
| Тело SKILL.md | **<500 строк** и **<5000 токенов** | spec, platform docs |
| Reference-файл | ссылка на один уровень от SKILL.md; при >100 строк — оглавление в начале | platform docs |
| Пути в тексте | только прямые слэши: `reference/guide.md` | platform docs |
| Имена MCP-инструментов | полностью: `Server:tool_name` | platform docs |

Для выгрузки на claude.ai и упаковки `package_skill.py` допустимы ТОЛЬКО шесть полей:
`name, description, license, compatibility, metadata, allowed-tools`. Любое другое поле
(`argument-hint`, `context`, `when_to_use`…) — жёсткая ошибка упаковки, а не игнор.

## 2. Frontmatter: что и когда ставить

| Поле | Ставить, когда |
|---|---|
| `description` | всегда. Единственное, что решает, сработает навык или нет |
| `when_to_use` | доп. триггерные фразы; помни — общий лимит 1536 вместе с description |
| `disable-model-invocation: true` | у навыка есть **побочные эффекты**: публикация, отправка, деплой, оплата, удаление. Бонус: описание уходит из листинга и освобождает бюджет |
| `user-invocable: false` | фоновое знание, которое человеку нечего вызывать вручную |
| `allowed-tools` | навык бесполезен без конкретных Bash/tool-вызовов. Грант живёт ОДИН ход. Внимание: у проектного навыка грант срабатывает даже в недоверенной папке |
| `disallowed-tools` | автономный цикл, которому нельзя, например, `AskUserQuestion` |
| `context: fork` (+ `agent`, `background`) | навык = самостоятельная ЗАДАЧА. Для навыка-справочника fork бессмыслен: субагент получит правила без задачи и вернётся ни с чем |
| `paths` | навык относится только к файлам по маске — точечно гасит ложные срабатывания |
| `model` / `effort` | задача заведомо требует другой модели или усилия, чем сессия |
| `argument-hint` / `arguments` | навык принимает аргументы |

## 3. `description` — правила

Формула: **[что делает: конкретные глаголы и объекты]. [Когда применять: контексты и
фразы пользователя]. [Чем НЕ является: соседние навыки].**

- третье лицо, не «Я помогу» и не «Ты можешь»;
- повелительная рамка «Use when…» / «Триггеры: …» — это инструкция агенту, а не аннотация;
- ключевой сценарий — в первом предложении (обрезка на 1536);
- конкретные термины, форматы, имена систем — по ним идёт сопоставление;
- без усилителей («обязательно вызови», «всегда используй»): просто перечисли случаи, где
  навык уместен, включая те, где пользователь не называет домен своими словами;
- границы: «НЕ: монтаж готового футажа → video-editor». Отсекает ложные срабатывания
  лучше, чем сужение основной формулировки;
- язык триггеров = язык пользователя. Русские фразы в описании правильны, если просьбы
  приходят по-русски.

Плохо: `Helps with documents` · `Обработка данных` · `Инструменты для работы с X`.
Хорошо: `Extract text and tables from PDF, fill forms, merge documents. Use when working
with PDF files or when the user mentions PDFs, forms, or document extraction.`

## 4. Тело: что писать и чего не писать

**Писать:** то, чего модель не знает — ваши конвенции, схемы, точные команды, пути,
имена ключей, грабли окружения, форматы вывода, последовательности, которые нельзя менять.

**Не писать:** объяснения общеизвестного (что такое PDF, как работает HTTP, зачем тесты),
пересказ того, что модель и так делает верно, мотивационные вставки, дублирование одного
правила в трёх местах, меню равноправных вариантов без выбора по умолчанию.

Тест на каждый абзац: **«ошибётся ли агент без этой строки?»** Нет — вырезать.

Свобода калибруется по месту, отдельно для каждого раздела:

- хрупкая операция, важна последовательность → точная команда и «не меняй флаги»;
- много валидных путей → цель и ограничения, без пошагового сценария;
- всегда: один дефолт плюс короткая аварийная альтернатива, а не список из пяти библиотек.

Рабочие приёмы (брать по надобности, не все сразу): секция «Грабли» с конкретными
неочевидными фактами; шаблон формата вывода дословно; чеклист для многошагового процесса;
петля «сделал → прогнал валидатор → починил → повтори»; план → валидация → исполнение
для пакетных и разрушительных операций.

Причину («почему так») объяснять коротко там, где она меняет решение агента в новой
ситуации. Каскад из ЗАГЛАВНЫХ «ALWAYS/NEVER/MUST» — признак того, что причину объяснить
не смогли.

## 5. Вложенные файлы и скрипты

- Больше 500 строк → выносить в `references/<тема>.md`, в SKILL.md оставлять навигацию.
- Ссылка обязана говорить, **когда** читать файл: «читай `references/api-errors.md`, если
  API вернул не-200» лучше, чем «подробности в references/».
- Один уровень вложенности. Цепочка SKILL.md → advanced.md → details.md приводит к
  частичному чтению (`head -100`) и потере данных.
- Многодоменный навык раскладывать по вариантам: `references/aws.md`, `gcp.md`, `azure.md`.
- `scripts/` — чёрный ящик: их ЗАПУСКАЮТ, а не читают. Канон Anthropic (webapp-testing):
  «Always run scripts with `--help` first… DO NOT read the source… These scripts can be very
  large and thus pollute your context window.» **Отсюда: рабочий `--help` — обязательное
  свойство скрипта навыка.** Скрипт, который до разбора аргументов открывает файл, поднимает
  браузер или идёт в API, ломает штатный способ работы с ним.
- В SKILL.md явно различать: «запусти X» и «прочитай X как справку».
- Скрипт решает, а не перекладывает: ловит ошибки и даёт внятное сообщение; константы
  объяснены (`REQUEST_TIMEOUT = 30  # ...`), а не `TIMEOUT = 47`.

## 6. Чеклист соответствия (вердикт по каждому пункту)

Метаданные

- S1 `name` ≤64, только `a-z0-9-`, совпадает с именем папки.
- S2 `description` непустое и ≤1024 знаков.
- S3 В описании есть И «что делает», И «когда применять» (маркер `Use when` / `Триггеры:` / эквивалент).
- S4 Ключевой сценарий — в первом предложении.
- S5 Третье лицо, без «Я помогу» / «Ты можешь».
- S6 Есть граница с соседними навыками, если такие есть («НЕ: … → другой-навык»).
- S7 Побочные эффекты (публикация, отправка, деплой, оплата, удаление) ⇒ `disable-model-invocation: true`.

Тело

- S8 Тело <500 строк.
- S9 Тело <5000 токенов (ориентир: <20 000 знаков).
- S10 Нет объяснений общеизвестного.
- S11 На каждый выбор есть дефолт, а не меню равных вариантов.
- S12 Нет повтора одного правила в разных секциях.
- S13 Инструкции сформулированы как постоянные, а не как разовые шаги (файл не перечитывается).
- S14 Формат вывода, если он важен, задан шаблоном, а не описан прозой.

Файлы

- S15 Все `references/*` упомянуты в SKILL.md с условием «когда читать».
- S16 Глубина ссылок = 1.
- S17 Reference-файлы >100 строк имеют оглавление.
- S18 Пути только с прямыми слэшами.
- S19 Каждый скрипт из `scripts/` отрабатывает `--help` без побочных действий и без сети.
- S20 Указано, что делать со скриптом: запускать или читать.

Проверяемость

- S21 Указаны зависимости и ключи, без которых навык не работает.
- S22 Имена MCP-инструментов даны как `Server:tool`.
- S23 Нет привязок ко времени («до августа 2025 …»); устаревшее — в раздел «старые схемы».
- S24 Нет устаревших моделей и эндпоинтов (сверять с `config/models.md`).

Вердикт: **соответствует** = ни одного «нет» среди S1–S9, S15, S19, S24.
Остальные «нет» — дефекты к исправлению, но не блокирующие.

## 7. Признаки текста «под старую модель»

Каждый — с детектором. Найдено ⇒ кандидат на вырезание; вырезать, если удаление не
меняет поведение агента.

| ID | Признак | Детектор |
|---|---|---|
| O1 | Вводная про общеизвестное: «## Overview», «Что такое X» с объяснением формата или протокола | `^#{1,3}\s*(Overview\|Введение\|Что такое\|About)` |
| O2 | Ролевая преамбула «You are an expert…», «Ты опытный…» | `(?i)you are an? (expert\|senior)\|Ты (эксперт\|опытный)` |
| O3 | Каскад ЗАГЛАВНЫХ вместо объяснения причины | ≥15 совпадений `\b(ALWAYS\|NEVER\|MUST\|IMPORTANT\|CRITICAL)\b` на файл |
| O4 | Одно правило повторено 2–3 раза «для надёжности» | поиск повторяющихся фраз |
| O5 | Меню равноправных вариантов без дефолта | «можно использовать A, B, C или D» |
| O6 | Длинные оговорки и хеджирование | `(?i)(не забудь\|обратите внимание, что\|важно помнить)` |
| O7 | Разжёвывание того, что модель делает сама (как открыть файл, как написать цикл) | глазами |
| O8 | 5+ однотипных примеров, отличающихся мелочью | глазами |
| O9 | Скриптованный диалог «если пользователь скажет X — ответь Y» | `(?i)(если пользователь\|if the user says)` |
| O10 | Эмодзи вместо структуры в заголовках | эмодзи в строках, начинающихся с `#` |
| O11 | Самооценка внутри навыка («это лучший способ», «работает отлично») | глазами |
| O12 | Приказ перепроверить СВОЮ только что сделанную работу: «double-check», «проверь ещё раз», «свежим взглядом», «второй проход», финальный чек-лист-обёртка | `(?i)(double-?check\|re-?verify\|verify before\|fresh eyes\|second pass\|перепровер\|проверь ещё раз\|убедись, что)` |
| O13 | Анти-форматные запреты, писанные против прошлого поколения: «без markdown», «не используй списки/жирный/заголовки» | `(?i)(no (markdown\|bullets\|bullet points\|headers)\|do ?n.?t use (markdown\|bullets)\|avoid (bullets\|markdown)\|без markdown\|не используй (списки\|буллеты\|жирный\|заголовки))` |
| O14 | Порог отсева вшит в саму детекцию: «сообщай только критичное», «confidence < N — выбрасывай», «обычно 2–5 находок» — теряется находка, а не её показ | `(?i)(only (report\|flag)\|be conservative\|suppression rule\|prioritize ruthlessly\|только (критич\|важн\|реальные проблемы)\|aim for \d+\s*[-–]\s*\d+)` |
| O15 | Подавление рассказа по ходу: «держи находки до финального ответа», «пиши о прогрессе кратко» | `(?i)(hold all findings\|final response only\|keep (it\|that\|updates) brief\|только в финальном ответе\|не отчитывайся по ходу)` |

O12–O15 добавлены 06.09.2026 по итогам сверки с живыми доками: модель перепроверяет себя
сама (лишние токены на ровном месте), формата теперь недобирает, а не перебирает, и молчит
в агентной работе по умолчанию. O14 — самый дорогой: порог в фазе поиска модель понимает
буквально и **не находит**; порог выносится отдельным проходом отчёта. Проверка ЧУЖОГО
выхода и внешние гейты (тесты, сборка, сканер, ответ сервера) под O12 не подпадают.

Пороговое правило: если после вычистки O1–O15 тело сократилось больше чем на треть и
ни один S-пункт не сломался — правка удачная.

## 8. Порядок безопасной правки

1. Копия рядом: `SKILL.md.bak-<ГГГГ-ММ-ДД>`. Ничего не удалять — ни навык, ни скрипт.
2. Одна правка — одна проверка. Для скрипта: `python <script> --help` до и после, вывод
   показать. Для тела: пересчитать строки и знаки, показать цифры.
3. Правка описания проверяется срабатыванием: 3–5 реалистичных запросов, из них 1–2
   «не должен сработать» (близкий по словам, но чужой по смыслу).
4. Стало хуже — откатить из `.bak` и сказать прямо.
5. Не трогать `settings.json` и `~/.claude.json`.
