# Почему навыки «не находятся» и как это чинится

## Механика

В системный промпт попадают только **имя навыка и его описание** — тело грузится
при вызове. На весь список есть бюджет в знаках, и при переполнении Claude Code
**срезает описания молча**, начиная с тех навыков, которые вызывались реже всего.
Ошибки нет нигде: навык лежит на диске, `/имя` работает, а сам себя модель
позвать уже не может.

Ловушка от этого замыкается: навык не звали → описание выкинуто → модель не
видит, что он умеет → не зовёт → он так и остаётся редко вызываемым. Для свежей
установки, где счётчик вызовов у всех нулевой, отбрасывание идёт практически
произвольно.

## Арифметика

    бюджет_в_знаках = окно_модели_в_токенах × 4 × доля
    запись видимая      = имя + 4 + длина строки
    запись без описания = имя + 2
    строка = «описание - when_to_use»     ← склейка, оба поля в бюджете

Имя присутствует **всегда** — убрать навык из листинга целиком нельзя, можно лишь
снять с него описание.

По умолчанию доля равна `0.01`. На окне в 200 000 токенов это 8 000 знаков. Пакет
до правки весил около 102 000 — то есть **срезалось порядка 93% описаний**, и
именно поэтому навыки казались нерабочими.

## Что сделано в пакете

    было    102 392 знака (~25 600 токенов), срезалось ~93%
    стало    61 600 знаков (~15 400 токенов), влезает целиком

Описания переписаны по принципу «поисковый ключ, а не витрина»: что делает —
первыми словами, дословные слова просьбы, собственные имена сервисов и скриптов,
отрицательная граница до соседнего навыка там, где их путают. Убраны подводки,
пересказ имени и перечисление всех возможностей.

Плюс подняты две настройки в `settings.json`:

```json
"skillListingBudgetFraction": 0.08,
"skillListingMaxDescChars": 400
```

Доля выбрана так, чтобы список влезал целиком даже на окне в 200 000 токенов:
61 600 знаков требуют не меньше 0.077. На окне в миллион та же доля не стоит
ничего лишнего — она лишь потолок.

Плата за это на маленьком окне — около 15 000 токенов, примерно 7% контекста.
Размен честный: альтернатива при доле по умолчанию — 88% описаний, выброшенных
молча. Кому дороже контекст, чем полнота списка, снижает долю или снимает
описания с неиспользуемых навыков (см. ниже).

**Доля — это потолок, а не резерв.** Если листинг влезает, неиспользованная часть
не стоит ни одного токена, поэтому поднимать её безопасно. Реальную цену задаёт
только суммарная длина описаний.

## Если навыков станет больше

Проверить вес:

```bash
python _check_desc.py          # длина и целостность шапок
```

Дальше по возрастанию потерь:

1. поднять `skillListingBudgetFraction` — бесплатно, пока листинг влезает;
2. сократить описания до 150 знаков — режет цену вдвое;
3. `skillOverrides` со значением `name-only` для служебных навыков — снимает
   описание, `/имя` продолжает работать;
4. то же самое в шапке навыка: `disable-model-invocation: true`.

## Что стоит знать про команды и плагины

Слэш-команды делят с навыками **один и тот же листинг** — их описания считаются
в тот же бюджет.

Навыки пакета доступны двумя путями: напрямую из `.claude/skills/` и как плагины
из встроенного маркетплейса. Пути дублируют друг друга, поэтому включать оба
сразу не нужно — иначе каждый навык окажется в списке дважды и займёт вдвое
больше бюджета.

## Стандарт описания

    description: "Что делает: ключевые имена. Триггеры: «слово», «фраза». НЕ X → skill-y."

Строго двойные кавычки, строго одна строка, внутренние кавычки — «ёлочки».
Незакрытая кавычка или перенос строки ломают разбор шапки, и навык исчезает из
списка без всякой ошибки.
