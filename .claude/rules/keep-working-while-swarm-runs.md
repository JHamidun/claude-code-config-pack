# Не засыпать, пока идёт фоновая работа

Разбор показал: спавн субагентов исправен. Ломается другое — **ход заканчивается,
сессия уходит в простой, и разбудить её нечему**. Событие о готовности приходит
не всегда: воркер мог умереть на терминальной ошибке, упереться в лимит или
оборваться вместе с соединением.

## Инвариант

**Работа в полёте → у сессии обязан быть будильник.** Одно из двух:

- фоновая работа держится **в переднем плане** (`run_in_background: false`) —
  тогда ход физически не может закончиться раньше неё;
- или запланирован **крон-будильник** (`CronCreate`), который разбудит сессию,
  даже если событие о готовности не придёт.

Третьего не дано. «Запустил в фон и закончил ход» — это и есть засыпание.

## Что выбирать

| Ситуация | Как запускать |
|---|---|
| Результат нужен следующим же шагом, делать больше нечего | передний план |
| Пока рой работает, есть чем заняться | фон **+ крон-будильник** |
| Рой дольше получаса | фон + крон, интервал соразмерен работе (не `*/1`) |
| Больше одного длинного роя | один крон на всех, проверяет всё разом |

Крон ставить **сразу при запуске**, а не «если зависнет». Ставить его постфактум
некому: сессия к тому моменту уже спит.

## Отдельный случай: упор в лимит

Восстановление после упора: **не перезапускать рой с нуля**, а
`Workflow({scriptPath, resumeFromRunId})` — готовые агенты вернутся из кэша.

Смежное: `rules/autonomous-mode.md` — про непрерывность работы внутри хода;
`rules/delegation.md` — когда вообще заводить рой.
