# Где искать, когда ответа нет сходу

Конфиг описывает не всё и местами описывает неверно: команда `/outlook` вела на
сетевую библиотеку, которая падает, тогда как рабочий путь — локальное приложение —
не был упомянут ни строкой. Диск был доступен месяцами, но не значился в маршрутизации,
и потому «не существовал». Отправка писем работала через права, о которых в конфиге
не сказано.

Отсюда правило: **отсутствие ответа в конфиге ничего не доказывает.** Прежде чем
сказать «такого нет» или спросить у владельца, пройди четыре источника — именно в
этом порядке, от дешёвого к дорогому.

## 1. Конфиг

`rules/routing.md` → `config/routing-ext.md` (там ещё 89 навыков без своей строки) →
`skills/`, `commands/`, `agents/`, `tools/`, `scripts/` списком. Файл на диске есть
чаще, чем строка о нём в таблице.

## 2. Память

`~/.claude/projects/<проект>/memory/` — MEMORY.md как указатель, дальше по ссылкам.
Там лежат решения задач, которые уже решались: рабочие команды, грабли, причины
прошлых поломок. Заметки живут дольше, чем разговор, и часто содержат ровно тот путь,
который сейчас ищется.

Быстрый вход по теме: `python ~/.claude/scripts/memory_brief.py "<тема>"` —
компактная выжимка вместо чтения всей папки.

## 3. История разговоров

Если задача уже делалась, но заметки не осталось — она осталась в переписке.

```bash
python ~/.claude/tools/search_chats.py search "<запрос>"      # компактный индекс
python ~/.claude/tools/search_chats.py timeline <id>          # контекст вокруг найденного
python ~/.claude/tools/search_chats.py get <id,id>            # полные тексты
```

Слои идут по возрастанию цены: сначала индекс, потом контекст, полные тексты — в
последнюю очередь. Так же ищутся прошлые решения по проектам:
`python ~/.claude/scripts/memory_graph.py cases "<проект>"`.

## 4. Сама система

Ключи — `~/.claude/.credentials.master.env` (568 переменных, имён больше, чем помнится).
Серверы — `~/.ssh/config`. Учётные записи почты — в самом почтовом приложении.
Установленные библиотеки — `pip list`: наличие `pywin32` означает доступ ко всему,
что умеет Windows-приложение на этой машине.

## Когда спрашивать владельца

Только после всех четырёх. Вопрос «а где взять X» уместен, если X не нашёлся ни в
конфиге, ни в памяти, ни в истории, ни в системе. Во всех остальных случаях это
перекладывание поиска на человека, у которого ответ и так лежит на его же диске.

Связано: `rules/try-before-refusing.md` — про то же, но со стороны действия: не
объявлять невозможным то, что не пробовал.
